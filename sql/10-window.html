Оконные функции

Обычные агрегаты сворачивают строки в одну; оконные функции, наоборот, сохраняют все строки и добавляют к каждой вычисленное значение по «окну» — набору строк, заданному OVER. Это инструмент для задач «последний заказ в группе», «нарастающий итог», «место в рейтинге», «разница с предыдущей строкой».

10.1Синтаксис: OVER и окно

Оконная функция вызывается как функция(…) OVER (…). PARTITION BY разбивает строки на группы (как GROUP BY, но без схлопывания), ORDER BY задаёт порядок внутри группы, а ROWS/RANGE — рамку окна.

-- номер строки внутри каждой категории по убыванию цены
SELECT name, category, price,
       ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC) AS rn
FROM products;
Окна в логическом порядке Оконные функции вычисляются после GROUP BY/HAVING, на этапе SELECT. Поэтому их нельзя использовать в WHERE: для фильтра по оконному значению нужен подзапрос или CTE.

10.2Ранжирование: ROW_NUMBER, RANK, DENSE_RANK

ФункцияПоведение при равных значениях
ROW_NUMBER()уникальный номер 1,2,3… (порядок среди равных произволен без доп. ключа)
RANK()равные значения получают один ранг, следующий — с пропуском (1,1,3)
DENSE_RANK()равные — один ранг, без пропусков (1,1,2)
SELECT name, price,
       ROW_NUMBER() OVER (ORDER BY price DESC) AS rn,
       RANK()       OVER (ORDER BY price DESC) AS rk,
       DENSE_RANK() OVER (ORDER BY price DESC) AS drk
FROM products ORDER BY price DESC;

10.3Агрегаты как окна

Агрегатные функции с OVER не схлопывают строки. Без ORDER BY они дают значение по всей партиции, с ORDER BY — нарастающий итог.

-- доля цены товара в своей категории
SELECT name, category, price,
       SUM(price) OVER (PARTITION BY category) AS cat_total,
       round(price * 100.0 / SUM(price) OVER (PARTITION BY category), 1) AS pct
FROM products;

-- нарастающий итог выручки по датам
SELECT o.created_at, SUM(i.qty * i.price) OVER (ORDER BY o.created_at) AS running_total
FROM orders o JOIN order_items i ON i.order_id = o.id;

10.4LAG и LEAD

LAG(expr) берёт значение из предыдущей строки окна, LEAD(expr) — из следующей. Классика — «разница с прошлым периодом».

SELECT o.created_at,
       SUM(i.qty * i.price) AS daily,
       LAG(SUM(i.qty * i.price)) OVER (ORDER BY o.created_at) AS prev,
       SUM(i.qty * i.price) - LAG(SUM(i.qty * i.price)) OVER (ORDER BY o.created_at) AS diff
FROM orders o JOIN order_items i ON i.order_id = o.id
GROUP BY o.created_at;

Классический паттерн «последняя строка в группе»: ROW_NUMBER() + PARTITION BY, затем фильтр WHERE rn = 1 во внешнем запросе.

-- последний заказ каждого клиента
WITH ranked AS (
    SELECT o.*, ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY created_at DESC) AS rn
    FROM orders o
)
SELECT customer_id, id, status FROM ranked WHERE rn = 1;

10.7Самопроверка

Чем оконная функция отличается от агрегата с GROUP BY?

  • Ничем
  • Оконная сохраняет все строки, агрегат схлопывает их в группы
  • Оконная быстрее
  • Оконная не поддерживает ORDER BY
Агрегат с GROUP BY возвращает одну строку на группу; оконная функция добавляет вычисленное значение к каждой строке, не удаляя их.

Почему нельзя использовать оконную функцию в WHERE?

  • Она вычисляется после WHERE (на этапе SELECT)
  • Она всегда медленная
  • Она не возвращает значение
  • Можно — это работает
Логический порядок: WHERE выполняется до SELECT, где считаются окна. Фильтр по окну — через подзапрос/CTE.

Чем RANK отличается от DENSE_RANK при равных значениях?

  • Ничем
  • RANK без пропусков, DENSE_RANK с пропусками
  • RANK даёт пропуски (1,1,3), DENSE_RANK — нет (1,1,2)
  • RANK работает только с числами
RANK пропускает номера после совпадений, DENSE_RANK идёт подряд.

Что делает LAG(x) OVER (ORDER BY …)?

  • Берёт x из следующей строки
  • Суммирует x по всем строкам
  • Удаляет дубликаты x
  • Берёт x из предыдущей строки окна
LAG — предыдущая строка, LEAD — следующая. Удобно для разниц между периодами.
Как найти «последнюю строку в каждой группе»?

Через ROW_NUMBER() OVER (PARTITION BY group_key ORDER BY sort_key DESC) в подзапросе/CTE, затем отфильтровать WHERE rn = 1 во внешнем запросе.

Что делает SUM(x) OVER (PARTITION BY g ORDER BY d)?

Нарастающий итог: для каждой строки — сумма x по всем строкам той же группы g с датой не позже текущей (по порядку d). Без ORDER BY это была бы просто сумма по всей группе.
