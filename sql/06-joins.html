JOIN: все виды соединений

Реляционная база хранит данные в разных таблицах, связанных ключами. JOIN собирает их обратно в один результат. Главное, что нужно чувствовать, — как меняется число строк: внутреннее соединение оставляет только совпадения, внешнее добавляет строки с NULL, а условие в ON и в WHERE применяется в разные моменты.

6.1INNER JOIN

Внутреннее соединение оставляет строки, для которых условие в ON истинно. Если у клиента нет заказов, он в результат не попадёт; если у клиента три заказа — его строка повторится трижды.

SELECT c.name, o.id, o.status
FROM customers c
JOIN orders o ON o.customer_id = c.id;   -- INNER JOIN == JOIN

-- соединение через USING, когда столбцы называются одинаково
SELECT c.name, o.id FROM customers c JOIN orders o USING (customer_id);
Соединение может размножать строки Соединение «многие-ко-многим» (например, заказы к позициям) умножает строки обеих таблиц. Если вы считаете суммы, размножение искажает агрегаты — агрегируйте до JOIN или используйте отдельные подзапросы.

6.2LEFT / RIGHT / FULL JOIN

Внешние соединения сохраняют строки одной или обеих таблиц, подставляя NULL в отсутствующие столбцы.

ВидСохраняетТиповая задача
LEFT JOINвсе строки левой таблицы«все клиенты и их заказы, если есть»
RIGHT JOINвсе строки правойто же, что LEFT с переставленными таблицами
FULL JOINвсе строки обеихсверка двух наборов, поиск расхождений
-- клиенты без заказов
SELECT c.name
FROM customers c LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;
Пишите LEFT JOIN, а не RIGHT JOIN RIGHT JOIN читается труднее. Любой RIGHT JOIN переписывается как LEFT JOIN перестановкой таблиц — так код читается слева направо: «из главной таблицы взять всех, присоединить второстепенную».

6.3CROSS JOIN и само-соединение

CROSS JOIN — декартово произведение: каждая строка одной таблицы соединяется с каждой строкой другой. Нужен редко (генерация комбинаций); случайный CROSS JOIN из-за забытого условия даёт миллиарды строк.

SELECT c.name, p.name FROM customers c CROSS JOIN products p;  -- 6 × 8 = 48 строк

Само-соединение — соединение таблицы с самой собой. Классический пример: «кто работает в одном городе с другим клиентом».

SELECT a.name AS c1, b.name AS c2, a.city
FROM customers a JOIN customers b ON a.city = b.city AND a.id < b.id;  -- без пар-дублей

6.4Неэквивалентные JOIN

Условие соединения не обязано быть равенством. Например, сопоставить каждую строку с «следующей по значению» или разбить на диапазоны.

-- все пары товаров, где один дороже другого
SELECT a.name, b.name FROM products a JOIN products b ON a.price < b.price;

-- «к какой ценовой группе относится товар» (таблица диапазонов)
SELECT p.name, g.label FROM products p
JOIN price_groups g ON p.price BETWEEN g.lo AND g.hi;

6.5ON против WHERE

Для INNER JOIN разницы в результате нет, но читаемость важна. Для LEFT JOIN разница принципиальна: условие в ON влияет на то, какие строки правой таблицы присоединяются, а условие в WHERE отбрасывает строки после соединения.

-- «все клиенты и их оплаченные заказы, если есть» — условие в ON
SELECT c.name, o.id FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id AND o.status = 'paid';

-- ловушка: WHERE после соединения превращает LEFT в INNER
SELECT c.name, o.id FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.status = 'paid';   -- клиенты без заказов выброшены

6.7Самопроверка

Сколько строк вернёт INNER JOIN, если у клиента нет заказов?

  • Одну строку с NULL
  • Ни одной — строка клиента не попадёт в результат
  • Все строки клиента
  • Ошибку
INNER JOIN оставляет только совпавшие пары. Клиент без заказов не имеет пары.

Чем LEFT JOIN отличается от RIGHT JOIN?

  • Какую таблицу сохранять целиком — левую или правую
  • Ничем
  • RIGHT JOIN быстрее
  • RIGHT JOIN не поддерживает NULL
Они зеркальны: RIGHT JOIN эквивалентен LEFT JOIN с переставленными таблицами.

Почему LEFT JOIN … WHERE o.status = 'paid' может «потерять» клиентов?

  • LEFT JOIN не поддерживает WHERE
  • status нельзя фильтровать
  • WHERE применяется после соединения и отбрасывает строки с NULL
  • Такого запроса нет в стандарте
У клиента без заказов o.status = NULL, условие unknown — строка выброшена, и LEFT стал INNER. Правильно — условие в ON.

Что такое CROSS JOIN?

  • Соединение по первичному ключу
  • Соединение без NULL
  • Только совпадающие строки
  • Декартово произведение: каждая строка с каждой
CROSS JOIN перемножает строки (m × n). Полезен для генерации комбинаций, опасен на больших таблицах.
Как соединение влияет на агрегаты и что с этим делать?

JOIN размножает строки, поэтому SUM/COUNT по соединённой таблице могут завышаться (одна и та же строка учитывается многократно). Решение — агрегировать в подзапросе/CTE до соединения либо агрегировать DISTINCT-значения.

Как найти строки, которые есть в одной таблице, но нет в другой?

Через антисоединение: LEFT JOIN … WHERE right.id IS NULL или NOT EXISTS. NOT EXISTS надёжнее с NULL. Для симметричной разницы двух таблиц — FULL JOIN с фильтром по NULL в обе стороны.
