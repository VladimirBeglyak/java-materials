Выражения и функции: CASE, строки, числа

В списке выборки и в WHERE можно вычислять: разветвлять логику через CASE, подставлять значения по умолчанию через COALESCE, приводить типы через CAST, обрабатывать строки и числа. Всё это считается в базе — значит, результат приходит готовым, без досчёта в приложении.

4.1CASE — условные выражения

CASE — это «if» внутри SQL-выражения. Есть две формы: с условиями и с поиском значения.

-- форма 1: набор условий WHEN … THEN (сверху вниз, первое совпадение)
SELECT name, price,
       CASE WHEN price > 20000 THEN 'дорогой'
            WHEN price > 2000  THEN 'средний'
            ELSE 'дешёвый'
       END AS price_group
FROM products;

-- форма 2: сравнение одного выражения со значениями
SELECT o.id,
       CASE o.status
            WHEN 'paid'    THEN 'оплачен'
            WHEN 'shipped' THEN 'отправлен'
            WHEN 'new'     THEN 'новый'
            ELSE 'отменён'
       END AS status_ru
FROM orders o;
CASE в GROUP BY / ORDER BY CASE — обычное выражение, поэтому его можно использовать в GROUP BY, ORDER BY и WHERE. Но в WHERE он обычно читается хуже, чем явные условия с AND/OR.

4.2COALESCE и NULLIF

-- COALESCE: первое не-NULL значение из списка
SELECT name, COALESCE(city, 'город не указан') AS city FROM customers;

-- NULLIF: вернуть NULL, если значения равны (защита от деления на ноль)
SELECT a / NULLIF(b, 0) FROM t;   -- если b = 0, результат NULL, а не ошибка

4.3CAST и преобразование типов

SELECT CAST(price AS TEXT) FROM products;      -- число в строку
SELECT CAST('42' AS INTEGER) + 1;              -- строку в число
SELECT price::text FROM products;              -- PostgreSQL-сокращение ::type
Неявные преобразования СУБД иногда приводит типы сама (например, сравнивая число и строку), но это источник сюрпризов и мешает использованию индексов. Приводите типы явно, особенно при сравнении в WHERE.

4.5Числовые функции

SELECT round(price * 1.2, 2)  AS with_vat,   -- округление до 2 знаков
       ceil(price / 1000)     AS thousands,  -- вверх
       floor(price / 1000)    AS floor_k,    -- вниз
       abs(price - 1000)      AS diff        -- модуль
FROM products;
Точность и деньги Не храните деньги во float/double — из-за двоичного представления накапливаются ошибки округления. Используйте numeric(12,2) (PostgreSQL) или DECIMAL(12,2) (MySQL).

4.7Самопроверка

Что вернёт COALESCE(NULL, NULL, 'x', 'y')?

  • NULL
  • x
  • y
  • Ошибку
COALESCE возвращает первое не-NULL значение из списка — это 'x'.

Чем полезна функция NULLIF?

  • Позволяет избежать деления на ноль и сравнивать значения, превращая равенство в NULL
  • Удаляет NULL из таблицы
  • Заменяет COALESCE
  • Она не существует
NULLIF(a,b) возвращает NULL, если a = b. Частый приём: x / NULLIF(y, 0), чтобы при y = 0 получить NULL вместо ошибки.

Как в PostgreSQL преобразовать число в текст?

  • price as text
  • text(price)
  • price::text или CAST(price AS TEXT)
  • convert(price)
Двойное двоеточие — PostgreSQL-сокращение для CAST.

Почему деньги нельзя хранить во float?

  • Float не поддерживает отрицательные значения
  • Float медленнее DECIMAL
  • Float занимает больше места
  • Из-за двоичного представления накапливаются ошибки округления
0.1 в двоичной системе — бесконечная дробь. Для денег используйте numeric/DECIMAL с фиксированной точностью.
Чем CASE с условиями отличается от CASE с поиском значения?

В форме 1 каждый WHEN — произвольное условие (проверяются сверху вниз). В форме 2 одно выражение сравнивается на равенство с перечисленными значениями. Форма 2 короче, когда нужно просто «перевести код в текст».

Можно ли использовать CASE в WHERE и зачем?

Можно, поскольку CASE — выражение. Но в WHERE его обычно заменяют явными условиями с AND/OR, которые читаются понятнее и лучше оптимизируются. В SELECT/GROUP BY/ORDER BY CASE незаменим для разбиения на категории.
