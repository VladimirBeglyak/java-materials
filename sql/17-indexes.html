Индексы и скорость: EXPLAIN

Написать запрос — половина дела; вторая половина — сделать его быстрым. Индекс — это структура, позволяющая найти строки без полного просмотра таблицы. EXPLAIN показывает, как СУБД собирается (или как выполнила) запрос, — это главный инструмент диагностики «почему медленно».

17.1Зачем нужны индексы

Без индекса поиск по условию читает таблицу целиком (Seq Scan — последовательное сканирование). Индекс позволяет найти нужные строки по ключу за логарифмическое время, как оглавление в книге.

Без индекса

WHERE email = 'anna@ex.com' — просмотр всех строк таблицы, O(n). На миллионах строк — секунды.

С индексом

Поиск по B-tree, O(log n) + чтение найденных строк. Миллисекунды.

Индекс — не бесплатно Каждый индекс ускоряет чтение, но замедляет INSERT/UPDATE/DELETE (его нужно поддерживать) и занимает место. Индексов должно быть ровно столько, сколько нужно запросам.

17.2B-tree и составные индексы

CREATE INDEX customers_city_idx ON customers (city);           -- по одному столбцу

CREATE INDEX orders_customer_status_idx                          -- составной
    ON orders (customer_id, status);
Порядок столбцов в составном индексе Индекс (a, b) ускоряет фильтры по a, по a+b, но не по одному b. Ставьте первым столбец с условием равенства, затем — сортировки/диапазона. «Правило левого префикса».

17.3EXPLAIN

EXPLAIN показывает план без выполнения, EXPLAIN ANALYZE — выполняет и добавляет реальные времена и число строк.

EXPLAIN SELECT * FROM orders WHERE customer_id = 1;

EXPLAIN (ANALYZE, BUFFERS)
SELECT c.name, o.id FROM customers c JOIN orders o ON o.customer_id = c.id
WHERE c.city = 'Минск';

17.4Покрывающие индексы

Если индекс содержит все нужные запросу столбцы, СУБД читает только индекс, не заглядывая в таблицу (Index Only Scan).

-- запросу нужны только id и email → индекс их покрывает
SELECT id, email FROM customers WHERE email = 'anna@ex.com';
CREATE INDEX customers_email_idx ON customers (email);   -- id уже в индексе (первичный ключ)

-- расширить индекс столбцами, которые не участвуют в поиске (INCLUDE)
CREATE INDEX orders_customer_idx ON orders (customer_id) INCLUDE (status, created_at);

17.5Почему запрос медленный: чек-лист

  1. Посмотрите EXPLAIN (ANALYZE, BUFFERS). Где тратится время — Seq Scan, сортировка, соединение?
  2. Нет индекса под условием WHERE/JOIN. Добавьте индекс по столбцам фильтра.
  3. Индекс есть, но не используется. Проверьте функции/преобразования над столбцом (lower(email) нужен индекс по выражению), ведущий % в LIKE.
  4. Запрос тащит лишнее. SELECT * вместо нужных столбцов, нет LIMIT, нет покрывающего индекса.
  5. N+1. Запрос выполняется в цикле по строкам — объедините в один JOIN или batch.

17.6Песочница: план SQLite

EXPLAIN QUERY PLAN (SQLite)

В SQLite план смотрится через EXPLAIN QUERY PLAN; в PostgreSQL — через EXPLAIN (ANALYZE, BUFFERS). Сравните планы «до» и «после» создания индекса — увидите, как Seq Scan сменяется поиском по индексу.

17.7Самопроверка

Что делает Seq Scan?

  • Ищет по индексу
  • Читает таблицу строку за строкой целиком
  • Сортирует строки
  • Соединяет две таблицы
Seq Scan — последовательное сканирование всей таблицы; на больших таблицах это основная причина медленных запросов.

Ускорит ли индекс (a, b) запрос с фильтром только по b?

  • Нет — индекс работает по левому префиксу, нужен a первым
  • Да, всегда
  • Только если b уникален
  • Только в MySQL
Составной индекс (a, b) использует столбцы слева направо; фильтр по одному b не сможет использовать его эффективно.

Чем EXPLAIN ANALYZE отличается от EXPLAIN?

  • Ничем
  • EXPLAIN ANALYZE не выполняет запрос
  • EXPLAIN ANALYZE выполняет запрос и показывает реальные времена и число строк
  • EXPLAIN ANALYZE только для INSERT
ANALYZE запускает запрос и добавляет фактические данные (actual time, rows) к плану.

Что такое покрывающий индекс?

  • Индекс по всем столбцам таблицы
  • Индекс только по первичному ключу
  • Индекс, который не используется
  • Индекс, содержащий все столбцы запроса — таблицу читать не нужно
Если все нужные столбцы есть в индексе, СУБД делает Index Only Scan, не читая таблицу.
Почему lower(email) = 'x' может не использовать индекс на email?

Индекс хранит исходные значения, а не lower(email). Нужен индекс по выражению: CREATE INDEX … ON t (lower(email)).

Что такое N+1 и как его лечить?

N+1 — когда для каждой из N строк выполняется ещё один запрос (например, в цикле за заказами клиентов). Лечится одним JOIN или пакетной выборкой.
