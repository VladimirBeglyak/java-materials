UPSERT, MERGE и массовые операции

Частая задача — «вставить, а если такая строка уже есть, обновить» (UPSERT) или синхронизировать таблицу с пришедшим набором данных (MERGE). Обе операции атомарны — в отличие от наивного «сначала SELECT, потом INSERT/UPDATE», который гоняет гонку при параллельных запросах.

12.1Зачем нужен UPSERT

Классический пример — счётчик остатков на складе: если запись о товаре есть, увеличить количество, если нет — создать. Сделать это через два запроса нельзя надёжно: между SELECT и INSERT другая транзакция может вставить ту же строку, и получится дубликат или потерянное обновление. UPSERT решает это одной атомарной командой.

12.2ON CONFLICT (PostgreSQL / SQLite)

-- вставить или обновить по конфликту с уникальным ключом
INSERT INTO product_stock (product_id, qty) VALUES (7, 5)
ON CONFLICT (product_id) DO UPDATE SET qty = product_stock.qty + EXCLUDED.qty;

-- или просто пропустить, если строка есть
INSERT INTO customers (email, name) VALUES ('anna@ex.com', 'Анна-2')
ON CONFLICT (email) DO NOTHING;

EXCLUDED — псевдотаблица со значениями, которые пытались вставить. Так «взять новое значение» пишется как EXCLUDED.col, а текущее — просто col.

12.3ON DUPLICATE KEY UPDATE (MySQL)

INSERT INTO product_stock (product_id, qty) VALUES (7, 5)
ON DUPLICATE KEY UPDATE qty = qty + VALUES(qty);   -- MySQL-синтаксис
Диалекты различаются PostgreSQL — ON CONFLICT, MySQL — ON DUPLICATE KEY UPDATE, стандарт SQL — MERGE. Смысл один, синтаксис разный — сверяйтесь с документацией своей СУБД.

12.4MERGE (стандарт SQL)

MERGE — более общий UPSERT: синхронизирует целевую таблицу с источником, выполняя INSERT, UPDATE или DELETE по условию совпадения.

MERGE INTO product_stock t
USING (VALUES (7, 5), (8, 3)) AS s(product_id, qty)
ON t.product_id = s.product_id
WHEN MATCHED THEN UPDATE SET qty = t.qty + s.qty
WHEN NOT MATCHED THEN INSERT (product_id, qty) VALUES (s.product_id, s.qty);

MERGE поддерживается в PostgreSQL 15+, SQL Server, Oracle; MySQL использует свой синтаксис ON DUPLICATE KEY.

12.5Массовые операции

Для загрузки миллионов строк INSERT по одной слишком медленный (каждая строка — отдельная операция). Способы ускорить:

-- 1) многострочный INSERT: меньше накладных расходов
INSERT INTO products (name, category, price) VALUES
  ('A', 'электроника', 10), ('B', 'посуда', 20), ('C', 'продукты', 30);

-- 2) COPY (PostgreSQL): пакетная загрузка из файла/потока
COPY products (name, category, price) FROM '/data/products.csv' CSV HEADER;

-- 3) в одной транзакции — COMMIT один раз, а не на каждую строку
BEGIN;
INSERT …; INSERT …; INSERT …;
COMMIT;
Правило для больших вставок Объединяйте строки в многострочный INSERT или COPY и держите всё в одной транзакции. Не делайте COMMIT на каждую строку — это превращает пакетную вставку в тысячи медленных транзакций.

12.7Самопроверка

Почему «SELECT потом INSERT/UPDATE» ненадёжен для UPSERT?

  • SELECT слишком медленный
  • Между SELECT и INSERT другая транзакция может вставить ту же строку (гонка)
  • SELECT не работает в транзакции
  • Это запрещено стандартом
Между проверкой и вставкой — окно гонки. UPSERT атомарен и решает конфликт внутри одной операции.

Что такое EXCLUDED в ON CONFLICT … DO UPDATE?

  • Значения, которые пытались вставить
  • Существующие значения строки
  • Удалённые строки
  • Заблокированные строки
EXCLUDED — псевдотаблица с предлагаемыми значениями; текущие значения доступны по обычному имени столбца.

Чем MERGE отличается от простого UPSERT?

  • Ничем
  • MERGE только удаляет
  • MERGE может выполнять INSERT, UPDATE и DELETE по условию совпадения с источником
  • MERGE работает только в MySQL
MERGE — обобщённая синхронизация: совпало — обновить/удалить, не совпало — вставить.

Как ускорить массовую вставку тысяч строк?

  • Многострочный INSERT/COPY и одна транзакция на пакет
  • COMMIT после каждой строки
  • Вставлять только по одной строке
  • Отключить первичные ключи
Пакетная вставка и один COMMIT на пакет резко снижают накладные расходы. COMMIT на строку — антипаттерн.
В чём разница между DO UPDATE и DO NOTHING в ON CONFLICT?

DO UPDATE обновляет существующую строку (например, увеличивает счётчик); DO NOTHING просто пропускает вставку, если строка с таким ключом уже есть.

Когда выбирать MERGE вместо ON CONFLICT?

Когда нужно синхронизировать таблицу с целым набором данных и возможны разные действия (вставить/обновить/удалить) в зависимости от совпадения. Для простого «вставить или обновить одну строку» ON CONFLICT короче.
