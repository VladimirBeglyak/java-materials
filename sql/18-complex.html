Сложные запросы: разбор задач

Реальные задачи почти всегда — комбинация уже изученных приёмов: JOIN + агрегация + окна + подзапросы. Здесь разберём несколько типовых задач «от вопроса к запросу», показывая сам ход мысли: как разложить формулировку на шаги SQL.

18.1Как подходить к сложному запросу

  1. Сформулируйте результат одной фразой. Что должно быть в каждой строке результата?
  2. Найдите источники. Из каких таблиц берутся данные, как они связаны (JOIN).
  3. Разбейте на подзадачи. Каждую подзадачу — отдельным CTE.
  4. Соберите и проверьте на малых данных. Прогоните в песочнице, сверьте числа вручную.

18.2Задача: топ-N в каждой группе

Вопрос: выведите по 2 самых дорогих товара в каждой категории.

WITH ranked AS (
    SELECT name, category, price,
           ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC) AS rn
    FROM products
)
SELECT category, name, price
FROM ranked WHERE rn <= 2
ORDER BY category, price DESC;
Разбор Окно PARTITION BY category нумерует товары внутри категории по убыванию цены; внешний фильтр rn <= 2 оставляет два лучших. Это универсальный паттерн «топ-N в группе».

18.3Задача: доли и проценты

Вопрос: какую долю выручки приносит каждая категория товаров?

WITH cat_revenue AS (
    SELECT p.category, SUM(i.qty * i.price) AS revenue
    FROM order_items i JOIN products p ON p.id = i.product_id
    GROUP BY p.category
)
SELECT category, revenue,
       round(revenue * 100.0 / SUM(revenue) OVER (), 1) AS share_pct
FROM cat_revenue
ORDER BY revenue DESC;
Разбор Сначала агрегируем по категориям (CTE). Затем оконная SUM(revenue) OVER () без PARTITION BY считает общую сумму по всем строкам, и доля — это revenue / общая_сумма.

18.4Задача: отчёт по клиентам

Вопрос: для каждого клиента — число заказов, сумма выручки и дата последнего заказа (включая клиентов без заказов).

SELECT c.name,
       COUNT(o.id) AS orders_cnt,
       COALESCE(SUM(i.qty * i.price), 0) AS revenue,
       MAX(o.created_at) AS last_order
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
LEFT JOIN order_items i ON i.order_id = o.id
GROUP BY c.id, c.name
ORDER BY revenue DESC;
Осторожно с JOIN перед агрегацией Соединение заказов с позициями размножает строки: COUNT(o.id) тогда посчитает позиции, а не заказы. В этой задаче COUNT(o.id) считает заказы с хотя бы одной позицией; для точного числа заказов агрегируйте заказы отдельным CTE.

18.5Задача: нарастающий итог по дням

Вопрос: нарастающая сумма выручки по датам заказов.

WITH daily AS (
    SELECT o.created_at, SUM(i.qty * i.price) AS day_revenue
    FROM orders o JOIN order_items i ON i.order_id = o.id
    GROUP BY o.created_at
)
SELECT created_at, day_revenue,
       SUM(day_revenue) OVER (ORDER BY created_at) AS running_total
FROM daily
ORDER BY created_at;

18.7Самопроверка

Какой универсальный паттерн решает «топ-N в каждой группе»?

  • ROW_NUMBER() OVER (PARTITION BY … ORDER BY …) + фильтр rn <= N
  • GROUP BY + LIMIT
  • DISTINCT
  • UNION ALL
Окно нумерует строки внутри группы, а внешний запрос отбирает нужное число по номеру.

Как посчитать долю категории в общей сумме?

  • revenue / SUM(revenue) OVER () — оконная сумма по всем строкам
  • revenue / COUNT(*)
  • SUM(revenue)
  • AVG(revenue)
SUM(x) OVER () без PARTITION BY считает общий итог по всему результату, на него и делим.

Почему JOIN перед COUNT(o.id) может исказить число заказов?

  • JOIN всегда медленный
  • COUNT не работает с JOIN
  • Соединение с позициями размножает строки заказа
  • JOIN удаляет строки
Один заказ с тремя позициями даст три строки в соединении — COUNT(o.id) посчитает три, а не один.
Сформулируйте алгоритм написания сложного запроса.

1) Опишите результат одной фразой; 2) определите таблицы-источники и связи; 3) разбейте на подзадачи через CTE; 4) соберите и проверьте на малых данных, сверяя числа вручную.

Чем «топ-N в группе» через ROW_NUMBER лучше, чем через GROUP BY + LIMIT?

GROUP BY + LIMIT даёт топ-N только по всей таблице, а не внутри каждой группы. ROW_NUMBER с PARTITION BY позволяет взять N лучших отдельно для каждой группы.
