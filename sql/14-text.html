Текст: строки, LIKE, регулярные выражения

Большинство реальных данных — текст: имена, email, адреса, логи. SQL умеет резать и склеивать строки, искать по шаблону через LIKE и полноценные регулярные выражения. Зная эти инструменты, вы перестанете «вытаскивать всё в приложение и фильтровать в цикле».

14.2LIKE и ILIKE

LIKE — поиск по простому шаблону: % — любая последовательность символов (включая пустую), _ — ровно один символ.

SELECT name FROM customers WHERE email LIKE '%@ex.com';      -- любой адрес на ex.com
SELECT name FROM customers WHERE name LIKE 'А___';           -- 4 буквы, начинается с «А»
SELECT name FROM customers WHERE name ILIKE '%а%';           -- содержит «а» без учёта регистра
Экранирование спецсимволов Чтобы найти сам символ % или _, экранируйте: LIKE '100\%' ESCAPE '\'. Ведущий % в шаблоне ('%text') мешает обычному индексу — для поиска по подстроке нужны другие средства (триграммы/полнотекст).

14.3Регулярные выражения (POSIX)

PostgreSQL поддерживает POSIX-регекс через операторы ~ (совпадение), ~* (без регистра), !~ (не совпадает).

-- email, оканчивающийся на домен из букв и точки
SELECT name, email FROM customers WHERE email ~ '^[^@]+@[a-z]+\.[a-z]+$';

-- имя начинается с гласной (без учёта регистра)
SELECT name FROM customers WHERE name ~* '^[аеёиоуыэюя]';
Регекс в других СУБД MySQL — REGEXP (или RLIKE), SQL Server — LIKE с ограниченным синтаксисом (регекс — через CLR), SQLite — REGEXP при подключённой функции. Синтаксис «~» — специфика PostgreSQL.

14.4Полнотекстовый поиск (введение)

Для поиска по большому тексту (статьи, описания) LIKE '%word%' плох: медленный и не понимает словоформы. PostgreSQL предлагает полнотекстовый поиск с индексами GIN.

-- поиск по всем формам слова (стемминг)
SELECT name FROM products
WHERE to_tsvector('russian', name) @@ to_tsquery('russian', 'мышь');
Когда что использовать Точное сравнение — =; простой шаблон — LIKE; сложный шаблон — регекс; поиск по словам в большом тексте — полнотекстовый индекс (GIN). Каждый следующий шаг дороже, но мощнее.

14.6Самопроверка

Что означает % в шаблоне LIKE?

  • Ровно один символ
  • Любую последовательность символов (включая пустую)
  • Только цифры
  • Конец строки
% — любая последовательность (включая пустую), _ — ровно один символ.

Чем ILIKE отличается от LIKE в PostgreSQL?

  • ILIKE игнорирует регистр, LIKE — чувствителен
  • Ничем
  • ILIKE быстрее
  • ILIKE работает только с числами
ILIKE — регистронезависимая версия LIKE.

Какой оператор в PostgreSQL ищет по POSIX-регексу без учёта регистра?

  • LIKE
  • ==
  • ~*
  • MATCH
~ — совпадение с регексом, ~* — без регистра, !~ — несовпадение.

Почему LIKE '%word%' плох для поиска в большом тексте?

  • Он не поддерживает русский
  • Он всегда ошибается
  • Он слишком строгий
  • Он медленный и не понимает словоформы — нужен полнотекстовый поиск
Ведущий % мешает индексу, а LIKE ищет буквальную подстроку, не понимая словоформ. Полнотекстовый индекс решает обе проблемы.
Как найти строки, содержащие сам символ %?

Экранировать его: LIKE '%\%%' ESCAPE '\' — символ после ESCAPE отменяет специальное значение следующего за ним символа.

В чём разница между LIKE, регексом и полнотекстовым поиском?

LIKE — простой шаблон с % и _; регекс — произвольный шаблон; полнотекстовый поиск — поиск по словам с учётом словоформ и индексами. Выбирайте самый простой достаточный инструмент.
