SELECT: выборка и реляционная модель

Любой запрос к данным начинается с SELECT. Он описывает, какие данные получить, а не как их искать — способ выбирает сама СУБД. Чтобы писать запросы осознанно, нужно понимать три вещи: таблица — это множество строк без гарантированного порядка, список выборки — это выражения, а SELECT * — почти всегда плохая идея в приложении.

1.1Таблица как отношение

В реляционной модели данные хранятся в таблицах (отношениях): у таблицы фиксированный набор столбцов (атрибутов), а строки — это кортежи значений. Два свойства, которые чаще всего всплывают на практике:

У строк нет порядка

Таблица — множество строк. Без ORDER BY СУБД может вернуть строки в любом порядке, и этот порядок может меняться между запусками.

Строки могут повторяться

В теории у отношения нет дубликатов, но SQL это не гарантирует: SELECT city FROM customers вернёт «Минск» столько раз, сколько клиентов из Минска. Повторения убирают явно — DISTINCT (тема 03).

1.2Базовый SELECT

Минимальная форма запроса — SELECT список FROM таблица. Список выборки — это выражения, а не только имена столбцов: в нём можно складывать, вызывать функции, писать литералы.

SELECT name, city                          -- два столбца как есть
FROM customers;

SELECT name, 'город: ' || city AS where    -- выражение + псевдоним
FROM customers;

SELECT price, price * 1.2 AS price_vat,    -- арифметика
       round(price * 1.2, 2) AS rounded    -- и функции
FROM products;

Здесь || — конкатенация строк (в MySQL используйте CONCAT). Выражение вычисляется для каждой строки: если в таблице 8 товаров, price * 1.2 посчитается 8 раз.

Что можно в списке выборки Столбец, литерал ('abc', 42), арифметика, вызов функции, CASE (тема 04), подзапрос, возвращающий одно значение (тема 07), оконная функция (тема 10). Но нельзя сослаться на псевдоним из того же списка — псевдонимы видны только в ORDER BY и снаружи (в подзапросе).

1.3Псевдонимы и квалификация имён

Псевдоним задаётся через AS (необязательно) и переименовывает столбец в результате. Псевдоним таблицы — через FROM customers AS c — сокращает запись и обязателен, когда в запросе несколько таблиц (тема 06).

SELECT c.name, c.city          -- c — псевдоним таблицы customers
FROM customers AS c;

SELECT name AS customer_name   -- AS можно опустить: SELECT name customer_name
FROM customers;
Кавычки и регистр Имена столбцов и таблиц в PostgreSQL без кавычек приводятся к нижнему регистру. Двойные кавычки "Name" сохраняют регистр и разрешают пробелы — но так делать почти никогда не нужно. Строковые литералы — только одинарные кавычки: 'Минск', а "Минск" — это идентификатор.

1.4SELECT * и его цена

SELECT * возвращает все столбцы. В песочнице и при отладке это удобно, но в приложении — антипаттерн:

Явный список столбцов

SELECT id, name, price FROM products — забираем ровно то, что нужно. Добавление столбца в таблицу не ломает код.

SELECT *

Тащит ненужные тяжёлые столбцы (TEXT, JSON), ломает код, который читает столбцы «по позиции», и мешает оптимизатору использовать покрывающие индексы (тема 17).

1.6Самопроверка

Гарантирован ли порядок строк в SELECT * FROM products?

  • Да, по первичному ключу
  • Нет — без ORDER BY порядок не определён
  • Да, по порядку вставки
  • Да, если есть индекс
Таблица — множество строк. Порядок зависит от плана, физического расположения и конкурентного доступа; единственный способ гарантировать порядок — ORDER BY.

Что вычисляется для каждой строки в SELECT price * 1.2 FROM products?

  • Значение посчитается один раз и скопируется
  • Ничего — это ошибка синтаксиса
  • Выражение price * 1.2 — для каждой строки таблицы
  • Только для строк с непустой ценой
Список выборки применяется к каждой строке результата независимо.

Почему в приложении лучше не использовать SELECT *?

  • Тащит лишние данные, ломается при изменении схемы и мешает оптимизатору
  • Он медленнее сам по себе
  • Он запрещён стандартом SQL
  • Он не поддерживает псевдонимы
Лишние тяжёлые столбцы увеличивают сетевой трафик; код, читающий столбцы по индексу позиции, ломается, если схема изменилась; оптимизатор не может использовать index-only scan.

Как в PostgreSQL указать строковый литерал Минск?

  • "Минск"
  • [Минск]
  • {Минск}
  • 'Минск'
Строки — одинарные кавычки. Двойные кавычки обозначают идентификаторы (имена столбцов/таблиц), квадратные скобки — идентификаторы в SQL Server.
Чем список выборки отличается от простого перечисления столбцов?

Это список выражений: столбец — частный случай выражения. Можно писать литералы, арифметику, вызовы функций, CASE и подзапросы; каждое выражение вычисляется для каждой строки.

Когда псевдоним столбца можно использовать в том же запросе?

Только в ORDER BY (и в HAVING/окнах в некоторых СУБД по расширению). В WHERE, GROUP BY и в списке выборки псевдоним ещё не существует из-за логического порядка выполнения.
