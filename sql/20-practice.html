20.1Итоговые задачи

Решайте в песочнице ниже. Формулировки намеренно «как из жизни» — без подсказки, какой приём использовать.

  1. Найдите трёх клиентов с наибольшей суммой выручки по оплаченным и отправленным заказам.
  2. Выведите товар, который принёс наибольшую выручку (сумма qty × price по всем заказам).
  3. Посчитайте средний чек (выручка / число заказов) отдельно для каждого города.
  4. Найдите клиентов, у которых есть и оплаченный, и отправленный заказ.
  5. Для каждого клиента выведите его самый дорогой заказ (по сумме позиций).
  6. Выведите долю каждой категории товаров в общей выручке, отсортировав по убыванию.
  7. Найдите товары, которые заказывали больше одного раза (суммарное количество > 1).
  8. Постройте нарастающую сумму выручки по датам заказов.

20.2Вопросы с собеседований

Чем WHERE отличается от HAVING?

WHERE фильтрует строки до группировки и не видит агрегаты; HAVING фильтрует группы после GROUP BY и видит агрегаты.

Чем INNER JOIN отличается от LEFT JOIN?

INNER оставляет только совпавшие пары; LEFT сохраняет все строки левой таблицы, дополняя недостающее NULL-ами.

Как работает оконная функция и когда она нужна?

Оконная функция вычисляет значение по «окну» строк (PARTITION BY/ORDER BY), не схлопывая их. Нужна для ранжирования, нарастающих итогов, lag/lead, «топ-N в группе».

Что такое транзакция и зачем она нужна?

Атомарная единица работы: либо все изменения, либо ни одного. Защищает от частичного состояния при сбоях и даёт изоляцию параллельных операций.

Как понять, почему запрос медленный?

EXPLAIN (ANALYZE, BUFFERS): искать Seq Scan на больших таблицах, отсутствующие индексы, функции над индексируемыми столбцами, N+1, лишние данные.

Что такое NULL и как с ним корректно сравнивать?

NULL — неизвестное значение; сравнение с ним даёт unknown. Проверка — IS NULL / IS NOT NULL, равенство с учётом NULL — IS NOT DISTINCT FROM.

20.3Самопроверка

Что вернёт SELECT DISTINCT a, b FROM t?

  • Уникальные a
  • Уникальные пары (a, b)
  • Уникальные b
  • Ошибку
DISTINCT применяется ко всей строке результата — уникальны комбинации всех выбранных столбцов.

Где используется псевдоним столбца из SELECT?

  • В ORDER BY (и далее снаружи), но не в WHERE/GROUP BY
  • Везде
  • Только в WHERE
  • Нигде
Логический порядок: псевдоним создаётся на шаге SELECT, поэтому виден только в ORDER BY и внешних запросах.

Какой запрос найдёт клиентов без заказов надёжно?

  • WHERE id NOT IN (SELECT customer_id FROM orders)
  • WHERE id IN (SELECT customer_id FROM orders)
  • WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id)
  • JOIN orders
NOT EXISTS корректно работает с NULL; NOT IN может вернуть пустоту при NULL в подзапросе.

Что делает SUM(x) OVER (PARTITION BY g ORDER BY d)?

  • Суммирует x по всей таблице
  • Удаляет дубликаты
  • Сортирует по g
  • Нарастающий итог x внутри группы g по порядку d
Агрегат с OVER и ORDER BY — скользящий итог по окну.

20.4Как продолжать практиковаться

  1. Решайте задачи регулярно. LeetCode (Database), SQL-Ex, StrataScratch — по одной задаче в день, формулируя ход мысли вслух.
  2. Читайте реальные планы. На PostgreSQL прогоняйте EXPLAIN своих запросов и ищите Seq Scan.
  3. Пишите на продакшен-подобных данных. Сгенерируйте таблицы на 1–10 млн строк и сравнивайте время запросов до/после индекса.
  4. Изучите внутренности. Следующий шаг — пособие «Реляционные базы данных изнутри»: планировщик, MVCC, блокировки, репликация.
  5. Соедините с приложением. JDBC/JPA — тема 22 пособия Java Core и тема 12 пособия Spring.
