Агрегация: GROUP BY и HAVING

Агрегаты сворачивают много строк в одну: сколько заказов у клиента, средний чек, максимум по группе. Ключевое правило — после GROUP BY в SELECT можно использовать только столбцы группировки и агрегаты, а фильтр по агрегатам ставится не в WHERE, а в HAVING. Понимание логического порядка SELECT снимает здесь все вопросы.

5.2GROUP BY

GROUP BY собирает строки в группы по значениям перечисленных столбцов, и агрегаты считаются отдельно для каждой группы.

SELECT category, COUNT(*) AS cnt, SUM(price) AS total
FROM products
GROUP BY category;

SELECT c.name, COUNT(o.id) AS orders_cnt
FROM customers c LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.id, c.name                  -- группируем по id и name клиента
ORDER BY orders_cnt DESC;
Правило группировки В PostgreSQL (и в стандарте) в списке выборки при GROUP BY можно использовать только столбцы группировки и выражения над агрегатами. MySQL по умолчанию это разрешает (ANY_VALUE), что скрывает ошибки — лучше включить ONLY_FULL_GROUP_BY.

5.3HAVING

HAVING фильтрует группы по агрегатам — выполняется после группировки. WHERE фильтрует строки до группировки.

-- города, где минимум 2 оплаченных/отправленных заказа
SELECT c.city, COUNT(*) AS cnt
FROM customers c JOIN orders o ON o.customer_id = c.id
WHERE o.status IN ('paid', 'shipped')   -- строки до группировки
GROUP BY c.city
HAVING COUNT(*) >= 2                    -- группы после агрегации
ORDER BY cnt DESC;

5.4DISTINCT в агрегатах и FILTER

-- несколько агрегатов с разными условиями за один проход (PostgreSQL)
SELECT customer_id,
       COUNT(*)                          AS orders_all,
       COUNT(*) FILTER (WHERE status = 'paid') AS orders_paid,
       SUM(qty * price)                  AS total
FROM orders o JOIN order_items i ON i.order_id = o.id
GROUP BY customer_id;

FILTER (WHERE …) — PostgreSQL-расширение; в других СУБД то же самое пишут через SUM(CASE WHEN … THEN 1 ELSE 0 END).

SELECT customer_id,
       COUNT(*) AS all_cnt,
       SUM(CASE WHEN status = 'paid' THEN 1 ELSE 0 END) AS paid_cnt
FROM orders GROUP BY customer_id;

5.6Самопроверка

Чем COUNT(*) отличается от COUNT(col)?

  • Ничем
  • COUNT(*) считает все строки, COUNT(col) — только не-NULL значения столбца
  • COUNT(*) работает только с GROUP BY
  • COUNT(col) быстрее всегда
COUNT(col) пропускает NULL, поэтому COUNT(*) может быть больше COUNT(col).

Где фильтровать по агрегату COUNT(*) > 1?

  • В WHERE
  • В ORDER BY
  • В HAVING
  • Нигде — это невозможно
Агрегаты считаются после WHERE (на этапе GROUP BY), поэтому фильтр по ним — в HAVING.

Что вернёт SELECT SUM(x) FROM t WHERE 1 = 0?

  • NULL
  • 0
  • Ошибку
  • Пустую таблицу
SUM по пустому множеству строк — NULL. Для нуля используйте COALESCE(SUM(x), 0).

После GROUP BY category можно ли написать SELECT category, name?

  • Да, всегда
  • Да, если name уникален
  • Да, в MySQL
  • Нет — name не входит в группировку и не агрегат
У группы нет «одного» значения name. В PostgreSQL это ошибка; MySQL при ONLY_FULL_GROUP_BY тоже.
Объясните логический порядок WHERE → GROUP BY → HAVING → SELECT.

Сначала WHERE отбирает строки. Затем GROUP BY собирает их в группы. HAVING фильтрует группы по агрегатам. И только потом SELECT вычисляет выражения и назначает псевдонимы. Поэтому WHERE не видит агрегаты и псевдонимы, а HAVING видит агрегаты, но не псевдонимы из SELECT.

Как посчитать число строк, удовлетворяющих условию, вместе с общим числом за один проход?

Через COUNT(*) FILTER (WHERE cond) в PostgreSQL, либо SUM(CASE WHEN cond THEN 1 ELSE 0 END) в любой СУБД.
