INSERT, UPDATE, DELETE, RETURNING

Запросы не только читают данные, но и меняют их. Три оператора — INSERT, UPDATE, DELETE — покрывают все изменения, а RETURNING возвращает изменённые строки сразу, без отдельного SELECT. Главное правило безопасности: прежде чем менять или удалять, проверьте условие через SELECT.

11.1INSERT

-- одна строка
INSERT INTO customers (name, city, email) VALUES ('Жанна', 'Минск', 'zh@ex.com');

-- несколько строк
INSERT INTO products (name, category, price) VALUES
  ('Флешка', 'электроника', 1200),
  ('Подставка', 'посуда', 700);

-- вставка из SELECT
INSERT INTO archived_orders (id, customer_id, status)
SELECT id, customer_id, status FROM orders WHERE status = 'cancelled';
Порядок столбцов Перечисляйте столбцы явно — так INSERT не сломается, если в таблице изменят порядок или добавят столбец со значением по умолчанию.

11.2UPDATE

UPDATE меняет существующие строки. Без WHERE он меняет всю таблицу.

UPDATE orders SET status = 'paid' WHERE id = 105 AND status = 'new';

-- обновление с подзапросом
UPDATE products SET price = price * 1.05 WHERE category = 'электроника';

-- обновление по данным другой таблицы (PostgreSQL)
UPDATE products p SET category = c.name
FROM categories c WHERE p.category_id = c.id;
UPDATE и DELETE без WHERE меняют или удаляют все строки. Привычка для ручной работы: BEGIN; UPDATE …; проверить; COMMIT; — внутри транзакции ошибку можно откатить (тема 16).

11.3DELETE

DELETE FROM orders WHERE status = 'cancelled' AND created_at < date('now', '-1 year');

-- удалить все строки (быстро, без перебора) — TRUNCATE
TRUNCATE TABLE staging_orders;
Мягкое удаление против жёсткого Во многих системах строки не удаляют физически, а помечают deleted_at. Это позволяет восстановление и аудит, но усложняет запросы (фильтр WHERE deleted_at IS NULL). Физическое DELETE оставьте для данных, которые действительно не нужны.

11.4RETURNING

RETURNING возвращает изменённые строки — так вы получаете сгенерированные id, значения по умолчанию или подтверждение изменений одним запросом.

INSERT INTO customers (name, city) VALUES ('Иван', 'Минск')
RETURNING id, created_at;                     -- сгенерированный id и дату

UPDATE orders SET status = 'paid' WHERE id = 105
RETURNING id, status;                         -- пусто, если ничего не изменилось

DELETE FROM orders WHERE id = 104
RETURNING id;                                 -- какие строки реально удалены
RETURNING — расширение PostgreSQL MySQL и SQL Server не поддерживают RETURNING (в SQL Server есть OUTPUT). Проверьте поддержку в своей СУБД.

11.6Самопроверка

Что сделает UPDATE products SET price = 0 без WHERE?

  • Ничего
  • Обнулит цену у всех строк таблицы
  • Ошибку
  • Обнулит только первую строку
Без WHERE оператор применяется ко всем строкам. Это частый источник катастроф при ручной работе.

Зачем нужен RETURNING?

  • Получить изменённые строки (id, значения по умолчанию) одним запросом
  • Откатить изменения
  • Ускорить UPDATE
  • Заблокировать строки
RETURNING возвращает изменённые строки, избавляя от отдельного SELECT после вставки.

Чем TRUNCATE отличается от DELETE без WHERE?

  • Ничем
  • TRUNCATE удаляет только часть строк
  • TRUNCATE обычно быстрее и не порождает многострочный журнал, но грубее
  • TRUNCATE — то же, что DELETE с WHERE
TRUNCATE освобождает хранилище целиком и быстрее, но без возможности фильтрации и (в некоторых СУБД) без отката.

Почему стоит перечислять столбцы в INSERT явно?

  • Это единственный допустимый синтаксис
  • Так быстрее
  • Так запрещены дубликаты
  • Запрос не сломается при изменении схемы таблицы
Явный список столбцов делает INSERT устойчивым к изменению порядка/добавлению столбцов.
Как безопасно выполнить опасный UPDATE/DELETE?

Сначала SELECT с тем же условием, чтобы увидеть затронутые строки. Затем обернуть в транзакцию: BEGIN; UPDATE/DELETE …; проверить через RETURNING или SELECT; COMMIT или ROLLBACK.

Что такое мягкое удаление и когда оно уместно?

Вместо DELETE ставится флаг/дата deleted_at. Уместно, когда нужны аудит, восстановление или «корзина». Цена — во всех запросах нужен фильтр WHERE deleted_at IS NULL.
