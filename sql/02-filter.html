WHERE: фильтрация и NULL

WHERE оставляет в результате только те строки, для которых условие истинно. Сложность не в синтаксисе, а в одном факте: сравнение с NULL даёт не true и не false, а третье значение — unknown. Большинство «странных» результатов запросов объясняется именно этим.

2.1Операторы сравнения и логики

Условие в WHERE собирается из сравнений и логических связок. Каждое сравнение вычисляется для каждой строки и даёт true, false или unknown.

ОператорСмысл
=, <> / !=равно / не равно
<, <=, >, >=сравнения
AND, OR, NOTлогика (AND приоритетнее OR)
IS NULL, IS NOT NULLпроверка на NULL
IN, BETWEEN, LIKEсокращения условий

Приоритет

NOT > AND > OR. Поэтому a OR b AND c — это a OR (b AND c). Когда сомневаетесь — ставьте скобки: читаемость важнее.

SELECT name, city FROM customers
WHERE city = 'Минск';                          -- точное равенство

SELECT name FROM products
WHERE price > 1000 AND category = 'электроника';  -- оба условия

SELECT name, city FROM customers
WHERE city = 'Минск' OR city = 'Москва';       -- эквивалентно IN ('Минск','Москва')

2.2IN, BETWEEN, LIKE

Три сокращения, которые делают условия короче и читаемее:

-- IN: равенство любому из списка
SELECT * FROM orders WHERE status IN ('paid', 'shipped');

-- BETWEEN: включительно, эквивалентно price >= 1000 AND price <= 5000
SELECT name, price FROM products WHERE price BETWEEN 1000 AND 5000;

-- LIKE: шаблон; % — любая последовательность, _ — один символ
SELECT name FROM customers WHERE email LIKE '%@ex.com';   -- заканчивается на @ex.com
SELECT name FROM customers WHERE name LIKE 'А___';        -- имя из 4 букв на «А»
LIKE чувствителен к регистру В PostgreSQL LIKE различает регистр, ILIKE — нет. В MySQL LIKE по умолчанию нечувствителен. Для поиска подстроки '%текст%'; ведущий % не даёт использовать обычный индекс (тема 17).

2.3NULL и трёхзначная логика

NULL означает «значение неизвестно или отсутствует». Любое сравнение с неизвестным даёт unknown, и WHERE отбрасывает такие строки (оставляет только true).

ВыражениеРезультат
NULL = NULLunknown
NULL <> 1unknown
NULL IS NULLtrue
true AND unknownunknown
false AND unknownfalse
true OR unknowntrue
NOT unknownunknown
ЛовушкаПричина
city <> 'Минск' не вернёт клиентов без городаNULL <> 'Минск' → unknown
NOT IN (1, NULL) вернёт пустотуx<>1 AND x<>NULL никогда не true
city NOT BETWEEN 'А' AND 'Я' пропускает NULLто же правило unknown
«Равно, включая NULL» Чтобы сравнить два значения, считая NULL равным NULL, используйте a IS NOT DISTINCT FROM b (PostgreSQL; в MySQL — <=>). Это нужно при сверке данных.

2.4Безопасная работа с NULL

-- явная проверка вместо сравнения
SELECT name FROM customers WHERE city IS NULL;

-- COALESCE: первое не-NULL значение (подробнее — тема 04)
SELECT name, COALESCE(city, '—') AS city FROM customers;

-- антисоединение без ловушки NOT IN: NOT EXISTS (тема 07)
SELECT name FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

2.6Самопроверка

Что вернёт SELECT * FROM t WHERE x NOT IN (1, 2, NULL)?

  • Все строки, кроме x = 1 и x = 2
  • Ошибку
  • Ни одной строки
  • Только строки с x = NULL
x NOT IN (1,2,NULL) = x<>1 AND x<>2 AND x<>NULL, а x<>NULL всегда unknown → условие никогда не true.

Строка с city = NULL попадёт в результат WHERE city <> 'Минск'?

  • Да, всегда
  • Нет — сравнение с NULL даёт unknown
  • Да, если есть индекс
  • Зависит от версии СУБД
unknown отбрасывается в WHERE. Нужно писать city <> 'Минск' OR city IS NULL.

Чем LIKE отличается от ILIKE в PostgreSQL?

  • LIKE чувствителен к регистру, ILIKE — нет
  • Ничем
  • ILIKE работает только с числами
  • LIKE быстрее всегда
ILIKE удобен для поиска без учёта регистра, но не использует обычный индекс по тексту.

Как правильно проверить, что значение не равно NULL?

  • x = NULL
  • x <> NULL
  • x != NULL
  • x IS NOT NULL
Сравнения с NULL дают unknown; для проверки на NULL существуют только IS NULL / IS NOT NULL.
Почему AND приоритетнее OR и как не запутаться?

По аналогии с умножением и сложением: a OR b AND c = a OR (b AND c). Чтобы не помнить, всегда ставьте скобки, когда в условии больше одной связки.

Как переписать NOT IN, чтобы не попасть в ловушку с NULL?

Использовать NOT EXISTS с коррелированным подзапросом (тема 07) либо гарантировать отсутствие NULL в списке через подзапрос с IS NOT NULL. NOT EXISTS надёжнее.
