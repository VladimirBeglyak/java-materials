Iterable и Iterator

Итератор — единый способ обойти любую коллекцию, не зная её устройства: массив, связный список, дерево, хеш-таблицу, бесконечный генератор. Разбираем контракт hasNext/next/remove, во что компилируется for-each, модель «курсора между элементами» у ListIterator (с симулятором), как написать свой итератор — от диапазона до обхода дерева — и типичные нарушения контракта.

2.1Контракт

public interface Iterator<E> {
    boolean hasNext();                 // есть ли ещё элемент; без побочных эффектов, можно вызывать сколько угодно раз
    E next();                          // вернуть следующий и сдвинуться; нет элемента → NoSuchElementException
    default void remove() {            // удалить элемент, возвращённый последним next(): один раз на next()
        throw new UnsupportedOperationException("remove");
    }
    default void forEachRemaining(Consumer<? super E> action) {
        while (hasNext()) action.accept(next());
    }
}
public interface Iterable<T> {
    Iterator<T> iterator();            // каждый вызов — НОВЫЙ независимый итератор
    default void forEach(Consumer<? super T> action) { for (T t : this) action.accept(t); }
    default Spliterator<T> spliterator() { … }   // тема 16
}
ПравилоНарушение
hasNext() идемпотентенитератор, который в hasNext читает следующую строку из файла и при повторном вызове пропускает её
next() без элемента — NoSuchElementExceptionвозврат null — клиенты не отличат конец от null-элемента
remove() — только после next(), один раздвойной remove или remove до next → IllegalStateException
Изменять коллекцию во время обхода — только через итераторlist.remove внутри for-each → ConcurrentModificationException (тема 03)

2.2Во что компилируется for-each

for (String s : list) {
    System.out.println(s);
}

for (int x : array) {
    sum += x;
}
for (Iterator<String> it = list.iterator(); it.hasNext(); ) {
    String s = it.next();                // + checkcast String
    System.out.println(s);
}
// для массивов — индексный цикл, без итератора:
for (int[] a = array, len = a.length, i = 0; i < len; i++) {
    int x = a[i];
    sum += x;
}

Итератор for-each скрыт — поэтому из такого цикла нельзя удалить элемент. Для удаления по условию есть removeIf (тема 03) или явный итератор. JIT обычно убирает объект итератора ArrayList через escape analysis, так что for-each по списку не создаёт мусора в горячем коде.

2.3ListIterator: курсор между элементами

Курсор ListIterator стоит между элементами (позиций n + 1). next() возвращает элемент справа и сдвигает курсор вправо, previous() — слева. remove() и set() действуют на элемент, возвращённый последним next/previous (lastRet), а add() вставляет перед курсором и сбрасывает lastRet.

2.4Пишем свои итераторы

record IntRange(int from, int to, int step) implements Iterable<Integer> {
    public Iterator<Integer> iterator() {
        return new Iterator<>() {
            private int next = from;
            public boolean hasNext() { return step > 0 ? next < to : next > to; }
            public Integer next() {
                if (!hasNext()) throw new NoSuchElementException();
                int r = next; next += step; return r;
            }
        };
    }
}
for (int i : new IntRange(0, 10, 3)) System.out.print(i + " ");   // 0 3 6 9
final class InOrder<T> implements Iterator<T> {
    private final Deque<Node<T>> stack = new ArrayDeque<>();
    InOrder(Node<T> root) { pushLeft(root); }
    private void pushLeft(Node<T> n) { for (; n != null; n = n.left) stack.push(n); }
    public boolean hasNext() { return !stack.isEmpty(); }
    public T next() {
        if (stack.isEmpty()) throw new NoSuchElementException();
        Node<T> n = stack.pop();
        pushLeft(n.right);                 // O(1) амортизированно, память O(высоты)
        return n.value;
    }
}
final class LineIterator implements Iterator<String>, Closeable {
    private final BufferedReader in; private String buffered; private boolean done;
    LineIterator(BufferedReader in) { this.in = in; }
    public boolean hasNext() {
        if (buffered != null) return true;
        if (done) return false;
        try { buffered = in.readLine(); } catch (IOException e) { throw new UncheckedIOException(e); }
        if (buffered == null) done = true;
        return buffered != null;
    }
    public String next() { if (!hasNext()) throw new NoSuchElementException(); String s = buffered; buffered = null; return s; }
    public void close() throws IOException { in.close(); }
}
Как работает итератор дерева со стеком
Дерево
8 (корень)3 ← 8 → 101 ← 3 → 66: 4, 7
Стек
[8, 3, 1]
Выдано
—

Спускаемся влево от корня, кладя узлы в стек: 8, 3, 1. На вершине — минимальный элемент.

Снимаем 1; у него нет правого поддерева — ничего не добавляем.

Снимаем 3; спускаемся влево от его правого ребёнка 6: кладём 6 и 4.

Каждый узел попадает в стек ровно один раз и снимается один раз — весь обход O(n), один шаг — O(1) в среднем. Память — O(высоты дерева), а не O(n).

Стек пуст — обход завершён. Так устроены итераторы TreeMap (там используются ссылки на родителя вместо стека).

2.5Тонкости

  • Iterable обходится многократно: каждый iterator() — новый итератор. Если ваш Iterable можно обойти только один раз (поток, сетевой курсор), явно документируйте или возвращайте Stream/Iterator, а не Iterable.
  • Итератор без remove — нормально: default-метод бросит UnsupportedOperationException.
  • Порядок обхода определяется реализацией: у HashSet он зависит от хэшей и ёмкости и может измениться после роста таблицы; у Set.of — случайный между запусками JVM (тема 14).
  • Enumeration (Vector, Hashtable, Collections.enumeration) превращается в итератор методом asIterator() (Java 9).

2.6Самопроверка

Список [A, B, C], ListIterator: next(), next(), remove(), remove(). Что произойдёт?

  • Удалятся B и A
  • Удалится B, второй remove бросит IllegalStateException
  • Удалятся B и C
  • ConcurrentModificationException
remove разрешён один раз на каждый next/previous.

Во что компилируется for-each по массиву int[]?

  • В Arrays.asList(array).iterator()
  • В Stream
  • В IntStream.forEach
  • В обычный индексный цикл по копии ссылки на массив и его длины
Итератор создаётся только для Iterable.

Что должен сделать next(), если элементов больше нет?

  • Бросить NoSuchElementException
  • Вернуть null
  • Вернуть последний элемент снова
  • Начать сначала
null может быть законным элементом коллекции.

Куда вставляет элемент ListIterator.add?

  • В конец списка
  • После элемента, возвращённого последним next
  • Перед курсором; следующий next вернёт тот же элемент, что и без вставки
  • В начало
И сбрасывает lastRet — remove/set сразу после add недоступны.
Почему hasNext() должен быть идемпотентным и как этого добиться для источника, который нельзя прочитать дважды?

Клиенты вызывают hasNext сколько угодно раз (в отладке, в обёртках, в условиях), и каждый вызов не должен терять данные. Для одноразового источника — буферизация «заглядывания вперёд»: hasNext читает следующий элемент в поле, если его ещё нет; next отдаёт и очищает буфер (пример LineIterator).

Итератор или Stream — что возвращать из своего API?

Коллекцию (List, Set), если данные уже в памяти и их немного — клиенту доступны все операции. Stream — если данные вычисляются лениво, их много или их удобно обрабатывать конвейером; но Stream одноразовый. Iterator — для пошагового обхода с внешним управлением, например при слиянии нескольких источников. Iterable — если обход можно повторять.
