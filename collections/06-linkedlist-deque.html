LinkedList и ArrayDeque

LinkedList — двусвязный список, который учебники рекомендуют «для частых вставок», а практика почти никогда. ArrayDeque — кольцевой буфер, лучшая реализация стека и очереди в JDK. Разбираем оба изнутри: обход узлов для get(i), накладные расходы на узел, работу кольцевого буфера с указателями head/tail (симулятор) и почему Stack устарел.

6.1LinkedList: двусвязный список

public class LinkedList<E> extends AbstractSequentialList<E> implements List<E>, Deque<E> {
    transient int size; transient Node<E> first, last;
    private static class Node<E> { E item; Node<E> next, prev; }   // 12 заголовок + 3×4 ссылки = 24 байта на узел
    Node<E> node(int index) {                                      // get(i), set(i), add(i, e) начинаются с поиска узла
        if (index < (size >> 1)) { Node<E> x = first; for (int i = 0; i < index; i++) x = x.next; return x; }
        else                     { Node<E> x = last;  for (int i = size - 1; i > index; i--) x = x.prev; return x; }
    }
}
Сколько узлов обойдёт get(i)?
Миф о быстрых вставках Вставка в середину LinkedList — O(1) только если узел уже найден (через ListIterator). Поиск позиции — O(n) по разбросанным в памяти узлам. ArrayList сдвигает элементы System.arraycopy по непрерывной памяти, что на современных CPU обычно быстрее даже для сотен тысяч элементов. Плюс 24 байта на узел против 4 байт на ссылку в массиве. 6.2ArrayDeque: кольцевой буфер

Массив и два индекса: head — первый элемент, tail — следующая свободная ячейка после последнего. Добавление в начало сдвигает head влево, в конец — tail вправо, индексы «заворачиваются» по модулю длины массива. Сдвигов элементов нет вообще.

Что попробовать Сделайте addLast ×3, затем addFirst ×2 — head «завернётся» в конец массива, хотя логически элементы идут подряд. Добавляйте, пока массив не заполнится, — увидите рост с «распрямлением» кольца. ArrayDeque не допускает null: null в poll означает «пусто».

for (char c : "({[]})".toCharArray()) {
    if ("([{".indexOf(c) >= 0) stack.push(c);

6.5Самопроверка

Что использовать как стек в современном Java?

  • Stack
  • LinkedList
  • ArrayDeque (push/pop/peek)
  • Vector
Stack наследует синхронизированный Vector и раскрывает лишние операции.

Почему цикл for (int i = 0; i < list.size(); i++) list.get(i) по LinkedList медленный?

  • Каждый get(i) обходит узлы от ближайшего конца — суммарно O(n²)
  • size() вычисляется за O(n)
  • LinkedList синхронизирован
  • Он не медленный
Используйте for-each (итератор) для последовательного обхода.

Что означает null, возвращённый ArrayDeque.poll()?

  • В очереди лежал null
  • Ошибка
  • Первый элемент удалён
  • Очередь пуста — null-элементы ArrayDeque запрещены
Поэтому null не допускается: иначе poll был бы неоднозначен.

Сколько элементов сдвигает ArrayDeque.addFirst?

  • Все
  • Ни одного: сдвигается индекс head по кольцу
  • Половину
  • Один
Копирование — только при росте массива.
Когда LinkedList всё-таки оправдан?

Редко: когда нужны частые вставки/удаления в середине очень длинного списка в позиции, уже найденной ListIterator-ом (и элементов так много, что сдвиг массива дорог); когда нужна очередь с null-элементами; когда важна стабильность времени операции без пиков роста массива. В большинстве задач ArrayList или ArrayDeque быстрее и компактнее — проверяйте бенчмарком.

Реализуйте скользящий максимум окна размера k за O(n).

ArrayDeque индексов, значения по которым убывают: для каждого i удалить из головы индексы ≤ i − k; удалить из хвоста индексы со значениями ≤ a[i] (они уже никогда не станут максимумом); добавить i в хвост; голова — индекс максимума окна. Каждый индекс добавляется и удаляется один раз — O(n).
