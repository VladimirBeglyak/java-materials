Sequenced Collections (Java 21)

25 лет в Java не было общего способа взять «последний элемент» коллекции: у List — get(size() − 1), у Deque — getLast(), у SortedSet — last(), а у LinkedHashSet — только перебор до конца. JEP 431 ввёл интерфейсы с определённым порядком встречи — SequencedCollection, SequencedSet, SequencedMap — с единым API для обоих концов и обратным представлением reversed().

15.1Новые интерфейсы

interface SequencedCollection<E> extends Collection<E> {
    SequencedCollection<E> reversed();          // представление в обратном порядке
    void addFirst(E e);  void addLast(E e);
    E getFirst();        E getLast();            // пустая → NoSuchElementException
    E removeFirst();     E removeLast();
}
interface SequencedSet<E> extends SequencedCollection<E>, Set<E> { SequencedSet<E> reversed(); }
interface SequencedMap<K, V> extends Map<K, V> {
    SequencedMap<K, V> reversed();
    Map.Entry<K, V> firstEntry();  lastEntry();  pollFirstEntry();  pollLastEntry();
    V putFirst(K k, V v);  V putLast(K k, V v);
    SequencedSet<K> sequencedKeySet();  SequencedCollection<V> sequencedValues();  SequencedSet<Entry<K, V>> sequencedEntrySet();
}
// встроены в иерархию: List и Deque → SequencedCollection; LinkedHashSet, SortedSet → SequencedSet;
// LinkedHashMap, SortedMap → SequencedMap. HashSet и HashMap — нет: у них нет определённого порядка.

15.4Самопроверка

Какие коллекции НЕ являются SequencedCollection?

  • ArrayList и LinkedList
  • TreeSet и LinkedHashSet
  • HashSet и PriorityQueue
  • ArrayDeque
У них нет определённого порядка встречи.

Что сделает linkedHashSet.addFirst(x), если x уже есть в множестве?

  • Переместит x в начало
  • Ничего
  • Бросит исключение
  • Добавит дубликат
Так же putFirst у LinkedHashMap перемещает ключ.

Что вернёт list.reversed()?

  • Новый перевёрнутый список-копию
  • Тот же список, перевёрнутый на месте
  • Неизменяемую копию
  • Представление: изменения через него отражаются в исходном списке
Без копирования данных.
Зачем понадобилось вводить SequencedCollection, если у List и Deque уже были нужные методы?

Не было общего типа для «коллекции с порядком»: нельзя было написать метод, принимающий и List, и LinkedHashSet, и Deque, и использовать их первый/последний элемент; у LinkedHashSet и LinkedHashMap не было эффективного доступа к последнему элементу и обратного обхода. Новые интерфейсы объединили существующие методы и добавили недостающие, включая обратные представления.
