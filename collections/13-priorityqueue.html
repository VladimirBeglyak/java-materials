PriorityQueue: двоичная куча

PriorityQueue всегда знает минимальный элемент, но не хранит элементы отсортированными. Внутри — двоичная куча, уложенная в обычный массив: дети узла i лежат в 2i+1 и 2i+2. Добавление «всплывает» вверх, извлечение «тонет» вниз — O(log n). Симулятор покажет каждый обмен, а заодно — почему итерация по PriorityQueue выдаёт «перемешанный» порядок.

13.1Куча в массиве

Мин-куча: каждый узел не больше своих детей; минимум — в корне queue[0]. Дерево полное (заполняется по уровням слева направо), поэтому его можно хранить без ссылок: родитель узла i — (i − 1) >>> 1, дети — 2i + 1 и 2i + 2.

Изменяемый приоритет Если изменить поле, по которому сравниваются элементы, уже внутри очереди — куча «сломается» без исключения: элемент окажется не на своём месте. Правильно: удалить (remove(o), O(n)), изменить, добавить снова; или хранить неизменяемые записи (приоритет, задача) и игнорировать устаревшие при извлечении (ленивое удаление — стандартный приём в алгоритме Дейкстры).

13.3Самопроверка

В PriorityQueue по очереди добавили 3, 1, 2. Что выведет System.out.println(pq)?

  • [1, 2, 3]
  • [3, 2, 1]
  • [1, 3, 2] — порядок массива кучи, а не сортировка
  • [3, 1, 2]
После offer(1) единица всплыла в корень, 3 ушла в q[1]; 2 добавилась в q[2] и осталась там (родитель 1 меньше). По порядку — только через poll.

Как найти 10 самых больших чисел из миллиона экономно по памяти?

  • Отсортировать все и взять последние 10
  • Мин-куча размера 10: добавлять и выбрасывать минимум при превышении
  • Макс-куча из всех элементов
  • TreeSet из всех элементов
O(n log k) времени и O(k) памяти; осторожно с дубликатами в TreeSet.
Почему PriorityQueue не годится как «отсортированный список»?

Куча поддерживает только частичный порядок (родитель ≤ детей): минимум за O(1), но произвольный элемент или k-й по порядку — нет; итерация идёт по массиву. Для постоянно отсортированного набора с поиском и диапазонами — TreeSet/TreeMap; для разовой сортировки — список и sort.

Как реализовать алгоритм Дейкстры с PriorityQueue, если у вершины уменьшается расстояние?

Java PriorityQueue не умеет decrease-key. Стандартный приём — ленивое удаление: при улучшении расстояния класть в очередь новую пару (расстояние, вершина), а при извлечении пропускать пары, где расстояние больше уже известного. Очередь содержит дубликаты, но сложность остаётся O((V + E) log V).
