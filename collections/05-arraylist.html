5.1Устройство

public class ArrayList<E> extends AbstractList<E> implements List<E>, RandomAccess, Cloneable, Serializable {
    private static final int DEFAULT_CAPACITY = 10;
    private static final Object[] DEFAULTCAPACITY_EMPTY_ELEMENTDATA = {};  // общий пустой массив
    transient Object[] elementData;   // ёмкость = elementData.length
    private int size;                 // сколько элементов реально

    public ArrayList() { elementData = DEFAULTCAPACITY_EMPTY_ELEMENTDATA; }   // массив на 10 — только при первом add

    private Object[] grow(int minCapacity) {
        int old = elementData.length;
        if (old > 0 || elementData != DEFAULTCAPACITY_EMPTY_ELEMENTDATA) {
            int newCap = ArraysSupport.newLength(old, minCapacity - old, old >> 1);  // old + old/2
            return elementData = Arrays.copyOf(elementData, newCap);
        }
        return elementData = new Object[Math.max(DEFAULT_CAPACITY, minCapacity)];
    }
    public void add(int index, E e) {
        …; modCount++;
        if (size == elementData.length) grow(size + 1);
        System.arraycopy(elementData, index, elementData, index + 1, size - index);  // сдвиг хвоста
        elementData[index] = e; size++;
    }
}

5.2Симулятор: ёмкость, сдвиги, копирования

ArrayList<Integer> list = new ArrayList<>();
Почему add в конец — амортизированно O(1) Рост в 1,5 раза: чтобы вырасти до n, массив перевыделяется ~log₁.₅(n) раз, а суммарно копируется 10 + 15 + 22 + … < 3n ссылок. На одно добавление — меньше трёх копирований в среднем. Отдельное добавление с ростом — O(n), поэтому при известном размере задайте ёмкость: new ArrayList<>(n).

5.4subList, toArray и копии

List<Integer> list = new ArrayList<>(List.of(0, 1, 2, 3, 4, 5));
List<Integer> mid = list.subList(1, 4);   // [1, 2, 3] — окно в тот же массив (offset 1, size 3)
mid.set(0, 100);                          // list = [0, 100, 2, 3, 4, 5]
mid.clear();                              // удаляет диапазон из исходного: list = [0, 4, 5]  ← идиома удаления диапазона
list.add(9);                              // структурное изменение в обход представления
mid.size();                               // ConcurrentModificationException

Integer[] a1 = list.toArray(new Integer[0]);   // предпочтительно: JVM оптимизирует, без гонки по размеру
Object[]  a2 = list.toArray();                  // Object[], не Integer[]
List<Integer> copy = new ArrayList<>(list);     // поверхностная копия (те же объекты-элементы)
List<Integer> frozen = List.copyOf(list);       // неизменяемая копия (null запрещены)
Утечка через subList bigList.subList(0, 10), сохранённый в поле, держит весь большой массив. Для долгого хранения делайте копию: new ArrayList<>(big.subList(0, 10)). То же с Arrays.asList(array) — он держит исходный массив.

Классическая «утечка устаревших ссылок» из Effective Java.
Почему коэффициент роста 1,5, а не 2?

Компромисс между частотой перевыделений и неиспользуемой памятью: при ×2 в среднем пустует до половины массива; при ×1,5 — до трети, а копирований чуть больше, но всё ещё O(1) амортизированно. Ещё один аргумент — переиспользование освобождённых блоков аллокатором (сумма предыдущих размеров при ×1,5 со временем может вместить новый блок), хотя в JVM с перемещающим GC это менее важно.

Как быстро удалить диапазон элементов из ArrayList?

list.subList(from, to).clear() — вызывает removeRange: один сдвиг хвоста и обнуление ячеек, O(n − from). Удаление по одному индексу в цикле — O(k·n).
