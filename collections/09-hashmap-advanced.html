9.1Начальная ёмкость

Конструктор new HashMap<>(c) принимает ёмкость таблицы, а не ожидаемое число элементов. Ёмкость округляется вверх до степени двойки (tableSizeFor), а таблица растёт, когда элементов больше 75% ёмкости. С Java 19 есть фабрика по числу элементов: HashMap.newHashMap(n) (и HashSet.newHashSet, LinkedHashMap.newLinkedHashMap).

Сколько будет resize для n элементов?

Пример: new HashMap<>(1000) → таблица 1024, порог 768 → при 769-м элементе resize до 2048. Guava Maps.newHashMapWithExpectedSize и Java 19 newHashMap считают правильно.

9.2Коллизии и hash flooding

Если злоумышленник может подобрать ключи с одинаковым хэшем (имена параметров HTTP-запроса, поля JSON), он превращает каждую вставку в обход длинной цепочки: n ключей — O(n²). В 2011 году эта атака (hash flooding) клала веб-серверы на многих платформах одним POST-запросом. Ответ Java 8 — деревья в корзинах: худший случай O(n log n) вместо O(n²). Для String коллизии строятся тривиально: "Aa" и "BB", и все их конкатенации одинаковой длины.

9.4Самопроверка

Сколько resize будет у new HashMap<>(1000) при добавлении 1000 элементов?

  • 0
  • 3
  • 1 — таблица 1024, порог 768
  • 10
Для n элементов нужна ёмкость ≥ n / 0.75 — используйте newHashMap(n).

Как одной строкой посчитать частоту слов в Map<String, Integer>?

  • map.merge(w, 1, Integer::sum)
  • map.put(w, map.get(w) + 1)
  • map.putIfAbsent(w, 1)
  • map.compute(w, null)
Вариант с get бросит NPE для нового слова.

Что произойдёт, если функция в compute вернёт null?

  • NullPointerException
  • В карту запишется null
  • Ничего
  • Запись с этим ключом будет удалена
Удобно для «уменьшить и удалить при нуле».

Что защищает HashMap в Java 8 от полной деградации при атаке коллизиями?

  • Случайная соль в String.hashCode
  • Превращение длинных цепочек в красно-чёрные деревья
  • Ограничение размера карты
  • Шифрование ключей
String.hashCode детерминирован и описан в спецификации.
Как сгруппировать заказы по клиенту в Map<Long, List<Order>>?

Цикл с map.computeIfAbsent(o.customerId(), k -> new ArrayList<>()).add(o) или стрим orders.stream().collect(Collectors.groupingBy(Order::customerId)) (тема 17). Если нужен порядок клиентов — groupingBy(..., LinkedHashMap::new, toList()) или TreeMap.

Почему опасно изменять HashMap внутри функции computeIfAbsent этой же карты?

computeIfAbsent уже нашёл корзину и держит ссылки на структуру; функция, добавляющая элементы (например, рекурсивная мемоизация fib через ту же карту), может вызвать resize — внешний вызов допишет узел в устаревшую таблицу. В Java 9+ HashMap бросает ConcurrentModificationException, ConcurrentHashMap — IllegalStateException «Recursive update» или взаимоблокировку. Решение: обычные get/put или отдельная структура.
