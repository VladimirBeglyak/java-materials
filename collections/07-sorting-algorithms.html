Сортировка (TimSort) и алгоритмы Collections

list.sort() для объектов — это TimSort: гибрид сортировки вставками и слиянием, который находит в данных уже упорядоченные участки и сливает их. На почти отсортированных данных он линейный. Для примитивов Arrays.sort использует другой алгоритм — Dual-Pivot Quicksort. Разбираем оба, стабильность, бинарный поиск с «точкой вставки» и полезные алгоритмы класса Collections.

ArrayList.sort сортирует собственный массив на месте и увеличивает modCount (итераторы, созданные до сортировки, станут недействительными). Реализация по умолчанию List.sort копирует список в массив, сортирует и записывает обратно через ListIterator.set — поэтому сортировка LinkedList тоже O(n log n).

7.2TimSort по шагам

TimSort на 24 элементах (minrun = 4 вместо реальных 32–64)
Почему стабильность важна Стабильная сортировка сохраняет относительный порядок равных элементов. Поэтому сортировку по нескольким ключам можно делать последовательно: сначала по имени, затем по отделу — внутри отдела имена останутся упорядоченными. И поэтому TimSort не может использовать быстрый, но нестабильный quicksort для объектов.

7.3Бинарный поиск и точка вставки

Collections.binarySearch(sorted, key)

Список должен быть отсортирован тем же компаратором, иначе результат не определён. (lo + hi) >>> 1 вместо (lo + hi) / 2 — защита от переполнения int (знаменитый баг, найденный в JDK в 2006 году). Для LinkedList binarySearch работает итератором — O(n) переходов, но O(log n) сравнений.

  • Это ошибка JDK
  • Равные примитивы неразличимы — стабильность не имеет смысла, а нестабильный Dual-Pivot Quicksort быстрее и без доп. памяти
  • int[] сортируется TimSort
  • Стабильность включается флагом
Для объектов стабильность различима — поэтому TimSort.

Что произойдёт с итератором ArrayList, созданным до вызова list.sort(...)?

  • Он продолжит обход в новом порядке
  • Ничего

  • Он вернёт старый порядок
ArrayList.sort считается структурным изменением.
Объясните идею TimSort.

Реальные данные часто частично упорядочены. TimSort проходит массив, выделяя естественные runs (неубывающие или строго убывающие — последние разворачиваются), короткие runs дополняет до minrun (32–64) бинарной сортировкой вставками, кладёт runs в стек и сливает их, поддерживая инварианты длин (A > B + C, B > C), чтобы слияния были сбалансированы. Слияние использует временный буфер размером с меньший run и режим galloping при длинных сериях. Стабильна, O(n log n) в худшем случае и O(n) на упорядоченных данных.

Как найти k наибольших элементов из миллиона без полной сортировки?

PriorityQueue (мин-куча) размера k: добавлять элементы, при превышении k — удалять минимум; итог — k наибольших за O(n log k) и O(k) памяти (тема 13). Для k порядка n — частичная сортировка или quickselect.
