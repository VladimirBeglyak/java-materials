EnumSet, EnumMap, IdentityHashMap, WeakHashMap

Специализированные множества и карты, которые в своих задачах в разы быстрее и компактнее HashMap: EnumSet — битовая маска в одном long, EnumMap — массив по ordinal, IdentityHashMap — открытая адресация и сравнение по ==, WeakHashMap — ключи, не мешающие сборке мусора. И заодно — как устроен сам HashSet.

11.1HashSet — это HashMap

public class HashSet<E> … {
    private transient HashMap<E, Object> map;
    private static final Object PRESENT = new Object();          // одно общее значение-заглушка
    public boolean add(E e)      { return map.put(e, PRESENT) == null; }
    public boolean contains(Object o) { return map.containsKey(o); }
    public Iterator<E> iterator() { return map.keySet().iterator(); }
}
// LinkedHashSet → LinkedHashMap, TreeSet → TreeMap, ConcurrentHashMap.newKeySet() → CHM
// любую Map можно превратить в Set: Collections.newSetFromMap(new WeakHashMap<>())

Следствие: элемент HashSet стоит столько же, сколько запись HashMap (~32 байта узла + слот таблицы), все свойства — порядок, null, fail-fast — те же.

11.2EnumSet: множество как биты

Для enum с ≤ 64 константами RegularEnumSet хранит множество в одном long: бит i = константа с ordinal() == i. Больше 64 — JumboEnumSet с массивом long. Все операции — побитовые, порядок итерации — по ordinal, памяти — 8 байт.

11.3IdentityHashMap: равенство по ==

Нарушает общий контракт Map сознательно: ключи сравниваются по ссылке, хэш — System.identityHashCode. Устроена иначе, чем HashMap: открытая адресация с линейным пробированием в одном массиве, где ключи и значения чередуются: [k0, v0, k1, v1, …].

11.4WeakHashMap

Ключи хранятся через WeakReference: когда на ключ больше нет сильных ссылок, GC его соберёт, а запись удалится при следующем обращении к карте (через ReferenceQueue). Применение — метаданные «рядом» с чужими объектами, не продлевающие им жизнь. Ловушки — значение, ссылающееся на ключ (запись не удалится никогда), строковые литералы и интернированные строки как ключи, отсутствие потокобезопасности. Подробно — в пособии «JVM изнутри», тема 15.

  • Сравнивает ключи по ==, использует identityHashCode и открытую адресацию
  • Хранит ключи в дереве
  • Потокобезопасна
  • Запрещает null

Сколько памяти дополнительно занимает элемент HashSet по сравнению с записью HashMap?

  • Вдвое меньше
  • Столько же — HashSet хранит элементы ключами HashMap с общим значением-заглушкой
  • Вдвое больше
  • Ноль байт
Для enum — EnumSet, для чисел — примитивные множества.
Зачем EnumMap, если HashMap работает с enum-ключами?

EnumMap — массив размером с число констант, индекс — ordinal: нет хэширования, коллизий, узлов; порядок итерации — по объявлению констант; меньше памяти и быстрее. null-ключи запрещены, значения — можно. Аналогично EnumSet вместо HashSet<Enum>.

Открытая адресация против цепочек: плюсы и минусы.

Открытая адресация (IdentityHashMap, многие C++/Rust таблицы, примитивные коллекции) хранит всё в одном массиве: нет узлов, лучше локальность памяти, меньше памяти. Минусы: деградация при высоком заполнении (кластеризация), сложнее удаление (сдвиг или «надгробия»), нужен низкий load factor. Цепочки (HashMap) терпимее к плохим хэшам и высокой загрузке, позволяют деревья в корзинах, но тратят память на узлы и хуже по кэшу.
