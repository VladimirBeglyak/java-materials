# labgen — генератор раздела «Практикум» для пособий

Берёт спецификацию главы (`labs/<пособие>/<NN>.lab`), **реально выполняет** все команды на локальном JDK,
подставляет настоящий вывод и вставляет раздел `<h2 id="hands-on">` в страницу главы перед заданным якорем
(обычно `quiz`). Повторный запуск заменяет блок между `<!-- hands-on:start -->` и `<!-- hands-on:end -->`
и перенумеровывает разделы главы.

## Запуск

```bash
./fetch-jars.sh                      # один раз: JOL, H2, JUnit, AssertJ, Mockito, Maven → jars/
python labgen.py jvm/03              # сгенерировать и вставить главу 03 пособия jvm
python labgen.py java-core/11 --dry  # только прогнать, страницу не трогать
python labgen.py jvm/03 --fresh      # игнорировать кэш и перезапустить все команды
python setup.py                      # раздел «подготовка рабочего места» в index.html пособий
```

Нужны JDK 25 в `PATH`, bash (на Windows — Git Bash; путь можно задать `LABGEN_BASH`), для главы jvm/22 — Docker.
Для пособия `computer-science` нужен Docker-образ `cs-lab` (Temurin 25 + gcc, binutils, strace, procps) — Dockerfile приведён
на странице `computer-science/index.html#lab-setup`; собрать: `docker build -t cs-lab .`. Раздел подготовки рабочего места
этого пособия написан вручную в его `index.html` (не через `setup.py`).
Вывод снят на JDK 25.0.2; строка с версией — константа `JDK` в `labgen.py`.

- `run/<пособие>/<NN>/` — рабочий каталог главы (общий для всех лаб главы, пересоздаётся при каждом прогоне).
- `cache.json` — выводы команд. Если спецификация главы не менялась, команды не перезапускаются.
- `review/<пособие>-<NN>.txt` — команды и вывод для проверки глазами. **Ответы в `@answer` сверяйте с этим выводом.**

## Формат спецификации

```
@chapter 03 | quiz                  номер главы | id h2, перед которым вставить раздел
@intro … @end                       вступление раздела (HTML)
@lab 3.1 | Заголовок | 15 мин
@goal … @end                        цель лабы (HTML)
@step текст шага (HTML, одна строка)
@file Path/Name.java … @end         файл: пишется в рабочий каталог и показывается
@run [opts] … @end                  команды: выполняются и показываются вместе с выводом
@exec [opts] … @end                 команды: выполняются, но не показываются (фон, kill, подготовка)
@output [title=…] … @end            вывод, заданный вручную
@ide текст                          синяя плашка «IDEA» (VM options и т. п.)
@note текст                         абзац-пояснение
@html … @end                        произвольный HTML
@predict вопрос                     шаг с полем прогноза; ответ — @answer … @end
@try … @end                         эксперименты: «вопрос ::: ответ» по строке
```

Опции `@run`/`@exec`: `noout`, `fail` (ненулевой код ожидаем), `grep=REGEX`, `head=N`, `tail=N`,
`timeout=S`, `title=…`, `open`.

В строке команды `показать ||| выполнить` — пользователь видит левую часть (форма для Windows/IDEA),
генератор выполняет правую (bash). Строка, начинающаяся с `#!`, выполняется, но не показывается.
`<pid>` в показываемых командах обычно заменяется в выполняемой части поиском через `jcmd | grep Класс`.

Внешние jar лабы берут из `../../../jars/` (относительно `run/<пособие>/<NN>/`).

## Компонент на странице

Разметку `.lab` оживляет `initLabs()` в `assets/app.js` пособия (галочки шагов, прогнозы — в localStorage,
переключатель «набираю руками»), стили — блок «Практикум: лабораторные» в `assets/style.css`.
Для нового пособия скопируйте оба блока и добавьте вызов `initLabs()` при `DOMContentLoaded`.

`edlib.py` — мелкая утилита для пакетных правок спецификаций: `python edlib.py fix.py`, где в `fix.py`
вызовы `ed(path, [(old, new), …])`.
