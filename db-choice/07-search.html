Поисковые движки: OpenSearch, Elasticsearch

Поиск для людей — не WHERE name LIKE '%…%'. Нужно понимать словоформы и опечатки, ранжировать по релевантности, считать фасеты («бренд: 12, цвет: 7») по миллионам документов за десятки миллисекунд. Это делают поисковые движки на основе Lucene. Разбираем инвертированный индекс, анализаторы, BM25, устройство кластера, синхронизацию с основной базой — и когда хватит поиска PostgreSQL.

7.1Инвертированный индекс и анализ текста

При индексации текст проходит анализатор: разбиение на слова (tokenizer), приведение к нижнему регистру, удаление стоп-слов, стемминг или лемматизация («ноутбуки» → «ноутбук»), синонимы. Получившиеся термы попадают в инвертированный индекс: терм → список документов (+ частоты, позиции). Запрос анализируется тем же анализатором и сводится к пересечению/объединению списков.

7.3Устройство: шарды, реплики, сегменты

  • Индекс делится на первичные шарды (число задаётся при создании; поменять — reindex/split), у каждого — реплики. Запрос рассылается на все шарды, результаты сливаются координатором.
  • Каждый шард — индекс Lucene из неизменяемых сегментов (как LSM): новые документы попадают в буфер и становятся видимы после refresh (по умолчанию раз в секунду) — поиск «почти в реальном времени».
  • Обновление документа = удаление старого + добавление нового; сегменты сливаются в фоне (merge).
  • Ориентиры: шард 10–50 ГБ; слишком много мелких шардов — накладные расходы на каждый.
Не основная база Нет транзакций, обновления дорогие, видимость с задержкой, исторически были случаи потери данных при разделениях сети, изменение маппинга требует переиндексации. Источник истины — основная база; поисковый индекс должен уметь пересобраться из неё целиком (полная переиндексация через alias: собрать новый индекс, переключить алиас).

7.5Когда хватит PostgreSQL

PostgreSQL FTS + pg_trgm

  • до миллионов документов
  • простая релевантность (ts_rank), стемминг, фразы
  • поиск по подстроке и опечаткам — триграммы
  • согласованность с данными в одной транзакции
  • нет второй системы

Поисковый движок

  • большие каталоги и высокий QPS поиска
  • сложная релевантность, бусты, синонимы, персонализация
  • фасеты по многим полям на каждой выдаче
  • автодополнение, подсветка
  • логи и полнотекстовая аналитика (ELK)

7.6Самопроверка

Почему поиск «ноутбуки» может не находить «ноутбук» в поисковом движке?

  • Индекс повреждён
  • Анализатор не делает стемминг (или запрос и поле анализируются разными анализаторами)
  • Нужен refresh
  • Документ слишком длинный
Совпадение — на уровне термов после анализа.

Как правильно обновлять поисковый индекс при изменении товара в PostgreSQL?

  • Писать в обе системы из контроллера
  • Перестраивать индекс при каждом запросе
  • Хранить товары только в поисковом движке
  • Через outbox или CDC с идемпотентной индексацией документа по id и версии
Двойная запись без координации даёт расхождения.

Почему документ, только что проиндексированный, может не находиться секунду?

  • Видимость появляется после refresh, который по умолчанию раз в секунду
  • Репликация синхронная
  • Индекс заблокирован
  • Документ ещё анализируется вечно
Near-real-time: компромисс между свежестью и стоимостью создания сегментов.

Что делает IDF в BM25?

  • Учитывает длину документа
  • Считает число повторов терма
  • Даёт больший вес редким в коллекции термам
  • Исправляет опечатки
«Ноутбук» в магазине ноутбуков почти ничего не различает, а «oled» — многое.
Как изменить маппинг поля в индексе с данными без простоя?

Создать новый индекс с новым маппингом, переиндексировать данные (из основной базы или _reindex из старого индекса), параллельно дописывать новые изменения в оба индекса (или догнать по CDC), переключить алиас, на который смотрит приложение, атомарно на новый индекс, удалить старый.

Что такое гибридный поиск и зачем он?

Объединение лексического (BM25: точные слова, артикулы, имена) и семантического поиска (векторы: смысл, перефразирования). Результаты двух поисков сливаются, например, Reciprocal Rank Fusion. Даёт лучшее качество, чем каждый по отдельности: векторы плохо ищут точные коды, BM25 — синонимы и смысл.
