Графовые базы

Когда главное в данных — связи: «друзья друзей, которые работают в той же компании», «через какие счета прошли деньги», «какие сервисы пострадают, если упадёт этот», — запросы превращаются в обходы на переменную глубину. Графовые базы хранят связи как прямые указатели и обходят их без JOIN. Разбираем модель property graph, Cypher, когда граф действительно выигрывает, а когда хватит рекурсивного CTE (песочница), и подводные камни: суперузлы и шардинг.

10.1Модель property graph

  • Узлы с метками и свойствами: (:Person {name: "Анна"}), (:Company {name: "Acme"}).
  • Связи — направленные, типизированные, тоже со свойствами: -[:WORKS_AT {since: 2021}]->.
  • Хранение со «смежностью без индекса» (index-free adjacency, Neo4j): узел хранит ссылки на свои связи, переход к соседу — разыменование указателя, а не поиск по индексу.
MATCH (me:Person {id: 42})-[:KNOWS]->(:Person)-[:KNOWS]->(fof:Person)-[:WORKS_AT]->(c:Company)
WHERE (me)-[:WORKS_AT]->(c) AND NOT (me)-[:KNOWS]->(fof) AND fof <> me
RETURN fof.name, count(*) AS mutual
ORDER BY mutual DESC LIMIT 10;

// кратчайший путь до 6 шагов
MATCH p = shortestPath((a:Person {id: 42})-[:KNOWS*..6]-(b:Person {id: 777})) RETURN p;

Для многих задач достаточно таблицы рёбер и рекурсивного CTE (в PostgreSQL — то же самое, плюс расширение Apache AGE для Cypher прямо в PostgreSQL).

10.4Когда граф — правильный выбор

ЗадачаПочему граф
Антифрод: кольца связанных аккаунтов, общие устройства и картыпаттерны на 3–6 шагов с фильтрами по пути
Рекомендации «люди/товары рядом»обходы с подсчётом общих соседей
Граф знаний, онтологии, GraphRAGгибкие связи разных типов, запросы по путям
Зависимости: сеть, сервисы, цепочки поставоканализ влияния, кратчайшие пути
Права доступа с вложенными группами (ReBAC, Zanzibar)проверка «есть ли путь пользователь → ресурс»
Подводные камни Суперузлы (знаменитость с миллионом подписчиков) делают обход через них неподъёмным — нужны фильтры по типам связей и ограничения. Шардинг графа — сложная задача: любой разрез режет связи, и обход начинает ходить по сети; большинство графовых баз масштабируют чтение репликами, а не разбиением. Аналитика по всему графу (PageRank, сообщества) — это пакетные алгоритмы (Neo4j GDS, Spark GraphFrames), а не OLTP-запросы.

10.5Варианты

  • Neo4j — самая зрелая, Cypher (основа стандарта GQL, ISO 2024), библиотека графовых алгоритмов.
  • Memgraph — в памяти, совместим с Cypher, для потоковых сценариев.
  • Amazon Neptune — управляемый, property graph (Gremlin/openCypher) и RDF (SPARQL).
  • Apache AGE — Cypher внутри PostgreSQL; рекурсивные CTE — для неглубоких обходов без новой системы.
  • RDF-хранилища (GraphDB, Virtuoso) — для семантических данных и онтологий.

10.6Самопроверка

Какой запрос — сильный довод в пользу графовой базы?

  • Список заказов клиента
  • Сумма продаж по месяцам
  • Найти цепочки переводов длиной до 6 между подозрительными счетами с фильтрами на каждом шаге
  • Поиск товара по названию
Обходы переменной глубины — специализация графов.

Что такое index-free adjacency?

  • Узел хранит прямые ссылки на свои связи, переход к соседу не требует поиска по индексу
  • Отсутствие любых индексов в базе
  • Хэш-индекс по рёбрам
  • Хранение графа в одной таблице
Стоимость шага не зависит от размера всего графа.

Почему графовые базы плохо шардируются?

  • Они не поддерживают репликацию
  • Любое разбиение режет связи, и обходы начинают ходить по сети между узлами
  • Узлы слишком большие
  • Cypher не поддерживает кластеры
Поэтому масштабируют в основном чтение и вертикально.
Иерархия категорий товаров (до 6 уровней) — нужна ли графовая база?

Нет. Дерево небольшой глубины хорошо ложится на реляционную модель: список смежности + рекурсивный CTE, материализованный путь (ltree в PostgreSQL), closure table или nested sets — в зависимости от соотношения чтения и изменений. Графовая база оправдана при произвольных связях разных типов и глубоких обходах с фильтрами.

Как совместить графовую базу с основной?

Основные сущности остаются в OLTP-базе (источник истины), в граф попадают только узлы и связи, нужные для обходов, с минимальными свойствами — через CDC или события. Граф должен уметь пересобираться из основной базы. Результаты обходов (рекомендации, оценка риска) возвращаются приложению или записываются обратно как производные данные.
