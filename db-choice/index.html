Выбор базы данных: какое хранилище для какой задачи

Практическое пособие для бэкенд-разработчика и архитектора: как по требованиям приложения выбрать хранилище, что на самом деле умеют реляционные, key-value, документные, wide-column, поисковые, временные, аналитические, графовые, векторные базы, журналы событий и объектные хранилища — и как собрать из нескольких из них согласованную систему. Цель — уметь обосновать выбор цифрами и паттернами доступа, а не модой.

Карта хранилищ

По горизонтали — тип нагрузки, по вертикали — модель данных. Почти любая система — реляционная база в центре и производные хранилища вокруг неё.

Начните с тем 01–02: оси выбора и устройство движков хранения объясняют всё остальное. Главы о типах хранилищ (03–15) независимы — читайте нужные. Завершите архитектурными темами 16–18.

Middle

Как работать с пособием

  1. Начните с мастера выбора (тема 01) на своей реальной задаче — и вернитесь к нему после курса.
  2. Для каждого класса хранилищ запомните три вещи: модель данных, путь доступа, который он делает дешёвым, и гарантию, которую он не даёт.
  3. Поднимайте системы локально: docker run для Redis, MongoDB, ClickHouse, OpenSearch, Kafka — и повторите примеры из блоков кода.
  4. Решите разборы в теме 17 до чтения эталона: сначала выберите хранилища сами, затем сравните аргументы.
  5. Отвечайте на тесты и отмечайте темы изученными — прогресс виден в меню слева.
Актуальность Ландшафт хранилищ меняется быстро: лицензии (Redis → Valkey, Elasticsearch ↔ OpenSearch), управляемые сервисы, новые версии. Принципы — модели, движки, гарантии, синхронизация — устойчивы; конкретные цифры (цены, лимиты, задержки) приведены как ориентиры, сверяйте их с документацией на момент решения. Песочницы работают на SQLite (sql.js) и требуют доступа к cdn.jsdelivr.net.

Связь с другими пособиями

Реляционная база — центр большинства систем, и её устройство подробно разобрано в пособии «Реляционные базы данных изнутри»: индексы, MVCC, WAL, репликация, эксплуатация. Кэширование, шардирование и очереди в контексте всей архитектуры — в пособии System Design.
