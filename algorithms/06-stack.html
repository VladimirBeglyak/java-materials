Стек и монотонный стек

Стек (LIFO) решает задачи, где важна «последняя открытая скобка», «предыдущий элемент», «ближайший больший/меньший». Особый случай — монотонный стек: он поддерживает элементы в неубывающем/невозрастающем порядке и за O(n) находит «следующий больший элемент» для всех позиций — то, что наивно требует O(n²).

6.1Классический стек

boolean isValid(String s) {
    Deque<Character> st = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '[' || c == '{') { st.push(c); continue; }
        if (st.isEmpty()) return false;
        char top = st.pop();
        if ((c == ')' && top != '(') || (c == ']' && top != '[') || (c == '}' && top != '{'))
            return false;
    }
    return st.isEmpty();
}
Признаки «стековой» задачи Парные скобки, отмена последнего действия (undo), вычисление выражений, «убрать соседние дубликаты», обход в глубину (стек вызовов). Всё, где «последний вошёл — первый обрабатывается».

6.2Монотонный стек

Поддерживаем стек в возрастающем порядке: перед добавлением нового элемента выталкиваем всё, что меньше него. Вытолкнутый элемент «узнаёт», что новый — его следующий больший.

int[] nextGreater(int[] a) {
    int n = a.length;
    int[] res = new int[n];
    Arrays.fill(res, -1);
    Deque<Integer> st = new ArrayDeque<>();   // храним индексы, стек по убыванию значений
    for (int i = 0; i < n; i++) {
        while (!st.isEmpty() && a[st.peek()] < a[i]) {
            res[st.pop()] = a[i];             // a[i] — следующий больший для вытолкнутого
        }
        st.push(i);
    }
    return res;
}
Сложность Каждый элемент кладётся и выталкивается ровно один раз — O(n), хотя внутри цикл while. Это классика «амортизированного» анализа.

6.3Самопроверка

Какая структура решает задачу про парные скобки?

  • Очередь
  • Стек (LIFO)
  • Куча
  • Хэш-таблица
Открывающую скобку кладём, закрывающая должна совпасть с вершиной — последняя открытая закрывается первой.

Что делает монотонный стек?

  • Сортирует массив
  • Поддерживает порядок элементов и находит «следующий больший/меньший» за O(n)
  • Удаляет дубликаты
  • Считает сумму
Выталкивая нарушающих порядок, каждый элемент узнаёт свой следующий больший/меньший.

Почему монотонный стек работает за O(n), несмотря на while?

  • Он не выполняется
  • while ограничен константой
  • Каждый элемент кладётся и выталкивается один раз суммарно
  • Это O(n²) на самом деле
Амортизированный анализ: суммарное число выталкиваний ≤ n.

Что вычисляет пример nextGreater?

  • Сумму массива
  • Максимум
  • Отсортированный массив
  • Для каждого элемента — первый элемент справа, больший его
При выталкивании текущий элемент становится «следующим большим» для вытолкнутого.
Какие задачи сигнализируют о монотонном стеке?

«Следующий/предыдущий больший или меньший элемент», «сколько дней до более тёплого дня» (daily temperatures), «наибольшая площадь гистограммы», «убрать k цифр, чтобы число было минимальным».

Как найти «предыдущий меньший», а не «следующий больший»?

Тем же стеком, но с другим порядком: поддерживать возрастающий стек (для «предыдущий меньший» элемент, оставшийся в стеке при вставке, и есть предыдущий меньший) или пройти массив в обратном порядке.
