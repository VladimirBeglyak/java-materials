Хэш-таблицы и множества

Хэш-таблица (HashMap/HashSet) даёт вставку, удаление и поиск за O(1) в среднем. Это универсальный инструмент «запоминания»: вместо повторного сканирования массива вы храните уже виденное и за один проход находите пары, дубликаты и анаграммы. Почти любая задача «найти пару/дубликат/совпадение» решается через хэш.

5.1Подсчёт частот

Map<Integer, Integer> freq = new HashMap<>();
for (int x : a) {
    freq.merge(x, 1, Integer::sum);     // или freq.put(x, freq.getOrDefault(x,0)+1)
}

Подсчёт частот — базовый приём: «есть ли дубликат», «самый частый», «k наиболее частых» (последний — уже куча, тема 07).

5.2Two Sum за O(n)

Вместо вложенного цикла O(n²) — один проход: для каждого x проверяем, был ли уже target − x.

int[] twoSum(int[] a, int target) {
    Map<Integer, Integer> seen = new HashMap<>();
    for (int i = 0; i < a.length; i++) {
        int need = target - a[i];
        if (seen.containsKey(need)) return new int[]{seen.get(need), i};
        seen.put(a[i], i);
    }
    return new int[]{-1, -1};
}
Хэш vs два указателя Для неотсортированного массива — хэш-таблица (O(n) времени, O(n) памяти). Для отсортированного — два указателя (O(n) времени, O(1) памяти). Часто спрашивают оба варианта.

5.3Анаграммы и группировка

Ключ хэш-таблицы может быть не только числом, но и преобразованной строкой — например, отсортированными буквами слова для группировки анаграмм.

Map<String, List<String>> groups = new HashMap<>();
for (String w : words) {
    char[] c = w.toCharArray();
    Arrays.sort(c);                      // ключ — отсортированные буквы
    groups.computeIfAbsent(new String(c), k -> new ArrayList<>()).add(w);
}

5.4Самопроверка

Какая средняя сложность операций HashMap?

  • O(n)
  • O(1)
  • O(log n)
  • O(n²)
Вставка/поиск/удаление в среднем O(1); наихудший случай O(n) при плохом хэше/коллизиях.

Как решить Two Sum для неотсортированного массива за O(n)?

  • Хэш-таблица: для каждого x ищем target−x среди уже виденных
  • Двоичный поиск
  • Сортировка и два указателя
  • Только перебор
Один проход с запоминанием виденных значений даёт O(n) времени, O(n) памяти.

Что удобно использовать как ключ при группировке анаграмм?

  • Длину слова
  • Первую букву
  • Отсортированные буквы слова
  • Случайное число
Анаграммы после сортировки букв совпадают — это и есть общий ключ группы.

Чем хэш-решение Two Sum отличается от решения двумя указателями?

  • Ничем
  • Хэш медленнее
  • Хэш не требует сортировки
  • Хэш работает O(n) времени + O(n) памяти, два указателя — O(n) времени + O(1) памяти (но нужна сортировка)
Компромисс времени/памяти и требования к порядку.
Какие задачи решает подсчёт частот?

Поиск дубликатов, самый частый элемент, число уникальных, k наиболее частых (совместно с кучей), проверка перестановки/анаграммы.

Когда хэш-таблица хуже двух указателей?

Когда массив уже отсортирован и важна память O(1): два указателя дают тот же O(n) без O(n) дополнительной памяти.
