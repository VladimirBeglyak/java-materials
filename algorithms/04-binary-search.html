Двоичный поиск

Двоичный поиск находит элемент в отсортированном диапазоне за O(log n). Но главный приём на собеседованиях — поиск по ответу: когда ответ монотонен по какому-то параметру, можно бинарным поиском «угадывать» его значение и проверять за O(n). Распознаётся по фразам «отсортированный массив», «найти минимальный/максимальный X, при котором условие выполняется».

4.1Классический поиск

int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;   // защита от переполнения
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
Тонкости mid = lo + (hi - lo)/2, а не (lo+hi)/2 — чтобы не переполнить int. Границы lo/hi — главный источник off-by-one ошибок.

4.2Lower bound и upper bound

Часто нужен не точный элемент, а первый ≥ target (lower bound) или первый > target (upper bound).

int lowerBound(int[] a, int target) {
    int lo = 0, hi = a.length;          // hi = n, не n-1!
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid;                  // кандидат, сужаем влево
    }
    return lo;
}

4.3Поиск по ответу

Если ответ лежит в диапазоне [min, max] и условие «ответ ≤ X выполнимо» монотонно, бинарным поиском ищем границу. Классика — «минимальная скорость, чтобы успеть» (Koko eating bananas).

// check(x): можно ли достичь цели при значении x
int lo = minPossible, hi = maxPossible;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (check(mid)) hi = mid;     // mid подходит — ищем меньше
    else lo = mid + 1;            // не подходит — нужно больше
}
return lo;                        // минимальный подходящий
Как распознать поиск по ответу Спрашивают «минимальный/максимальный X» + есть проверка за O(n), монотонная по X. Тогда сложность O(n log range) вместо перебора по всем X.

4.4Самопроверка

Какая сложность двоичного поиска?

  • O(n)
  • O(log n)
  • O(n log n)
  • O(1)
Каждый шаг делит диапазон пополам — O(log n).

Зачем писать mid = lo + (hi - lo) / 2?

  • Чтобы не переполнить int при больших lo+hi
  • Это быстрее
  • Это короче
  • Нет разницы
(lo+hi) может переполнить int; разностная форма безопасна.

Что возвращает lower bound?

  • Последний элемент меньше target
  • Первый элемент равный target
  • Первый индекс с a[i] >= target
  • Первый элемент больше target
Lower bound — первая позиция, куда можно вставить target, сохранив порядок.

Когда применяют «поиск по ответу»?

  • Когда ответ монотонен и есть проверка check(x) за O(n)
  • Всегда
  • Только для строк
  • Когда массив не отсортирован
Монотонность + быстрая проверка позволяют бинарно искать сам ответ.
Чем lower bound отличается от upper bound?

Lower bound — первый a[i] ≥ target; upper bound — первый a[i] > target. Их разность даёт число вхождений target.

Сформулируйте признак задачи «поиск по ответу».

Просят минимальный/максимальный X, при этом есть монотонная по X проверка за O(n) — можно бинарным поиском найти границу за O(n log range).
