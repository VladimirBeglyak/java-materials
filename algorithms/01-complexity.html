Сложность и план решения задачи

Прежде чем писать алгоритм, нужно уметь оценивать его по времени и памяти и понимать, какая сложность вообще достижима для задачи. На собеседовании вас почти всегда попросят назвать Big O — и это не формальность, а проверка понимания. Здесь же — универсальный 5-шаговый план, как подходить к любой задаче.

1.1Что такое Big O

Big O описывает, как растёт время/память при росте входных данных n, отбрасывая константы и младшие члены. Это «порядок роста», а не точное время.

СложностьНазваниеn = 10⁶ (примерное время)
O(1)константамгновенно
O(log n)логарифм~20 операций
O(n)линейная1 млн операций
O(n log n)линейно-логарифмическая~20 млн
O(n²)квадратичная10¹² — уже плохо
O(2ⁿ)экспоненциальнаянереально при n > ~25
Правило быстрой оценки Если n до 10⁶ — нужно O(n) или O(n log n); до 10⁴ — можно O(n²); до ~20 — допустим перебор O(2ⁿ). Сложность диктует, какой алгоритм вообще подходит.

1.2Как оценивать по коду

// O(1): константные операции
int x = a[0] + a[1];

// O(n): один цикл
for (int i = 0; i < n; i++) { … }

// O(n²): вложенные циклы
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) { … }

// O(log n): деление пополам (двоичный поиск)
while (lo < hi) { int mid = (lo + hi) / 2; … }
  1. Найдите доминирующий цикл — самый вложенный по количеству итераций.
  2. Вложенные циклы перемножаются, последовательные — складываются.
  3. Отбросьте константы: O(2n) = O(n), O(n + 5) = O(n).
  4. Учтите скрытые стоимости: обращение к HashMap — O(1) в среднем, но наихудший O(n) при коллизиях; строки в Java неизменяемы — конкатенация в цикле O(n²).

1.3Память

Кроме времени спрашивают и память: сколько дополнительных структур создаёт алгоритм. Рекурсия тоже ест память — стек вызовов глубины d занимает O(d).

ПриёмПамять
in-place (меняем входной массив)O(1)
дополнительный массив/хэш-таблица размера nO(n)
рекурсия глубины nO(n) стек

1.4План решения: 5 шагов

  1. Поймите задачу. Перескажите своими словами, уточните ограничения (размер входа, отсортировано ли, есть ли дубликаты, могут ли быть отрицательные).
  2. Придумайте примеры. Маленький, краевые (пусто, один элемент, все одинаковые), большой.
  3. Начните с грубой силы. Сформулируйте самое простое решение и оцените его сложность — это база, от которой оптимизируете.
  4. Оптимизируйте. Ищите паттерн (этот курс — каталог паттернов) и структуру данных, которая убирает лишнюю работу.
  5. Проверьте. Прогоните на примерах, назовите время и память, обсудите крайние случаи.
Говорите вслух На собеседовании ценят сам ход мысли, а не мгновенный ответ. Проговаривайте: «начну с грубой силы O(n²), затем оптимизирую через хэш-таблицу до O(n)». Это показывает инженерное мышление.

1.5Самопроверка

Какая сложность у вложенных циклов по n?

  • O(n)
  • O(n²)
  • O(log n)
  • O(1)
Вложенные циклы перемножаются: n × n = n².

n до 10⁶. Какая сложность обычно приемлема?

  • O(n) или O(n log n)
  • O(n²)
  • O(2ⁿ)
  • O(n³)
При n=10⁶ O(n²)=10¹² операций — слишком медленно. Нужен линейный или линейно-логарифмический.

Сколько дополнительной памяти у in-place алгоритма?

  • O(n)
  • O(log n)
  • O(1)
  • O(n²)
In-place меняет входные данные, не выделяя структур размера n.

С чего лучше начать решение задачи на собеседовании?

  • Сразу писать оптимизированный код
  • Молча думать
  • Пропустить примеры
  • С грубой силы, оценить её и оптимизировать по шагам
Грубая сила даёт базу и показывает ход мысли; оптимизация идёт от неё.
Почему O(2n) и O(n) — одно и то же?

Big O описывает порядок роста, отбрасывая константы. Удвоение константы не меняет, как алгоритм масштабируется при росте n.

Назовите 5 шагов плана решения.

Понять задачу (и ограничения), придумать примеры и крайние случаи, сформулировать грубую силу с оценкой, оптимизировать через паттерн/структуру, проверить и назвать сложность.
