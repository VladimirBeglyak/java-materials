Загрузка компьютера — простыми словами

Вы нажали кнопку питания, а через полминуты видите рабочий стол. Что происходит в эти секунды? Компьютер похож на театр перед спектаклем: сначала включают свет, потом проверяют сцену, приходит режиссёр, а за ним — актёры. Пройдём этот путь по шагам.

9.1Кнопка питания: первое, что делает процессор

Когда подаётся питание, память пуста, операционной системы нет, и процессор ничего не знает. Но у него есть «врождённое знание»: после включения всегда начинать читать команды с одного и того же, заранее известного адреса. Это вектор сброса. Как сторож, у которого в инструкции написано: «утром первым делом открой дверь номер один».

По этому адресу находится не оперативная память, а маленькая микросхема с программой, которая не стирается при выключении, — прошивка.

Главная мысль После включения процессор всегда начинает с одного известного адреса, где ждёт прошивка.

9.2Прошивка UEFI: проверить сцену

Прошивка (сегодня это UEFI, раньше — BIOS) — как технический персонал театра. Она включает и настраивает оперативную память, проверяет, какие устройства подключены (диски, клавиатура, видеокарта), и ищет, откуда грузить операционную систему. Именно в этот момент можно нажать клавишу и войти в настройки — выбрать, с какого диска загружаться.

Главная мысль UEFI готовит железо и находит на диске программу, которая загрузит операционную систему.

В полной главе: 9.2 Прошивка: UEFI

9.3Цепочка доверия: проверка пропусков

А вдруг вместо настоящей операционной системы на диск подложили вредоносную? Для этого есть Secure Boot: каждый следующий участник загрузки должен показать «пропуск» — цифровую подпись. Прошивка проверяет подпись загрузчика, загрузчик — подпись ядра. Как охрана, где каждый пост проверяет следующего. Если подпись не сходится — дальше не пустят.

Есть ещё TPM — маленький «сейф» на плате. Он записывает, что именно загружалось, и хранит ключи (например, для шифрования диска), выдавая их, только если загрузка прошла как обычно.

Главная мысль При загрузке каждый шаг проверяет подпись следующего. Так подменить систему незаметно очень трудно.

В полной главе: 9.3 Цепочка доверия: Secure Boot и TPM

9.4Загрузчик: тот, кто приводит режиссёра

Загрузчик — небольшая программа на диске (например, GRUB в Linux или Windows Boot Manager). Если на компьютере несколько систем, именно он показывает меню выбора. Его работа — найти файл ядра операционной системы, положить его в память и передать ему управление.

Главная мысль Загрузчик — посредник: находит ядро ОС на диске, кладёт в память и запускает.

В полной главе: 9.4 Загрузчик

9.5Старт ядра: режиссёр пришёл

Ядро операционной системы — главная её часть, тот самый «директор». Проснувшись, оно берёт всё в свои руки: настраивает виртуальную память (глава 08), будит остальные ядра процессора, загружает драйверы — маленькие программы, которые умеют говорить с конкретными устройствами, — и подключает диск с файлами.

Главная мысль Ядро настраивает память, процессор и устройства. С этого момента компьютером управляет операционная система.

В полной главе: 9.5 Старт ядра

9.6Первая программа и все остальные

Закончив подготовку, ядро запускает одну самую первую обычную программу. В Linux у неё номер 1 (PID 1), чаще всего это systemd. Дальше она запускает всё остальное: сеть, службы, экран входа. Это как режиссёр, который поручает помощнику собрать всех актёров. Когда вы видите экран входа — загрузка закончена.

От кнопки до экрана входа
⏻ питание → процессор читает команду по адресу сбросаUEFI: память ✓  диски ✓  клавиатура ✓  → ищу загрузчикSecure Boot: подпись загрузчика ✓загрузчик: нашёл ядро, положил в память, запускаюядро: память, ядра процессора, драйверы, диск ✓PID 1 (systemd): сеть, службы, экран входа → готово

Процессор начинает с адреса, зашитого в нём самом.

UEFI проверяет и настраивает железо.

Secure Boot не пустит неподписанный загрузчик.

Находит и запускает ядро ОС.

Директор берёт управление на себя.

PID 1 запускает всё остальное.

Главная мысль Загрузка — эстафета: прошивка → загрузчик → ядро → первая программа → всё остальное.

9.7Запуск Java — та же эстафета в миниатюре

Когда вы пишете java Hello, происходит похожая цепочка: небольшая программа java загружает виртуальную машину Java, та готовит память и служебные потоки, загружает базовые классы, затем ваш класс — и только потом вызывает ваш main. Поэтому даже «Hello, world» стартует не мгновенно.

Главная мысль Любой сложный запуск — эстафета, где каждый готовит почву следующему.

9.9Проверьте себя

Откуда процессор знает, что делать сразу после включения?

  • спрашивает операционную систему
  • всегда начинает с одного известного адреса, где лежит прошивка
  • ждёт команды с клавиатуры
  • скачивает из интернета
В момент включения ОС ещё нет. Есть только прошивка в микросхеме, которая не стирается.

Какой порядок загрузки правильный?

  • ядро → прошивка → загрузчик
  • загрузчик → ядро → прошивка
  • прошивка → загрузчик → ядро → первая программа
  • первая программа → ядро → прошивка
Эстафета идёт от самого простого к самому сложному: каждый запускает следующего.

Зачем нужен Secure Boot?

  • чтобы при загрузке нельзя было незаметно подменить загрузчик или ядро
  • чтобы компьютер загружался быстрее
  • чтобы экономить батарею
  • чтобы шифровать интернет
Каждый шаг проверяет подпись следующего — как охрана, проверяющая пропуска.

Что такое драйвер?

  • человек за рулём
  • вирус
  • часть процессора
  • программа, которая умеет «разговаривать» с конкретным устройством
Ядро не знает подробностей каждой видеокарты или принтера — этим занимаются драйверы.

Почему даже «Hello, world» на Java запускается не мгновенно?

  • Java медленно печатает
  • сначала нужно запустить и подготовить виртуальную машину Java, и только потом вызвать main
  • программа каждый раз скачивается
  • так задумано для безопасности
Запуск JVM — своя маленькая эстафета: память, служебные потоки, базовые классы, и только потом ваш код.
