18.1Путешествие первое: от Enter до надписи на экране

Вы набрали в терминале java Hello и нажали Enter. Вот что происходит:

java Hello — от клавиши до пикселя
клавиатура → прерывание → ядро передаёт «Enter» терминалу   (гл. 10)терминал просит ядро: создай процесс, запусти программу java   (гл. 11, 14)ядро: новое адресное пространство, стек, библиотеки   (гл. 08, 04, 14)JVM: куча, служебные потоки, загрузка классов с диска   (гл. 09, 12)JVM выполняет main: процессор читает команды, данные идут через кэш   (гл. 03, 06)System.out.println → системный вызов write → ядро → терминал   (гл. 10)терминал рисует буквы → видеокарта → экран   (гл. 01, 16)

Клавиатура «звонит» прерыванием, ядро передаёт символ программе-терминалу.

Терминал просит ядро создать процесс и загрузить в него программу java.

Ядро выдаёт новую «квартиру», готовит стек главного потока и подключает библиотеки.

Виртуальная машина Java готовит кучу и читает файлы классов с диска (из кэша файлов, если они уже читались).

Байт-код выполняется: сначала через интерпретатор, горячее — после JIT.

Чтобы вывести текст, программа просит ядро: «запиши эти байты в терминал».

Терминал превращает байты в буквы (по таблице UTF-8), а видеокарта — в точки на экране.

Всё это — примерно за десятую долю секунды, и в основном это время уходит на запуск JVM.

Главная мысль Даже простейшая программа задействует почти все слои: прерывания, процессы, память, диск, процессор, системные вызовы, видеокарту.

18.2Что появляется при запуске программы

Создаёт ОС

Процесс со своей виртуальной памятью, главный поток со стеком, таблица открытых файлов (с готовыми «вводом», «выводом» и «ошибками»).

Создаёт JVM

Куча для объектов, служебные потоки (сборщик мусора, JIT-компилятор), область для загруженных классов и скомпилированного кода.

Главная мысль «Квартиру» с жильцами выдаёт ОС, а Java обставляет её своей мебелью: куча, сборщик мусора, JIT.

18.3Путешествие второе: запрос из браузера в Java-сервис

  1. Браузер превращает адрес сайта в IP-адрес и отправляет пакеты по сети (глава 01: всё — байты).
  2. Сетевая карта сервера принимает пакеты и кладёт в память, «звонит» ядру (глава 13).
  3. Ядро собирает пакеты, кладёт данные в «почтовый ящик» соединения и сообщает Java-программе через epoll (глава 13).
  4. Java-сервис берёт запрос, его поток (или виртуальный поток) получает ядро от планировщика (глава 11).
  5. Код обрабатывает запрос: процессор выполняет команды, данные бегают между кэшем и памятью (главы 03, 06).
  6. Если нужна база данных — ещё один сетевой запрос и ожидание. Поток в это время спит и не занимает ядро.
  7. Ответ идёт обратно: программа кладёт его в сокет, ядро режет на пакеты, сетевая карта отправляет.
Главная мысль Запрос проходит через сеть, ядро, планировщик, процессор и память — и обычно большую часть времени просто ждёт сеть и базу.

18.4Бюджет времени: где на самом деле тратятся миллисекунды

Если весь запрос занимает 50 миллисекунд, куда они уходят? Чаще всего так:

ЧтоСколько примерно
Дорога по интернету туда и обратнодесятки миллисекунд (зависит от расстояния)
Запрос в базу данныхот одной до десятков миллисекунд
Работа вашего кодачаще всего меньше миллисекунды
Системные вызовы, переключениямикросекунды

Вывод: чтобы ускорить сервис, сначала ищите ожидания — лишние запросы к базе, походы в другие сервисы, медленный диск. Ускорять сам код имеет смысл, только когда ожидания уже убраны.

Главная мысль Обычно время съедает ожидание сети и базы, а не вычисления. Ищите его в первую очередь.

18.7Проверьте себя

Как текст из System.out.println попадает в терминал?

  • Java рисует его прямо на экране
  • через видеокарту напрямую
  • программа делает системный вызов write, и ядро передаёт байты терминалу
  • через интернет
Вывод — это работа с внешним миром, а её делает ядро по просьбе программы.

Запрос к сервису занимает 200 мс. Что, скорее всего, съедает большую часть времени?

  • ожидание базы данных, других сервисов или сети
  • сложение чисел в коде
  • переключение потоков
  • прерывания клавиатуры
Вычисления обычно занимают доли миллисекунды. Время уходит на ожидание.

Сервис внезапно перезапустился, в логах ничего нет, а в Kubernetes — статус OOMKilled. Куда смотреть?

  • на кодировку
  • на скорость сети
  • на точность дробей
  • на расход памяти относительно лимита контейнера
Контейнер превысил лимит памяти, и ядро его убило (главы 08 и 15).

Пока Java-поток ждёт ответа базы данных, что он делает с ядром процессора?

  • крутится в цикле и занимает ядро
  • спит и не занимает ядро — планировщик отдаёт его другим
  • выключает ядро
  • ускоряет базу
Ждущий поток снимается с ядра. Поэтому много ждущих потоков не грузят процессор.

Почему запуск «Hello» на Java занимает заметное время?

  • печать текста — долгая операция
  • процессор медленный
  • основное время уходит на запуск и подготовку JVM
  • программа скачивается из интернета
Сам main — микросекунды. А JVM нужно подготовить память, потоки и загрузить классы.
