Процессор: команды и цикл исполнения

Процессор — это регистры, АЛУ и управляющая логика, которая бесконечно повторяет один цикл: взять команду по адресу из счётчика команд, понять, что она означает, выполнить и перейти к следующей. Программа — просто числа в памяти. Разберём устройство ядра, набор команд x86-64 и ARM64, как условия и циклы превращаются в сравнения и переходы, и как адресуются массивы и поля объектов. В симуляторе можно пошагово выполнить программу на учебном процессоре.

3.1Архитектура фон Неймана

Схема, описанная в 1945 году и используемая до сих пор: процессор, память, в которой лежат и данные, и сама программа, и устройства ввода-вывода, связанные общими шинами. Главная идея — программа хранится в памяти как данные: её можно загрузить с диска, сгенерировать на лету (JIT-компилятор JVM пишет машинный код в память и передаёт на него управление), изменить.

Узкое место фон Неймана: процессор считает гораздо быстрее, чем память успевает отдавать команды и данные. Борьба с этим — главный сюжет архитектуры последних 40 лет: кэши, раздельные кэши команд и данных на первом уровне (элемент «гарвардской» архитектуры), предвыборка, конвейер.

3.2Регистры — рабочий стол процессора

Регистр — ячейка памяти внутри ядра (из триггеров, тема 02), доступ к которой занимает ноль лишних тактов. Регистров мало, поэтому компилятор тщательно решает, какие значения держать в них, а какие «выталкивать» в память (register allocation, spilling).

Регистр x86-64Назначение (по соглашению System V для Linux)ARM64

Имена несут историю: у 64-битного RAX младшие 32 бита — EAX (i386), младшие 16 — AX (8086, 1978), младший байт — AL. Запись в EAX обнуляет старшие 32 бита RAX — частая деталь при чтении дизассемблера JIT-кода.

Сколько «регистров» на самом деле. Архитектурных регистров в x86-64 16, а физических в современном ядре — около 200–300: механизм переименования (тема 05) отображает архитектурные имена на физические, чтобы независимые команды выполнялись параллельно.

3.3Цикл выборка — декодирование — исполнение

  1. Fetch (выборка): прочитать байты команды по адресу в PC (из кэша команд L1i).
  2. Decode (декодирование): определить операцию, регистры-операнды, режим адресации, длину команды. У x86 команда длиной 1–15 байт, и декодер — одна из самых сложных частей ядра; современные x86 разбивают команды на внутренние микрооперации (µops) и кэшируют уже декодированные.
  3. Execute (исполнение): АЛУ считает, блок адресации вычисляет адрес, блок загрузки читает память.
  4. Memory / Writeback: записать результат в регистр или память, обновить флаги.
  5. Обновить PC: PC += длина команды, либо, если это переход, PC = адрес перехода.

Всё, что умеет компьютер — циклы, вызовы функций, исключения, многозадачность, — сводится к тому, какое значение окажется в PC на следующем шаге. Цикл — это переход назад. Вызов функции — переход с запоминанием адреса возврата (тема 04). Прерывание — аппаратная подмена PC на адрес обработчика (тема 10).

Симулятор учебного процессора

Четыре регистра R0–R3, флаг Z, память из 16 ячеек, счётчик команд PC. Выберите программу или напишите свою и выполняйте по шагу: подсвечивается команда, на которую указывает PC. Команды: LOAD r, [a], STORE r, [a], MOV r, n, ADD r, s, SUB r, s, ADDI r, n, CMP r, s, JMP L, JZ L, JNZ L, JN L (переход, если результат отрицательный), HALT.

3.4Набор команд (ISA): договор между железом и программами

Архитектура набора команд (instruction set architecture) — это спецификация: какие есть регистры, команды, режимы адресации, как кодируются команды в байты, как устроены прерывания и защита памяти. Она отделяет программы от конкретной микросхемы: код, скомпилированный под x86-64 в 2005 году, исполняется на процессоре 2026 года с совершенно другим внутренним устройством.

x86-64 (Intel, AMD)ARM64 (AArch64: Apple M, AWS Graviton, телефоны)RISC-V
философияCISC: сложные команды, операнды могут быть в памятиRISC: простые команды, работа с памятью только через load/storeRISC, открытая спецификация
длина команды1–15 байтровно 4 байта4 байта (2 — в сжатом расширении)
регистров общего назначения163131 + нулевой

Различие CISC/RISC сегодня в основном снаружи: x86 декодирует свои сложные команды во внутренние RISC-подобные микрооперации. Практическое следствие для Java — JVM прячет ISA: один и тот же jar работает на x86 и ARM, а JIT генерирует код под конкретный процессор, включая его расширения (AVX-512, SVE). Но модель памяти процессора (x86 строже ARM) влияет на то, насколько заметны ошибки синхронизации — код с гонкой может «работать» на ноутбуке с x86 и падать на сервере ARM.

3.5Как конструкции языка становятся командами

Компилятор (gcc для C, C2/Graal для Java во время работы) превращает выражения в команды. Синтаксис Intel: команда приёмник, источник.

long sum(long *a, long n) {      // a → RDI, n → RSI (соглашение о вызовах, тема 04)
    long s = 0;
    for (long i = 0; i < n; i++)
        s += a[i];
    return s;                     // результат — в RAX
}
// sum:
//     test  rsi, rsi                ; n & n — выставить флаги по n
//     jle   .L4                     ; n <= 0 → сразу вернуть 0
//     mov   rax, rdi                ; p = a  (индекс i превращён в указатель)
//     lea   rcx, [rdi+rsi*8]        ; end = a + n*8 — адрес, без чтения памяти
//     mov   edx, 0                  ; s = 0
// .L3:
//     add   rdx, QWORD PTR [rax]    ; s += *p  — операнд прямо в памяти (CISC)
//     add   rax, 8                  ; p++ (long — 8 байт)
//     cmp   rax, rcx                ; p == end ?
//     jne   .L3                     ; нет → назад: это и есть цикл
// .L1:
//     mov   rax, rdx                ; результат в RAX
//     ret
// .L4:
//     mov   edx, 0
//     jmp   .L1
  • Условие if (x < y) — это cmp x, y (вычитание, которое лишь ставит флаги) и условный переход: jl для знаковых, jb для беззнаковых (тема 02). Часто компилятор обходится вовсе без перехода — командой условной пересылки cmov (тема 05: так не страдает предсказатель ветвлений).
  • Цикл — проверка и переход назад. Оптимизатор переписывает индексы в указатели, разворачивает тело (unrolling) и векторизует (тема 05).
  • Адресация [base + index*scale + disp] вычисляется прямо в команде: элемент массива a[i] — [rdi + rsi*8], поле объекта — [reg + смещение поля]. Поэтому в JIT-коде Java чтение obj.field — одна команда mov со смещением, известным из раскладки объекта (JVM, тема 10), а arr[i] — сравнение с length (проверка границ) и одна команда чтения.
  • lea (load effective address) вычисляет адрес, ничего не читая, — компиляторы используют её как быструю арифметику: lea eax, [rdi+rdi*4] — это x * 5.
  • Деление на константу компилятор заменяет умножением на «магическое» обратное число и сдвигом: деление (idiv) стоит 20–90 тактов на старых и ~10–18 на новых ядрах, умножение — 3.
Посмотреть машинный код JIT HotSpot умеет печатать сгенерированный код: -XX:+UnlockDiagnosticVMOptions -XX:+PrintAssembly (нужна библиотека-дизассемблер hsdis), а удобнее — JITWatch или perfasm в JMH (JVM, тема 17). В лабораторных этой главы мы смотрим на код C-компилятора: он статичен и короче, а принципы те же.

Лаба 3.1Эмулятор: программа — это данные25 мин

Реализовать цикл fetch-decode-execute и убедиться, что команды и данные лежат в одной памяти.

  1. Создайте файл ToyCpu.java:
    import java.util.Arrays;

public class ToyCpu {
    // формат команды: код операции * 100 + аргумент; память общая для кода и данных
    static final int HALT = 0, LOAD = 1, ADDM = 2, STORE = 3, DEC = 4, JZ = 5, JMP = 6;
    static final String[] NAMES = {"HALT", "LOAD", "ADDM", "STORE", "DEC", "JZ", "JMP"};

    public static void main(String[] args) {
        int[] mem = new int[32];
        // while (n != 0) { sum += n; n--; }     n — в ячейке [20], sum — в [21]
        int[] code = {
            1_20,   // 0: LOAD  [20]   acc = n
            5_08,   // 1: JZ    8      n == 0 → на HALT
            2_21,   // 2: ADDM  [21]   acc = acc + sum
            3_21,   // 3: STORE [21]   sum = acc
            1_20,   // 4: LOAD  [20]
            4_00,   // 5: DEC          acc--
            3_20,   // 6: STORE [20]   n = acc
            6_00,   // 7: JMP   0      в начало цикла
            0_00    // 8: HALT
        };
        System.arraycopy(code, 0, mem, 0, code.length);
        mem[20] = args.length > 0 ? Integer.parseInt(args[0]) : 5;

        int pc = 0, acc = 0, steps = 0;
        while (true) {
            int ir = mem[pc];                  // FETCH: команда — просто число из памяти
            int op = ir / 100, arg = ir % 100; // DECODE
            int next = pc + 1;
            switch (op) {                      // EXECUTE
                case LOAD -> acc = mem[arg];
                case ADDM -> acc += mem[arg];
                case STORE -> mem[arg] = acc;
                case DEC -> acc--;
                case JZ -> { if (acc == 0) next = arg; }
                case JMP -> next = arg;
                case HALT -> { }
                default -> throw new IllegalStateException("неизвестная команда " + ir + " по адресу " + pc);
            }
            steps++;
            if (steps <= 9 || op == HALT)
                System.out.printf("шаг %2d  pc=%d  %-5s %2d   acc=%d  n=%d  sum=%d%n", steps, pc, NAMES[op], arg, acc, mem[20], mem[21]);
            if (op == HALT) break;
            pc = next;                         // обновление PC
        }
        System.out.println("выполнено команд: " + steps);
        System.out.println("память: " + Arrays.toString(Arrays.copyOf(mem, 22)));
    }
}
  2. Чему будет равна сумма в ячейке [21] и сколько команд выполнит эмулятор для n = 5? Где в дампе памяти программа, а где данные?

java ToyCpu
    Вывод (JDK 25.0.2)

    Сумма 5 + 4 + 3 + 2 + 1 = 15. Тело цикла — 8 команд (адреса 0–7), 5 итераций = 40 команд, плюс финальные LOAD, JZ и HALT — 43. В дампе первые девять чисел (120, 508, 221…) — это программа, ячейка 20 — n (стала 0), 21 — сумма. Для процессора между ними нет разницы: если бы STORE записал в ячейку 0–8, программа изменила бы сама себя.

Поэкспериментируйте
  • Запустите java ToyCpu 0.
    Три команды: LOAD, JZ (acc = 0 — переход на 8), HALT. Проверка условия в начале цикла — это while; если бы JZ стоял в конце, тело выполнилось бы хотя бы раз (do-while) и n ушло бы в −1, −2… почти навсегда.
  • Сделайте так, чтобы программа сама заменила свой HALT: добавьте перед циклом запись числа 6_00 (JMP 0) в ячейку 8.
    Программа станет самомодифицирующейся и никогда не остановится: на месте HALT окажется переход в начало. Именно поэтому ОС помечает страницы с кодом «только чтение и исполнение» (тема 08), а JIT JVM переключает права страниц code cache при записи нового кода.

    Появятся векторные команды paddq/movdqu с регистрами XMM: компилятор складывает по два long за команду (SIMD, тема 05) и добавляет «хвост» для нечётного n.
Лаба 3.3Флаги, знак и деление на константу15 мин

Увидеть разные команды для знакового и беззнакового сравнения и как компилятор избавляется от деления.

  1. Создайте файл ops.c:
    int lt_signed(long a, long b)                     { return a < b; }
int lt_unsigned(unsigned long a, unsigned long b) { return a < b; }
long div10(long x)                                { return x / 10; }
long div_n(long x, long n)                        { return x / n; }
long times5(long x)                               { return x * 5; }
    docker run --rm -v "${PWD}:/lab" cs-lab gcc -O2 -S -masm=intel -fno-asynchronous-unwind-tables -fcf-protection=none -o - ops.c
    Вывод (JDK 25.0.2)
    lt_signed:
	xor	eax, eax
	cmp	rdi, rsi
	setl	al
	ret
lt_unsigned:
	xor	eax, eax
	cmp	rdi, rsi
	setb	al
	ret
div10:
	movabs	rax, 7378697629483820647
	imul	rdi
	sar	rdi, 63
	sar	rdx, 2
	mov	rax, rdx
	sub	rax, rdi
	ret
div_n:
	mov	rax, rdi
	cqo
	idiv	rsi
	ret

	lea	rax, [rdi+rdi*4]
	ret
  2. Найдите в выводе: какой командой записан результат знакового и беззнакового сравнения? Есть ли команда деления в div10? Как умножается на 5?

    Сравнение одно и то же — cmp rdi, rsi, а флаги читаются по-разному: setl (less — по SF и OF) и setb (below — по CF). В div10 деления нет: умножение imul на магическую константу 7378697629483820647 (≈ 2⁶⁶/10), сдвиг sar и поправка на знак (вычитание x >> 63). В div_n делитель неизвестен — там настоящий idiv и подготовка cqo (знаковое расширение RAX в RDX:RAX). Умножение на 5 — lea rax, [rdi+rdi*4].

Лаба 3.4Стоимость операций в Java15 мин

Измерить цепочки зависимых операций: сложение, деление на неизвестное число и деление на константу, которое JIT заменяет умножением.

  1. Создайте файл Cost.java:
    public class Cost {
    static long add(long x, int n)          { for (int i = 0; i < n; i++) x = x + 7 ^ i; return x; }
    static long divVar(long x, long d, int n) { for (int i = 0; i < n; i++) x = x / d + 1_000_003 ^ i; return x; }
    static long divConst(long x, int n)     { for (int i = 0; i < n; i++) x = x / 7 + 1_000_003 ^ i; return x; }

    public static void main(String[] args) {
        long d = args.length > 0 ? Long.parseLong(args[0]) : 7;   // делитель неизвестен JIT
        int n = 50_000_000;
        long sink = 0;
        for (int round = 0; round < 3; round++) {
            long t0 = System.nanoTime(); sink += add(round, n);
            long t1 = System.nanoTime(); sink += divVar(round + 1_000_000_000L, d, n);
            long t2 = System.nanoTime(); sink += divConst(round + 1_000_000_000L, n);
            long t3 = System.nanoTime();
            System.out.printf("раунд %d: сложение %.2f нс/оп, деление на переменную %.2f нс/оп, деление на константу %.2f нс/оп%n",
                    round, (t1 - t0) / (double) n, (t2 - t1) / (double) n, (t3 - t2) / (double) n);
        }
        System.out.println("(контрольная сумма " + (sink & 0xFF) + ")");
    }
}
  2. Во сколько раз деление на переменную медленнее сложения? А деление на константу?
    javac Cost.java
java Cost 7
    Вывод (JDK 25.0.2)
    раунд 0: сложение 0.67 нс/оп, деление на переменную 6.94 нс/оп, деление на константу 3.05 нс/оп
раунд 1: сложение 0.72 нс/оп, деление на переменную 6.86 нс/оп, деление на константу 3.18 нс/оп
раунд 2: сложение 0.57 нс/оп, деление на переменную 7.03 нс/оп, деление на константу 2.82 нс/оп
(контрольная сумма 1)

    Порядок чисел (у вас будут свои): сложение с XOR — доли наносекунды (≈ 1–2 такта на итерацию), деление на переменную — примерно на порядок медленнее (команда idiv с задержкой в десятки тактов на этом поколении меньше, но цепочка зависимостей не даёт её спрятать), деление на константу — заметно быстрее деления на переменную: C2, как и gcc, заменил его умножением. Первый раунд часто медленнее — код ещё интерпретируется или работает на C1 (прогрев, JVM, тема 16).

Поэкспериментируйте
  • Почему в цикле стоит ^ i?
    Без него JIT мог бы вычислить цикл быстрее, чем по шагам (или вынести инвариант), — зависимость от i делает каждую итерацию настоящей. Измерять микрооперации вручную вообще ненадёжно; для серьёзных замеров — JMH.

3.8Самопроверка

Что делает команда cmp rax, rbx?

  • копирует rbx в rax
  • вычисляет rax − rbx, результат не сохраняет, но выставляет флаги
  • сравнивает и сразу переходит
  • обнуляет флаги
cmp — это sub без записи результата. Решение о переходе принимает следующая команда jcc по флагам.

Чем ARM64 отличается от x86-64 с точки зрения набора команд?

  • ARM не умеет 64-битную арифметику
  • x86 не поддерживает SIMD
  • у ARM фиксированная длина команд 4 байта и доступ к памяти только load/store, у x86 — переменная длина и операнды в памяти
  • ничем, это один набор
Классическая пара RISC/CISC. Плюс разная модель памяти: x86 TSO, ARM слабая.

Как процессор выполняет цикл?

  • условный переход назад: PC получает адрес начала тела
  • специальным блоком «цикл»
  • копирует тело N раз
  • прерыванием таймера
Любое управление — это запись нового значения в PC. Развёртывание цикла делает компилятор, не процессор.

Почему JIT-код для obj.field — одна команда?

  • поля хранятся в регистрах
  • JVM кэширует все поля
  • JIT превращает поле в константу
  • смещение поля в объекте известно заранее, и адрес [ссылка + смещение] вычисляется в самой команде mov
Режим адресации base + displacement. Для массива — base + index·scale + заголовок.
Опишите цикл исполнения команды.

Выборка байтов команды по адресу в PC, декодирование (операция, операнды, длина), исполнение в АЛУ или блоке адресации, обращение к памяти, запись результата и флагов, обновление PC: следующая команда или адрес перехода. В современном ядре эти этапы разнесены по конвейеру, и одновременно в работе десятки команд.

Что такое ISA и почему Java-разработчику обычно не нужно о ней думать?

Набор команд, регистров, режимов адресации и правил (модель памяти, прерывания), которые процессор гарантирует программам. JVM исполняет переносимый байткод, а JIT сам генерирует машинный код под текущую ISA. Думать о ней приходится при анализе производительности (векторизация, стоимость операций) и модели памяти (x86 прощает гонки, ARM — нет).

Почему компилятор заменяет деление на константу умножением?

Деление — одна из самых медленных целочисленных операций (порядка десятков тактов), умножение — 3 такта. x / 10 равно старшей половине произведения x на заранее вычисленное число ≈ 2⁶⁴/10 со сдвигом и поправкой для отрицательных. Если делитель неизвестен при компиляции, остаётся настоящая команда деления.

Где в процессоре «живут» переменные Java-метода?

В JIT-коде — в регистрах, пока их хватает; остальные «выталкиваются» в кадр на стеке потока. В интерпретаторе локальные переменные — слоты кадра в памяти стека (тема 04 и JVM, тема 03). Поля объектов — в куче, читаются командой mov со смещением.
