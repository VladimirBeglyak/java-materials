Видеокарта — простыми словами

Процессор — несколько очень умных поваров. Видеокарта — тысячи простых работников, которые делают одно и то же одновременно. Разберёмся, для каких задач хороша такая «армия», почему ей не нравятся «если», почему данные на видеокарту возить дорого и как картинка попадает на экран.

16.1Профессор или школьный класс

Представьте два способа проверить тысячу простых примеров на сложение. Можно позвать одного профессора математики: он считает очень быстро и умеет решать что угодно, но он один. А можно раздать примеры классу из тридцати школьников: каждый считает медленнее профессора, но все одновременно — и класс закончит раньше.

Процессор (CPU) — несколько профессоров: умные, быстрые, умеют сложные задачи с развилками. Видеокарта (GPU) — тысячи школьников: каждый умеет простое, но все работают параллельно. Для картинки на экране, где нужно посчитать цвет миллионов точек по одной формуле, «класс» подходит идеально.

Главная мысль CPU — мало, но умных. GPU — очень много простых. GPU выигрывает, когда одну и ту же операцию нужно сделать с огромным количеством данных.

16.2Хором по одной команде — и беда с «если»

Работники видеокарты организованы в отряды (по 32 штуки — варп). Отряд делает всё хором: учитель говорит «сложить» — все складывают, каждый свои числа.

А что если в задании есть «если»? Допустим, половине отряда нужно сделать одно, а половине — другое. Хор не умеет петь две песни сразу. Поэтому сначала первая половина делает своё, а вторая стоит и ждёт, потом наоборот. Время удваивается. Это называют расхождением, и это главная причина, почему сложная логика с развилками на видеокарте работает плохо.

Главная мысль Видеокарта сильна, когда все работники делают одно и то же. Развилки заставляют части отряда ждать.

16.3Доставка дороже работы

У видеокарты своя память, отдельная от памяти компьютера. Чтобы она что-то посчитала, данные нужно туда отвезти по шине, а результат — привезти обратно. Это как отправить задачи в другой город, где сидит класс: решат быстро, но почта туда-обратно займёт время.

Если задача маленькая, доставка съест весь выигрыш, и процессор посчитает быстрее сам. GPU выгоден, когда данных много, а вычислений над ними ещё больше — и когда данные можно оставить на видеокарте и делать с ними много шагов подряд.

Главная мысль Передача данных на видеокарту и обратно стоит времени. Маленькие задачи лучше решать на процессоре.

16.4Как картинка попадает на экран

  1. Программа описывает сцену: где какие предметы, откуда смотрит камера.
  2. Видеокарта переводит каждый предмет в треугольники и считает, куда они попадают на экране.
  3. Для каждой точки экрана (а их миллионы) работники параллельно вычисляют цвет: освещение, текстуры, тени.
  4. Готовый кадр складывается в память видеокарты — кадровый буфер.
  5. Экран 60 (или 120, 144) раз в секунду забирает свежий кадр.

Чтобы не показать наполовину нарисованный кадр, видеокарта рисует в один буфер, пока экран показывает другой, а потом они меняются местами.

Главная мысль Картинка — это миллионы точек, цвет каждой считается параллельно. Готовый кадр экран забирает много раз в секунду.

16.5Специальные ускорители

Видеокарты оказались отличными для нейросетей: обучение — это огромное количество одинаковых умножений. Поэтому появились ещё более узкие «специалисты»: блоки для перемножения матриц (тензорные ядра), чипы только для нейросетей, блоки для сжатия видео и шифрования. Чем уже задача, тем быстрее и экономнее под неё можно сделать железо.

Главная мысль Чем специализированнее чип, тем лучше он делает свою задачу — и тем хуже всё остальное.

16.6А что с Java?

Обычный бэкенд-сервис на Java видеокарту не использует: его работа — ждать базу и сеть, разбирать запросы, а это задачи для процессора. С видеокартой Java обычно работает косвенно: через библиотеки машинного обучения или вызывая внешние сервисы, где модели крутятся на GPU. Для бэкендера важнее понимать саму идею: «много простых параллельно» против «мало умных».

Главная мысль Для типичного Java-сервиса GPU не нужен. Полезно понимать, когда задачу стоит отдать «классу», а когда — «профессору».

16.8Проверьте себя

Для какой задачи видеокарта подходит лучше процессора?

  • обработка одного запроса пользователя со множеством проверок
  • чтение файла с диска
  • одинаковый расчёт для миллионов точек изображения
  • ожидание ответа базы данных
Одна операция над огромным количеством данных — идеальная работа для «класса» GPU.

Почему развилки «если» замедляют видеокарту?

  • отряд делает всё хором, поэтому разные ветки выполняются по очереди, а остальные ждут
  • видеокарта не умеет сравнивать
  • развилки занимают много памяти
  • не замедляют
Это расхождение: хор не поёт две песни одновременно.

Почему маленькую задачу бывает быстрее решить на процессоре, даже если GPU мощнее?

  • GPU нужно долго включать
  • доставка данных на видеокарту и обратно съедает весь выигрыш
  • GPU не умеет маленькие задачи
  • это неправда
Пересылка по шине — как почта в другой город. Окупается только на больших объёмах.

Зачем видеокарте два кадровых буфера?

  • для двух мониторов
  • для запаса памяти
  • для 3D-очков
  • чтобы рисовать новый кадр, пока экран показывает готовый, и не показывать недорисованное
Рисуем в один, показываем другой, потом меняем местами.

Нужна ли видеокарта типичному бэкенд-сервису на Java?

  • да, без неё он не запустится
  • да, она ускоряет базу данных
  • обычно нет: его работа — ждать сеть и базу и разбирать запросы
  • только для логов
Такие задачи с развилками и ожиданием — работа для процессора.
