Как устроен компьютер

Computer science для Java-разработчика: как биты становятся числами и текстом, как процессор исполняет команды, что такое поток, стек и кадр, почему кэш решает всё, как устроены виртуальная память, ядро ОС, диски, сеть, загрузка, контейнеры и ускорители — и как всё это видно из Java. Каждое утверждение, которое можно проверить, проверяется в лабораторной: на JDK 25 и в Linux-контейнере с gcc и strace.

Как устроена тема целиком

Курс идёт снизу вверх: каждый слой построен из предыдущего и объясняет «магию» следующего. На верхнем слое — ваша Java-программа, и в каждой главе показано, как механизмы слоя видны из неё.

Как работать с пособием

  1. Прогоняйте симуляторы в каждой главе: процессор, конвейер, кэш, MESI, планировщик — меняйте параметры и предсказывайте результат до того, как посмотрите.
  2. Делайте лабораторные: Java-код набирайте в IDEA, Linux-эксперименты (strace, gcc, /proc) запускайте в Docker. Под каждой командой — настоящий вывод для сверки.
  3. Связывайте с Java: почти каждая глава заканчивается разделом о том, где механизм проявляется в JVM, со ссылками на пособия JVM, Java Core и Concurrency.
  4. Отвечайте на вопросы самопроверки вслух; в теме 19 — карточки по всему курсу с повторением трудных.
О точности Числа и выводы в лабораторных сняты настоящим запуском на машине Intel Core Ultra 5 125H, Windows 11, OpenJDK 25.0.2 и Docker Desktop (Linux-ядро WSL 2, образ eclipse-temurin:25-jdk с JDK 25.0.4). На вашей машине абсолютные значения будут другими — соотношения и поведение те же. Числа в тексте глав — порядки величин для типичного железа 2024–2026 годов; конкретные задержки и размеры зависят от модели процессора и версий ПО.

Практикум: подготовка рабочего места

Лабораторные двух видов. Java-программы запускаются на вашей машине — нужен JDK 25 и IDE. Эксперименты с ОС (системные вызовы через strace, машинный код через gcc и objdump, файлы /proc и /sys, cgroups) требуют Linux — для них используется Docker-контейнер с готовым набором инструментов.

1. JDK и IDE

  1. JDK 25: в IntelliJ IDEA — File → Project Structure → SDK → Add SDK → Download JDK → 25. Проверка: java -version в терминале.
  2. Проект cs-lab (File → New → Project → Java, без системы сборки), для каждой главы — модуль cs01, cs02… Классы — прямо в src. Language level — 25.
  3. Команды из пособия выполняйте во встроенном терминале IDEA (Alt+F12), перейдя в каталог с исходником (cd cs04/src): javac Имя.java и java Имя или сразу java Имя.java. VM options (-Xss, -Xmx) — Run → Edit Configurations → Modify options → Add VM options.

2. Docker и образ cs-lab

  1. Установите Docker Desktop (Windows, macOS) или Docker Engine (Linux). На Windows Docker работает в лёгкой виртуальной машине WSL 2 — в темах 09 и 15 это пригодится как пример.
  2. Создайте в любом каталоге файл Dockerfile: 
    FROM eclipse-temurin:25-jdk
RUN apt-get update && apt-get install -y --no-install-recommends \
        gcc libc6-dev binutils strace procps util-linux file \
    && rm -rf /var/lib/apt/lists/*
WORKDIR /lab
  3. Соберите образ (один раз, около минуты): docker build -t cs-lab .
  4. Проверка: docker run --rm cs-lab sh -c "gcc --version; strace -V; java -version"

3. Как запускаются команды в контейнере

Команды лабораторных монтируют текущий каталог в контейнер как /lab: файлы, набранные в IDEA, сразу видны внутри.

ОболочкаМонтирование текущего каталога
PowerShell (Windows, терминал IDEA по умолчанию)docker run --rm -v "${PWD}:/lab" cs-lab … — как в пособии
cmddocker run --rm -v "%cd%:/lab" cs-lab …
bash, zsh (Linux, macOS)docker run --rm -v "$(pwd):/lab" cs-lab …
Git Bash на WindowsMSYS_NO_PATHCONV=1 docker run --rm -v "$(pwd -W):/lab" cs-lab … (иначе пути превратятся в C:\…)
  • strace внутри контейнера требует права на трассировку — в командах есть --cap-add=SYS_PTRACE.
  • Несколько экспериментов (сброс page cache, права root) используют --privileged — только для учебных целей, в продакшене так не делают (тема 17).
  • В контейнере свой JDK 25 из образа Temurin — последняя цифра версии в выводе может отличаться от вашей локальной.

4. Как проходить лабораторную

  1. Наберите код руками (кнопки copy можно скрыть переключателем «набираю руками» в начале практикума главы).
  2. На шагах с вопросом сначала запишите прогноз — он сохраняется в браузере, — затем запустите и нажмите «Сверить».
  3. Сравните вывод с образцом: отличия в числах ожидаемы, отличия в поведении — повод разобраться.
  4. Блок «Поэкспериментируйте» — меняйте по одной детали и предсказывайте результат.
