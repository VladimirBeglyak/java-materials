13.1Путь сообщения: от провода до программы

Данные по сети приходят маленькими пакетами — как письма. Путь письма внутри компьютера:

  1. Сетевая карта принимает сигнал из провода или по Wi-Fi и сама (через DMA) кладёт пакет в память.
  2. Она «звонит» прерыванием: «пришла почта».
  3. Ядро разбирает пакет: проверяет, кому адресовано, собирает письма в правильном порядке, просит переслать потерянные (это делает протокол TCP).
  4. Ядро кладёт готовые данные в почтовый ящик конкретного соединения.
  5. Программа забирает данные из ящика, когда делает чтение.
Главная мысль Почти всю сетевую работу делает ядро. Программа только забирает готовые данные из «ящика» своего соединения и кладёт туда то, что хочет отправить.

13.2Сокет — почтовый ящик с номером

Сокет — это «почтовый ящик» для одного соединения. Программа получает от ядра номер этого ящика и дальше говорит: «прочитай из ящика 7», «положи в ящик 7». Интересно, что для ядра сокет — то же самое, что открытый файл: такой же номер, такие же «прочитать» и «записать». В Unix есть поговорка: «всё есть файл».

У сервера есть ещё особый ящик — «приёмная»: туда приходят новые клиенты. Каждый раз, когда кто-то подключается, сервер получает для него отдельный новый ящик.

Главная мысль Сокет — ящик одного соединения, у которого есть номер. Читать и писать в него можно почти как в файл.

13.3Как обслужить тысячу клиентов

Самое простое: на каждого клиента — свой почтальон (поток), который стоит у его ящика и ждёт. Пришло письмо — обработал, снова ждёт. Это блокирующий способ. Понятно и удобно, но если клиентов десять тысяч, нужно десять тысяч почтальонов, и почти все они просто стоят. Каждый поток стоит памяти, а планировщику тяжело.

Умнее: один почтальон и дежурный у табло. Почтальон говорит дежурному: «Вот список из десяти тысяч ящиков. Разбуди меня, когда в каких-нибудь из них что-то появится». Дежурный будит его со списком: «пришло в ящики 15, 203 и 7801». Почтальон быстро их обрабатывает и снова просит разбудить. В Linux такой дежурный называется epoll. Так работают Nginx, Netty, Node.js.

Почтальон и дежурный (epoll)
почтальон → дежурному: следи за ящиками 1 … 10 000
почтальон спитприходят письма в ящики 15 и 7801
дежурный: будит почтальона → «готовы: 15, 7801»почтальон: читает 15, отвечает; читает 7801, отвечает
нигде не ждал ни секундыпочтальон → дежурному: «разбуди, когда будет ещё»
один поток обслуживает тысячи соединений

Программа один раз говорит ядру, за какими сокетами следить.

Ядро будит программу и сразу сообщает, где есть данные.

Программа обрабатывает только готовые ящики — без ожидания.

Почтальон снова засыпает, пока что-то не придёт.

Минус этого способа — код сложнее: нельзя просто «подождать ответ», надо писать «когда придёт ответ — сделай вот это». Поэтому в Java 21 появились виртуальные потоки: программист пишет простой код «как будто почтальон на каждого клиента», а Java под капотом сама использует дежурного. Ждущий виртуальный поток ничего не занимает, их можно держать сотни тысяч.

Главная мысль Поток на клиента — просто, но дорого. Один поток + epoll — дёшево, но сложно. Виртуальные потоки дают простой код и дешёвое ожидание сразу.

13.4Лишние копирования и zero-copy

Когда сервер отдаёт файл в сеть обычным способом, данные несколько раз перекладываются: с диска в память ядра, оттуда в память программы, потом обратно в память ядра для отправки. Это как если бы посылку со склада сначала принесли вам домой, а вы потом отнесли её на почту — хотя склад мог бы отправить её сам.

Zero-copy («без копирования») — способ сказать ядру: «отправь этот файл в этот сокет сам», без захода данных в программу. Так раздают видео и большие файлы.

Главная мысль Каждое копирование данных стоит времени. Zero-copy позволяет ядру отправить файл в сеть напрямую.

13.7Проверьте себя

Кто собирает сетевые пакеты в правильном порядке и просит переслать потерянные?

  • сама программа
  • ядро ОС (протокол TCP)
  • процессор видеокарты
  • провод
Программа получает уже готовый поток данных, всю «почтовую» работу делает ядро.

Почему «поток на каждого клиента» плохо работает при 50 000 клиентов?

  • потоки не умеют читать из сети
  • клиенты начнут мешать друг другу
  • интернет станет медленнее
  • 50 000 потоков — это много памяти и работы для планировщика, а почти все они просто ждут
Каждый поток — свой стек и место в очереди планировщика. Ждущих почтальонов слишком дорого держать.

Что делает epoll?

  • сообщает программе, в каких сокетах появились данные
  • шифрует соединение
  • ускоряет провод
  • создаёт потоки
Дежурный у табло: одна программа следит за тысячами ящиков и обрабатывает только готовые.

Чем хороши виртуальные потоки Java?

  • они быстрее считают
  • они работают без ядра ОС
  • код пишется просто, как с обычными потоками, а ожидание почти ничего не стоит
  • они не нужны
Под капотом Java использует тот же «дежурный» механизм, а программист пишет понятный последовательный код.

Что такое zero-copy?

  • удаление копий файлов
  • отправка файла в сеть ядром напрямую, без захода данных в программу
  • запрет копировать файлы
  • сжатие данных
Склад отправляет посылку сам, не принося её вам домой.
