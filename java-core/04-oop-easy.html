4.1Четыре принципа на примере машины

Класс — чертёж машины, объект — конкретная машина, собранная по чертежу. Машин по одному чертежу может быть сколько угодно.

Инкапсуляция

Двигатель спрятан под капотом, у водителя только руль и педали. Данные объекта закрыты, снаружи — только нужные методы.

Наследование

«Грузовик — это машина, плюс кузов». Новый класс получает всё от родителя и добавляет своё.

Полиморфизм

Команда «поехали» одинакова для любой машины, а едет каждая по-своему.

Абстракция

Водителю важно «умеет ехать», а не как устроена коробка передач.

Главная мысль Класс — чертёж, объект — изделие. Спрятать детали, переиспользовать, вызывать одинаково.

4.3Конструкторы и порядок сборки

Конструктор — инструкция «как собрать объект». Если класс — наследник, сначала собирается «родительская часть», потом своя: фундамент раньше стен. Статические части класса (общие для всех объектов) готовятся один раз — при первой загрузке класса, раньше любого объекта.

Главная мысль Сначала static (один раз), потом родитель, потом наследник.

В полной главе: 4.3 Конструкторы и порядок инициализации

4.4Переопределение и перегрузка

Переопределение (override)

Наследник по-своему реализует метод родителя. Какой вариант вызвать, решается во время работы по настоящему типу объекта. Это и есть полиморфизм.

Перегрузка (overload)

Несколько методов с одним именем и разными параметрами в одном классе. Какой вызвать, решает компилятор заранее по типам аргументов.

Аннотация @Override просит компилятор проверить, что вы действительно переопределяете метод, а не случайно создали новый из-за опечатки.

Главная мысль Override — решение во время работы по объекту. Overload — решение компилятора по аргументам.

В полной главе: 4.4 Полиморфизм: переопределение и перегрузка

4.5Абстрактный класс и интерфейс

Интерфейс — обещание «умею делать вот это»: «умею летать», «умею сравниваться». Класс может дать сколько угодно таких обещаний. Абстрактный класс — недоделанный чертёж с общей частью: «все животные дышат одинаково, а голос у каждого свой». Наследоваться можно только от одного класса.

Практическое правило: описывайте возможности интерфейсами, а абстрактный класс берите, когда у наследников действительно много общего состояния и кода.

Главная мысль Интерфейс — «что умею» (много), абстрактный класс — общая основа (один).

В полной главе: 4.5 Абстрактный класс и интерфейс

4.6Классы внутри классов

Класс можно объявить внутри другого. Статический вложенный — просто «сосед по файлу», связанный по смыслу. Внутренний (не static) — привязан к конкретному объекту внешнего класса и тайно держит ссылку на него; из-за этого он может удерживать в памяти большой внешний объект. Если связь с объектом не нужна — делайте вложенный класс static.

Главная мысль Вложенный класс — по умолчанию static, чтобы не держать лишнюю ссылку.

4.7Перечисления

enum — тип с фиксированным списком значений: дни недели, статусы заказа. Это лучше, чем числа или строки: опечатку поймает компилятор. У значений enum могут быть поля и методы.

Главная мысль Фиксированный список вариантов — enum, а не строки и числа.

В полной главе: 4.7 Перечисления

4.8Композиция вместо наследования

Наследование — «является»: грузовик является машиной. Композиция — «имеет»: машина имеет двигатель. Наследование жёстко связывает классы: изменили родителя — может сломаться наследник. Композиция гибче: двигатель можно заменить. Поэтому совет: наследуйтесь, только когда отношение «является» действительно верно, а в остальных случаях собирайте объект из частей.

Главная мысль «Является» — наследование, «имеет» — композиция. Во многих случаях лучше композиция.

4.10Проверьте себя

Что выполняется раньше при создании объекта-наследника?

  • конструктор наследника
  • конструктор родителя
  • одновременно
  • как повезёт
Сначала фундамент — родительская часть.

Чем переопределение отличается от перегрузки?

  • override выбирается во время работы по объекту, overload — компилятором по аргументам
  • ничем
  • overload только для конструкторов
  • override только для static
На этом построен полиморфизм.

Сколько интерфейсов может реализовать класс?

  • один
  • два
  • ни одного
  • сколько угодно
А наследоваться можно только от одного класса.

Машина и двигатель. Какая связь правильнее?

  • машина наследует двигатель
  • двигатель наследует машину
  • композиция: машина имеет двигатель
  • никакой
«Имеет» — композиция.

Какой модификатор выбирать по умолчанию для полей?

  • public
  • private
  • protected
  • неважно
Чем меньше открыто, тем проще менять класс.
