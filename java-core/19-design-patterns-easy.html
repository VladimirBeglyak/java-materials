19.2Как создавать объекты

Фабрика

Вместо «new Конкретный» — «дай подходящий». Как пиццерия: заказываете «маргариту», а как её готовят — не ваше дело.

Строитель (Builder)

Когда у объекта много необязательных параметров. Как заказ бургера: «булочка, котлета, без лука, двойной сыр» — по шагам, потом «готово».

Одиночка (Singleton)

Один экземпляр на всё приложение. Сегодня его обычно заменяет контейнер Spring — самодельные синглтоны трудно тестировать.

Главная мысль Фабрика прячет «какой класс создать», строитель упрощает сборку сложного объекта.

19.3Как соединять объекты

Адаптер

Переходник для розетки: заставляет чужой интерфейс выглядеть как нужный вам.

Декоратор

Чехол на телефон: оборачивает объект и добавляет возможности, не меняя его. Буферизация поверх чтения файла.

Прокси и фасад

Прокси — секретарь перед начальником (глава 15). Фасад — одна простая кнопка «включить кинотеатр» вместо пяти пультов.

Главная мысль Адаптер подгоняет интерфейс, декоратор добавляет поведение, фасад упрощает сложное.

19.4Как объекты взаимодействуют

Стратегия

Способ доставки на выбор: курьер, почта, самовывоз. Алгоритм можно подменить, не меняя остальной код. В Java — часто просто лямбда.

Наблюдатель

Подписка на рассылку: при событии все подписчики получают уведомление.

Шаблонный метод

Общий рецепт с «пустыми местами»: порядок шагов задан, отдельные шаги подставляют наследники.

Главная мысль Стратегия — сменный алгоритм, наблюдатель — подписка на события.

19.5Когда паттерн вредит

Паттерн решает конкретную проблему. Если проблемы нет, он только добавляет классы и сложность: фабрика для одного класса, стратегия с единственной реализацией, «на будущее». Хорошее правило: сначала простой код, а паттерн — когда появилась реальная причина (второй вариант поведения, сложная сборка объекта).

Главная мысль Паттерн «на всякий случай» — лишняя сложность. Вводите по необходимости.
