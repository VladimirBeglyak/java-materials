18.1Символ — это не char

В Unicode больше миллиона мест для символов. char в Java — 16 бит, этого хватает на большинство букв, но не на всё. Эмодзи и редкие иероглифы записываются парой char. Поэтому "😀".length() равно 2, а обрезка строки «по length» может разрезать эмодзи пополам. А «буква на экране» иногда состоит из нескольких кодов (буква + знак ударения, эмодзи-семья). Для подсчёта настоящих символов есть codePointCount.

Главная мысль length() считает char, а не символы. Эмодзи — это два char.

18.2Регистр, сравнение и язык

Правила больших и маленьких букв зависят от языка. В турецком маленькая i превращается в İ (с точкой). Если сервер настроен на турецкий язык, "title".toUpperCase() даст «TİTLE», и сравнение с «TITLE» не пройдёт. Для технических строк (ключи, команды) указывайте Locale.ROOT. А для сортировки по-русски (с ё на своём месте) нужен Collator, а не обычное сравнение.

Главная мысль Для технических строк — Locale.ROOT. Для сортировки текстов людей — Collator.

18.3Форматирование

String.format и formatted подставляют значения в шаблон: "%.2f" — число с двумя знаками после запятой. Внимание: разделитель дробной части зависит от языка — в России запятая, в США точка. Для денег и чисел, которые увидит человек, используйте NumberFormat с нужным Locale; для данных между системами — фиксированный формат.

Главная мысль Формат для людей зависит от языка, формат для машин должен быть фиксированным.

18.4Полезные методы String

  • strip() — убрать пробелы по краям (учитывает Unicode, в отличие от старого trim).
  • isBlank() — пустая или только пробелы.
  • repeat(n), lines(), String.join.
  • Текстовые блоки """…""" для многострочного текста.
Главная мысль strip, isBlank, lines, join покрывают большую часть повседневных задач.

18.5Регулярные выражения: шаблон поиска

Регулярное выражение — шаблон, описывающий, как выглядит искомый текст: \d{3}-\d{2} — «три цифры, дефис, две цифры». Основные кирпичики: \d — цифра, \w — буква/цифра, . — любой символ, * — сколько угодно, + — один и больше, ? — может быть, скобки — группы. В Java шаблон компилируют один раз (Pattern.compile) и используют много раз — это быстрее, чем String.matches в цикле.

Главная мысль Regex — шаблон текста. Компилируйте Pattern один раз.

18.6Катастрофический перебор

Некоторые шаблоны с вложенными повторами, например (a+)+$, на «почти подходящей» строке начинают перебирать огромное число вариантов разбиения — и проверка строки из 30 символов может занять минуты. Злоумышленник может специально прислать такую строку и «повесить» сервер — это атака ReDoS.

Почему (a+)+$ зависает на «aaaa…ab»
строка: aaaaaaaaaaaaaaaaaaab — почти подходит, но в конце bдвижок: «aaaa…a» можно разбить на группы по-разному:
(aaaa)(aaa)…, (aa)(aaaaa)…, (a)(a)(a)…в конце b → не совпало → пробуем следующее разбиение
вариантов разбиения — 2 в степени длины20 букв — миллион попыток, 30 букв — миллиард
защита: шаблоны без вложенных повторов, ограничение длины ввода

Почти подходит, но последний символ ломает совпадение.

Вложенные + дают множество способов поделить буквы.

Движок пробует каждый.

Время растёт экспоненциально.

Главная мысль Избегайте вложенных повторов в regex и ограничивайте длину входа от пользователей.

18.8Проверьте себя

Чему равно "😀".length()?

  • 1
  • 2
  • 4
  • 0
Эмодзи — суррогатная пара из двух char.

Почему toUpperCase для технических строк лучше вызывать с Locale.ROOT?

  • так быстрее
  • так короче
  • иначе ошибка компиляции
  • иначе на сервере с турецким языком «i» превратится в «İ»
Правила регистра зависят от языка.

Как правильно использовать регулярное выражение в цикле по миллиону строк?

  • один раз Pattern.compile, затем matcher для каждой строки
  • String.matches в цикле
  • создавать Pattern на каждой итерации
  • не использовать regex
Компиляция шаблона — дорогая операция.

Что опасного в шаблоне (a+)+$?

  • он не компилируется
  • он находит лишнее
  • на коварной строке он перебирает экспоненциально много вариантов (ReDoS)
  • ничего
Вложенные повторы — классический источник ReDoS.

Как правильно отсортировать список русских фамилий?

  • обычным sort по строкам
  • с Collator для русского языка
  • по длине
  • по hashCode
Обычное сравнение идёт по номерам символов, и «ё» оказывается не на своём месте.
