3.1Строку нельзя изменить

Строка в Java — как надпись, высеченная в камне. Методы toUpperCase(), replace(), trim() не меняют исходную строку, а возвращают новую. Поэтому s.toUpperCase(); без присваивания ничего не делает — результат выброшен.

Зачем так? Неизменяемую строку можно безопасно передавать куда угодно и использовать из многих потоков, она надёжный ключ для HashMap, и её можно хранить в общем пуле.

Главная мысль Методы строк возвращают новую строку. Не забудьте сохранить результат.

3.2Что внутри

Внутри строка — массив байтов. Если все символы латинские, каждый занимает 1 байт, иначе — 2 байта (это называется «компактные строки»). Ещё строка запоминает свой хэш при первом вычислении, чтобы не считать его каждый раз.

Главная мысль Строка — массив байтов; латиница хранится компактнее.

3.3Пул строк и ловушка ==

Одинаковые строки, написанные прямо в коде (литералы), Java хранит в пуле в одном экземпляре — как библиотека, где одна книга на всех читателей. Поэтому "abc" == "abc" даёт true: это один и тот же объект. А строка, собранная во время работы программы (из ввода, из кусков), — новый объект, и == вернёт false, хотя буквы те же.

== сравнивает адреса, equals — содержимое. Для строк — всегда equals.

Главная мысль == «работает» для литералов случайно, благодаря пулу. Сравнивайте equals.

3.4Склейка и StringBuilder

Каждое + со строкой создаёт новую строку. Склеить пару кусков — нормально. Но если в цикле на тысячу шагов делать s = s + x, каждый раз копируется вся накопленная строка — работы получается квадрат от длины. Для склейки в цикле используют StringBuilder — изменяемый «черновик», куда кусочки дописываются в конец, а в конце из него делают строку.

Главная мысль В цикле — StringBuilder. Одиночный + — нормально.

3.5Ловушки API

  • substring(2, 5) — с индекса 2 включительно до 5 не включая.
  • split(".") — аргумент — регулярное выражение, а точка в нём означает «любой символ». Нужно split("\\.").
  • isBlank() — пустая или из пробелов; isEmpty() — только пустая.
  • Сравнение без учёта регистра — equalsIgnoreCase.
Главная мысль Конец диапазона не включается, split принимает regex.

3.6Строки и байты

Чтобы сохранить строку в файл или отправить по сети, её превращают в байты по какой-то кодировке. Если записать в одной, а прочитать в другой — получатся кракозябры. Всегда указывайте кодировку явно, почти всегда это UTF-8 (StandardCharsets.UTF_8).

Главная мысль Строка → байты только с явной кодировкой, обычно UTF-8.

3.8Проверьте себя

Что напечатает код: s = "abc"; s.toUpperCase(); print(s)?

  • ошибку
  • abc
  • пустую строку
Метод вернул новую строку, но её никуда не сохранили.

Как правильно сравнивать строки по содержимому?

  • equals
  • ==
  • compareTo == 1
  • hashCode
== сравнивает адреса.

Почему "abc" == "abc" даёт true?

  • == сравнивает буквы
  • это всегда так для строк
  • случайность
  • литералы хранятся в пуле в одном экземпляре
Для строк, собранных во время работы, это не сработает.

Чем склеивать строку из тысячи кусков в цикле?

  • оператором + в цикле
  • StringBuilder
  • String.concat в цикле
  • массивом char вручную
+ в цикле каждый раз копирует всё накопленное.

Почему "a.b.c".split(".") не делит по точкам?

  • split не работает с точками
  • нужна двойная точка
  • аргумент — регулярное выражение, где точка — «любой символ»
  • делит
Нужно экранировать: "\\.".
