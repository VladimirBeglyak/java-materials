17.1Почему не Date и Calendar

Старые классы Date и Calendar изменяемы (их можно случайно испортить, передав куда-то), не потокобезопасны, с путаницей (месяцы в Calendar с нуля: январь — 0) и смешивают понятия. С Java 8 есть java.time — неизменяемые, понятные типы. Используйте его.

Главная мысль Новый код — только java.time.

17.3Главное правило: момент и «время на стене»

Когда в Москве 15:00, в Лондоне 12:00, а момент — один и тот же. Момент (Instant) одинаков для всего мира. Время на стене зависит от того, на какие часы смотреть. Правило: храните и передавайте моменты (в UTC), а в местное время переводите только при показе человеку. LocalDateTime без пояса — это «время на стене неизвестно где», и момент из него не получить.

Главная мысль Храним Instant (UTC), показываем в поясе пользователя.

17.4Часовые пояса и перевод часов

Во многих странах дважды в год переводят часы. Весной одного часа нет вовсе (2:30 ночи не существует), осенью один час случается дважды (2:30 бывает два раза). Поэтому «плюс сутки» и «плюс 24 часа» — не всегда одно и то же. Используйте пояса по названию (Europe/Berlin), а не фиксированные смещения (+01:00): правила поясов меняются, и Java знает их историю.

17.5Арифметика и сравнение

Все типы неизменяемы: date.plusDays(1) возвращает новую дату, исходная не меняется (как со строками). Для промежутков — Duration (секунды) и Period (дни, месяцы, годы). Сравнивать — isBefore, isAfter. Осторожно с месяцами: 31 января + 1 месяц = 28 (или 29) февраля.

Главная мысль plus/minus возвращают новый объект. Месяцы разной длины.

17.6Форматирование и разбор

Для передачи между системами используйте стандарт ISO-8601 (2026-11-01T12:00:00Z) — его понимают все. Для показа людям — DateTimeFormatter с нужным шаблоном и языком. Типичная ошибка в шаблоне: YYYY — это «неделя-год», а нужен yyyy; в конце декабря они расходятся.

Главная мысль Между системами — ISO-8601, для людей — форматтер. yyyy, а не YYYY.

В полной главе: 17.6 Форматирование и разбор

17.7Тестируемость: Clock

Если код сам спрашивает «который час» (Instant.now()), его трудно тестировать: время каждый раз разное. Решение — передавать в код объект Clock. В работе это настоящие часы, а в тестах — «остановленные» на нужной дате. Тогда проверка «подписка истекла через 30 дней» становится простой.

Главная мысль Передавайте Clock — и время в тестах станет управляемым.

В полной главе: 17.7 Тестируемость: Clock

17.8База данных и JSON

В базе момент храните в типе «время с поясом» (в PostgreSQL — timestamptz), в JSON — строкой ISO-8601 с Z или смещением. Даты без времени (день рождения) — отдельным типом date. Не храните время числом миллисекунд без пояснения и не храните моменты как местное время без пояса.

Главная мысль В базе — timestamptz, в JSON — ISO-8601.
