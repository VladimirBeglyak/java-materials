Дата и время: java.time

Время — источник самых дорогих и трудноуловимых ошибок: отчёт сдвинулся на день, подписка продлилась на час раньше, тест падает только в ночь перевода часов. Почти все они происходят от одной причины — перепутаны «момент времени» и «дата на календаре». Пакет java.time разводит эти понятия по разным типам; нужно понимать, какой тип что означает.

17.3Главное правило: момент и «время на стене»

Instant2026-10-10T09:15:30Z
+ ZoneId →
ZonedDateTime12:15:30 Europe/Moscow
→ toLocalDateTime →
LocalDateTime2026-10-10T12:15:30 — зона потеряна
Instant now = Instant.now();                                  // момент: одинаков во всём мире
ZonedDateTime moscow = now.atZone(ZoneId.of("Europe/Moscow")); // тот же момент глазами москвича
ZonedDateTime tokyo  = now.atZone(ZoneId.of("Asia/Tokyo"));    // и токийца
moscow.toInstant().equals(tokyo.toInstant());                  // true — это один момент

LocalDateTime wall = moscow.toLocalDateTime();                 // «12:15 на стене» — без зоны это НЕ момент
Instant back = wall.atZone(ZoneId.of("Europe/Moscow")).toInstant();   // чтобы вернуться, зону нужно знать
Типичная ошибка LocalDateTime.now() берёт время в зоне по умолчанию JVM. На ноутбуке разработчика это Москва, в контейнере — UTC: одно и то же значение в БД означает разные моменты. Для событий используйте Instant.now(), а зону сервера (-Duser.timezone=UTC) делайте явной.

17.7Тестируемость: Clock

@Service
class TrialService {
    private final Clock clock;                                   // бин: Clock.systemUTC()
    TrialService(Clock clock) { this.clock = clock; }

    boolean isExpired(Instant startedAt) {
        return Instant.now(clock).isAfter(startedAt.plus(Duration.ofDays(14)));
    }
}

// тест: время под контролем, никаких Thread.sleep и «тест падает после полуночи»
Clock fixed = Clock.fixed(Instant.parse("2026-10-10T00:00:00Z"), ZoneOffset.UTC);
assertTrue(new TrialService(fixed).isExpired(Instant.parse("2026-09-01T00:00:00Z")));

Правило: в бизнес-коде нет вызовов Instant.now()/LocalDate.now() без аргумента — только с внедрённым Clock.

Лаба 17.1Один момент — разное «время на стене»15 мин

Увидеть разницу между Instant, LocalDateTime, ZonedDateTime и OffsetDateTime на одном моменте.

  1. Создайте файл Moment.java:
    import java.time.*;

public class Moment {
    public static void main(String[] args) {
        Instant launch = Instant.parse("2026-10-21T09:00:00Z");
        System.out.println("Instant (UTC):      " + launch);
        for (String zone : new String[] { "Europe/Moscow", "Asia/Almaty", "America/New_York", "Asia/Kolkata" }) {
            ZonedDateTime z = launch.atZone(ZoneId.of(zone));
            System.out.printf("%-18s  %s  (смещение %s)%n", zone, z.toLocalDateTime(), z.getOffset());
        }
        LocalDateTime wall = LocalDateTime.of(2026, 10, 21, 12, 0);
        System.out.println("LocalDateTime 12:00 в Москве = " + wall.atZone(ZoneId.of("Europe/Moscow")).toInstant());
        System.out.println("LocalDateTime 12:00 в Нью-Йорке = " + wall.atZone(ZoneId.of("America/New_York")).toInstant());
        System.out.println("зона JVM по умолчанию: " + ZoneId.systemDefault());
    }
}
  2. Одинаковы ли два последних Instant и почему LocalDateTime нельзя хранить как «момент события»?

Лаба 17.2Перевод часов: пропущенный и повторённый час20 мин

Создать время, которого не существует, и время, которое случилось дважды, и посмотреть, что с ними делает java.time.

  1. Создайте файл Dst.java:
    import java.time.*;

public class Dst {
    public static void main(String[] args) {
        ZoneId berlin = ZoneId.of("Europe/Berlin");
        // 29 марта 2026: 02:00 → 03:00, часа 02:xx не существует
        ZonedDateTime gap = ZonedDateTime.of(LocalDateTime.of(2026, 3, 29, 2, 30), berlin);
        System.out.println("02:30 в «дыре»:   " + gap);

        // 25 октября 2026: 03:00 → 02:00, час 02:xx повторяется
        ZonedDateTime overlap = ZonedDateTime.of(LocalDateTime.of(2026, 10, 25, 2, 30), berlin);
        System.out.println("02:30 (раннее):   " + overlap);
        System.out.println("02:30 (позднее):  " + overlap.withLaterOffsetAtOverlap());

        ZonedDateTime before = ZonedDateTime.of(LocalDateTime.of(2026, 10, 24, 12, 0), berlin);
        System.out.println("plusDays(1):      " + before.plusDays(1));
        System.out.println("plusHours(24):    " + before.plusHours(24));
        System.out.println("часов между полуднями: " + Duration.between(before, before.plusDays(1)).toHours());
    }
}
  2. Что станет с 02:30 29 марта? Отличаются ли plusDays(1) и plusHours(24) 24 октября?

    Вывод (JDK 25.0.2)

    02:30 в «дыре» сдвигается вперёд на длину перехода: 03:30+02:00. В октябре 02:30 существует дважды: по умолчанию берётся раннее смещение (+02:00), withLaterOffsetAtOverlap даёт +01:00. plusDays(1) сохраняет «время на стене» — 12:00 следующего дня (прошло 25 часов), plusHours(24) прибавляет ровно 24 часа — 11:00. «День» и «24 часа» — разные вещи: Period против Duration.

Лаба 17.3Конец месяца и YYYY вместо yyyy15 мин

Поймать две ошибки, которые проходят все тесты, кроме тестов в последние дни месяца и года.

  1. Создайте файл Edges.java:
    import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.util.Locale;

public class Edges {
    public static void main(String[] args) {
        LocalDate jan31 = LocalDate.of(2026, 1, 31);
        System.out.println("31 янв + 1 мес      = " + jan31.plusMonths(1));
        System.out.println("31 янв + 1 мес + 1  = " + jan31.plusMonths(1).plusMonths(1));
        System.out.println("31 янв + 2 мес      = " + jan31.plusMonths(2));

        Locale ru = Locale.forLanguageTag("ru-RU");
        DateTimeFormatter good = DateTimeFormatter.ofPattern("dd.MM.yyyy", ru);
        DateTimeFormatter bad = DateTimeFormatter.ofPattern("dd.MM.YYYY", ru);
        for (LocalDate d : new LocalDate[] { LocalDate.of(2025, 12, 28), LocalDate.of(2025, 12, 29), LocalDate.of(2026, 6, 1) }) {
            System.out.println(d + ":  yyyy → " + d.format(good) + "   YYYY → " + d.format(bad));
        }
    }
}

Лаба 17.4Clock: тестируемое «сейчас»15 мин

Убрать now() из бизнес-логики, передав Clock, и проверить логику на фиксированном и «ускоренном» времени.

  1. Создайте файл Subscription.java:
    import java.time.*;

public class Subscription {
    private final Clock clock;
    private final Instant expiresAt;

    Subscription(Clock clock, Instant expiresAt) {
        this.clock = clock;
        this.expiresAt = expiresAt;
    }

    boolean isActive() { return Instant.now(clock).isBefore(expiresAt); }
    long daysLeft() { return Duration.between(Instant.now(clock), expiresAt).toDays(); }

    public static void main(String[] args) {
        Instant bought = Instant.parse("2026-01-01T00:00:00Z");
        Instant expires = bought.plus(Duration.ofDays(30));
        Clock atPurchase = Clock.fixed(bought, ZoneOffset.UTC);
        Clock day29 = Clock.offset(atPurchase, Duration.ofDays(29));
        Clock day31 = Clock.offset(atPurchase, Duration.ofDays(31));

        for (Clock c : new Clock[] { atPurchase, day29, day31 }) {
            var sub = new Subscription(c, expires);
            System.out.printf("%s: активна=%b, осталось дней %d%n", Instant.now(c), sub.isActive(), sub.daysLeft());
        }
        System.out.println("реальные часы: " + new Subscription(Clock.systemUTC(), expires).isActive());
    }
}
    javac Subscription.java

    Вывод (JDK 25.0.2)

17.10Самопроверка

Сервис сохраняет LocalDateTime.now() как время создания заказа. Сервис перенесли из Москвы в контейнер с зоной UTC. Что произойдёт?

  • Ничего, LocalDateTime учитывает зону
  • Новые записи будут на 3 часа «раньше» старых: значение без зоны интерпретируется по-разному
  • Ошибка при записи в БД
  • JVM автоматически пересчитает старые записи
LocalDateTime — не момент времени. Для событий — Instant.

Чем Period отличается от Duration?

  • Period точнее
  • Duration только для дат
  • Period — календарные годы, месяцы, дни; Duration — точное количество секунд и наносекунд
  • Ничем
«Плюс месяц» и «плюс 30 × 24 часа» — разные операции; в дни перевода часов различаются даже «плюс день» и «плюс 24 часа».

Шаблон "YYYY-MM-dd" для даты 29 декабря 2025 года выдаст…

  • 2026-12-29 — YYYY означает год по неделям, а эта неделя относится к 2026
  • 2025-12-29
  • Ошибку
  • 2025-52-29
Классический баг, проявляющийся раз в год в последних числах декабря. Нужно yyyy или uuuu.

Как сделать тестируемым код, зависящий от текущего времени?

  • Вызывать Thread.sleep в тестах
  • Менять системные часы
  • Использовать System.currentTimeMillis()
  • Внедрять java.time.Clock и в тесте подставлять Clock.fixed
Clock — стандартная абстракция источника времени; все now()-методы принимают его аргументом.
В каком виде хранить и передавать время события?

Как момент: Instant (в БД — timestamptz/UTC, в JSON — ISO-8601 с Z или смещением). Преобразование в местное время — только на границе с пользователем, с его ZoneId.

Когда хранить Instant недостаточно?

Для будущих событий, заданных местным временем (встреча, рейс, расписание): правила зоны могут измениться, и сохранённый Instant станет неверным. Хранят LocalDateTime + ZoneId и вычисляют момент при необходимости.

Что такое gap и overlap и как java.time их обрабатывает?

Gap — несуществующее местное время при переводе часов вперёд: atZone сдвигает на длину разрыва. Overlap — время, наступающее дважды при переводе назад: выбирается более раннее смещение, второе — withLaterOffsetAtOverlap(). Проверка — ZoneRules.getValidOffsets.

Почему для замера длительности нельзя использовать Instant.now()?

Системные часы корректируются (NTP, ручная установка) и могут скакнуть назад или вперёд. System.nanoTime() монотонен и предназначен именно для интервалов.
