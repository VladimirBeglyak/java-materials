18.1Unicode: символ — это не char

Unicode нумерует символы кодовыми точками (code points) от U+0000 до U+10FFFF. Java-строка — последовательность 16-битных char в кодировке UTF-16. Символы выше U+FFFF (эмодзи, редкие иероглифы) занимают два char — суррогатную пару. А то, что человек видит как один символ, может состоять из нескольких кодовых точек (буква + модификатор, флаг, семейство из эмодзи).

Симулятор: из чего состоит строка
"👍".length();                         // 2 — а не 1
"👍".charAt(0);                        // половина символа (старший суррогат) — мусор при выводе
s.substring(0, 10);                    // может разрезать суррогатную пару
new StringBuilder("ab👍").reverse();   // reverse умеет пары, но не комбинируемые знаки

s.codePoints().count();                               // число кодовых точек
s.codePoints().mapToObj(Character::toString).toList(); // обход по кодовым точкам

// Одинаковый на вид текст может не совпадать по equals: «é» = U+00E9 или e + U+0301
String a = Normalizer.normalize(input, Normalizer.Form.NFC);   // нормализуйте перед сравнением и сохранением

// Ограничение «не более 255 символов» в БД может считать байты, а не символы: VARCHAR в MySQL utf8mb4 — до 4 байт на символ

18.2Регистр, сравнение и Locale

// Сервер в турецкой локали (или пользовательская Locale по умолчанию = tr-TR):
"TITLE".toLowerCase();                 // "tıtle" — с «ı» без точки!
"title".toUpperCase();                 // "TİTLE" — с «İ» с точкой
"FILE".toLowerCase().equals("file");   // false → сломан поиск по ключам, расширениям, заголовкам HTTP
key.toLowerCase(Locale.ROOT);                          // для технических идентификаторов — всегда Locale.ROOT
a.equalsIgnoreCase(b);                                 // не зависит от локали
String.CASE_INSENSITIVE_ORDER.compare(a, b);

Collator ru = Collator.getInstance(Locale.forLanguageTag("ru"));   // сортировка для людей: «ё» рядом с «е»
names.sort(ru);                                        // String.compareTo сравнивает коды char: «Ё» окажется перед «А»

Правило: всё, что видит машина (ключи, enum, протоколы), — Locale.ROOT; всё, что видит человек (сортировка, числа, даты), — явная Locale пользователя. Методы без параметра Locale берут локаль JVM, и поведение зависит от сервера.

18.3Форматирование

String.format("%-10s|%5d|%8.2f|%s", "apple", 42, 3.14159, true);   // "apple     |   42|    3,14|true" — запятая зависит от Locale!
"Заказ %d на сумму %s".formatted(id, total);                         // то же, метод экземпляра (Java 15)
String.format(Locale.ROOT, "%.2f", 3.14159);                         // "3.14" — для машинных форматов

String json = """
        {
          "id": %d,
          "name": "%s"
        }
        """.formatted(id, name);                                     // text block: отступ определяется закрывающими кавычками

NumberFormat.getCurrencyInstance(Locale.forLanguageTag("ru-RU")).format(1234567.5);   // 1 234 567,50 ₽
NumberFormat.getCompactNumberInstance(Locale.US, NumberFormat.Style.SHORT).format(1_250_000);  // 1M
new DecimalFormat("#,##0.00", DecimalFormatSymbols.getInstance(Locale.ROOT)).format(1234.5);   // 1,234.50
Не собирайте JSON, SQL и HTML форматированием строк: кавычка или тег в данных ломают структуру и открывают инъекции. Для JSON — сериализатор, для SQL — параметры PreparedStatement (тема 22), для HTML — экранирование шаблонизатора.

18.5Регулярные выражения

private static final Pattern ORDER = Pattern.compile(                 // компилировать ОДИН раз — это дорого
        "(?<prefix>[A-Z]{2})-(?<year>\\d{4})-(?<num>\\d+)");            // именованные группы

Matcher m = ORDER.matcher("Заказы: RU-2026-00042, KZ-2025-7");
while (m.find()) {                                                     // find — следующее вхождение в тексте
    System.out.println(m.group("prefix") + " " + m.group("year") + " " + Integer.parseInt(m.group("num")));
}
ORDER.matcher("RU-2026-00042").matches();                              // matches — вся строка целиком
"a1b22c333".replaceAll("\\d+", "#");                                   // a#b#c#  (компилирует Pattern при каждом вызове!)
ORDER.matcher(text).replaceAll(r -> r.group("num"));                   // замена функцией (Java 9)
ORDER.matcher(text).results().map(MatchResult::group).toList();        // все совпадения стримом
КонструкцияЗначение
\d \w \s, \D \W \Sцифра, «словесный» символ, пробельный — и их отрицания. По умолчанию только ASCII; для Unicode — флаг (?U) или \p{L}, \p{IsCyrillic}
* + ? {n,m}жадные квантификаторы: берут максимум и возвращают по одному
*? +? ??ленивые: берут минимум

(?=…) (?!…) (?<=…) (?<!…)просмотр вперёд и назад без поглощения символов

Песочница регулярных выражений

Синтаксис JavaScript в этих пределах совпадает с Java. В Java-строке каждый обратный слэш нужно удвоить: \d → "\\d".

18.6Катастрофический перебор (ReDoS)

Движок java.util.regex — с возвратами (backtracking). Если шаблон допускает много способов разбить один и тот же текст, а в конце совпадения нет, движок перебирает их все. Число вариантов растёт экспоненциально.

Pattern p = Pattern.compile("^(a+)+$");
p.matcher("aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!").matches();   // 30 букв «a» и «!» — секунды; 40 — часы
// Вложенные квантификаторы (a+)+, (a|aa)+, (\w+\s?)+ на пользовательском вводе = отказ в обслуживании

Как защищаться

Избегать вложенных и перекрывающихся квантификаторов; использовать сверхжадные ++ и атомарные группы; ограничивать длину ввода до применения regex; для недоверенных шаблонов — движок без возвратов (RE2/J).

Когда regex не нужен

Проверка «только цифры» — цикл или chars().allMatch(Character::isDigit). Разбор JSON, XML, HTML, CSV — парсер. Email — простая проверка на «@» и письмо с подтверждением; «полный» regex по RFC нечитаем и всё равно не гарантирует, что ящик существует.

18.7Самопроверка

Что вернёт "a.b.c".split(".")?

  • ["a", "b", "c"]
  • ["a.b.c"]
  • Пустой массив: точка в regex означает «любой символ», все элементы пустые и отброшены
  • Исключение
Аргумент split — регулярное выражение. Нужно split("\\.") или split(Pattern.quote(".")).

Чем matches() отличается от find()?

  • Ничем
  • matches требует совпадения всей строки, find ищет очередное вхождение в любом месте
  • find работает только с группами
  • matches быстрее
"abc123".matches("\\d+") → false, а find() найдёт «123».

Почему key.toLowerCase() без аргумента опасен для технических ключей?

  • Результат зависит от локали JVM: в турецкой «I» превращается в «ı»
  • Метод медленный
  • Он изменяет исходную строку
  • Он не работает с ASCII
Для идентификаторов — toLowerCase(Locale.ROOT) или equalsIgnoreCase.

Чему равно "👍".length()?

  • 1
  • 4
  • 0
  • 2 — символ вне BMP хранится суррогатной парой из двух char
length() считает единицы UTF-16. Кодовые точки — codePointCount, байты UTF-8 — 4.
Чем char отличается от кодовой точки и от видимого символа?

char — 16-битная единица UTF-16. Кодовая точка — номер символа Unicode; выше U+FFFF занимает два char. Видимый символ (графема) может состоять из нескольких кодовых точек: буква с комбинируемым знаком, эмодзи с модификаторами. Отсюда ошибки в length, substring, reverse и ограничениях длины.

Почему Pattern нужно компилировать один раз?

Компиляция строит автомат и стоит на порядки дороже применения. String.matches/replaceAll/split компилируют шаблон при каждом вызове. Pattern неизменяем и потокобезопасен — хранится в static final; Matcher — нет, создаётся на каждый текст.

Что такое катастрофический перебор и как его избежать?

Экспоненциальное число вариантов разбора при вложенных/перекрывающихся квантификаторах и отсутствии совпадения. Избегать таких конструкций, применять сверхжадные квантификаторы и атомарные группы, ограничивать длину ввода, для чужих шаблонов брать движок с линейным временем.
