16.1Как отвечать на вопрос по Java Core

  1. Определение одной фразой. «HashMap — хэш-таблица с разрешением коллизий цепочками».
  2. Зачем это существует. Какую задачу решает и чем было бы плохо без этого.
  3. Как устроено. Механика на один уровень глубже вопроса: поля, алгоритм, сложность.
  4. Ловушка. Что ломается при неправильном использовании — и пример из практики.
  5. Граница применимости. Когда взять другое: TreeMap, ConcurrentHashMap.

Задачи ниже решайте так: сначала запишите ожидаемый вывод, затем объясните почему, и только потом раскрывайте ответ. Расхождение — повод вернуться к указанной теме.

16.2Что выведет код

1 · Обёртки

Integer a = 100, b = 100, c = 1000, d = 1000;
System.out.println(a == b);
System.out.println(c == d);
System.out.println(c.equals(d));
Ответ

true, false, true. Автоупаковка вызывает Integer.valueOf, который для −128…127 возвращает объекты из кэша. Для 1000 создаются два разных объекта, а == сравнивает ссылки. Тема 02.

2 · Long и Integer

Long l = 1L;
System.out.println(l == 1);
System.out.println(l.equals(1));
System.out.println(l.equals(1L));
Ответ

true, false, true. В первом случае l распаковывается и сравниваются числа. Во втором литерал 1 упаковывается в Integer, а Long.equals сначала проверяет, что аргумент — Long. Тема 02.

3 · Тернарный оператор

Integer a = null;
Integer b = true ? a : 0;
System.out.println(b);
Ответ

NullPointerException. Операнды имеют типы Integer и int, поэтому тип всего выражения — int, и a распаковывается до присваивания. Тема 02.

4 · Инкремент

int i = 0;
i = i++;
System.out.println(i);

int x = 5;
x = x++ + ++x;
System.out.println(x);
Ответ

0 и 12. i++ возвращает старое значение (0), затем увеличивает переменную до 1, после чего присваивание записывает в неё сохранённый 0. Во втором: x++ даёт 5 (x становится 6), ++x даёт 7; сумма 12.

5 · Символы и строки

System.out.println('a' + 'b' + "c");
System.out.println("c" + 'a' + 'b');
System.out.println(1 + 2 + "3" + 4 + 5);
Ответ

195c, cab, 3345. Выражение вычисляется слева направо. 'a' + 'b' — сложение двух char как чисел (97 + 98); как только слева появляется строка, + становится конкатенацией. Тема 02.

6 · Пул строк

String s1 = "java";
String s2 = new String("java");
String s3 = "ja" + "va";
String part = "ja";
String s4 = part + "va";
System.out.println(s1 == s2);
System.out.println(s1 == s3);
System.out.println(s1 == s4);
System.out.println(s1 == s4.intern());
Ответ

false, true, false, true. new всегда создаёт новый объект. "ja" + "va" — константа, вычисленная компилятором. part + "va" вычисляется при выполнении и даёт новый объект; intern() возвращает экземпляр из пула. Тема 03.

7 · Конструктор и переопределённый метод

class Base {
    Base() { print(); }
    void print() { System.out.println("Base"); }
}
class Derived extends Base {
    int value = 42;
    @Override void print() { System.out.println("Derived " + value); }
}
new Derived();
Ответ

Derived 0. Конструктор Base выполняется раньше, чем инициализаторы полей Derived, а вызов print() виртуальный — срабатывает версия потомка, которая видит значение по умолчанию. Тема 04.

8 · Перегрузка и переопределение

class Animal {
    void hello(Animal a) { System.out.println("Animal-Animal"); }
}
class Dog extends Animal {
    void hello(Dog d) { System.out.println("Dog-Dog"); }
    @Override void hello(Animal a) { System.out.println("Dog-Animal"); }
}
Animal a = new Dog();
Dog d = new Dog();
a.hello(d);
d.hello(a);
d.hello(d);
Ответ

Dog-Animal, Dog-Animal, Dog-Dog. Компилятор выбирает сигнатуру по объявленным типам: у переменной типа Animal виден только hello(Animal); при выполнении вызывается его переопределённая версия из Dog. Во втором вызове аргумент объявлен как Animal. Только в третьем и получатель, и аргумент объявлены как Dog. Тема 04.

9 · Поля и статические методы

class P { String name = "P"; static String id() { return "P"; } }
class C extends P { String name = "C"; static String id() { return "C"; } }
P obj = new C();
System.out.println(obj.name + " " + obj.id() + " " + ((C) obj).name);
Ответ

P P C. Поля и статические методы не переопределяются, а скрываются: выбор делается по объявленному типу ссылки при компиляции. Тема 04.

10 · Изменяемый элемент множества

class Point {                        // equals и hashCode — по x и y
    int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
    @Override public boolean equals(Object o) { return o instanceof Point p && x == p.x && y == p.y; }
    @Override public int hashCode() { return Objects.hash(x, y); }
}
Set<Point> set = new HashSet<>();
Point p = new Point(1, 1);
set.add(p);
p.x = 2;
System.out.println(set.contains(p));
System.out.println(set.contains(new Point(1, 1)));
System.out.println(set.size());
Ответ

false, false, 1. Поиск изменённого p идёт в бакет нового хэша — там пусто. Поиск (1, 1) попадает в нужный бакет, но лежащий там объект уже равен (2, 1), и equals возвращает false. Элемент есть, но недоступен. Тема 05.

11 · finally

static int f() { int x = 1; try { return x; } finally { x = 2; } }
static int g() { try { throw new IllegalStateException(); } finally { return 3; } }

System.out.println(f());
System.out.println(g());
Ответ

1 и 3. В f возвращаемое значение вычислено до finally. В g оператор return в finally отменяет летящее исключение — оно исчезает без следа. Тема 06.

12 · try-with-resources

record Res(String name) implements AutoCloseable {
    Res { System.out.println("open " + name); }
    public void close() { System.out.println("close " + name); }
}
try (Res a = new Res("A"); Res b = new Res("B")) {
    System.out.println("body");
    throw new IllegalStateException();
} catch (IllegalStateException e) {
    System.out.println("catch");
} finally {
    System.out.println("finally");
}
Ответ

open A, open B, body, close B, close A, catch, finally. Ресурсы закрываются в обратном порядке и до выполнения catch и finally. Тема 06.

13 · Стирание типов

List<String> strings = new ArrayList<>();
List<Integer> ints = new ArrayList<>();
System.out.println(strings.getClass() == ints.getClass());

List raw = strings;
raw.add(1);
System.out.println(strings.size());
String s = strings.get(0);
Ответ

true, 1, затем ClassCastException в последней строке. При выполнении оба списка — просто ArrayList. Через сырой тип в список строк попало число; ошибка возникает там, где компилятор вставил приведение к String. Тема 07.

14 · remove

List<Integer> list = new ArrayList<>(List.of(1, 2, 3));
list.remove(1);
list.remove(Integer.valueOf(1));
System.out.println(list);
Ответ

[3]. Первый вызов — remove(int index): удалён элемент с индексом 1, остаётся [1, 3]. Второй — remove(Object): удалено значение 1. Тема 08.

15 · Arrays.asList

int[] a = {1, 2, 3};
Integer[] b = {1, 2, 3};
System.out.println(Arrays.asList(a).size());
List<Integer> list = Arrays.asList(b);
b[0] = 99;
System.out.println(list.get(0));
list.add(4);
Ответ

1, 99, затем UnsupportedOperationException. Массив примитивов воспринимается как один элемент типа int[]. Список от Arrays.asList — представление массива: изменения видны в обе стороны, а размер менять нельзя. Тема 08.

16 · Отрицательные числа

System.out.println(Math.abs(Integer.MIN_VALUE));
System.out.println(-7 % 3);
System.out.println(Math.floorMod(-7, 3));
Ответ

-2147483648, -1, 2. У Integer.MIN_VALUE нет положительной пары в диапазоне int, и abs возвращает его же. Остаток в Java наследует знак делимого. Поэтому индекс «по хэшу» считают как Math.floorMod(hash, n), а не Math.abs(hash) % n. Тема 02.

17 · Ленивый стрим

List<String> list = new ArrayList<>(List.of("a", "b"));
Stream<String> stream = list.stream().filter(x -> { System.out.print(x); return true; });
list.add("c");
System.out.println(stream.count());
Ответ

abc3. До терминальной операции ничего не выполняется, а стрим коллекции привязывается к данным в момент её запуска — поэтому элемент, добавленный после создания стрима, тоже попадает в обработку. Полагаться на это в рабочем коде не следует. Тема 11.

16.4Экспресс-тест по всему курсу

Десять вопросов на понимание механизмов. Выберите ответ — увидите объяснение и ссылку на тему, где это разобрано.

String s1 = "a" + "b"; String s2 = "ab"; System.out.println(s1 == s2);

  • false
  • Зависит от JVM
  • true — константное выражение склеивается компилятором и попадает в пул
  • Ошибка компиляции
Тема 03: литералы и константные выражения интернируются.

В HashSet лежит объект, после вставки у него изменили поле, участвующее в hashCode. Что вернёт set.contains(obj)?

  • true
  • Скорее всего false: поиск пойдёт в другой бакет
  • ConcurrentModificationException
  • NullPointerException
Тема 05: ключи хэш-коллекций должны быть неизменяемыми.

List<? extends Number> list = new ArrayList<Integer>(); list.add(1);

  • Ошибка компиляции: в «producer» нельзя добавлять
  • Добавит 1
  • ClassCastException
  • Предупреждение unchecked
Тема 07: PECS — extends только для чтения.

Что вернёт метод int f() { try { return 1; } finally { return 2; } }?

  • 1
  • Ошибку компиляции
  • Исключение
  • 2 — return в finally заменяет результат
Тема 06: finally выполняется всегда; return в нём подавляет и значение, и исключения.

Stream.of(1,2,3).map(x -> { System.out.print(x); return x; }); — что напечатается?

  • 123
  • Ничего
  • 1
  • 321
Тема 11: без терминальной операции конвейер не выполняется.

Что напечатает System.out.println(0.1 + 0.2 == 0.3);?

  • true
  • Ошибка компиляции
  • false
  • NaN
Тема 02: 0.1 не представимо точно в двоичном виде; сумма равна 0.30000000000000004.

Класс Child extends Parent; конструктор Parent вызывает переопределённый в Child метод, читающий поле Child, инициализированное значением 5. Что увидит метод?

  • 0 (или null) — инициализаторы Child ещё не выполнялись
  • 5
  • Ошибку компиляции
  • StackOverflowError
Тема 04: порядок инициализации — сначала родитель целиком.

Какая структура даёт O(1) для добавления и удаления с обоих концов?

  • ArrayList
  • TreeSet
  • PriorityQueue
  • ArrayDeque
Тема 08: кольцевой массив; PriorityQueue даёт O(log n) и только с одного конца.

Объект больше не нужен программе, но лежит в static Map. Удалит ли его GC?

  • Да, при следующей сборке
  • Нет: он достижим от GC root (статическое поле) — это утечка
  • Да, после Full GC
  • Только с -XX:+UseG1GC
Тема 14: GC удаляет недостижимые, а не «ненужные» объекты.

Integer x = null; int y = x;

  • y = 0
  • Ошибка компиляции
  • NullPointerException при распаковке
  • y = -1
Тема 02: автораспаковка — это скрытый вызов x.intValue().
