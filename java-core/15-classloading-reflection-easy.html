15.1Жизнь класса

JVM не загружает все классы сразу — только когда класс впервые понадобился. Дальше три шага: загрузка (найти .class и прочитать), связывание (проверить байткод, подготовить статические поля), инициализация (выполнить статические блоки). Инициализация происходит ровно один раз и безопасна для потоков.

Главная мысль Классы загружаются лениво и инициализируются один раз.

15.2Загрузчики: сначала спроси старшего

Загрузчики классов выстроены в иерархию: базовый (для java.lang и т. п.), платформенный и прикладной (для вашего кода и библиотек). Правило: прежде чем искать класс самому, загрузчик спрашивает родителя. Как в библиотеке: сначала смотрят в главном фонде, и только если там нет — в своём отделе. Поэтому никто не может подменить java.lang.String своей версией.

Кто загрузит класс com.shop.Order
прикладной загрузчик: «Order? сначала спрошу родителя»платформенный: «спрошу своего родителя»базовый: «у меня такого нет»
платформенный: «у меня тоже нет»прикладной: ищет в classpath → нашёл в shop.jar → загрузил

Сначала — вверх по цепочке.

Каждый спрашивает родителя.

Системные загрузчики такого класса не знают.

Только теперь прикладной загрузчик ищет в classpath.

Главная мысль Загрузчик сначала спрашивает родителя. Системные классы подменить нельзя.

15.3Рефлексия: программа смотрит на себя в зеркало

Рефлексия позволяет во время работы узнать, какие у класса поля, методы и аннотации, создать объект по имени класса, вызвать метод, даже приватный. Так работают фреймворки: Spring находит классы с аннотациями и создаёт их, Jackson читает поля объекта для JSON, JUnit находит методы с @Test. В обычном коде рефлексию используют редко: она медленнее, обходит проверки компилятора и ломается при переименованиях.

Главная мысль Рефлексия — инструмент фреймворков. В прикладном коде — только при необходимости.

В полной главе: 15.3 Рефлексия

15.4Аннотации: наклейки на коде

Аннотация (@Override, @Test, @Transactional) — наклейка с пометкой. Сама по себе она ничего не делает. Её читают: компилятор (проверка @Override), процессоры аннотаций при сборке (Lombok, MapStruct генерируют код) или фреймворки во время работы через рефлексию.

Главная мысль Аннотация — пометка. Действие выполняет тот, кто её читает.

В полной главе: 15.4 Аннотации

15.5Динамические прокси: секретарь вместо начальника

Прокси — объект-«секретарь», который стоит перед настоящим объектом и перехватывает вызовы: может записать в журнал, открыть транзакцию, проверить права, а потом передать вызов дальше. Spring так реализует @Transactional и @Cacheable. Отсюда известная ловушка: если метод класса вызывает другой свой метод напрямую (this.save()), вызов идёт мимо секретаря — и аннотация не срабатывает.

Главная мысль Прокси перехватывает вызовы снаружи. Вызов изнутри объекта проходит мимо него.

В полной главе: 15.5 Динамические прокси

15.6JIT: разогрев программы

Сначала JVM исполняет байткод интерпретатором — медленно, но сразу. Параллельно она считает, какие методы вызываются чаще всего, и компилирует их в машинный код: сначала быстро и просто, потом — тщательно, с оптимизациями (встраивание маленьких методов, удаление лишних проверок). Поэтому сервис после старта «разогревается», и замерять скорость нужно после разогрева.

Главная мысль JIT компилирует горячий код во время работы — скорость растёт после разогрева.

15.7Быстрый старт

Для быстрого запуска есть: CDS — заранее подготовленный архив загруженных классов; AOT-кэш в новых версиях Java — сохранение результатов прошлых запусков; GraalVM native image — компиляция всей программы заранее в обычный исполняемый файл: старт за миллисекунды и мало памяти, но долгая сборка и сложности с рефлексией.

Главная мысль Важен старт — CDS, AOT-кэш или native image.

Почему нельзя подменить java.lang.String своим классом?

  • это запрещено лицензией
  • String — final
  • JVM проверяет имя автора
  • загрузчик сначала спрашивает родителя, и String загрузит системный загрузчик
