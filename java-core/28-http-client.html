HTTP-клиент: HttpClient и RestClient

Вызывать HTTP API — ежедневная задача. В стандартной библиотеке с JDK 11 есть java.net.http.HttpClient — современная замена устаревшему HttpURLConnection. Поверх него в Spring — высокоуровневые RestClient и WebClient. Здесь — как выбрать клиент и как обращаться с таймаутами.

28.1java.net.http.HttpClient

HttpClient (JDK 11+) — стандартный клиент: HTTP/2, WebSocket, асинхронность. Создаётся один раз (держит пул соединений) и переиспользуется.

HttpClient client = HttpClient.newBuilder()
        .connectTimeout(Duration.ofSeconds(10))
        .build();

HttpRequest request = HttpRequest.newBuilder()
        .uri(URI.create("https://api.example.com/orders/42"))
        .timeout(Duration.ofSeconds(5))
        .header("Accept", "application/json")
        .GET()
        .build();

HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());
System.out.println(response.statusCode() + " " + response.body());
Два таймаута connectTimeout на клиенте — на установление соединения; timeout на запросе — на весь запрос до ответа. В проде оба нужны, иначе зависший сервис повесит ваш поток.

28.2Асинхронный вызов

String body = "{\"status\":\"paid\"}";
HttpRequest post = HttpRequest.newBuilder()
        .uri(URI.create("https://api.example.com/orders"))
        .header("Content-Type", "application/json")
        .POST(HttpRequest.BodyPublishers.ofString(body))
        .build();

CompletableFuture<HttpResponse<String>> future =
        client.sendAsync(post, HttpResponse.BodyHandlers.ofString());

future.thenApply(HttpResponse::body)
      .thenAccept(System.out::println);
JSON через Jackson Для готового объекта используйте BodyHandlers.ofString() + mapper.readValue(...), либо сам напишите BodyHandler поверх ofInputStream(). Стандартная библиотека JSON не парсит.

28.3Spring RestClient

В Spring 6.1 появился RestClient — современная замена RestTemplate: fluent-API, синхронный, с поддержкой конвертеров (JSON автоматически).

RestClient client = RestClient.builder()
        .baseUrl("https://api.example.com")
        .build();

Order order = client.get()
        .uri("/orders/{id}", 42)
        .retrieve()
        .body(Order.class);            // JSON → объект автоматически

ResponseEntity<Void> resp = client.post()
        .uri("/orders")
        .body(new Order("paid"))
        .retrieve()
        .toBodilessEntity();
RestClient vs WebClient RestClient — синхронный, простой (для MVC и обычных вызовов). WebClient — реактивный (Mono/Flux), для WebFlux-стека. RestTemplate оставлен для совместимости, новые проекты начинают с RestClient.

28.5Самопроверка

Чем HttpClient лучше HttpURLConnection?

  • Поддерживает HTTP/2, WebSocket и асинхронность, удобный API
  • Он быстрее компилируется
  • Он не требует JDK
  • Ничем
HttpClient — современная замена: HTTP/2, sendAsync, WebSocket, таймауты.

Чем отличаются connectTimeout и timeout запроса?

  • connectTimeout — на соединение, timeout — на весь запрос до ответа
  • Ничем
  • timeout — только для POST
  • connectTimeout не нужен
Оба важны: зависший сервис не должен вечно держать поток.

Что возвращает sendAsync?

  • HttpResponse напрямую
  • void
  • CompletableFuture<HttpResponse>
  • Stream
Асинхронный вызов возвращает CompletableFuture для композиции.

Какой Spring-клиент выбрать для синхронного вызова в MVC?

  • WebClient
  • RestTemplate (устарел)
  • HttpURLConnection
  • RestClient
RestClient — современная синхронная замена RestTemplate; WebClient — для реактивного стека.
Как распарсить JSON-ответ HttpClient в объект?

Получить тело как строку через BodyHandlers.ofString() и распарсить Jackson-ом (ObjectMapper.readValue), либо написать свой BodyHandler поверх ofInputStream(). Стандартная библиотека JSON не разбирает.

Почему HttpClient создают один раз, а не на каждый запрос?

Клиент держит пул соединений и executor; пересоздание теряет переиспользование соединений и плодит ресурсы. Один экземпляр — на всё приложение.
