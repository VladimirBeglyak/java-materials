Коллекции: List, Queue, Deque

Выбор коллекции — это выбор структуры данных, а значит, сложности операций и расхода памяти. Глава о линейных коллекциях: как устроен ArrayList, почему LinkedList почти никогда не нужен, чем List.of отличается от Arrays.asList и откуда берётся ConcurrentModificationException в однопоточном коде.

8.3ArrayList изнутри

Внутри — обычный массив Object[] elementData и счётчик size. Ёмкость массива больше числа элементов; когда место кончается, создаётся массив в 1,5 раза больше, и элементы копируются.

List<String> list = new ArrayList<>();     // массив ещё не выделен
list.add("a");                            // выделен массив на 10 элементов
// рост ёмкости: 10 → 15 → 22 → 33 → 49 → …  (old + old / 2)

List<String> big = new ArrayList<>(100_000);   // размер известен — избежать двух десятков перевыделений
list.remove(0);                           // System.arraycopy: все элементы сдвигаются влево
  • Амортизированная O(1). Отдельное добавление иногда стоит O(n) (копирование), но за счёт роста в геометрической прогрессии среднее время остаётся постоянным.
  • Массив не уменьшается сам. Список, выросший до миллиона элементов и очищенный, продолжает держать массив на миллион ссылок. trimToSize() или новый список.
  • Удаление многих элементов через remove(i) в цикле — O(n²). removeIf(predicate) делает это за один проход.

8.4ArrayList или LinkedList

Практический вывод: ArrayList по умолчанию, LinkedList — почти никогда
  • «Вставка в середину за O(1)» у связного списка верна, только если вы уже стоите на нужном узле. Чтобы до него дойти, нужно O(n) переходов по ссылкам — медленнее, чем сдвиг массива одной командой копирования памяти.
  • Память. Узел — 24 байта плюс нагрузка на сборщик мусора от миллионов мелких объектов.
  • Очередь и стек — единственная ниша, где нужны быстрые операции с начала, — лучше обслуживает ArrayDeque.
Автор LinkedList Джошуа Блох сам признавался, что не пользуется этим классом.

8.5Очереди, стек, куча

ДействиеБросает исключениеВозвращает особое значение
Добавитьadd(e)offer(e) → false
Извлечь из началаremove()poll() → null
Посмотреть началоelement()peek() → null
Deque<String> stack = new ArrayDeque<>();     // стек: LIFO
stack.push("a"); stack.push("b");
stack.pop();                                  // "b"

Deque<String> queue = new ArrayDeque<>();     // очередь: FIFO
queue.offer("a"); queue.offer("b");
queue.poll();                                 // "a"

ArrayDeque — кольцевой буфер на массиве: оба конца двигаются без копирования. Не допускает null (он служит признаком «пусто»). Классы Stack и Vector — наследие Java 1.0 с синхронизацией на каждом методе; в новом коде их не используют.

PriorityQueue

Двоичная куча в массиве: в начале всегда наименьший элемент (по Comparable или переданному компаратору). Остальные элементы не отсортированы — обход через for или toString() выдаст их в порядке внутреннего массива.

PriorityQueue<Integer> heap = new PriorityQueue<>();      // минимальная куча размером не больше K
for (int x : data) {
    heap.offer(x);
    if (heap.size() > k) heap.poll();                     // выбросить наименьший из отобранных
}
// в куче остались K наибольших; сортировка всего массива стоила бы O(n log n)

var maxHeap = new PriorityQueue<Integer>(Comparator.reverseOrder());

8.6Итераторы и ConcurrentModificationException

Цикл for-each — это скрытый Iterator. Коллекции хранят счётчик структурных изменений modCount; итератор запоминает его при создании и сверяет на каждом шаге. Несовпадение означает, что коллекцию изменили в обход итератора, — и он бросает исключение. Это поведение называют fail-fast.

for (String s : list) {
    if (s.isBlank()) list.remove(s);       // ConcurrentModificationException на следующей итерации
}
list.removeIf(String::isBlank);            // лучший вариант

for (Iterator<String> it = list.iterator(); it.hasNext(); ) {
    if (it.next().isBlank()) it.remove();  // удаление через сам итератор разрешено
}

List<String> kept = list.stream().filter(s -> !s.isBlank()).toList();   // новая коллекция
Fail-fast — диагностика, а не гарантия Проверка выполняется «по возможности». Известный курьёз: удаление предпоследнего элемента в for-each исключения не вызывает — цикл просто завершается на шаг раньше, пропустив последний элемент. Полагаться на исключение нельзя; в многопоточном коде нужны потокобезопасные коллекции, итераторы которых не бросают его вовсе.

8.8Ловушки и полезное

List<Integer> nums = new ArrayList<>(List.of(10, 20, 30));
nums.remove(1);                       // удалит элемент по ИНДЕКСУ 1 → [10, 30]
nums.remove(Integer.valueOf(10));     // удалит ЗНАЧЕНИЕ 10 → [30]
  • list.contains(x) в цикле — O(n²). Если нужна проверка принадлежности, сложите элементы в HashSet.
  • Сортировка list.sort(cmp) — алгоритм TimSort: O(n log n), устойчивый (равные элементы сохраняют взаимный порядок), очень быстрый на частично упорядоченных данных. Устойчивость позволяет сортировать последовательно по нескольким признакам.
  • В массив: list.toArray(new String[0]) или list.toArray(String[]::new). Без аргумента вернётся Object[].
  • Пустой результат — List.of(), а не null: вызывающему не нужна проверка.
  • Sequenced Collections (Java 21). У List, Deque, LinkedHashSet, LinkedHashMap появился общий интерфейс с методами getFirst(), getLast(), addFirst(), removeLast(), reversed() — вместо list.get(list.size() - 1).

8.10Самопроверка

Во сколько раз растёт внутренний массив ArrayList при переполнении?

  • В 2 раза
  • На 10 элементов
  • В 1,5 раза: newCapacity = old + (old >> 1)
  • На 1 элемент
Геометрический рост даёт амортизированную O(1) для add. Если размер известен заранее — new ArrayList<>(n) избавит от копирований.

Что выбрать для очереди и стека в однопоточном коде?

  • ArrayDeque — кольцевой массив, быстрее LinkedList и Stack
  • Stack — он для этого создан
  • LinkedList — вставка O(1)
  • Vector
Stack и Vector синхронизированы и устарели; LinkedList тратит объект-узел на элемент и плохо дружит с кэшем процессора.

Что произойдёт: List<String> l = List.of("a", "b"); l.add("c");?

  • Список станет [a, b, c]
  • UnsupportedOperationException — List.of возвращает неизменяемый список
  • Ошибка компиляции
  • NullPointerException
Неизменяемость здесь проверяется только во время выполнения: интерфейс List один и тот же.
Как растёт ArrayList и почему добавление в конец считается O(1)?

При заполнении создаётся массив в 1,5 раза больше, элементы копируются — это O(n). Но копирования случаются всё реже: суммарная работа на n добавлений пропорциональна n, поэтому в среднем на одно добавление приходится постоянное время (амортизированная O(1)).

В каком случае LinkedList быстрее ArrayList?

Теоретически — при частых вставках и удалениях в начале списка или в позиции, на которой уже стоит итератор. На практике для операций с концов быстрее ArrayDeque, а вставка в произвольное место требует O(n) переходов по ссылкам с промахами кэша и проигрывает сдвигу массива. Реальных задач, где LinkedList выигрывает, почти нет.

Почему удаление элемента в цикле for-each вызывает ConcurrentModificationException без единого дополнительного потока?

for-each использует итератор, который запомнил счётчик изменений коллекции. list.remove() увеличивает счётчик в обход итератора, и следующий вызов next() обнаруживает расхождение. Название исключения означает «одновременное изменение» в смысле «во время обхода», а не «из другого потока». Удалять нужно через iterator.remove() или removeIf.

Чем Arrays.asList, List.of и Collections.unmodifiableList отличаются друг от друга?

Arrays.asList — список фиксированного размера поверх массива: менять элементы можно, добавлять и удалять нельзя, изменения видны в массиве. List.of — полностью неизменяемый список без null. unmodifiableList — доступное только для чтения представление другого списка: сам он не меняется через эту ссылку, но изменения оригинала в нём видны.

Что выведет обход PriorityQueue циклом for?

Элементы в порядке внутреннего массива кучи, а не по возрастанию. Гарантируется только то, что peek() и poll() возвращают наименьший. Чтобы получить отсортированную последовательность, нужно извлекать элементы через poll(), пока очередь не опустеет.

List<Integer> list содержит [5, 6, 7]. Что останется после list.remove(5)?

Будет IndexOutOfBoundsException: выбрана перегрузка remove(int index), а индекса 5 нет. Чтобы удалить значение, нужно передать объект: list.remove(Integer.valueOf(5)).
