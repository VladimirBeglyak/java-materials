24.1Из чего состоит исходник: лексика и литералы

Компилятор сначала режет текст на лексемы: идентификаторы, ключевые слова, литералы, операторы, разделители. Исходник — это Юникод (по умолчанию в UTF-8 с Java 18), поэтому int длина = 5; — корректный код, хотя так писать не принято.

Ключевые слова. 51 зарезервированное слово (class, goto и const — зарезервированы, но не используются) и контекстные слова, которые ключевыми становятся только в своём месте: var, record, yield, sealed, permits, non-sealed, module, exports, when. 24.2Операторы, приоритет и порядок вычисления

Две разные вещи часто путают. Приоритет и ассоциативность определяют, как расставить скобки: a + b * c — это a + (b * c). Порядок вычисления определяет, в какой последовательности выполняются операнды. В Java он строго задан: слева направо, каждый операнд полностью вычисляется до выполнения операции (JLS §15.7). В C и C++ порядок для многих операторов не определён, в Java — определён всегда.

int[] a = {0, 0};

a[k] = k = 1;           // a[0] = 1: индекс вычислен ДО правой части

System.out.println(1 + 2 + "");  // "3"
System.out.println(1 & 2 == 2);  // не компилируется: == связывает сильнее &, получается 1 & true
  • && и || вычисляют правый операнд только при необходимости: s != null && s.isEmpty() безопасно. & и | на boolean вычисляют оба операнда всегда — иногда это нужно (оба вызова с побочными эффектами), чаще это ошибка.
  • Составное присваивание содержит приведение: b += 1 для byte b — это b = (byte) (b + 1) (тема 02). Поэтому int x = 0; x += 3.7; компилируется и даёт 3.
  • Целочисленное деление на ноль — ArithmeticException; деление double на ноль — Infinity или NaN.
  • Math.abs(Integer.MIN_VALUE) отрицателен: у −2³¹ нет положительной пары в int. Безопасный вариант — Math.absExact.

Тип тернарного оператора

Тип выражения c ? a : b выводится из обоих операндов, а не из той ветки, что сработала. Отсюда NPE при распаковке (тема 02) и неожиданные символы:

char ch = 'X';
int zero = 0;
System.out.println(true ? ch : 0);     // X  — 0 константа, помещается в char → тип char
System.out.println(true ? ch : zero);  // 88 — zero переменная int → двоичное повышение до int
Object o = true ? 1 : "s";             // Integer: операнды разных видов → ссылочный тип

24.3Биты: побитовые операции и сдвиги

С нуля: число — это ряд лампочек

Любое целое число в памяти — это ряд бит, каждый из которых либо 0, либо 1. Удобно представлять их как ряд лампочек: горит — 1, не горит — 0. У каждой позиции свой «вес», и каждый следующий вес слева вдвое больше: 1, 2, 4, 8, 16, 32, 64, 128… Число равно сумме весов горящих лампочек.

вес:     128  64  32  16   8   4   2   1
биты:      0   0   0   0   1   1   0   1
                           8 + 4     + 1  = 13

В Java такую запись можно писать прямо в коде: 0b00001101 — это 13. А посмотреть биты любого числа — Integer.toBinaryString(13) вернёт "1101".

Побитовая операция берёт два числа, ставит их друг под другом и для каждого столбика (каждой пары лампочек) отдельно решает, гореть ли лампочке в ответе. Никаких переносов, как при сложении, нет — столбики не влияют друг на друга.

Сдвиги: подвинуть все лампочки

x << n сдвигает все биты на n позиций влево; освободившиеся справа места заполняются нулями. Каждый бит переезжает на позицию с вдвое большим весом — значит, число удваивается на каждом шаге. Это как в десятичной системе дописать ноль справа: 13 → 130 — умножение на 10; в двоичной дописать ноль — умножение на 2.

  13       = 0000 1101
  13 << 1  = 0001 1010 = 26   (×2)
  13 << 3  = 0110 1000 = 104  (×8)
  1 << n   = единица на позиции n: 1, 2, 4, 8, 16…  — так получают «лампочку номер n»

x >> n — сдвиг вправо: младшие биты «выпадают» за край, число делится на 2ⁿ с отбрасыванием остатка. Слева вдвигается копия знакового бита, поэтому отрицательное число остаётся отрицательным: -8 >> 1 == -4.

  13       = 0000 1101
  13 >> 1  = 0000 0110 = 6    (13 / 2, остаток 1 выпал)
  13 >> 2  = 0000 0011 = 3    (13 / 4)

x >>> n — тоже сдвиг вправо, но слева всегда нули, даже у отрицательных чисел. Нужен, когда число — не «количество», а просто набор бит (хэш, байты из файла): тогда знак не имеет смысла, и его нельзя размножать.

Точные правила

Целые в Java хранятся в дополнительном коде: старший бит — знак, -x == ~x + 1. Что это такое, объяснено с нуля (на примере одометра) в пособии «Как устроен компьютер», тема 01, раздел 1.3. Здесь — что с этим делает язык.

Три ловушки сдвигов
  1. Дистанция берётся по модулю: для int используются только 5 младших бит (n & 31), для long — 6 (n & 63). Поэтому 1 << 32 == 1, а не 0, и 1 << -1 == Integer.MIN_VALUE. Нужен 64-битный результат — 1L << 32.
  2. byte и short повышаются до int перед сдвигом. byte b = -1; b >>>= 4; оставит −1: -1 расширился до 32 единиц, сдвиг дал 0x0FFFFFFF, приведение к byte отрезало младшие 8 единиц. Правильно — (b & 0xFF) >>> 4.
  3. Приоритет ниже арифметики: 1 << n - 1 — это 1 << (n - 1); x & 1 == 0 не компилируется (== связывает сильнее).
boolean isOdd = (x & 1) != 0;              // быстрее и вернее, чем x % 2 == 1 (для отрицательных % даёт -1)
boolean pow2 = x > 0 && (x & (x - 1)) == 0; // степень двойки: у неё ровно один единичный бит
int unsignedByte = b & 0xFF;               // байт 0..255 из byte -128..127 (чтение бинарных форматов)
int mid = (lo + hi) >>> 1;                 // середина без переполнения — так в Arrays.binarySearch
int h = key.hashCode(); h ^= (h >>> 16);   // «размешивание» хэша в HashMap (тема 09)
int idx = h & (table.length - 1);          // остаток от деления на степень двойки

Integer.bitCount(0b1011);          // 3 — число единиц (одна инструкция POPCNT на x86)
Integer.numberOfLeadingZeros(1);   // 31
Integer.highestOneBit(100);        // 64
Integer.toBinaryString(-1);        // 32 единицы
Integer.toUnsignedString(-1);      // "4294967295" — беззнаковая интерпретация
Integer.compareUnsigned(-1, 1);    // 1: как беззнаковое -1 больше

Флаги в одном числе — по-прежнему распространённый приём (модификаторы в java.lang.reflect.Modifier, флаги доступа в class-файле), но в прикладном коде вместо битовых масок лучше EnumSet: он внутри устроен как long-маска, но типобезопасен.

Числа больше long — BigInteger: произвольная длина, неизменяемый, все операции — методы (a.multiply(b), pow, mod, modPow, isProbablePrime). BigInteger.TWO.pow(100) посчитается точно, а Math.pow(2, 100) вернёт приблизительный double.

24.4Управление потоком: ветвления, циклы, метки

switch: оператор и выражение

Классический switch с двоеточием — это таблица переходов с проваливанием: управление прыгает на подходящую метку case и идёт дальше, пока не встретит break. Стрелочная форма (Java 14+) не проваливается, а как выражение обязана быть исчерпывающей (тема 12).

switch (day) {                 // старая форма: забытый break — классическая ошибка
    case SATURDAY:
    case SUNDAY:
        weekend = true;        // провалились из SATURDAY специально
        break;
    default:
        weekend = false;
}
boolean weekend2 = switch (day) {  // выражение: проваливания нет, все варианты обязаны быть покрыты
    case SATURDAY, SUNDAY -> true;
    default -> false;
};
  • Что можно в switch: char, byte, short, int, их обёртки, String, enum, а с Java 21 — любой ссылочный тип в образцах (case Circle c ->). long, float, double, boolean — нет (примитивы в образцах — предварительная возможность Java 23–25).
  • null в switch без case null даёт NPE: switch по строке начинается с вызова hashCode() (JVM, тема 03).
  • Плотные значения компилируются в tableswitch (переход по индексу), редкие — в lookupswitch (двоичный поиск).

Циклы и метки

while проверяет условие до тела, do … while — после (тело выполнится хотя бы раз). Классический for (init; cond; update) — сокращение для while. Улучшенный for (T x : src) работает для массивов (компилируется в цикл по индексу) и для всего, что реализует Iterable (компилируется в Iterator — отсюда ConcurrentModificationException, тема 08).

outer:
for (int[] row : grid) {
    for (int v : row) {
        if (v < 0) continue outer;   // перейти к следующей строке
        if (v == target) break outer; // выйти из обоих циклов сразу
    }
}

Метка ставится перед любым оператором; break label выходит из помеченного оператора, continue label — переходит к следующей итерации помеченного цикла. Это не goto: прыгнуть можно только наружу. Часто вложенный цикл с меткой лучше вынести в метод с return — читается проще.

Недостижимый код — ошибка компиляции Компилятор проводит анализ потока (JLS §14.22): оператор после return, break, throw или бесконечного while (true) без break не компилируется. Но if (false) { … } разрешён специально — для условной компиляции: if (DEBUG) log(...) с static final boolean DEBUG = false javac просто выбросит из байткода.

24.5Массивы

Массив — объект в куче фиксированной длины с заголовком, полем длины и элементами подряд (JVM, тема 10). Его класс создаёт сама JVM: int[].class.getName() — "[I", String[] — "[Ljava.lang.String;". Элементы инициализируются значениями по умолчанию: 0, false, null.

int[] a = new int[3];               // [0, 0, 0]
int[] b = {1, 2, 3};                // инициализатор — только при объявлении
b = new int[] {4, 5};               // в выражении — с new
int[][] grid = new int[3][];        // «рваный» массив: массив ссылок на массивы
grid[0] = new int[5]; grid[1] = new int[1];
a.length;                           // поле, не метод; a[3] → ArrayIndexOutOfBoundsException
int[] c = b.clone();                // копия массива; для массива объектов — поверхностная!

Ковариантность и ArrayStoreException

Массивы ковариантны: String[] является подтипом Object[]. Это решение из Java 1.0 (generics ещё не было, а Arrays.sort(Object[]) хотелось вызывать для любых массивов) пробивает дыру в типизации, которую JVM закрывает проверкой при каждой записи:

Object[] objs = new String[2];  // компилируется
objs[0] = "ok";
objs[1] = 42;                   // ArrayStoreException: java.lang.Integer — проверка в рантайме (инструкция aastore)

Generics сделаны инвариантными именно чтобы такая ошибка ловилась при компиляции (тема 07), и поэтому же нельзя создать new T[] или new List<String>[10].

24.6Методы: сигнатура, varargs, выбор перегрузки

Сигнатура метода — имя и типы параметров (после стирания generics). Тип результата, имена параметров и throws в сигнатуру не входят: два метода, отличающиеся только типом результата, в одном классе объявить нельзя (а в байткоде — можно, этим пользуются мостовые методы, тема 25).

Varargs

void log(String fmt, Object... args) — синтаксический сахар: параметр имеет тип Object[], а компилятор на месте вызова сам создаёт массив. Последствия:

  • каждый вызов выделяет массив — поэтому в List.of и в логгерах SLF4J есть перегрузки на 1, 2, 3… аргумента;
  • log("x", (Object[]) null) передаст null вместо массива, а log("x", null) — тоже (с предупреждением), но log("x", (Object) null) — массив из одного null;
  • передача int[] в Object... даёт массив из одного элемента — самого int[]: Arrays.asList(new int[]{1,2}).size() == 1;
  • varargs с generic-типом (T...) создаёт массив стёртого типа — отсюда предупреждение о загрязнении кучи и @SafeVarargs (тема 07).

Как компилятор выбирает перегрузку

Выбор делается при компиляции по статическим типам аргументов (в отличие от переопределения, которое решается в рантайме по фактическому классу объекта — тема 04). Алгоритм JLS §15.12.2 идёт фазами и останавливается на первой, где нашёлся хоть один подходящий метод:

  1. Фаза 1 — строгий вызов: только тождество, расширение примитивов (int → long → float → double) и подтипы ссылок. Без упаковки и без varargs.
  2. Фаза 2 — свободный вызов: разрешены упаковка и распаковка (int ↔ Integer), всё ещё без varargs.
  3. Фаза 3 — переменная арность: varargs-методы как varargs.

Внутри фазы из подходящих выбирается наиболее специфичный (тот, чьи параметры подходят и для другого). Если такого нет — ошибка «reference to m is ambiguous».

static void m(long x)    { System.out.println("long"); }
static void m(Integer x) { System.out.println("Integer"); }
static void m(int... x)  { System.out.println("varargs"); }

m(5);         // long     — фаза 1: расширение int → long побеждает упаковку
m(Integer.valueOf(5)); // Integer
static void n(Object o)  {}   static void n(String s) {}
n(null);      // n(String): оба подходят, String специфичнее Object
static void k(String s)  {}   static void k(Integer i) {}
k(null);      // ошибка компиляции: ambiguous — ни один не специфичнее

Правило фаз существует ради обратной совместимости: до Java 5 автоупаковки и varargs не было, и добавление их не должно было изменить выбор метода в старом коде. Поэтому старый «расширяющий» вариант всегда выигрывает у нового «упаковывающего».

Симулятор выбора перегрузки

Отметьте, какие перегрузки m(...) объявлены в классе, и выберите аргумент. Симулятор проходит фазы JLS §15.12.2 и показывает, какой метод выберет javac.

Рекурсия и стек

Каждый вызов создаёт кадр в стеке потока (JVM, тема 03); глубокая рекурсия кончается StackOverflowError — обычно на нескольких тысячах–десятках тысяч уровней при стеке по умолчанию 1 МБ (-Xss). Оптимизации хвостовой рекурсии в Java нет: глубокую рекурсию переписывают на цикл с явным стеком (ArrayDeque).

Definite assignment (JLS гл. 16): компилятор доказывает, что локальная переменная присвоена на каждом пути до чтения, и что final-переменная присвоена ровно один раз. Поэтому так можно:

final String label;
if (score > 90) label = "A";
else if (score > 70) label = "B";
else label = "C";            // без этой ветки — ошибка «variable label might not have been initialized»
System.out.println(label);

Effectively final — переменная, которой после инициализации ничего не присваивают. Только такие можно захватывать в лямбдах и анонимных классах (тема 10), потому что захватывается копия значения.

Затенение и сокрытие

  • Затенение (shadowing): локальная переменная или параметр с именем поля скрывают поле внутри метода — классическое this.name = name. Локальную переменную с именем другой локальной в том же методе объявить нельзя (в отличие от C++ и JavaScript).
  • Сокрытие полей (hiding): поле в подклассе с тем же именем не переопределяет, а прячет поле родителя. Какое поле прочитается — решает статический тип ссылки: Parent p = new Child(); p.name — поле Parent.
  • Сокрытие статических методов: статический метод с той же сигнатурой в подклассе тоже не полиморфен — вызов p.staticMethod() через ссылку компилируется в вызов метода статического типа. Поэтому статические методы вызывают через имя класса (тема 04).

24.8Пакеты, импорт и точка входа

Пакет — пространство имён и единица доступа: без модификатора (package-private) член виден только внутри пакета. Полное имя класса — java.util.ArrayList; import лишь разрешает писать короткое имя и ничего не загружает — в байткоде всегда полные имена.

package com.shop.order;          // первая инструкция файла; каталоги: com/shop/order/

import java.util.List;           // один тип
import java.util.*;              // все типы пакета (но не подпакетов!)
import static java.lang.Math.max; // статический член
import module java.sql;          // Java 25 (JEP 511): все пакеты, экспортируемые модулем java.sql

// java.lang.* импортирован всегда; при конфликте имён (java.util.Date и java.sql.Date)
// одиночный импорт побеждает импорт «*», а два одинаковых имени через «*» — ошибка при использовании

Точка входа. Классически — public static void main(String[] args). С Java 25 (JEP 512, финальная версия) есть компактные исходные файлы: класс можно не объявлять, а main может быть экземплярным и без параметров:

void main() {
    IO.println("Привет");   // java.lang.IO — простой ввод-вывод для учебных программ
}

Запуск java Hello.java. Компилятор оборачивает такой файл в неявный класс; при выборе метода запуска лаунчер предпочитает main(String[]), а затем main(), статический или экземплярный (тогда он создаёт объект конструктором без параметров).

        for (int i = 0; i < grid.length; i++) {
            for (int j = 0; j < grid[i].length; j++) {

                    System.out.println("отрицательное в строке " + i + " — к следующей строке");
                    continue outer;

                if (grid[i][j] == 8) {
                    System.out.println("нашли 8 в [" + i + "][" + j + "] — выходим из обоих циклов");
                    break outer;

            }

        }

        for (int code = 1; code <= 4; code++) {
            System.out.print("code " + code + ": ");
            switch (code) {
                case 1:
                    System.out.print("один ");
                case 2:
                    System.out.print("два ");

                    System.out.print("три ");

            System.out.println();

            switch (s) {
                case "a" -> System.out.println("a");

            }
        } catch (NullPointerException e) {

        }
    }

Увидеть, что поля и статические методы выбираются по статическому типу ссылки, а экземплярные методы — по объекту.

  1. Создайте файл Hiding.java:
    public class Hiding {
    static class Parent {
        String name = "parent-field";
        static String kind() { return "Parent.kind()"; }
        String who() { return "Parent.who()"; }
    }

    static class Child extends Parent {
        String name = "child-field";
        static String kind() { return "Child.kind()"; }
        @Override String who() { return "Child.who()"; }
    }

    public static void main(String[] args) {
        Parent p = new Child();
        Child c = (Child) p;
        System.out.println("p.name   = " + p.name);
        System.out.println("c.name   = " + c.name);
        System.out.println("p.kind() = " + p.kind());
        System.out.println("p.who()  = " + p.who());
        System.out.println("((Parent) c).name = " + ((Parent) c).name);
    }
}

    p.name = parent-field, c.name = child-field — у объекта два поля, выбор по типу ссылки. p.kind() = Parent.kind() — статический метод скрыт, а не переопределён (javac предупреждает про вызов через экземпляр только с -Xlint:static). p.who() = Child.who() — единственный полиморфный вызов. Лаба 24.7Биты на практике: столбики, флаги, цвет, маска сети25 мин

Увидеть побитовые операции «по столбикам» и решить четыре практические задачи, где они действительно нужны.

  1. Создайте файл BitsPractice.java:
    public class BitsPractice {
    // число в виде 8 «лампочек»
    static String b8(int v) {
        return String.format("%8s", Integer.toBinaryString(v & 0xFF)).replace(' ', '0');
    }

    static final int READ = 1, WRITE = 2, EXEC = 4;          // 001, 010, 100 — у каждого права своя лампочка

    static String perms(int p) {
        return ((p & READ) != 0 ? "r" : "-") + ((p & WRITE) != 0 ? "w" : "-") + ((p & EXEC) != 0 ? "x" : "-");
    }

    public static void main(String[] args) {
        int a = 12, b = 10;
        System.out.println("1) столбики:");
        System.out.println("   a     = " + b8(a) + "  (" + a + ")");
        System.out.println("   b     = " + b8(b) + "  (" + b + ")");
        System.out.println("   a & b = " + b8(a & b) + "  (" + (a & b) + ")");
        System.out.println("   a | b = " + b8(a | b) + "  (" + (a | b) + ")");
        System.out.println("   a ^ b = " + b8(a ^ b) + "  (" + (a ^ b) + ")");
        System.out.println("   13 << 1 = " + b8(13 << 1) + " (" + (13 << 1) + "),  13 >> 1 = " + b8(13 >> 1) + " (" + (13 >> 1) + ")");

        System.out.println("2) права доступа во флагах:");
        int p = READ | WRITE;
        System.out.println("   READ | WRITE      → " + b8(p) + " " + perms(p));
        p |= EXEC;
        System.out.println("   добавили EXEC     → " + b8(p) + " " + perms(p));
        p &= ~WRITE;
        System.out.println("   отняли WRITE      → " + b8(p) + " " + perms(p));
        System.out.println("   можно писать? " + ((p & WRITE) != 0) + ", можно исполнять? " + ((p & EXEC) != 0));

        System.out.println("3) цвет #FF8800 в одном int:");
        int color = 0xFF8800;
        int red = (color >> 16) & 0xFF, green = (color >> 8) & 0xFF, blue = color & 0xFF;
        System.out.println("   red=" + red + " green=" + green + " blue=" + blue);
        int darker = ((red / 2) << 16) | ((green / 2) << 8) | (blue / 2);
        System.out.printf("   вдвое темнее: #%06X%n", darker);

        System.out.println("4) байт из файла: byte b = (byte) 200 → " + (byte) 200 + ", а (b & 0xFF) → " + ((byte) 200 & 0xFF));

        System.out.println("5) IP-адреса в одной подсети /24?");
        int ip1 = (192 << 24) | (168 << 16) | (1 << 8) | 10;     // 192.168.1.10
        int ip2 = (192 << 24) | (168 << 16) | (1 << 8) | 200;    // 192.168.1.200
        int ip3 = (192 << 24) | (168 << 16) | (2 << 8) | 10;     // 192.168.2.10
        int mask = -1 << 8;                                      // 24 единицы и 8 нулей: 255.255.255.0
        System.out.println("   .1.10 и .1.200: " + ((ip1 & mask) == (ip2 & mask)) + ",  .1.10 и .2.10: " + ((ip1 & mask) == (ip3 & mask)));

        System.out.println("6) индекс бакета HashMap (таблица на 16):");
        for (int h : new int[] {5, 21, 37, 100}) System.out.println("   hash " + h + ": h & 15 = " + (h & 15) + ", h % 16 = " + (h % 16));
    }
}

24.10Самопроверка

Чему равно 1 << 32 для int?

  • 0
  • 1
  • 4294967296
  • ошибка компиляции
Дистанция сдвига для int берётся по модулю 32 (используются 5 младших бит): 32 & 31 = 0, сдвиг на 0 оставляет 1. Для 64-битного результата нужен 1L << 32.

int x = 5; x = x++; Чему равно x?

  • 6
  • неопределённое поведение
  • 5
  • ошибка компиляции
В Java порядок вычисления определён: x++ возвращает 5 и увеличивает x до 6, затем присваивание записывает 5. В байткоде это iload, iinc, istore.

Объявлены m(long) и m(Integer). Что вызовет m(5)?

  • m(long)
  • m(Integer)
  • ошибка: ambiguous
  • зависит от JVM
Фаза 1 разрешения перегрузки не допускает упаковку; расширение int → long допустимо, поэтому m(long) найден в фазе 1, и до упаковки дело не доходит.

Что произойдёт: Object[] a = new String[1]; a[0] = 1;?

  • ошибка компиляции
  • a[0] станет "1"
  • ClassCastException
  • ArrayStoreException во время выполнения
Массивы ковариантны, поэтому код компилируется, но JVM знает настоящий тип элементов (String) и проверяет каждую запись инструкцией aastore.

Что напечатает System.out.println(017 + 1);?

  • 18
  • 16
  • 0171
  • ошибка компиляции
Ведущий ноль делает литерал восьмеричным: 017 = 15, плюс 1 = 16.
Чем приоритет операторов отличается от порядка вычисления?

Приоритет и ассоциативность говорят, как сгруппировать выражение (где мысленные скобки). Порядок вычисления говорит, когда выполняется каждый операнд. В Java операнды вычисляются строго слева направо и полностью до операции, поэтому f() + g() * h() вызовет f, g, h именно в этом порядке, хотя умножение «выполняется первым».

Чем >> отличается от >>>? Где нужен второй?

>> — арифметический сдвиг: слева дублируется знаковый бит, отрицательное число остаётся отрицательным (деление на 2ⁿ с округлением вниз). >>> — логический: слева нули. Нужен, когда число трактуется как набор бит или беззнаковое: хэши (h ^ (h >>> 16)), середина (lo + hi) >>> 1 без переполнения, разбор бинарных форматов.

Почему массивы ковариантны, а generics — нет?

Ковариантность массивов появилась в Java 1.0, чтобы писать общие методы вроде sort(Object[]) без generics. Плата — проверка типа при каждой записи и ArrayStoreException в рантайме. Generics спроектированы инвариантными, чтобы ошибка ловилась компилятором; гибкость возвращают wildcard-типы (? extends, ? super).

Как javac выбирает перегруженный метод? Почему расширение побеждает упаковку?

По статическим типам аргументов, в три фазы: строгая (расширение и подтипы), свободная (+ упаковка/распаковка), переменная арность (varargs). Останавливается на первой фазе, где есть кандидаты, и выбирает наиболее специфичный. Порядок фаз сохраняет поведение кода, написанного до Java 5: появление автоупаковки и varargs не должно было менять выбор метода.

Что такое definite assignment и зачем он нужен?

Набор правил JLS, по которым компилятор доказывает, что локальная переменная получила значение на каждом пути выполнения до чтения, а final — ровно один раз. Благодаря этому в Java нет «мусора» в неинициализированных локальных переменных (как в C), а у локальных переменных нет значений по умолчанию — они и не нужны.

Поле в подклассе с тем же именем, что у родителя: что прочитает Parent p = new Child(); p.name?

Поле родителя. Поля не полиморфны: подкласс прячет (hides) поле, а выбор делается при компиляции по статическому типу ссылки. Полиморфны только экземплярные методы. Отсюда правило: поля — private, доступ через методы.
