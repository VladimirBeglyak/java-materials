Платформа: JDK, JVM, байткод

Java — это не только язык, но и виртуальная машина, которая исполняет скомпилированный код. Понимание пути от файла .java до машинных команд объясняет, почему программа «прогревается», что такое classpath и откуда берётся UnsupportedClassVersionError.

1.1JDK, JRE, JVM

JVM

Виртуальная машина: загружает классы, проверяет и исполняет байткод, управляет памятью и потоками. Спецификация одна, реализаций несколько; самая распространённая — HotSpot.

JRE

JVM + стандартная библиотека (java.lang, java.util, …). Всё, что нужно для запуска программы. Oracle не выпускает его отдельно с Java 11; у некоторых сборок (Temurin) JRE-вариант остался.

JDK

JRE + инструменты разработки: компилятор javac, jar, javap, jshell, jcmd, jlink. То, что устанавливает разработчик и что лежит в базовом образе контейнера.

OpenJDK — открытая эталонная реализация. Oracle JDK, Eclipse Temurin, Amazon Corretto, Azul Zulu, BellSoft Liberica — это сборки одного и того же кода OpenJDK, отличающиеся сроками поддержки, лицензией и набором исправлений. Для приложения они взаимозаменяемы.

1.2От исходника до процессора

  • «Write once, run anywhere». Файл .class не зависит от ОС и процессора: зависима только сама JVM.
  • Прогрев. Первые секунды код исполняется интерпретатором и работает на порядок медленнее. По мере накопления статистики JIT заменяет его машинным кодом. Отсюда правило: производительность Java-сервиса измеряют после прогрева и специальным инструментом (JMH), а не System.nanoTime() вокруг одного вызова. Подробнее — в теме 15.
  • Не только Java. Kotlin, Scala, Groovy компилируются в тот же байткод и работают на той же JVM.

1.3Байткод

Байткод — набор команд для стековой машины: у каждого метода есть массив локальных переменных и стек операндов. Команды кладут значения на стек, снимают их и кладут результат.

static int add(int a, int b) {
    return a + b;
}
static int add(int, int);
  Code:
     0: iload_0        // положить на стек локальную переменную 0 (a)
     1: iload_1        // положить на стек локальную переменную 1 (b)
     2: iadd           // снять два int, положить сумму
     3: ireturn        // вернуть int с вершины стека

Префикс команды указывает тип: i — int, l — long, d — double, a — ссылка. Для byte, short, char и boolean отдельной арифметики нет — на стеке они живут как int, и это объясняет несколько правил языка из темы 02.

Что внутри файла .class Сигнатура 0xCAFEBABE, номер версии формата, пул констант (строки, имена классов и методов), описания полей и методов с байткодом. Версия формата привязана к версии Java: 52 — Java 8, 55 — Java 11, 61 — Java 17, 65 — Java 21, 69 — Java 25. JVM отказывается загружать класс новее, чем она сама: UnsupportedClassVersionError: class file version 65.0, this version of the Java Runtime only recognizes up to 61.0 означает «собрано под 21, запущено на 17».

1.4Запуск программы

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, " + (args.length > 0 ? args[0] : "world"));
    }
}
javac -d out src/Hello.java          # компиляция в каталог out
java -cp out Hello Java              # запуск: classpath + имя класса + аргументы
java -jar app.jar                    # запуск архива; класс берётся из Main-Class в MANIFEST.MF
java Hello.java                      # Java 11+: скомпилировать в память и запустить одной командой

Classpath — список каталогов и JAR-архивов, в которых JVM ищет классы. Имя класса com.shop.Order соответствует пути com/shop/Order.class относительно элемента classpath. Класс не найден — ClassNotFoundException или NoClassDefFoundError (разница — в теме 06). Если один класс есть в двух архивах, загрузится тот, что раньше в списке, — источник трудноуловимых конфликтов версий библиотек.

Java 25: точка входа без церемоний 
void main() {
    IO.println("Hello, world");
}
В «компактном исходном файле» не нужны ни объявление класса, ни public static, ни String[] args. Это упрощение для обучения и скриптов; в приложениях по-прежнему используют обычные классы.

Важные параметры JVM: -Xmx и -Xms — максимальный и начальный размер кучи, -Xss — размер стека потока, -Dимя=значение — системное свойство, -XX:+UseZGC и подобные — выбор сборщика мусора (тема 14).

1.7Интерактив: стековая машина JVM

JVM — стековая машина: у каждого вызова метода есть свой кадр (frame) с массивом локальных переменных и стеком операндов. Инструкции байткода берут операнды со стека и кладут результат обратно. Пройдите по шагам метод calc(3, 4):

int calc(int a, int b) {       //  0: iload_1      5: istore_3
    int c = a + b * 2;         //  1: iload_2      6: iload_3
    return c;                  //  2: iconst_2     7: ireturn
}                              //  3: imul
                               //  4: iadd
Симулятор: выполнение байткода
Локальные переменные кадра
0: this1: a = 32: b = 43: c = —3: c = 11
Стек операндов (вершина справа)
34281111

iload_1

Положить на стек значение локальной переменной №1 (a). Префикс i — тип int; для long было бы lload, для ссылок — aload.

iload_2

На стек — переменная №2 (b). Сложение пока не выполняется: умножение приоритетнее, и компилятор расположил инструкции в нужном порядке.

iconst_2

Константа 2. Для чисел от −1 до 5 есть однобайтовые инструкции iconst_m1 … iconst_5; дальше — bipush, sipush, а большие значения берутся из пула констант (ldc).

imul

Снять два верхних значения (4 и 2), перемножить, положить 8.

iadd

Снять 3 и 8, положить 11. Переполнение int не проверяется — результат молча «заворачивается».

istore_3

Снять вершину стека и записать в локальную переменную №3 (c). Стек пуст.

iload_3

Снова загрузить c — для возврата. JIT-компилятор уберёт лишнюю пару store/load; javac оптимизаций почти не делает.

ireturn

Снять значение со стека, уничтожить кадр и положить результат на стек операндов вызывающего метода. Так значения передаются между методами.

Глубина стека операндов и число локальных переменных вычисляются компилятором и записаны в class-файле (stack=3, locals=4) — JVM выделяет кадр фиксированного размера.

1.8Самопроверка

Что создаёт javac из файла Order.java?

  • Машинный код для текущего процессора
  • Платформенно-независимый байткод в файле Order.class
  • Исполняемый файл Order.exe
  • Исходный код на C
Байткод один для всех ОС и процессоров; в машинный код его превращает JVM во время выполнения (интерпретатор и JIT).

Когда JIT компилирует метод в машинный код?

  • При запуске программы, все методы сразу
  • При компиляции javac
  • Во время выполнения, когда метод стал «горячим» по счётчикам вызовов и циклов
  • Только по флагу -XX:+JIT
Сначала код интерпретируется и профилируется; горячие методы компилирует C1, самые горячие — C2 с агрессивными оптимизациями.

Что нужно установить на сервер, чтобы запускать готовое Java-приложение, и что — чтобы разрабатывать?

  • Для запуска достаточно среды выполнения (JVM + библиотеки), для разработки нужен JDK с javac и инструментами
  • Для запуска нужен JDK, для разработки — JRE
  • В обоих случаях только JVM
  • Ничего: байткод исполняет операционная система
JDK = среда выполнения + компилятор и утилиты (javac, jar, jshell, jcmd). Отдельный JRE с Java 11 не выпускается; минимальный образ собирают jlink.
Java — компилируемый или интерпретируемый язык?

И то, и другое. javac компилирует исходный код в байткод. JVM сначала интерпретирует байткод, а часто исполняемые методы JIT-компилятор переводит в машинный код во время работы программы. Поэтому Java переносима, как интерпретируемые языки, и после прогрева быстра, как компилируемые.

Чем JDK отличается от JRE и что нужно в образе контейнера?

JRE — JVM и стандартная библиотека, достаточные для запуска. JDK добавляет инструменты разработки и диагностики. Oracle с Java 11 отдельный JRE не выпускает (у части сборок он есть). В образ кладут либо JDK целиком (удобно — есть jcmd для диагностики), либо урезанную среду, собранную jlink.

Что означает ошибка UnsupportedClassVersionError?

Класс скомпилирован под более новую версию Java, чем JVM, на которой его запускают. Версия формата записана в заголовке файла. Решение — запустить на подходящей JVM либо собрать с флагом --release N под нужную версию.

Почему первые запросы к только что запущенному сервису медленные?

Классы загружаются и инициализируются лениво, при первом обращении; код исполняется интерпретатором, пока JIT не накопит статистику и не скомпилирует горячие методы; заполняются пулы соединений и кэши. Поэтому перед включением экземпляра в балансировку его прогревают, а нагрузочные замеры исключают начальный период.

Чем invokevirtual отличается от invokestatic и почему это важно?

invokestatic вызывает метод, известный при компиляции. invokevirtual выбирает реализацию во время выполнения по фактическому классу объекта — на этом построен полиморфизм. Отсюда правило: статические методы не переопределяются, а скрываются (тема 04).
