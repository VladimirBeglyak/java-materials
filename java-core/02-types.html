Типы, обёртки, передача по значению

В Java два мира: восемь примитивных типов, которые хранят само значение, и ссылочные типы, которые хранят адрес объекта. Почти все «неожиданности» начального уровня — сравнение через ==, NullPointerException при распаковке, «не изменившийся» аргумент метода — следствия этого деления.

2.2Преобразования и арифметика

Расширение (в сторону типа с большим диапазоном) выполняется неявно: byte → short → int → long → float → double, char → int. Сужение требует явного приведения и молча отбрасывает старшие биты.

int big = 200;
byte b = (byte) big;            // -56: остались младшие 8 бит
long l = Integer.MAX_VALUE + 1; // -2147483648: переполнение случилось в int, ДО присваивания в long
long ok = Integer.MAX_VALUE + 1L; // 2147483648: один операнд long — вся операция в long

int i = 7 / 2;                  // 3: целочисленное деление отбрасывает дробную часть
double d = 7 / 2;               // 3.0: деление уже выполнено в int
double d2 = 7 / 2.0;            // 3.5
int r = -7 % 3;                 // -1: знак остатка совпадает со знаком делимого
Переполнение не вызывает ошибку Целочисленная арифметика «заворачивается» по модулю 2³². Integer.MAX_VALUE + 1 == Integer.MIN_VALUE, и программа продолжает работать с неверным числом. Классические жертвы: перемножение миллисекунд (24 * 60 * 60 * 1000 * 30 не помещается в int), вычисление середины (lo + hi) / 2, счётчики. Там, где переполнение недопустимо, — Math.addExact, Math.multiplyExact, Math.toIntExact: они бросают ArithmeticException.

Арифметика типов короче int

byte a = 10, c = 20;
byte sum = a + c;        // ошибка компиляции: результат a + c имеет тип int
byte sum2 = (byte) (a + c);
a += c;                  // компилируется: составное присваивание содержит неявное приведение
short s = 1;  s = s + 1; // ошибка компиляции        s += 1; // корректно
char ch = 'a' + 1;       // 'b': константное выражение, помещающееся в char

Причина — в байткоде (тема 01): отдельной арифметики для byte, short и char нет, операнды всегда повышаются минимум до int.

2.3Числа с плавающей точкой и деньги

System.out.println(0.1 + 0.2);            // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);     // false
System.out.println(1.0 / 0);              // Infinity, не исключение
System.out.println(0.0 / 0 == 0.0 / 0);   // false: NaN не равен ничему, даже себе
System.out.println(Double.isNaN(0.0 / 0)); // true — единственный правильный способ проверки

float и double хранят число в двоичном виде (стандарт IEEE 754), а 0,1 в двоичной системе — бесконечная дробь, как 1/3 в десятичной. Ошибка округления неизбежна и накапливается.

Деньги не хранят в double Варианты: long в минимальных единицах (копейки) или BigDecimal. С BigDecimal три ловушки: 
new BigDecimal(0.1);       // 0.1000000000000000055511151231257827… — унаследовал ошибку double
new BigDecimal("0.1");     // ровно 0.1 — создавать только из строки или BigDecimal.valueOf(0.1)

new BigDecimal("2.0").equals(new BigDecimal("2.00"));          // false: equals сравнивает и масштаб
new BigDecimal("2.0").compareTo(new BigDecimal("2.00")) == 0;  // true: сравнивать через compareTo

BigDecimal.ONE.divide(new BigDecimal("3"));                    // ArithmeticException: бесконечная дробь
BigDecimal.ONE.divide(new BigDecimal("3"), 2, RoundingMode.HALF_EVEN); // 0.33 — всегда задавать округление

2.4Ссылочные типы: стек и куча

  • == для ссылок сравнивает адреса, то есть отвечает на вопрос «это один и тот же объект?». Сравнение содержимого — equals() (тема 05).
  • null — ссылка, не указывающая никуда. Обращение через неё — NullPointerException. С Java 14 сообщение точно называет, что именно было null: Cannot invoke "String.length()" because "user.name" is null.
  • Массив — тоже объект в куче, даже int[]. Переменная массива — ссылка.
  • «Локальные переменные в стеке, объекты в куче» — рабочая модель. Оптимизатор может не создавать объект вовсе, если тот не покидает метод (тема 14), но на поведение программы это не влияет.

2.5Передача параметров — всегда по значению

В метод передаётся копия значения переменной. Для примитива это копия числа. Для ссылочного типа — копия ссылки: метод получает второй «указатель» на тот же объект.

static void change(int n, Point p, Point q) {
    n = 100;              // меняется локальная копия числа
    p.x = 100;            // меняется объект, на который указывают обе ссылки — снаружи видно
    q = new Point(9, 9);  // локальная копия ссылки переведена на новый объект — снаружи НЕ видно
}

int n = 1;  Point p = new Point(1, 2);  Point q = new Point(1, 2);
change(n, p, q);
// n == 1,  p.x == 100,  q.x == 1
Формулировка для собеседования «В Java всё передаётся по значению. Для объектов значением является ссылка, поэтому метод может изменить состояние объекта, но не может заставить переменную вызывающего кода указывать на другой объект». Ответ «объекты передаются по ссылке» неверен: при настоящей передаче по ссылке третья строка примера изменила бы q снаружи. По той же причине невозможно написать метод swap(a, b), меняющий местами две переменные.

final для ссылки запрещает переприсваивание переменной, но не изменение объекта: final List<String> list = new ArrayList<>(); list.add("x"); — корректно.

2.6Обёртки и autoboxing

У каждого примитива есть класс-обёртка. Он нужен там, где требуется объект: в коллекциях и generics (List<int> невозможен), для значения «отсутствует» (null). Компилятор сам вставляет преобразования: boxing — Integer.valueOf(i), unboxing — obj.intValue().

Integer a = 127, b = 127;
System.out.println(a == b);        // true
Integer c = 128, d = 128;
System.out.println(c == d);        // false
System.out.println(c.equals(d));   // true

Integer.valueOf возвращает заранее созданные объекты для значений от −128 до 127, а для остальных создаёт новые. Поэтому == «работает» на маленьких числах в тестах и ломается в продакшене на идентификаторе 128. Кэшируются также Byte, Short, Long (в том же диапазоне), Character (0–127) и Boolean. Обёртки сравнивают только через equals.

Четыре ловушки распаковки 
Integer count = map.get("missing");   // null
int n = count;                        // NullPointerException: неявный count.intValue()

Integer x = flag ? 1 : nullableInteger;  // NPE при flag == false и nullableInteger == null!
// тип тернарного выражения с операндами int и Integer — int, поэтому второй операнд распаковывается

Long total = 0L;
for (int i = 0; i < 1_000_000; i++) total += i;  // миллион лишних объектов: распаковка, сложение, упаковка

Long id = 1;                          // ошибка компиляции: int не упаковывается в Long
Long.valueOf(1).equals(1);            // false: 1 упаковался в Integer, а Integer не равен Long
  • Память. int — 4 байта. Integer — 16 байт объекта плюс ссылка на него. List<Integer> на миллион элементов занимает около 20 МБ против 4 МБ у int[] и обходится медленнее из-за разброса объектов по памяти. В горячих местах — массивы примитивов и IntStream.
  • Конструкторы обёрток устарели. new Integer(5) помечен к удалению; используйте Integer.valueOf или автоупаковку.
  • Разбор строк: Integer.parseInt("42") возвращает int, Integer.valueOf("42") — Integer.

2.8Самопроверка

Что выведет System.out.println((byte) 200);?

  • 200
  • Ошибку компиляции
  • -56
  • 127
200 = 1100 1000 в двоичном виде. В byte старший бит — знаковый: 200 − 256 = −56.

Метод void change(List<String> list) { list.add("x"); list = new ArrayList<>(); }. Что увидит вызывающий?

  • Свой список без изменений
  • Свой список с добавленным "x"; присваивание новой ссылки снаружи не видно
  • Новый пустой список
  • null
В метод передаётся копия ссылки. Через неё можно изменить объект, но переприсваивание меняет только локальную копию.

Каким типом хранить денежные суммы?

  • double — он точнее float
  • float
  • String
  • BigDecimal (создавая из строки) или long в минимальных единицах
Двоичная плавающая точка не представляет точно 0.1; ошибки накапливаются. new BigDecimal("0.10") точен, а new BigDecimal(0.1) унаследует неточность double.
Почему Integer a = 128, b = 128; a == b даёт false, а для 127 — true?

Автоупаковка вызывает Integer.valueOf, который для диапазона −128…127 возвращает объекты из кэша, а вне его создаёт новые. == сравнивает ссылки: в первом случае это один объект, во втором — два разных. Сравнивать обёртки нужно через equals.

Java передаёт объекты по ссылке или по значению?

По значению. Значением переменной ссылочного типа является ссылка, и копируется именно она. Метод может менять состояние объекта через свою копию ссылки, но присваивание параметру нового объекта не влияет на переменную вызывающего кода.

Что выведет long x = Integer.MAX_VALUE + 1; и почему?

−2147483648. Оба операнда имеют тип int, сложение выполняется в int и переполняется; только после этого результат расширяется до long. Чтобы получить 2147483648, один из операндов должен быть long: + 1L.

Почему short s = 1; s = s + 1; не компилируется, а s += 1; — компилируется?

Операнды типа short повышаются до int, результат s + 1 имеет тип int и не может быть присвоен short без приведения. Составное присваивание s += 1 по определению эквивалентно s = (short) (s + 1) — приведение встроено.

Как правильно сравнить два значения BigDecimal и почему не equals?

Через compareTo(...) == 0. Метод equals учитывает масштаб: 2.0 и 2.00 для него разные. По той же причине BigDecimal — плохой ключ для HashMap, если масштаб не нормализован (stripTrailingZeros()).

Где возникнет NPE: Integer x = cond ? 0 : map.get(key);?

Когда cond ложно и ключа нет. Один операнд — int, другой — Integer, поэтому тип всего выражения — int, и map.get(key) распаковывается. Результат null вызывает исключение ещё до присваивания. Исправление — сделать оба операнда Integer: Integer.valueOf(0).
