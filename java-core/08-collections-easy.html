8.1Семейство коллекций

List — список

Элементы по порядку, с номерами, повторы разрешены. Как список покупок.

Set — множество

Без повторов. Как набор марок в коллекции — дубликат не нужен.

Queue / Deque — очередь

Добавляем с одного конца, забираем с другого (или с любого — Deque).

Map — словарь

Пары «ключ → значение». Формально не Collection, но живёт рядом (глава 09).

В коде переменную обычно объявляют интерфейсом (List), а создают конкретную реализацию (ArrayList) — так её проще заменить.

Главная мысль List — порядок с номерами, Set — без повторов, Queue — очередь, Map — словарь.

8.3ArrayList изнутри: растущая полка

ArrayList — массив с запасом мест. Когда места кончаются, он заводит новый массив примерно в полтора раза больше и переносит туда всё. Переезд дорогой, но редкий, поэтому в среднем добавление в конец быстрое. Если заранее знаете размер, можно сразу попросить нужную вместимость — переездов не будет.

Полка растёт

новая полка на 15 мест, переносим 10 элементов[a b c d e f g h i j k _ _ _ _]
следующие 4 добавления — без переездов

Копирование всех элементов — дорогая, но редкая операция.

Главная мысль ArrayList растёт переездами в полтора раза — поэтому добавление в конец в среднем быстрое.

8.4ArrayList или LinkedList

LinkedList — цепочка записок, где каждая знает соседей. В теории вставка в середину у неё быстрая. Но чтобы добраться до середины, нужно пройти записки по одной, а сами записки разбросаны по памяти и плохо дружат с кэшем процессора. На практике ArrayList почти всегда быстрее. Если нужна очередь — берите ArrayDeque.

Главная мысль По умолчанию — ArrayList. LinkedList почти никогда.

8.5Очереди, стек, куча

  • ArrayDeque — очередь и стек сразу: добавлять и забирать с обоих концов. Используется вместо старого класса Stack.
  • PriorityQueue — «приёмный покой»: выдаёт не первого пришедшего, а самого маленького (или по заданному правилу).
Главная мысль Очередь и стек — ArrayDeque, очередь по приоритету — PriorityQueue.

В полной главе: 8.5 Очереди, стек, куча

8.6Нельзя менять коллекцию во время обхода

Представьте, что вы пересчитываете людей в очереди, а кто-то в это время уходит из середины. Счёт сбивается. Коллекции Java защищаются от этого: если её изменили во время обхода циклом for-each, при следующем шаге будет ConcurrentModificationException. Удалять во время обхода можно через сам итератор (iterator.remove()) или проще — list.removeIf(условие).

Главная мысль Не удаляйте в for-each. Используйте removeIf или итератор.

В полной главе: 8.6 Итераторы и ConcurrentModificationException

8.7Неизменяемые коллекции и «окна»

List.of(...) создаёт список, который нельзя изменить: попытка добавить — исключение. Это удобно, чтобы отдать данные наружу без риска. Осторожно с «окнами» (представлениями): Collections.unmodifiableList(x) не копирует данные, а лишь запрещает менять их через это окно — если изменить исходный список, изменения будут видны.

Главная мысль List.of — неизменяемая копия, unmodifiableList — окно только для чтения на живой список.

8.8Ловушки

  • Arrays.asList возвращает список фиксированной длины — add бросит исключение.
  • list.remove(1) у списка Integer удаляет элемент по индексу 1, а не число 1.
  • List.of не принимает null.
Главная мысль Знайте особенности «быстрых» способов создания списков.

8.10Проверьте себя

Какой список выбирать по умолчанию?

  • LinkedList
  • ArrayList
  • Vector
  • Stack
Он быстрее почти во всех реальных сценариях.

Вы удаляете элементы из списка внутри for-each. Что будет?

  • всё нормально
  • удалятся все элементы
  • список отсортируется
  • ConcurrentModificationException
Используйте removeIf.

Что происходит, когда в ArrayList заканчивается место?

  • создаётся массив побольше, элементы переносятся
  • исключение
  • старые элементы удаляются
  • новый элемент не добавляется
Полка «переезжает» в полтора раза больше.

Нужно часто проверять «есть ли такой элемент». Что лучше?

  • ArrayList
  • LinkedList
  • HashSet
  • массив
Поиск в HashSet мгновенный, в списке — перебор.

Что делает List.of(1, 2, 3).add(4)?

  • добавляет 4
  • бросает UnsupportedOperationException
  • возвращает false
  • ничего
List.of — неизменяемый список.
