Stream API — простыми словами

Stream API позволяет описывать обработку данных как конвейер: «возьми заказы, оставь оплаченные, достань суммы, сложи». Разберёмся, как работает конвейер, почему он ленивый, какие операции главные, что такое коллекторы, где ловушки и когда нужны параллельные стримы.

11.1Конвейер: источник, станции, итог

Стрим состоит из трёх частей:

  1. Источник — откуда берутся элементы: список, массив, файл.
  2. Промежуточные операции — станции конвейера: filter (отбраковать), map (переделать), sorted (упорядочить).
  3. Терминальная операция — итог: собрать в список, посчитать, найти первый.

Стрим одноразовый: после итога его нельзя запустить ещё раз. И он не меняет исходную коллекцию.

Главная мысль Источник → станции → итог. Стрим одноразовый и не трогает исходные данные.

11.2Ленивость: ничего не происходит без итога

Промежуточные операции только описывают конвейер. Пока не вызвана терминальная операция, ни один элемент никуда не едет. А когда вызвана — элементы идут не «сначала все через фильтр, потом все через map», а по одному через все станции. Поэтому findFirst может остановиться на первом же подходящем элементе, не обрабатывая остальные миллионы.

Числа [1, 2, 3, 4]: filter(чётное) → map(×10) → findFirst
конвейер построен, итог не вызван → ничего не происходитfindFirst() → поехали
1 → filter: нечётное, отброшено2 → filter: чётное ✓ → map: 20 → findFirst: нашли!3 и 4 даже не трогали
результат: 20

Без итога конвейер стоит.

Элемент проходит станции по очереди.

Первый подходящий сразу идёт в итог.

Ленивость экономит работу.

Главная мысль Без терминальной операции стрим ничего не делает; элементы идут по одному через весь конвейер.

11.3Главные операции

  • filter — оставить подходящие; map — превратить каждый элемент; flatMap — «развернуть» вложенные списки в один поток.
  • sorted, distinct, limit, skip — порядок, уникальность, обрезка.
  • count, sum, min/max, anyMatch, findFirst — итоги.
  • reduce — «сверни всё в одно значение».
Главная мысль filter, map и collect покрывают большую часть задач.

В полной главе: 11.3 Основные операции

11.4Коллекторы: как собрать результат

collect собирает элементы во что-то: в список (toList()), во множество, в map. Самый полезный — groupingBy: «разложи заказы по городам» или «посчитай заказы по статусам». Ещё есть joining — склеить строки через запятую.

Главная мысль groupingBy — сгруппировать, toList — собрать, joining — склеить.

11.5Ловушки

  • toMap с повторяющимися ключами падает — нужно сказать, как объединять значения.
  • Побочные эффекты внутри map и filter (изменение внешних списков) делают код хрупким.
  • peek — для отладки, а не для логики: он может и не вызваться.
  • Не всё нужно делать стримом — простой цикл иногда понятнее.
Главная мысль Стрим без побочных эффектов, toMap — с правилом слияния, сложное — циклом.

В полной главе: 11.5 Ловушки

11.6Параллельные стримы

parallelStream() делит работу между ядрами. Помогает только на больших объёмах с тяжёлыми вычислениями и легко делимым источником (массив, ArrayList). На маленьких данных и при работе с базой или сетью — чаще вредит: накладные расходы больше выигрыша, а все параллельные стримы делят один общий пул потоков.

Главная мысль Параллельный стрим — только для больших вычислений и только после замера.

В полной главе: 11.6 Параллельные стримы

11.7Gatherers: свои станции конвейера

В Java 24 появились Gatherers — способ сделать собственную промежуточную операцию. Например, «разбей поток на окна по 3 элемента» или «скользящее окно». Раньше для такого приходилось выходить из стрима.

Главная мысль Gatherers — свои станции конвейера, когда стандартных не хватает.

11.9Проверьте себя

Что произойдёт, если написать стрим с filter и map, но без терминальной операции?

  • ошибка компиляции
  • всё отфильтруется
  • ничего: конвейер не запустится
  • исходный список изменится
Стримы ленивые.

Как разложить заказы по городам?

  • collect(groupingBy(город))
  • sorted()
  • distinct()
  • flatMap
groupingBy создаёт map «город → список заказов».

Можно ли использовать один и тот же стрим дважды?

  • да
  • нет: после терминальной операции он закрыт
  • да, если он короткий
  • только параллельный
Стрим одноразовый — создайте новый из источника.

Когда parallelStream скорее навредит?

  • на миллионах чисел с тяжёлым расчётом
  • на большом массиве
  • никогда
  • на маленьком списке или при обращениях к базе и сети
Накладные расходы больше выигрыша, и общий пул потоков занят.

Что делает flatMap?

  • сортирует
  • удаляет дубликаты
  • превращает «список списков» в один поток элементов
  • считает сумму
Например, все товары из всех заказов.
