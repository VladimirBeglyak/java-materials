Типы и передача по значению — простыми словами

В Java два вида значений: простые числа и буквы (примитивы) и объекты. Разберёмся, чем они отличаются, почему деньги нельзя хранить в double, что на самом деле передаётся в метод и откуда берутся сюрпризы с Integer.

2.1Примитивы: коробки фиксированного размера

Примитивный тип — это коробка, в которой лежит само значение. Коробки разного размера:

ТипЧто хранитРазмер
byte, short, int, longцелые числа: от маленьких до очень больших1, 2, 4, 8 байт
float, doubleдробные числа4, 8 байт
charодин символ UTF-162 байта
booleanда / нет—

Чаще всего используют int (до ~2 миллиардов), long для больших чисел и double для дробей.

Главная мысль Восемь примитивов — коробки фиксированного размера, внутри лежит само значение.

2.2Переливание из коробки в коробку

Из маленькой коробки в большую можно переложить без потерь — Java делает это сама. Из большой в маленькую — только явно, и лишнее отрезается: (byte) 300 даёт 44. А если число в int переросло максимум, оно «заворачивается» в минус без всякой ошибки — как счётчик пробега, перескочивший через ноль.

Ещё сюрприз: 5 / 2 даёт 2, а не 2,5 — деление целых отбрасывает дробную часть.

Главная мысль В большую коробку — сам, в меньшую — явно и с потерями. Целые числа переполняются молча.

2.3Дроби и деньги

double хранит большинство дробей приблизительно — как 1/3 в виде 0,333. Поэтому 0.1 + 0.2 даёт 0.30000000000000004. Для науки это неважно, а для денег — недопустимо. Деньги считают в BigDecimal (точные десятичные дроби) или в целых копейках в long.

Главная мысль double приблизителен. Деньги — BigDecimal или целые копейки.

2.4Объекты: бумажка с адресом

С объектами иначе. Сам объект живёт в общей памяти — куче. А переменная хранит только ссылку — бумажку с адресом объекта. Если написать b = a, скопируется бумажка, а объект останется один. Изменили объект через b — изменения видны и через a: обе бумажки ведут в один дом.

null — пустая бумажка, без адреса. Попытка пойти по ней — NullPointerException.

Главная мысль Объектная переменная хранит адрес. Две переменные могут указывать на один объект.

2.5В метод всегда передаётся копия

Java передаёт в метод копию значения переменной. Для примитива это копия числа: метод может менять свою копию, исходное число не изменится. Для объекта — копия бумажки с адресом:

Что метод может, а что нет
в main: list → [адрес дома №5]   (в доме: пустой список)
вызываем change(list) — метод получает КОПИЮ бумажкив методе: copy.add("x") → идём по адресу №5, кладём "x"
в main видно: список ["x"] — дом-то одинв методе: copy = new ArrayList() → копия бумажки теперь ведёт в дом №9
в main list по-прежнему → дом №5. Заменить объект вызывающего метод не может

Копируется адрес, не объект.

По копии адреса можно изменить сам объект — это видно снаружи.

Переписать свою бумажку можно, но у вызывающего бумажка прежняя.

Главная мысль Java — всегда «по значению». Для объектов значение — это адрес: объект изменить можно, подменить у вызывающего — нельзя.

2.6Обёртки: число в коробке-объекте

Коллекции умеют хранить только объекты, поэтому у каждого примитива есть объект-обёртка: Integer для int, Double для double и т. д. Java сама заворачивает и разворачивает (autoboxing). Две ловушки:

  • == сравнивает адреса. Для маленьких чисел (от −128 до 127) Java переиспользует готовые объекты, поэтому Integer 100 == 100 — true, а 1000 == 1000 — false. Сравнивайте через equals.
  • null не разворачивается. Если Integer равен null, а его используют как int, будет NullPointerException.
Главная мысль Обёртки — объекты: сравнивайте equals, остерегайтесь null.

2.8Проверьте себя

  • нет, передаётся копия списка

  • только если список пустой
  • зависит от версии Java
Копия адреса ведёт к тому же объекту.

Метод внутри написал list = new ArrayList<>(). Изменится ли список у вызывающего?

  • да, станет пустым
  • да, удалится
  • будет ошибка
  • нет: метод переписал только свою копию адреса
Подменить объект вызывающего метод не может.
