12.2var: компилятор сам поймёт тип

var list = new ArrayList<String>(); — тип очевиден справа, повторять его слева не нужно. Это не «динамическая типизация»: тип выводится при компиляции и дальше не меняется. Используйте var там, где тип и так ясен, и не используйте, где без типа код становится загадкой.

Главная мысль var — сокращение записи, тип всё равно строгий.

12.3switch-выражения

Новый switch со стрелками -> возвращает значение и не «проваливается» в следующий вариант (старая ловушка с забытым break). Для enum компилятор проверит, что вы учли все значения.

Главная мысль switch со стрелками: возвращает значение, без break и провалов.

В полной главе: 12.3 switch-выражения

12.4Records: класс-данные в одну строку

record Point(int x, int y) {} — и у вас есть неизменяемый класс с полями, конструктором, методами доступа, правильными equals, hashCode и toString. Раньше на это уходило 50 строк. Records идеальны для DTO, ключей map, результатов методов. Ограничения: поля нельзя менять, наследоваться от другого класса нельзя.

Главная мысль record = неизменяемые данные + equals/hashCode/toString бесплатно.

В полной главе: 12.4 Records

12.5Sealed: закрытый список наследников

sealed interface Shape permits Circle, Square — «фигура бывает только кругом или квадратом, и больше никем». Как список блюд в меню: нового без согласования не добавишь. Компилятор знает все варианты и может проверить, что вы обработали каждый.

Главная мысль sealed фиксирует все возможные варианты типа — компилятор их знает.

12.6Сопоставление с образцом

Раньше: «если это круг — приведи к кругу и возьми радиус». Теперь проверка и распаковка в одном шаге: if (shape instanceof Circle c). А switch умеет разбирать объект по типам и даже «вскрывать» record:

switch по sealed-типу
sealed Shape permits Circle, Square
area = switch (shape) {
  case Circle c  -> π · r²
  case Square s  -> сторона²
}добавили в permits новый тип Triangleкомпилятор: «switch не покрывает Triangle» — ошибка компиляции
забыть новый случай невозможно

default не нужен — компилятор видит, что случаи покрыты.

Иерархия расширилась.

Каждое место, где забыли новый тип, подсветит компилятор.

Главная мысль sealed + switch по типам = компилятор следит, что учтены все варианты.

12.9Проверьте себя

Делает ли var Java динамически типизированной?

  • да
  • нет: тип выводится при компиляции и не меняется
  • только в циклах
  • только для чисел
var — лишь сокращение записи.

Что record даёт «бесплатно»?

  • изменяемые поля
  • наследование от любого класса
  • конструктор, методы доступа, equals, hashCode, toString
  • сохранение в базу
Именно поэтому records удобны для данных.

Зачем нужен sealed-интерфейс?

  • чтобы зафиксировать список возможных реализаций и дать компилятору проверять полноту
  • чтобы запретить вызывать его методы
  • для скорости
  • для шифрования
Компилятор знает все варианты.

В sealed-иерархию добавили новый тип. Что сделает switch по типам без default?

  • молча пропустит
  • упадёт во время работы
  • выберет первый case
  • не скомпилируется, пока не добавите новый case
Проверка полноты.

Чем новый switch со стрелками лучше старого?

  • быстрее работает
  • возвращает значение и не «проваливается» в следующий case
  • работает только со строками
  • ничем
Забытый break больше не ошибка.
