Современная Java: records, sealed, pattern matching

После Java 8 язык изменился сильнее, чем за предыдущие пятнадцать лет. Записи, запечатанные иерархии и сопоставление с образцом вместе дают новый способ моделировать данные — компактный и проверяемый компилятором. Глава о том, что появилось между 9-й и 25-й версиями и как этим пользоваться.

12.2var

var просит компилятор вывести тип локальной переменной из инициализатора. Это не динамическая типизация: тип определяется при компиляции раз и навсегда.

var orders = new HashMap<String, List<Order>>();    // хорошо: тип очевиден справа, слева не дублируется
for (var entry : orders.entrySet()) { … }
try (var reader = Files.newBufferedReader(path)) { … }

var result = service.process(data);    // плохо: читатель не знает тип, пока не откроет метод
var list = new ArrayList<>();          // ловушка: выведется ArrayList<Object>
var count = 1;                         // int; для long нужно 1L

var x;                                 // ошибка: нет инициализатора
var n = null;                          // ошибка: тип не выводится
var f = () -> 42;                      // ошибка: лямбде нужен целевой тип

var разрешён только для локальных переменных, переменных циклов и параметров лямбд — не для полей, параметров методов и возвращаемых типов. Критерий: с var код должен читаться не хуже, чем без него.

12.3switch-выражения

int days;
switch (month) {
    case FEBRUARY:
        days = 28;
        break;
    case APRIL:
    case JUNE:
        days = 30;
        break;       // забыли break — «провалились» дальше
    default:
        days = 31;
}
int days = switch (month) {
    case FEBRUARY -> 28;
    case APRIL, JUNE, SEPTEMBER, NOVEMBER -> 30;
    default -> {
        log.debug("длинный месяц");
        yield 31;      // значение из блока
    }
};
  • Стрелка -> исключает «проваливание»: выполняется ровно одна ветка.
  • Выражение возвращает значение, поэтому переменную можно сделать final.
  • Полнота. Выражение обязано покрывать все варианты. Для enum и sealed-типов default можно не писать — и тогда добавление новой константы станет ошибкой компиляции во всех местах, где её забыли обработать. Это главная причина не писать default «на всякий случай».

12.4Records

Запись — класс, единственное назначение которого — нести неизменяемые данные. Объявление перечисляет компоненты; остальное создаёт компилятор.

public record Money(BigDecimal amount, String currency) {

    public Money {                                   // компактный конструктор: проверка и нормализация
        Objects.requireNonNull(currency);
        if (amount.signum() < 0) throw new IllegalArgumentException("отрицательная сумма");
        amount = amount.setScale(2, RoundingMode.HALF_EVEN);   // присваивание полям произойдёт после блока
    }

    public static Money rub(String amount) { return new Money(new BigDecimal(amount), "RUB"); }
    public Money plus(Money other) { return new Money(amount.add(other.amount), currency); }
}

var price = Money.rub("99.90");
price.amount();                       // метод доступа без приставки get
price.equals(Money.rub("99.9"));      // true — сравнение по компонентам после нормализации
System.out.println(price);            // Money[amount=99.90, currency=RUB]
Что создаётся автоматическиЧего у записи быть не может
private final поле на каждый компонентДругих полей экземпляра
Канонический конструкторРодительского класса (запись неявно final и наследует Record)
Методы доступа amount(), currency()Сеттеров — поля финальны

Запись может реализовывать интерфейсы, иметь статические поля и методы, дополнительные конструкторы (обязанные вызывать канонический) и вложенные типы.

Где использовать

  • DTO запросов и ответов, события, сообщения.
  • Объекты-значения: деньги, координаты, диапазон дат.
  • Составные ключи HashMap.
  • Возврат нескольких значений из метода.
  • Проекции запросов Spring Data.

Где не подходит

  • Сущности JPA: нужен конструктор без параметров, изменяемость, прокси.
  • Объекты с изменяемым состоянием и жизненным циклом.
  • Классы, которым нужно скрывать представление: компоненты записи — её публичный API.
Запись неизменяема поверхностно 
record Team(String name, List<String> members) {
    Team { members = List.copyOf(members); }      // без этой строки список можно изменить снаружи
}
Ссылка в поле финальна, но объект по ней — нет. Изменяемые компоненты копируют в компактном конструкторе (тема 05). И ещё: массив в компоненте ломает equals — массивы сравниваются по ссылке.

12.5Sealed-типы

Запечатанный класс или интерфейс перечисляет всех, кому разрешено его наследовать. Иерархия становится закрытой: компилятор знает полный список вариантов.

public sealed interface PaymentResult permits Success, Declined, Failed { }

public record Success(String txId, BigDecimal amount) implements PaymentResult { }
public record Declined(String reason) implements PaymentResult { }
public record Failed(Exception cause, boolean retryable) implements PaymentResult { }

Каждый разрешённый наследник обязан объявить, что с ним дальше: final (записи финальны неявно), sealed — со своим списком, или non-sealed — снова открыт. Наследники должны находиться в том же модуле (или пакете); если они объявлены в том же файле, permits можно опустить.

Sealed + record = алгебраические типы данных Запись — «и»: результат успеха состоит из идентификатора и суммы. Запечатанный интерфейс — «или»: результат платежа — это успех, или отказ, или сбой. Вместе они позволяют описать предметную область так, что недопустимые состояния невозможно выразить, а компилятор проверяет обработку всех вариантов. Сравните с классом из десяти допускающих null полей и поля status, где осмысленны три комбинации из тысячи.

12.6Сопоставление с образцом

if (obj instanceof String s && !s.isBlank()) {     // проверка, приведение и объявление переменной сразу
    return s.strip();
}
if (!(obj instanceof Order order)) return false;   // после этой строки order доступен
String describe(PaymentResult result) {
    return switch (result) {
        case Success(String txId, var amount) when amount.signum() == 0 -> "нулевой платёж " + txId;
        case Success(String txId, var amount) -> "оплачено " + amount + ", транзакция " + txId;
        case Declined(var reason)             -> "отклонено: " + reason;
        case Failed(var cause, boolean retryable) when retryable -> "временный сбой, повторить";
        case Failed(_, _)                     -> "ошибка, требуется разбор";      // _ — Java 22
    };   // default не нужен: иерархия запечатана, компилятор проверил полноту
}
  • Образец записи раскладывает объект на компоненты; образцы вкладываются: case Line(Point(var x1, var y1), Point p2).
  • when — дополнительное условие ветки.
  • Порядок важен. Более частный образец должен стоять раньше общего; обратный порядок — ошибка компиляции («образец поглощён предыдущим»).
  • null. Обычный switch бросает NPE на null. С образцами можно написать case null -> … или case null, default -> ….
  • Добавили четвёртый вариант в permits — все switch без default перестанут компилироваться и покажут, где требуется решение.
Когда это лучше полиморфизма Классический приём — виртуальный метод describe() в каждом наследнике — хорош, когда поведение принадлежит самому типу. switch по запечатанной иерархии лучше, когда операций много и они относятся к разным слоям (форматирование для пользователя, сериализация, расчёт): не нужно раздувать доменные классы и писать Visitor.

12.9Самопроверка

Что record генерирует автоматически?

  • Только геттеры
  • Геттеры и сеттеры
  • Канонический конструктор, методы доступа по именам компонентов, equals, hashCode, toString
  • Только toString
Поля private final, сеттеров нет. Методы доступа называются как компоненты: point.x(), не getX().

Где нельзя использовать var?

  • В полях класса, параметрах методов и без инициализатора
  • В цикле for-each
  • Для локальной переменной с инициализатором
  • В try-with-resources
var — вывод типа только для локальных переменных с инициализатором (и параметров лямбд). Тип остаётся статическим.

Чем switch-выражение отличается от старого оператора switch?

  • Работает только со строками
  • Возвращает значение, не «проваливается» между ветками со стрелкой и обязан быть исчерпывающим
  • Ничем, кроме синтаксиса
  • Не поддерживает enum
Ветки case X -> … не требуют break; для блока значение возвращает yield.
Делает ли var Java динамически типизированной?

Нет. Тип выводится компилятором из инициализатора и фиксируется; присвоить переменной значение другого типа нельзя. var — сокращение записи, применимое только к локальным переменным.

Что компилятор создаёт для записи и чем запись отличается от обычного класса с Lombok @Value?

Финальные поля, канонический конструктор, методы доступа, equals, hashCode, toString. В отличие от класса с Lombok, запись — конструкция языка: не требует обработчика аннотаций, не может иметь дополнительных полей и наследования, поддерживается образцами в switch и instanceof, безопаснее сериализуется.

Почему в switch по sealed-типу лучше не писать default?

Без default компилятор проверяет, что перечислены все разрешённые наследники. Когда появится новый, код перестанет компилироваться во всех местах, требующих решения. С default новый вариант молча попадёт в общую ветку — ошибка обнаружится в продакшене.

Запись record Report(String title, List<Row> rows) — неизменяема ли она?

Только поверхностно. Ссылку rows заменить нельзя, но сам список можно изменить через ссылку, оставшуюся у создателя, или через report.rows().add(...). Нужна защитная копия в компактном конструкторе: rows = List.copyOf(rows).

Что такое guard в образце и в каком порядке должны идти ветки?

Условие после when, уточняющее ветку: case Success s when s.amount().signum() == 0. Ветки проверяются сверху вниз, поэтому более частные образцы (с условием, с подтипом) ставят раньше общих; если общий стоит выше и полностью покрывает частный, компилятор сообщит об ошибке.
