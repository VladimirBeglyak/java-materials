Современная Java: records, sealed, pattern matching

После Java 8 язык изменился сильнее, чем за предыдущие пятнадцать лет. Записи, запечатанные иерархии и сопоставление с образцом вместе дают новый способ моделировать данные — компактный и проверяемый компилятором. Глава о том, что появилось между 9-й и 25-й версиями и как этим пользоваться.

12.2var

var (variable — «переменная») просит компилятор вывести (определить сам) тип локальной переменной из инициализатора (выражения справа от =). Это не динамическая типизация (как в JavaScript или Python, где тип переменной может меняться): тип определяется при компиляции раз и навсегда.

var orders = new HashMap<String, List<Order>>();    // хорошо: тип очевиден справа, слева не дублируется
for (var entry : orders.entrySet()) { … }
try (var reader = Files.newBufferedReader(path)) { … }

var result = service.process(data);    // плохо: читатель не знает тип, пока не откроет метод
var list = new ArrayList<>();          // ловушка: выведется ArrayList<Object>
var count = 1;                         // int; для long нужно 1L

var x;                                 // ошибка: нет инициализатора
var n = null;                          // ошибка: тип не выводится
var f = () -> 42;                      // ошибка: лямбде нужен целевой тип

var разрешён только для локальных переменных, переменных циклов и параметров лямбд — не для полей, параметров методов и возвращаемых типов. Критерий: с var код должен читаться не хуже, чем без него.

Главное var выводит тип локальной переменной при компиляции — это не динамическая типизация. Используйте, когда тип и так очевиден из правой части.

12.3switch-выражения

switch («переключатель») выбирает ветку кода по значению: «если день — понедельник, то…, если вторник, то…». Старый switch был оператором (просто выполнял код), новый — выражение: он возвращает значение, как формула.

int days;
switch (month) {
    case FEBRUARY:
        days = 28;
        break;
    case APRIL:
    case JUNE:
        days = 30;
        break;       // забыли break — «провалились» дальше
    default:
        days = 31;
}
int days = switch (month) {
    case FEBRUARY -> 28;
    case APRIL, JUNE, SEPTEMBER, NOVEMBER -> 30;
    default -> {
        log.debug("длинный месяц");
        yield 31;      // значение из блока
    }
};
  • Стрелка -> исключает «проваливание» (fall-through: в старом switch без break выполнялись и все следующие ветки): выполняется ровно одна ветка.
  • Выражение возвращает значение, поэтому переменную можно сделать final.
  • Полнота (exhaustiveness). Выражение обязано покрывать все варианты. Для enum и sealed-типов default можно не писать — и тогда добавление новой константы станет ошибкой компиляции во всех местах, где её забыли обработать. Это главная причина не писать default «на всякий случай».
Главное Новый switch со стрелкой не «проваливается», возвращает значение и проверяет полноту. Для enum и sealed-типов не пишите default — тогда забытый вариант станет ошибкой компиляции.

12.4Records

Запись (record) — класс, единственное назначение которого — нести неизменяемые данные, как бланк с заполненными графами. Вместо пятидесяти строк с полями, конструктором, геттерами, equals, hashCode и toString — одна строка record Money(BigDecimal amount, String currency) {}. Объявление перечисляет компоненты (поля записи); остальное создаёт компилятор.

public record Money(BigDecimal amount, String currency) {

    public Money {                                   // компактный конструктор: проверка и нормализация
        Objects.requireNonNull(currency);
        if (amount.signum() < 0) throw new IllegalArgumentException("отрицательная сумма");
        amount = amount.setScale(2, RoundingMode.HALF_EVEN);   // присваивание полям произойдёт после блока
    }

    public static Money rub(String amount) { return new Money(new BigDecimal(amount), "RUB"); }
    public Money plus(Money other) { return new Money(amount.add(other.amount), currency); }
}

var price = Money.rub("99.90");
price.amount();                       // метод доступа без приставки get
price.equals(Money.rub("99.9"));      // true — сравнение по компонентам после нормализации
System.out.println(price);            // Money[amount=99.90, currency=RUB]

Запись может реализовывать интерфейсы, иметь статические поля и методы, дополнительные конструкторы (обязанные вызывать канонический) и вложенные типы.

Где использовать

  • DTO (Data Transfer Object — «объект для передачи данных» между слоями или по сети) запросов и ответов, события, сообщения.
  • Объекты-значения: деньги, координаты, диапазон дат.
  • Составные ключи HashMap.
  • Возврат нескольких значений из метода.
  • Проекции запросов Spring Data (выборка части полей из базы в отдельный тип).

Где не подходит

  • Сущности JPA (классы, сохраняемые в базу данных): нужен конструктор без параметров, изменяемость, прокси (объекты-заместители для ленивой загрузки).
  • Объекты с изменяемым состоянием и жизненным циклом (создание, работа, закрытие).
  • Классы, которым нужно скрывать представление: компоненты записи — её публичный API.
Запись неизменяема поверхностно 
record Team(String name, List<String> members) {
    Team { members = List.copyOf(members); }      // без этой строки список можно изменить снаружи
}
Ссылка в поле финальна, но объект по ней — нет. Изменяемые компоненты копируют в компактном конструкторе (тема 05). И ещё: массив в компоненте ломает equals — массивы сравниваются по ссылке.
Главное record — неизменяемый носитель данных: поля, конструктор, геттеры, equals, hashCode и toString создаются сами. Хорош для DTO, значений и ключей, не подходит для сущностей JPA. Изменяемые компоненты копируйте в компактном конструкторе.

12.5Sealed-типы

Запечатанный (sealed) класс или интерфейс перечисляет всех, кому разрешено его наследовать, — как закрытый клуб со списком членов у входа. Иерархия (дерево «родитель — наследники») становится закрытой: компилятор знает полный список вариантов. Список задаётся словом permits («разрешает»).

public sealed interface PaymentResult permits Success, Declined, Failed { }

public record Success(String txId, BigDecimal amount) implements PaymentResult { }
public record Declined(String reason) implements PaymentResult { }
public record Failed(Exception cause, boolean retryable) implements PaymentResult { }

Каждый разрешённый наследник обязан объявить, что с ним дальше: final (записи финальны неявно), sealed — со своим списком, или non-sealed — снова открыт. Наследники должны находиться в том же модуле (или пакете, если модулей нет); если они объявлены в том же файле, permits можно опустить.

Sealed + record = алгебраические типы данных (Алгебраический тип данных — тип, собранный из других операциями «и» и «или»; термин из функциональных языков.) Запись — «и»: результат успеха состоит из идентификатора и суммы. Запечатанный интерфейс — «или»: результат платежа — это успех, или отказ, или сбой. Вместе они позволяют описать предметную область (понятия бизнеса, которые моделирует программа) так, что недопустимые состояния невозможно выразить, а компилятор проверяет обработку всех вариантов. Сравните с классом из десяти допускающих null полей и поля status, где осмысленны три комбинации из тысячи.
Главное sealed-класс перечисляет всех наследников через permits. Вместе с record это описание «или–и», где компилятор знает все варианты.

12.6Сопоставление с образцом

Сопоставление с образцом (pattern matching) — проверка «подходит ли объект под шаблон» вместе с извлечением данных: «если это круг — возьми его радиус». Раньше приходилось сначала проверять тип через instanceof, потом отдельно приводить; теперь это одна запись.

if (obj instanceof String s && !s.isBlank()) {     // проверка, приведение и объявление переменной сразу
    return s.strip();
}
if (!(obj instanceof Order order)) return false;   // после этой строки order доступен
String describe(PaymentResult result) {
    return switch (result) {
        case Success(String txId, var amount) when amount.signum() == 0 -> "нулевой платёж " + txId;
        case Success(String txId, var amount) -> "оплачено " + amount + ", транзакция " + txId;
        case Declined(var reason)             -> "отклонено: " + reason;
        case Failed(var cause, boolean retryable) when retryable -> "временный сбой, повторить";
        case Failed(_, _)                     -> "ошибка, требуется разбор";      // _ — Java 22
    };   // default не нужен: иерархия запечатана, компилятор проверил полноту
}
  • Образец записи (record pattern) раскладывает объект на компоненты (деконструкция — обратное конструированию); образцы вкладываются: case Line(Point(var x1, var y1), Point p2).
  • when («когда») — дополнительное условие ветки.
  • Порядок важен. Более частный образец должен стоять раньше общего; обратный порядок — ошибка компиляции («образец поглощён предыдущим»).
  • null. Обычный switch бросает NPE (NullPointerException) на null. С образцами можно написать case null -> … или case null, default -> ….
  • Добавили четвёртый вариант в permits — все switch без default перестанут компилироваться и покажут, где требуется решение.
Когда это лучше полиморфизма Классический приём — виртуальный (переопределяемый) метод describe() в каждом наследнике — хорош, когда поведение принадлежит самому типу. switch по запечатанной иерархии лучше, когда операций много и они относятся к разным слоям (форматирование для пользователя, сериализация, расчёт): не нужно раздувать доменные классы (классы предметной области) и писать Visitor («посетитель» — паттерн для добавления операций к иерархии, тема 19).
Главное instanceof и switch умеют проверить тип и сразу достать данные, в том числе разложить record на компоненты. Частные образцы — раньше общих, null — отдельной веткой, условия — через when.

  1. Создайте файл Money.java:
    import java.math.BigDecimal;

public record Money(BigDecimal amount, String currency) {
    public Money {
        if (amount.signum() < 0) throw new IllegalArgumentException("отрицательная сумма: " + amount);
        currency = currency.toUpperCase();
    }

    public Money plus(Money other) {
        if (!currency.equals(other.currency)) throw new IllegalArgumentException("разные валюты");
        return new Money(amount.add(other.amount), currency);

    public static void main(String[] args) {
        Money a = new Money(new BigDecimal("10.50"), "rub"), b = new Money(new BigDecimal("4.50"), "RUB");
        System.out.println(a.plus(b) + ", equals: " + a.equals(new Money(new BigDecimal("10.50"), "RUB")));
        try { new Money(new BigDecimal("-1"), "rub"); } catch (IllegalArgumentException e) { System.out.println(e.getMessage()); }
    }
}

  2. Какие методы есть в javap, хотя вы их не писали?

Лаба 12.2Sealed-иерархия и исчерпывающий switch25 мин

Описать выражения как sealed-интерфейс с record-ами и вычислять их switch-ем с паттернами — без default.

  1. Создайте файл Expr.java:
    public sealed interface Expr permits Expr.Num, Expr.Add, Expr.Mul, Expr.Neg {
    record Num(double value) implements Expr { }
    record Add(Expr left, Expr right) implements Expr { }
    record Mul(Expr left, Expr right) implements Expr { }
    record Neg(Expr inner) implements Expr { }

    static double eval(Expr e) {
        return switch (e) {
            case Num n -> n.value();
            case Add(Expr l, Expr r) -> eval(l) + eval(r);
            case Mul(Num(var a), Num(var b)) when a == 0 || b == 0 -> 0;     // вложенный паттерн + guard
            case Mul(Expr l, Expr r) -> eval(l) * eval(r);
            case Neg(Expr inner) -> -eval(inner);
        };
    }

    static String show(Expr e) {
        return switch (e) {
            case Num(var v) -> String.valueOf(v);
            case Add(var l, var r) -> "(" + show(l) + " + " + show(r) + ")";
            case Mul(var l, var r) -> show(l) + " * " + show(r);
            case Neg(var i) -> "-" + show(i);
        };
    }

    static void main() {
        Expr e = new Add(new Num(2), new Mul(new Num(3), new Neg(new Num(4))));
        IO.println(show(e) + " = " + eval(e));
    }
}

java Expr

Лаба 12.3Паттерны в instanceof и switch по null10 мин

Проверить новые формы паттерн-сопоставления, включая case null.

  1. Создайте файл Patterns.java:
    public class Patterns {
    static String describe(Object o) {
        return switch (o) {
            case null -> "это null";
            case Integer i when i > 100 -> "большое число " + i;
            case Integer i -> "число " + i;
            case String s when s.isBlank() -> "пустая строка";
            case String s -> "строка длины " + s.length();
            case int[] arr -> "массив int из " + arr.length;
            default -> "что-то ещё: " + o.getClass().getSimpleName();
        };
    }

    public static void main(String[] args) {
        Object[] samples = { 7, 500, "", "hello", new int[3], 2.5, null };
        for (Object o : samples) System.out.println(describe(o));
        Object x = "text";
        if (x instanceof String s && s.length() > 2) System.out.println("instanceof с паттерном: " + s.toUpperCase());
    }
}

12.11Самопроверка

Что record генерирует автоматически?

  • Только геттеры
  • Геттеры и сеттеры
  • Канонический конструктор, методы доступа по именам компонентов, equals, hashCode, toString
  • Только toString
Поля private final, сеттеров нет. Методы доступа называются как компоненты: point.x(), не getX().

Где нельзя использовать var?

  • В полях класса, параметрах методов и без инициализатора
  • В цикле for-each
  • Для локальной переменной с инициализатором
  • В try-with-resources
var — вывод типа только для локальных переменных с инициализатором (и параметров лямбд). Тип остаётся статическим.

Чем switch-выражение отличается от старого оператора switch?

  • Работает только со строками
  • Возвращает значение, не «проваливается» между ветками со стрелкой и обязан быть исчерпывающим
  • Ничем, кроме синтаксиса
  • Не поддерживает enum
Ветки case X -> … не требуют break; для блока значение возвращает yield.

Что компилятор НЕ создаёт автоматически для record Point(int x, int y)?

  • equals и hashCode
  • Сеттеры setX и setY
  • Методы x() и y()
  • toString
Компоненты записи финальны — менять их нельзя.

Зачем в switch-выражении по sealed-интерфейсу не писать default?

  • default запрещён
  • Так быстрее
  • Иначе не скомпилируется
  • Тогда при добавлении нового наследника компилятор укажет все места, где его забыли обработать
Полнота проверяется только без «ловушки на всё остальное».
Делает ли var Java динамически типизированной?

Нет. Тип выводится компилятором из инициализатора и фиксируется; присвоить переменной значение другого типа нельзя. var — сокращение записи, применимое только к локальным переменным.

Что компилятор создаёт для записи и чем запись отличается от обычного класса с Lombok @Value?

Финальные поля, канонический конструктор, методы доступа, equals, hashCode, toString. В отличие от класса с Lombok, запись — конструкция языка: не требует обработчика аннотаций, не может иметь дополнительных полей и наследования, поддерживается образцами в switch и instanceof, безопаснее сериализуется.

Почему в switch по sealed-типу лучше не писать default?

Без default компилятор проверяет, что перечислены все разрешённые наследники. Когда появится новый, код перестанет компилироваться во всех местах, требующих решения. С default новый вариант молча попадёт в общую ветку — ошибка обнаружится в продакшене.

Запись record Report(String title, List<Row> rows) — неизменяема ли она?

Только поверхностно. Ссылку rows заменить нельзя, но сам список можно изменить через ссылку, оставшуюся у создателя, или через report.rows().add(...). Нужна защитная копия в компактном конструкторе: rows = List.copyOf(rows).

Что такое guard в образце и в каком порядке должны идти ветки?

Условие после when, уточняющее ветку: case Success s when s.amount().signum() == 0. Ветки проверяются сверху вниз, поэтому более частные образцы (с условием, с подтипом) ставят раньше общих; если общий стоит выше и полностью покрывает частный, компилятор сообщит об ошибке.
