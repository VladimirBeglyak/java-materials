7.1Свой загрузчик

Свой загрузчик — наследник ClassLoader, который умеет находить байты класса там, где нужно: в отдельной папке плагина, в базе, по сети. Обычно переопределяют только «найди байты» (findClass), а делегирование родителю остаётся стандартным. Ещё загрузчик может проверять подписи или расшифровывать классы.

Главная мысль Свой загрузчик решает, откуда брать байты классов.

7.2Горячая перезагрузка

Изменить уже загруженный класс нельзя. Но можно выбросить старый загрузчик и загрузить новые версии классов новым загрузчиком. Старые объекты продолжают жить со старыми классами, новые — создаются из новых. Так работают «перезапуск без перезапуска» в инструментах разработки (например, Spring DevTools держит отдельный загрузчик для вашего кода).

Главная мысль Перезагрузка = новый загрузчик для новых версий классов.

7.3Загрузчики в реальных системах

  • Tomcat — свой загрузчик на каждое веб-приложение: два приложения могут использовать разные версии библиотеки.
  • Spring Boot fat jar — особый загрузчик умеет читать JAR-ы, вложенные в JAR.
  • Плагины (IDE, Jenkins, Elasticsearch) — изоляция плагинов друг от друга.
Главная мысль Изоляция приложений и плагинов — главное применение своих загрузчиков.

7.4Выгрузка классов и утечки

Почему после пяти передеплоев кончается Metaspace
приложение задеплоено → загрузчик L1 загрузил его 5000 классовпередеплой → новый загрузчик L2, старый L1 должен исчезнутьно в общем классе сервера осталась ссылка на объект приложения
(ThreadLocal в чужом потоке, зарегистрированный драйвер, кэш)объект держит свой класс → класс держит L1 → L1 держит все 5000 классов
каждый передеплой — ещё одна копия → OutOfMemoryError: Metaspace

Каждый класс помнит свой загрузчик.

Старые классы могут уйти, только если ушёл весь загрузчик.

Одна ссылка снаружи держит всё.

Лечение — снимать регистрации и чистить ThreadLocal при остановке.

Главная мысль Класс выгружается только со всем загрузчиком. Одна забытая ссылка — утечка всех классов.

7.5Java-агенты

Агент — специальная программа, которая подключается к JVM (флагом -javaagent или на лету) и может менять байткод классов при их загрузке. Так работают APM-системы и трассировка (OpenTelemetry), профилировщики, моки статических методов, покрытие тестов. Сила и опасность одновременно: агент может изменить что угодно.

Главная мысль Агенты правят байткод при загрузке — основа мониторинга и инструментов.

7.7Проверьте себя

Когда класс может быть выгружен из JVM?

  • когда нет объектов этого класса
  • по таймеру
  • только когда недостижим весь его загрузчик
  • никогда
Классы выгружаются вместе с загрузчиком.

После нескольких передеплоев — OutOfMemoryError: Metaspace. Что подозревать?

  • утечку загрузчика: старые классы удерживает забытая ссылка
  • мало кучи
  • медленный диск
  • DNS
Каждый деплой добавляет копию классов.

Как два веб-приложения в одном Tomcat используют разные версии одной библиотеки?

  • никак
  • через модули
  • через рефлексию
  • у каждого свой загрузчик классов
Изоляция загрузчиками.

Что делает Java-агент?

  • собирает мусор
  • может менять байткод классов при их загрузке
  • компилирует Java
  • управляет сетью
Основа APM и профилировщиков.

Можно ли изменить уже загруженный класс без агента?

  • да, через рефлексию
  • да, перезаписав .class-файл
  • нет: можно только загрузить новую версию другим загрузчиком
  • да, через static-блок
На этом построена горячая перезагрузка.
