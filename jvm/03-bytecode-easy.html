Байткод и стековая машина — простыми словами

JVM исполняет не Java, а байткод — простые команды для стековой машины. Разберёмся, что такое кадр метода, как стопка операндов заменяет регистры, какие бывают инструкции, во что компилируются привычные конструкции Java и как интерпретатор HotSpot их исполняет.

3.1Кадр метода

Каждый вызов метода получает кадр на стеке потока (вспомните «тарелки» из курса «Как устроен компьютер»). В кадре две части: ячейки локальных переменных (параметры и переменные метода, у каждой свой номер) и стопка операндов — рабочий стол для вычислений.

Главная мысль Кадр = нумерованные ячейки переменных + стопка операндов.

3.2Как считает стековая машина

int c = a + b * 2 (a = 5, b = 3)
iload_1   положить a      стопка: [5]iload_2   положить b      стопка: [5, 3]
iconst_2  положить 2      стопка: [5, 3, 2]imul      снять 3 и 2, положить 6      стопка: [5, 6]iadd      снять 5 и 6, положить 11     стопка: [11]istore_3  снять 11 в ячейку 3 (c)    стопка: []

Значение из ячейки переменной кладётся на стопку.

Ещё два значения сверху.

Операция снимает два верхних и кладёт результат.

То же для сложения.

Результат уходит в ячейку переменной c.

Главная мысль Положить на стопку → операция над верхними → сохранить. Никаких регистров.

3.3Набор инструкций

Инструкций около двухсот, и они удобно группируются: загрузка и сохранение (iload, astore), арифметика (iadd, imul), переходы (if_icmplt, goto), работа с объектами (new, getfield), вызовы (invokevirtual и другие, глава 04), возврат (ireturn). Первая буква подсказывает тип: i — int, l — long, a — ссылка.

Главная мысль Загрузить, посчитать, перейти, создать, вызвать, вернуть. Буква — тип.

3.4Во что компилируется Java

  • if и циклы — сравнения и переходы.
  • new Order() — new (выделить память) + invokespecial <init> (вызвать конструктор).
  • склейка строк — invokedynamic (с Java 9).
  • switch по строкам — switch по hashCode + equals.
  • лямбда — скрытый метод + invokedynamic.
Главная мысль Привычные конструкции превращаются в простые команды. Посмотреть — javap -c.

В полной главе: 3.4 Во что компилируются конструкции Java

3.5Как интерпретирует HotSpot

Интерпретатор HotSpot не огромный switch по командам, а «шаблонный»: при старте JVM для каждой инструкции генерируется кусочек машинного кода, и интерпретатор прыгает от кусочка к кусочку. Это быстрее наивного подхода, но всё равно в разы медленнее скомпилированного кода — поэтому горячие методы отдают JIT (глава 16).

Главная мысль Интерпретатор быстрый для старта, но медленный для горячего кода — его ускоряет JIT.

3.7Проверьте себя

Что делает инструкция iadd?

  • загружает переменную
  • сохраняет результат
  • снимает два int со стопки и кладёт их сумму
  • вызывает метод add
Операции работают с верхушкой стопки.

Из чего состоит кадр метода?

  • из ячеек локальных переменных и стопки операндов
  • из полей класса
  • из кучи
  • из регистров процессора
Свой кадр у каждого вызова.

Во что превращается new Order()?

  • в одну инструкцию create
  • в вызов фабрики
  • в рефлексию
  • в new (выделить память) и вызов конструктора <init>
Две отдельные операции.

Что означает первая буква в iload, lload, aload?

  • номер переменной
  • тип значения: int, long, ссылка
  • приоритет
  • ничего
Байткод типизирован.

Почему горячие методы не оставляют интерпретатору?

  • интерпретатор ошибается
  • интерпретатор не умеет циклы
  • скомпилированный код в разы быстрее
  • так требует спецификация
Поэтому есть JIT.
