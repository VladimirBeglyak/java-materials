23.2Задачи: что будет напечатано

1. class A { static { System.out.print("A"); } static final String X = "x"; } — что выведет System.out.print(A.X);?

x — без «A»: X — константа времени компиляции, javac подставил строку прямо в байткод вызывающего класса, класс A даже не загружается.

2. Integer a = 127, b = 127, c = 128, d = 128; System.out.println((a == b) + " " + (c == d));

true false: автоупаковка — Integer.valueOf, кэш −128..127 (верхнюю границу можно поднять -XX:AutoBoxCacheMax). 128 — разные объекты.

3. class P { P() { init(); } void init() {} } class C extends P { int v = 5; void init() { System.out.print(v); } } — new C()?

0: конструктор P вызывает переопределённый init() до того, как выполнились инициализаторы полей C (v = 5 присваивается после super()). Поле содержит значение по умолчанию.

4. Два URLClassLoader с родителем null загружают один и тот же jar. l1.loadClass("Foo") == l2.loadClass("Foo")?

false: два определяющих загрузчика — два разных класса; у каждого свои статические поля.

5. String s1 = "ja" + "va"; String s2 = "java"; String p = "ja"; String s3 = p + "va"; — s1 == s2, s2 == s3, s2 == s3.intern()?

true, false, true: «ja» + «va» свёрнуто компилятором в литерал из пула; p + «va» вычисляется в рантайме (indy-конкатенация) — новый объект; intern() возвращает экземпляр из пула строк.

6. Цикл for (int i = 0; i < 1_000_000; i++) list.add(new Point(i, i)); — сколько объектов Point создаст C2?

1 млн: объекты сбегают в список (GlobalEscape), скалярная замена невозможна. Если бы Point использовался только для вычисления внутри итерации — выделений могло бы не быть вовсе.

23.3Разбор инцидентов

После обновления библиотеки в рантайме NoSuchMethodError, хотя всё компилируется.

Конфликт версий транзитивных зависимостей: код скомпилирован против версии с методом, в рантайме выбрана другая (дескриптор отличается, хотя бы возвращаемым типом). mvn dependency:tree -Dverbose, -verbose:class (откуда загружен класс), выравнивание версий через BOM/dependencyManagement, enforcer.

Через сутки после деплоя — OutOfMemoryError: Metaspace, хотя приложение не перезагружается.

Генерация классов без выгрузки: создание прокси/лямбд/скриптов (Groovy, Janino, cglib) в цикле, новые загрузчики на каждый запрос, defineHiddenClass без возможности выгрузки. VM.classloader_stats и Xlog:class+load покажут, какие классы появляются; кэшировать сгенерированные классы.

p99 задержек 800 мс раз в несколько минут, в логе GC паузы 20 мс.

Время до safepoint (Xlog:safepoint — Reaching safepoint), троттлинг CPU контейнера (cfs_throttled), паузы ОС (swap, transparent huge pages compaction), паузы самого приложения (блокировки, пул соединений). Сопоставить метки времени задержек с JFR-событиями.

После перехода на Java 21 и виртуальные потоки пропускная способность упала.

Закрепление носителей (pinning) в synchronized-блоках с блокирующим I/O (до Java 24) — потоки-носители заняты, параллелизм упал до числа ядер; проверить jdk.VirtualThreadPinned в JFR. Также ThreadLocal-кэши (каждый виртуальный поток создаёт свой экземпляр дорогого объекта), ограниченные пулы соединений, теперь ставшие узким местом. Обновиться до 24+ или заменить synchronized на ReentrantLock, ограничить конкурентность семафором.

  1. Создайте файл Mystery.java:
    import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Mystery {
    static final Map<String, List<String>> AUDIT = new HashMap<>();
    static final Object REGISTRY = new Object();
    static volatile long checksum;

    static void handle(int id) {
        synchronized (REGISTRY) {
            AUDIT.computeIfAbsent("req-" + id, k -> new ArrayList<>()).add("payload-" + "x".repeat(200));
            long h = 0;
            for (int i = 0; i < 200_000; i++) h = h * 31 + i;
            checksum += h;
        }
    }

    public static void main(String[] args) throws Exception {
        System.out.println("pid " + ProcessHandle.current().pid());
        ExecutorService pool = Executors.newFixedThreadPool(8);
        for (int id = 0; ; id++) {
            final int req = id;
            pool.submit(() -> handle(req));
            if (id % 100 == 0) Thread.sleep(20);
        }
    }
}

    IDEAVM options: -Xmx256m -Xlog:gc:file=mystery-gc.log -XX:StartFlightRecording=filename=mystery.jfr,duration=20s

  3. Проблема 1: почему из 8 потоков пула работает фактически один?

    Весь handle — внутри synchronized (REGISTRY). В дампе один поток RUNNABLE с - locked <…> (a java.lang.Object), остальные семь — BLOCKED с waiting to lock того же адреса. Лечение: сузить критическую секцию до работы с общей картой, а вычисление вынести наружу; карту заменить на ConcurrentHashMap.

  4. Проблема 2: что ест CPU?

    Цикл вычисления h внутри handle — на первом месте в jfr view hot-methods (Mystery.handle). При этом он ещё и выполняется под блокировкой, поэтому на 8 потоках сервис использует одно ядро.

  5. Проблема 3: почему растёт память, и что покажет лог GC через час?

    AUDIT — статическая карта, в которую на каждый запрос добавляется запись и никогда не удаляется: в гистограмме растут String, byte[], HashMap$Node, ArrayList. Плюс очередь задач пула неограничена (newFixedThreadPool использует LinkedBlockingQueue без предела) — FutureTask и лямбды копятся, потому что задачи приходят быстрее, чем обрабатываются. В логе GC «занято после сборки» растёт до Full GC и OutOfMemoryError. Лечение: ограниченный кэш/запись аудита во внешнее хранилище и ограниченная очередь с политикой отказа.

Поэкспериментируйте
  • Исправьте все три проблемы и повторите расследование. Какие улики должны исчезнуть?
    В дампе — потоки пула попеременно RUNNABLE без waiting to lock; в гистограмме — стабильные числа между снимками; в логе GC — ровная «занятость после сборки»; загрузка CPU — несколько ядер вместо одного.

23.5Итоговый тест

Где хранятся значения статических полей класса в HotSpot (Java 8+)?

  • В metaspace
  • В стеке потока main
  • В куче, в объекте java.lang.Class
  • В code cache
Метаданные — metaspace, значения — в зеркале класса в куче.

Какая инструкция используется для вызова метода через ссылку интерфейсного типа?

  • invokeinterface
  • invokevirtual
  • invokestatic
  • invokedynamic
Через itable.

Что из перечисленного НЕ является GC root?

  • Локальная переменная работающего потока
  • Статическое поле загруженного класса
  • Глобальная JNI-ссылка
  • Объект в старом поколении, на который ссылается только другой недостижимый объект
Недостижимые цепочки — мусор независимо от поколения.

Почему после деплоя первые минуты сервис медленнее?

  • Из-за TLAB
  • Код интерпретируется или работает на C1, профиль собирается, классы загружаются лениво — прогрев
  • GC отключён
  • Kubernetes ограничивает трафик
Лечится прогревом, AOT cache, CRaC.

Что значит «made not entrant» в PrintCompilation?

  • Метод удалён
  • Ошибка компиляции
  • Версия кода больше не используется для новых вызовов (заменена или деоптимизирована)
  • Метод стал синхронизированным
Код удалится, когда его перестанут исполнять.

Pod с limits.memory 2Gi и -Xmx2g. Что произойдёт под нагрузкой?

  • Вероятно, OOM killer: процессу нужна память и вне кучи
  • OutOfMemoryError: Java heap space
  • Ничего
  • JVM сама уменьшит кучу
Куча — 60–75% лимита.
