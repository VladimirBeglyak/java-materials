13.1Треугольник компромиссов

Паузы

Насколько надолго замирает программа. Важно для веб-сервисов.

Пропускная способность

Какую долю времени программа работает, а не ждёт уборки. Важно для пакетной обработки.

Память

Сколько лишней памяти нужно сборщику.

Улучшить одну вершину можно только за счёт других. Короткие паузы стоят памяти и процессора; максимальная пропускная способность — длинных пауз.

Главная мысль Паузы, пропускная способность, память — выбрать все три нельзя.

13.2Serial и Parallel

Serial — один уборщик, все ждут: просто и экономно, подходит маленьким программам и контейнерам с одним ядром. Parallel — бригада уборщиков, все по-прежнему ждут, но уборка быстрее: максимальная пропускная способность, хорош для пакетных задач, где паузы не страшны. Оба останавливают программу на всё время сборки.

Главная мысль Serial — маленьким, Parallel — пакетным задачам. Паузы на всю уборку.

13.3G1: регионы

Как G1 убирает кучу по частям
куча поделена на тысячи одинаковых регионов:
одни — для молодых, другие — для старых, третьи — пустыемолодые регионы заполнились → малая сборка: живых копируем в свободные регионыпараллельно с программой G1 помечает старые регионы и считает,
где больше всего мусорасмешанная сборка: убирает молодые + самые «мусорные» старые регионы,
столько, чтобы уложиться в целевую паузу (по умолчанию 200 мс)

Не две большие области, а много маленьких.

Копирование живых молодых объектов.

Анализ старых регионов без остановки.

Сначала самые грязные — отсюда название Garbage First.

Главная мысль G1 убирает кучу по регионам, начиная с самых грязных, стараясь уложиться в целевую паузу.

13.4ZGC: паузы меньше миллисекунды

ZGC делает почти всё — и пометку, и перенос объектов — одновременно с работой программы. Как переезд, во время которого жильцы продолжают жить: если кто-то тянется к вещи, которую уже перевезли, «барьер» на чтении ссылки подсказывает новый адрес. Паузы — доли миллисекунды независимо от размера кучи, даже терабайтной. Цена — больше процессора и запас памяти. Shenandoah — похожий сборщик с той же целью.

Главная мысль ZGC переносит объекты, не останавливая программу. Паузы крошечные, цена — ресурсы.

13.5Какой выбрать

СитуацияСборщик
обычный веб-сервисG1 (по умолчанию)
нужны минимальные паузы, большая кучаZGC
пакетная обработка, паузы не важныParallel
маленький контейнер, 1 ядро, мало памятиSerial

Менять сборщик стоит по измерениям, а не по моде: включите логи GC (глава 14) и посмотрите, есть ли вообще проблема.

Главная мысль По умолчанию G1; паузы критичны — ZGC; выбор — по логам, а не наугад.

Что значит Garbage First?

  • G1 сначала убирает регионы, где больше всего мусора
  • сначала убирается молодое поколение
  • мусор удаляется до сборки

Максимум освобождённой памяти за паузу.

Как ZGC добивается пауз меньше миллисекунды?

  • не собирает мусор
  • работает только с маленькой кучей
  • отключает потоки
  • помечает и переносит объекты параллельно с программой
Барьеры подсказывают новые адреса.

Ночная пакетная обработка данных, паузы не важны, важна скорость. Что выбрать?

  • ZGC
  • Parallel
  • Serial
  • без сборщика
Максимальная пропускная способность.
