JVM изнутри: от class-файла до продакшена

Полный разбор виртуальной машины Java для разработчика: что лежит в class-файле и как исполняется байткод, как загрузчики классов находят, связывают и инициализируют классы, как устроены объекты в памяти и как их убирают сборщики мусора, что делает JIT и почему он иногда откатывается, как работают потоки, блокировки и safepoints — и как всё это диагностировать и настраивать в контейнерах. Цель — для любого странного поведения Java-программы назвать механизм JVM, который его вызывает.

Как работать с пособием

  1. Смотрите своими глазами. Почти каждое утверждение курса проверяется инструментами JDK: javap -v, -Xlog:class+load, -XX:+PrintCompilation, -Xlog:gc*, jcmd, JFR. Для этого в каждой главе есть практикум — лабораторные с кодом для набора в IDE и реальным выводом JDK 25.
  2. Предсказывайте до шага симулятора и до кнопки «Показать ответ» — так проверяется модель в голове.
  3. Читайте исходники HotSpot там, где интересно: src/hotspot/share в репозитории openjdk/jdk — classfile, oops, gc, opto (C2), runtime.
  4. Пройдите тренажёр темы 23 до конца и вернитесь к темам, где «Повторить».
  5. Отмечайте темы изученными — прогресс виден в меню слева.
Версии Основа — HotSpot JDK 21 (LTS) с отметками об изменениях в 22–25: FFM API (22), AOT cache (24–25), компактные заголовки (24–25), synchronized и виртуальные потоки (24), поколенческий ZGC (21+). Внутренние детали (пороги, размеры, имена флагов) приведены для HotSpot x86-64/AArch64 Linux и могут отличаться в других версиях и реализациях — проверяйте -XX:+PrintFlagsFinal.

Практикум: подготовка рабочего места

В каждой главе перед самопроверкой есть раздел «Практикум: пишем и запускаем» — около ста лабораторных, где вы набираете код, запускаете его и смотрите, как JVM загружает классы, раскладывает объекты, собирает мусор и компилирует код: javap, -Xlog, jcmd, JFR, JOL. Ожидаемый вывод под каждой командой снят настоящим запуском на OpenJDK 25.0.2 (Windows x64, 18 логических процессоров, 32 ГБ): числа, адреса и времена у вас будут свои, а поведение — тем же.

1. JDK и IDE

  1. JDK 25 (LTS): в IntelliJ IDEA — File → Project Structure → SDK → Add SDK → Download JDK → версия 25 (Oracle OpenJDK, Temurin или Corretto). Проверка в терминале: java -version и javac -version должны показать 25.
  2. Проект jvm-lab (File → New → Project → Java, без системы сборки). Для каждой главы — свой модуль: File → New → Module → ch01, ch02… Классы кладите прямо в src (пакет по умолчанию): имена классов внутри главы не повторяются, а команды из пособия работают без пакетов.
  3. Language level модуля — 25 (Project Structure → Modules → Language level), иначе новые возможности языка не скомпилируются.

2. Где в IDEA то, что в пособии написано командой

В пособииВ IntelliJ IDEA
java Helloзелёный ▶ рядом с main (Ctrl+Shift+F10)
java -Xmx64m -Xlog:gc HelloRun → Edit Configurations… → Modify options → Add VM options → -Xmx64m -Xlog:gc

javap -c -p HelloView → Show Bytecode (курсор в классе) или в терминале: javap -c -p -cp out/production/ch01 Hello

IDEA компилирует классы в out/production/<модуль>. Команды в пособии написаны так, будто вы стоите в каталоге с исходником: проще всего в терминале перейти в src модуля (cd ch01/src) и запускать javac Hello.java / java Hello там же — или однофайловым режимом java Hello.java без отдельной компиляции.

4. Как проходить лабораторную

  1. Наберите код руками (кнопки copy можно скрыть переключателем «набираю руками» в начале практикума).
  2. На шагах со знаком ? сначала запишите прогноз в поле — он сохраняется в браузере, — затем запустите и нажмите «Сверить».
  3. Сравните свой вывод с образцом под спойлером «Вывод». Если отличается не только числами — это повод разобраться, а не пропустить.
  4. Блок «Поэкспериментируйте» — главное: меняйте по одной детали и предсказывайте результат. Ответы спрятаны под стрелками.
  5. Отмечайте шаги галочкой «сделал» — прогресс лабораторной виден в её заголовке.
