19.1JNI: переходник через C

JNI (Java Native Interface) — старый способ вызова нативного кода. Метод в Java помечается native, а реализацию пишут на C в особом формате, компилируют под каждую платформу и загружают библиотеку. Как переводчик-посредник, которого нужно отдельно нанимать в каждой стране. Минусы: много ручной работы, сборка под каждую ОС, а ошибка в C-коде роняет всю JVM, а не выбрасывает исключение.

Главная мысль JNI работает, но требует кода на C под каждую платформу, и ошибки в нём роняют JVM.

19.3JNI, FFM, Unsafe

Статусстарый, работаетрекомендуемыйвнутренний, уходит

Unsafe — внутренний «чёрный ход» JDK для прямой работы с памятью. Им пользовались библиотеки ради скорости, но его методы для памяти постепенно выводят из употребления в пользу FFM и VarHandle.

Главная мысль Новый код — FFM. JNI — для старого, Unsafe — уходит.

Нативный код вне защиты JVM.

Главное преимущество FFM API перед JNI?

  • быстрее компилируется
  • работает только на Linux
  • не требует JVM
  • не нужно писать код на C, и работа с памятью безопаснее
Всё описывается на Java.

  • компилирует код
  • загружает библиотеки
  • шифрует память
