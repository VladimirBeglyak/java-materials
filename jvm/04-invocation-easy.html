4.2vtable: выбор метода за один шаг

Если Animal a = new Cat() и вызывается a.speak(), нужна версия кошки. JVM не перебирает иерархию: у каждого класса есть таблица методов (vtable), где под одним и тем же номером у кошки лежит «мяукнуть», а у собаки — «гавкнуть». Вызов — «взять у объекта его класс, взять из таблицы метод №N». Как кнопки лифта: кнопка «5» в любом доме ведёт на пятый этаж своего дома.

Главная мысль vtable: у каждого класса таблица, номер метода одинаков, содержимое своё.

4.3invokedynamic

Первый вызов лямбды
в байткоде: invokedynamic «сделай мне Runnable» + ссылка на «настройщика»первое выполнение: JVM зовёт настройщика (bootstrap-метод)настройщик создаёт класс-обёртку для лямбды и возвращает «связку» (CallSite)все следующие вызовы идут сразу по связке — как обычный быстрый вызов

javac не решает, как реализовать лямбду.

Решение принимается при первом выполнении.

Результат запоминается в месте вызова.

JIT может встроить такой вызов как обычный.

Так реализованы лямбды, склейка строк, records (equals/hashCode/toString) и switch с образцами. Плюс: реализацию можно улучшать в новых версиях JDK без перекомпиляции ваших классов.

Главная мысль invokedynamic откладывает решение «что вызвать» до первого выполнения.

4.4MethodHandle против рефлексии

Рефлексия (Method.invoke) на каждый вызов проверяет доступ и упаковывает аргументы — медленно. MethodHandle — «прямая ссылка на метод»: проверки делаются один раз при создании, а если ссылка хранится в static final поле, JIT вызывает её почти как обычный метод. Современная рефлексия в JDK сама построена на MethodHandle.

Главная мысль MethodHandle — быстрая «ссылка на метод»; рефлексия — гибко, но медленнее.

4.5Ошибки связывания

  • NoSuchMethodError — код скомпилирован против одной версии библиотеки, а запущен с другой, где метода нет или у него другая сигнатура.
  • NoSuchFieldError — то же для поля.
  • AbstractMethodError — класс не реализует метод, который появился в интерфейсе более новой версии.
  • IncompatibleClassChangeError — класс превратился в интерфейс, метод стал статическим и т. п.

Почти всегда причина — конфликт версий библиотек в classpath.

Главная мысль Ошибки связывания = «компилировали с одной версией, запускаем с другой».

4.7Проверьте себя

Какая инструкция вызывает конструктор?

  • invokestatic
  • invokespecial
  • invokedynamic
  • invokevirtual
Также приватные методы и super.

Как JVM быстро находит нужную версию переопределённого метода?

  • перебирает родителей
  • через рефлексию
  • спрашивает компилятор
  • по таблице методов класса объекта (vtable)
Один переход по номеру.

Что реализовано через invokedynamic?

  • лямбды и склейка строк
  • только конструкторы
  • статические методы
  • исключения
Также records и switch с образцами.

После обновления библиотеки — NoSuchMethodError. Вероятная причина?

  • опечатка в коде
  • мало памяти
  • код собран против одной версии, а в classpath другая
  • ошибка JIT
Смотрите дерево зависимостей.

Почему MethodHandle быстрее рефлексии при частых вызовах?

  • он кэширует результат
  • проверки делаются один раз, а JIT может встроить вызов
  • он работает без JVM
  • он не быстрее
Особенно в static final поле.
