8.1Дескриптор модуля

Файл module-info.java — паспорт модуля: имя, requires — от каких модулей зависит, exports — какие пакеты доступны другим, opens — какие пакеты можно исследовать рефлексией, а также какие сервисы модуль предоставляет и использует.

Главная мысль requires — что нужно, exports — что показываю, opens — что разрешаю рефлексии.

8.2Строгая проверка доступа

Раньше public значило «доступно всем». Теперь public-класс из неэкспортированного пакета снаружи модуля не виден — как служебные помещения в магазине: дверь есть, но покупателям туда нельзя. Поэтому, например, внутренние классы JDK (sun.misc и прочие) больше нельзя просто так использовать. Рефлексия во внутренние пакеты тоже запрещена, пока модуль их не откроет — отсюда ошибки InaccessibleObjectException и флаги --add-opens у старых библиотек.

Главная мысль public без exports — невидим снаружи модуля. Внутренности JDK закрыты.

8.3Classpath и модули вместе

Большинство приложений по-прежнему запускаются через classpath — тогда всё ваше попадает в один безымянный модуль, который видит все экспортированные пакеты. JAR без module-info, положенный в modulepath, становится автоматическим модулем. Это позволяет переходить на модули постепенно — или не переходить вовсе.

Главная мысль Classpath продолжает работать: ваш код — в безымянном модуле.

8.4jdeps и jlink: маленький runtime

Собираем runtime только из нужного

8.5Слои модулей

Слой — набор модулей со своими загрузчиками. Через слои можно загрузить в одну JVM две версии одной библиотеки — каждую в своём слое, как в разных квартирах одного дома. Это редкий, но мощный инструмент для систем плагинов.

Главная мысль Слои — изолированные наборы модулей, две версии библиотеки в одной JVM.

8.7Проверьте себя

Виден ли снаружи модуля public-класс из пакета без exports?

  • да, он же public
  • только в тестах
  • нет
  • только через рефлексию
Модуль сам решает, что показывать.

Старая библиотека падает с InaccessibleObjectException на Java 17. Почему?

  • она рефлексией лезет во внутренние пакеты JDK, которые теперь закрыты
  • она скомпилирована неправильно
  • не хватает памяти
  • нет интернета
Временный обход — --add-opens, правильно — обновить библиотеку.

Зачем нужен jlink?

  • для компиляции
  • для отладки
  • для тестов
  • чтобы собрать маленький runtime только из нужных модулей
Меньше образ контейнера.

Обязательно ли переводить приложение на модули?

  • да, с Java 9
  • нет: classpath работает, код живёт в безымянном модуле
  • да, иначе не запустится
  • только для Spring
Переход можно делать постепенно или не делать.

Что означает requires в module-info?

  • какие пакеты я открываю
  • какие сервисы предоставляю
  • от каких модулей я завишу
  • какую версию Java требую
