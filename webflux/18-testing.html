Тестирование: StepVerifier и WebTestClient

Реактивный код нельзя проверить, просто вызвав метод: он вернёт описание, а ошибка «утонет» в onError, если на неё не подписаться. reactor-test даёт StepVerifier — декларативную проверку последовательности сигналов, виртуальное время для тестов с задержками на сутки, TestPublisher и PublisherProbe. Для HTTP-слоя — WebTestClient и @WebFluxTest.

~1,5 часаStepVerifierwithVirtualTimeTestPublisherPublisherProbeWebTestClient@WebFluxTestинтерактивтест

18.1StepVerifier

@Test
void pricesAreConverted() {
    StepVerifier.create(service.prices("EUR"))
        .expectNext(new Price("A", 10))
        .expectNextMatches(p -> p.amount() > 0)
        .assertNext(p -> assertThat(p.sku()).startsWith("B"))
        .expectNextCount(3)
        .verifyComplete();              // = expectComplete().verify() — именно verify() подписывается!
}

@Test
void failsOnUnknownCurrency() {
    StepVerifier.create(service.prices("XXX"))
        .expectErrorSatisfies(e -> assertThat(e).isInstanceOf(UnknownCurrency.class)
                                               .hasMessageContaining("XXX"))
        .verify(Duration.ofSeconds(5)); // таймаут: без него зависший поток подвесит тест
}

18.2Пройдёт ли тест?

Издатель + сценарий StepVerifier → результат
// правильно: издатель создаётся внутри Supplier, ПОСЛЕ подмены планировщиков
StepVerifier.withVirtualTime(() -> service.dailyReport())
    .expectSubscription()
    .expectNoEvent(Duration.ofHours(23))     // за 23 часа ничего не пришло
    .thenAwait(Duration.ofHours(1))
    .expectNextCount(1)
    .verifyComplete();

// неправильно: Mono.delay уже захватил настоящий parallel() при сборке
Mono<Report> r = service.dailyReport();
StepVerifier.withVirtualTime(() -> r) ... // зависнет

18.3TestPublisher и PublisherProbe

TestPublisher<String> src = TestPublisher.create();
StepVerifier.create(service.normalize(src.flux()))
    .then(() -> src.emit("a", "b"))          // emit = next... + complete
    .expectNext("A", "B")
    .verifyComplete();
src.assertMinRequested(1);                   // оператор действительно запрашивал данные

PublisherProbe<User> fallback = PublisherProbe.of(Mono.just(User.GUEST));
when(cache.get(id)).thenReturn(Mono.empty());
when(guestProvider.get()).thenReturn(fallback.mono());
StepVerifier.create(service.user(id)).expectNext(User.GUEST).verifyComplete();
fallback.assertWasSubscribed();              // switchIfEmpty действительно подписался на fallback

18.4WebTestClient

@WebFluxTest(UserController.class)            // только web-слой: контроллеры, фильтры, кодеки, security
class UserControllerTest {
    @Autowired WebTestClient client;
    @MockitoBean UserService users;          // Spring Framework 6.2+ (Boot 3.4+); @MockBean удалён в Boot 4

    @Test
    void returns404WhenMissing() {
        when(users.find(42L)).thenReturn(Mono.empty());
        client.get().uri("/api/users/42").exchange()
              .expectStatus().isNotFound();
    }

    @Test
    void streamsEvents() {
        when(users.events()).thenReturn(Flux.just(e1, e2));
        FluxExchangeResult<Event> res = client.get().uri("/api/events")
              .accept(MediaType.TEXT_EVENT_STREAM).exchange()
              .expectStatus().isOk()
              .returnResult(Event.class);
        StepVerifier.create(res.getResponseBody()).expectNext(e1, e2).verifyComplete();
    }

    @Test
    @WithMockUser(roles = "ADMIN")           // или client.mutateWith(mockJwt().authorities(...))
    void adminCanDelete() {
        when(users.delete(1L)).thenReturn(Mono.empty());
        client.mutateWith(csrf()).delete().uri("/api/users/1").exchange()
              .expectStatus().isNoContent();
    }
}

Режимы WebTestClient

  • bindToController(c) / bindToRouterFunction(r) — без Spring-контекста
  • @WebFluxTest — срез с автоконфигурацией
  • @SpringBootTest(webEnvironment = RANDOM_PORT) — реальный сервер и сеть
  • bindToServer().baseUrl(...) — любой живой сервер

Интеграционные тесты

  • Testcontainers + @ServiceConnection для PostgreSQL/R2DBC, Kafka, Redis
  • MockWebServer (OkHttp) или WireMock — для WebClient
  • BlockHound в тестах — ловит блокировки в event loop (тема 20)
  • @DataR2dbcTest — срез репозиториев

18.5Самопроверка

Тест написан как StepVerifier.create(flux).expectNext(1).expectComplete();. Что не так?

  • Нужен expectNextCount
  • Нет verify(): подписки не было, тест ничего не проверил
  • expectComplete лишний
  • Всё правильно
verify() (или verifyComplete) запускает подписку и проверку.

Почему издатель для withVirtualTime передаётся через Supplier?

  • Так короче
  • Для ленивых исключений
  • Чтобы операторы времени при сборке захватили уже подменённый VirtualTimeScheduler
  • Чтобы тест был параллельным
Mono.delay выбирает планировщик в момент создания.

Как проверить, что fallback в switchIfEmpty действительно был вызван (подписан)?

  • PublisherProbe.assertWasSubscribed()
  • Mockito.verify на методе, возвращающем Mono
  • log()
  • expectNextCount(1)
Mockito проверит вызов метода, но не подписку на его результат.
Почему verify(Duration) лучше, чем verify()?

verify() блокирует до терминального сигнала. Если код содержит ошибку и никогда не завершается (забытый complete, пустой Sinks, зависший внешний вызов), тест повиснет до таймаута CI. verify(Duration) превращает это в понятную ошибку «VerifySubscriber timed out». Глобально — StepVerifier.setDefaultTimeout(Duration.ofSeconds(10)).
