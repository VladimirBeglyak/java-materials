Mono и Flux: создание, cold и hot

Способов создать издатель десятки, и выбор между ними — не вкусовщина: Mono.just(call()) вызовет сервис сразу при сборке, а Mono.fromCallable(this::call) — при каждой подписке. Разбираем фабрики, разницу между холодными и горячими издателями, операторы share, cache, replay и мосты из императивного кода.

3.2generate и create

Flux<Long> fib = Flux.generate(
    () -> new long[]{0, 1},                  // начальное состояние
    (s, sink) -> {
        sink.next(s[0]);                     // ровно один next за вызов
        return new long[]{s[1], s[0] + s[1]};
    });
fib.take(10).subscribe(System.out::println);  // генератор вызван 10 раз
Flux<Event> events = Flux.create(sink -> {
    Listener l = new Listener() {
        public void onEvent(Event e) { sink.next(e); }
        public void onClose()        { sink.complete(); }
        public void onFailure(Throwable t) { sink.error(t); }
    };
    bus.register(l);
    sink.onDispose(() -> bus.unregister(l));          // отмена/завершение
    sink.onRequest(n -> bus.poll(n));                 // если источник умеет «тянуть»
}, FluxSink.OverflowStrategy.BUFFER);                 // что делать, если спроса нет

create позволяет производителю толкать элементы из любого потока и в любом количестве — лишнее буферизуется по стратегии (BUFFER по умолчанию, неограниченный буфер!), DROP, LATEST, ERROR, IGNORE. Подробно — в теме 08.

3.3Холодные и горячие издатели

Холодный издатель запускает работу заново для каждого подписчика (HTTP-запрос, запрос к БД, range). Горячий производит данные независимо от подписчиков, поздний подписчик видит только новые элементы (клики, котировки, Sinks.many().multicast()). Операторы превращают холодный в горячий.

null запрещён Reactive Streams запрещает null в onNext. Mono.just(null) бросит NPE, map(x -> null) — NPE в onError. Отсутствие значения выражается пустым Mono: Mono.justOrEmpty, mapNotNull, filter.

Mono<String> m = Mono.just(restCall()); — никто не подписался. Сколько раз выполнен restCall?

  • 0
  • 1

Аргумент just вычисляется Java до вызова метода.

Какой оператор превратит холодный WebClient-запрос в общий для параллельных подписчиков, но позволит повторить запрос, когда все отпишутся?

  • cache()
  • replay().autoConnect()
  • share()
  • defer()
refCount отключается при нуле подписчиков.

Чем generate отличается от create?

  • generate синхронный, один next на вызов, по спросу; create — колбэчный, многократный push из любых потоков
  • Ничем
  • create только для Mono
  • generate горячий
generate естественно поддерживает противодавление.

Что вернёт Flux.just(1,2).map(x -> x == 2 ? null : x)?

  • 1, null
  • только 1, complete
  • 1, 2
  • 1, затем onError(NullPointerException)
null в onNext запрещён; используйте mapNotNull, если нужно отфильтровать.
Нужен Mono, который при каждой подписке читает актуальное значение поля. Как?

Mono.fromSupplier(() -> this.value) или Mono.defer(() -> Mono.just(this.value)). Mono.just(this.value) захватит значение один раз при сборке.

Как гарантированно закрыть ресурс при отмене или ошибке?

Flux.using(() -> open(), r -> Flux.fromIterable(r.lines()), r -> r.close()) для синхронных ресурсов; usingWhen — для ресурсов с асинхронным закрытием (транзакции, соединения R2DBC): отдельные колбэки на complete, error и cancel. Альтернатива — doFinally(signal -> ...), вызываемый при любом завершении, включая cancel.
