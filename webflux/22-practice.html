22.2Проектирование: эндпоинт-агрегатор

Задача: GET /api/dashboard/{userId} собирает профиль (обязательный), 10 последних заказов (обязательные), рекомендации (некритичные, медленные) и баланс бонусов (некритичный). SLA — 500 мс p99.

@GetMapping("/api/dashboard/{userId}")
Mono<Dashboard> dashboard(@PathVariable String userId) {
    Mono<Profile> profile = profiles.get(userId)
        .timeout(Duration.ofMillis(300))
        .retryWhen(Retry.backoff(1, Duration.ofMillis(50)).filter(this::transient));
    Mono<List<Order>> orders = orderRepo.findTop10ByUserIdOrderByCreatedAtDesc(userId)
        .collectList()
        .timeout(Duration.ofMillis(300));
    Mono<List<Reco>> recos = recoClient.forUser(userId)
        .take(5).collectList()
        .timeout(Duration.ofMillis(200))
        .onErrorReturn(List.of());                       // деградация вместо ошибки
    Mono<Optional<Balance>> balance = bonus.balance(userId)
        .map(Optional::of)
        .timeout(Duration.ofMillis(200))
        .onErrorReturn(Optional.empty())
        .defaultIfEmpty(Optional.empty());               // пустой Mono не должен обнулить zip
    return Mono.zip(profile, orders, recos, balance)
        .map(t -> new Dashboard(t.getT1(), t.getT2(), t.getT3(), t.getT4().orElse(null)))
        .timeout(Duration.ofMillis(450))                  // общий бюджет
        .name("dashboard").tap(Micrometer.observation(registry));
}
  • Все четыре вызова параллельны (zip) — время ≈ максимум, а не сумма.
  • Обязательные части падают целиком (ответ 5xx/504), некритичные деградируют.
  • Бюджеты таймаутов вложены: части меньше общего, общий меньше SLA.
  • Пустой Mono в zip обезврежен через Optional/defaultIfEmpty.
  • Наблюдаемость: имя последовательности и Observation.

22.4Вопросы с собеседований

Что такое backpressure и как он реализован в Reactor?

Механизм, позволяющий потребителю ограничить скорость производителя. По протоколу Reactive Streams подписчик вызывает Subscription.request(n), и издатель не имеет права выдать больше. Операторы с очередями (publishOn, flatMap) запрашивают prefetch и пополняют его по порогу 75%. Для источников, не умеющих замедляться, — стратегии onBackpressureBuffer/Drop/Latest/Error.

Разница между map и flatMap, flatMap и concatMap?

map — синхронное преобразование 1→1. flatMap — асинхронное 1→Publisher, подписывается на внутренние издатели параллельно (до concurrency=256) и выдаёт по готовности. concatMap — по одному внутреннему издателю, сохраняет порядок. flatMapSequential — параллельно, но выдаёт в исходном порядке. switchMap — отменяет предыдущий внутренний при новом элементе.

Чем publishOn отличается от subscribeOn?

publishOn переключает поток для операторов ниже себя (сигналы onNext/onComplete). subscribeOn переключает поток, в котором происходит подписка и запросы вверх, — то есть поток синхронного источника; где бы он ни стоял, действует на всю цепочку до первого publishOn; из нескольких побеждает ближайший к источнику. На асинхронный источник (WebClient) subscribeOn не влияет.

Что значит «ничего не происходит, пока не подпишешься»?

Операторы при вызове лишь строят описание конвейера (assembly). Работа — запросы к БД, HTTP-вызовы — начинается при subscribe() и выполняется заново для каждой подписки (для холодных издателей). В WebFlux подписывается фреймворк на Mono, возвращённый контроллером.

Hot и cold publishers — примеры и как превратить один в другой?

Cold: каждый подписчик получает свою последовательность с начала — WebClient-запрос, R2DBC-запрос, Flux.range. Hot: данные идут независимо от подписчиков — Sinks.many().multicast(), события UI, котировки. Превращение: share() (publish().refCount()), publish().autoConnect(n), replay(n), cache().

Как передать requestId или пользователя через реактивную цепочку?

Через Reactor Context: contextWrite в WebFilter (в конце цепочки), чтение — Mono.deferContextual / transformDeferredContextual. Для логов и трассировки — spring.reactor.context-propagation=auto и Micrometer context-propagation, которые восстанавливают MDC из Context на каждом сигнале. ThreadLocal напрямую не работает: цепочка перескакивает между потоками.

Что произойдёт, если вызвать block() в контроллере WebFlux?

Reactor обнаружит, что поток помечен как NonBlocking (event loop Netty, parallel), и бросит IllegalStateException «block()/blockFirst()/blockLast() are blocking, which is not supported in thread reactor-http-nio-N». Даже если бы не бросил — заблокированный event loop остановил бы все соединения потока.

Как работают транзакции в реактивном Spring?

ReactiveTransactionManager (R2dbcTransactionManager) хранит транзакционное соединение в Reactor Context. @Transactional работает на методах, возвращающих Publisher: транзакция начинается при подписке и фиксируется/откатывается по терминальному сигналу (при отмене — откат). Операции вне возвращённой цепочки (отдельный subscribe) в транзакцию не попадают. Программный вариант — TransactionalOperator.

Как обработать ошибку одного элемента и продолжить Flux?

Внутри flatMap: flux.flatMap(x -> call(x).onErrorResume(e -> Mono.empty())). Ошибка, дошедшая до внешнего потока, его завершает. onErrorContinue существует, но поддерживается не всеми операторами и ведёт себя неочевидно — его не рекомендуют.

Нужен ли WebFlux, если есть виртуальные потоки?

Для типичного CRUD поверх JDBC — обычно нет: MVC на виртуальных потоках проще и масштабируется сопоставимо. WebFlux оправдан для стриминга с противодавлением, шлюзов, богатой асинхронной композиции и полностью неблокирующего стека (тема 21).

Почему пустой Mono из контроллера даёт 200, а не 404?

Пустота — нормальное завершение без значения, а не ошибка. ResponseBodyResultHandler пишет пустое тело с 200. Для 404 — Mono<ResponseEntity> с defaultIfEmpty(notFound) или switchIfEmpty(Mono.error(new ResponseStatusException(NOT_FOUND))).

Как протестировать код с delay на час?

StepVerifier.withVirtualTime(() -> publisher) — издатель создаётся внутри Supplier, чтобы операторы времени взяли VirtualTimeScheduler; затем thenAwait(Duration.ofHours(1)) и проверки. Тест выполняется за миллисекунды.

Какой оператор параллельно вызывает сервис для каждого элемента, но выдаёт результаты в исходном порядке?

  • concatMap
  • switchMap
  • flatMapSequential

Где поставить contextWrite, чтобы контекст увидели все операторы обработки запроса?

  • Не важно
