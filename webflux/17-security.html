ТЕМА 17 · WEBFLUX

Реактивный Spring Security

Spring Security для WebFlux — отдельная реализация: вместо цепочки Servlet-фильтров — SecurityWebFilterChain из WebFilter-ов, вместо SecurityContextHolder — Reactor Context, все менеджеры и сервисы возвращают Mono. Разбираем конфигурацию, путь запроса через фильтры безопасности, JWT resource server, методную безопасность и особенности CSRF.

~1,5 часаSecurityWebFilterChainServerHttpSecurityReactiveAuthenticationManagerJWT@PreAuthorizeCSRFинтерактивтест

17.1Конфигурация

@Configuration
@EnableWebFluxSecurity
@EnableReactiveMethodSecurity
class SecurityConfig {
    @Bean
    SecurityWebFilterChain api(ServerHttpSecurity http) {
        return http
            .securityMatcher(pathMatchers("/api/**", "/admin/**", "/actuator/**"))
            .authorizeExchange(ex -> ex
                .pathMatchers("/actuator/health").permitAll()
                .pathMatchers("/admin/**").hasRole("ADMIN")
                .pathMatchers(HttpMethod.POST, "/api/orders").hasAuthority("SCOPE_orders:write")
                .anyExchange().authenticated())
            .oauth2ResourceServer(rs -> rs.jwt(jwt -> jwt.jwtAuthenticationConverter(rolesConverter())))
            .csrf(ServerHttpSecurity.CsrfSpec::disable)       // stateless API с Bearer-токенами
            .securityContextRepository(NoOpServerSecurityContextRepository.getInstance())   // без WebSession
            .build();
    }
}
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://auth.example.com/realms/shop   # ключи через JWKS, кэшируются

17.3Пользователь в коде

@GetMapping("/me")
Mono<Profile> me(@AuthenticationPrincipal Jwt jwt) {               // 1. аргумент метода
    return profiles.find(jwt.getSubject());
}

Mono<String> currentUser() {                                      // 2. в сервисе
    return ReactiveSecurityContextHolder.getContext()
        .map(SecurityContext::getAuthentication)
        .map(Authentication::getName)
        .switchIfEmpty(Mono.error(new AccessDeniedException("no auth")));
}

@PreAuthorize("hasRole('ADMIN') or #ownerId == authentication.name")   // 3. методная безопасность
Mono<Void> deleteOrder(String ownerId, long id) { ... }               // метод ОБЯЗАН возвращать Publisher
SecurityContext — в Context, а не в потоке SecurityContextHolder.getContext() в реактивном коде пуст. Контекст безопасности не дойдёт и до кода, выполняемого вне цепочки (subscribe() в другом месте, @Async, ручной executor). Для вызовов WebClient с токеном пользователя — ServerBearerExchangeFilterFunction, который берёт токен из Context.

17.4Логин, сессии и CSRF

Сессии

  • По умолчанию SecurityContext хранится в WebSession (WebSessionServerSecurityContextRepository) — для form login.
  • Сессии в памяти инстанса; для кластера — Spring Session (реактивный Redis).
  • Stateless API: NoOpServerSecurityContextRepository.
  • Пользователи: MapReactiveUserDetailsService или свой ReactiveUserDetailsService; пароли — PasswordEncoderFactories.createDelegatingPasswordEncoder().

CSRF

  • CsrfWebFilter проверяет токен у изменяющих запросов.
  • Токен — Mono<CsrfToken> в атрибутах exchange: пока на него никто не подписался, cookie не создаётся. Для SPA с CookieServerCsrfTokenRepository.withHttpOnlyFalse() нужен WebFilter, который подписывается на токен.
  • С 6.x по умолчанию — XorServerCsrfTokenRequestAttributeHandler (защита от BREACH).
  • Для чистого Bearer-API без cookie CSRF не нужен.
@Bean
WebFilter csrfCookieFilter() {
    return (ex, chain) -> {
        Mono<CsrfToken> token = ex.getAttribute(CsrfToken.class.getName());
        return (token != null ? token.then() : Mono.empty()).then(chain.filter(ex));
    };
}

17.5Самопроверка

Запрос с истёкшим JWT на permitAll-эндпоинт. Результат?

  • 200, токен игнорируется
  • 403
  • 401: невалидный токен отвергается при аутентификации
  • 500
Аутентификация выполняется до авторизации; невалидные учётные данные — ошибка.

Почему @PreAuthorize не работает на методе, возвращающем void, в WebFlux-приложении с @EnableReactiveMethodSecurity?

  • Реактивная методная безопасность требует Publisher (Mono/Flux) в качестве результата
  • Нужен @Secured
  • @PreAuthorize только для контроллеров
  • Работает всегда
Проверка встраивается в цепочку возвращаемого Mono.

Где хранится аутентификация во время обработки запроса?

  • SecurityContextHolder (ThreadLocal)
  • HttpServletRequest
  • Статическая карта по requestId
  • Reactor Context (Mono<SecurityContext>)
ReactorContextWebFilter кладёт её туда.

Аутентифицированный пользователь без нужной роли обращается к /admin. Статус?

  • 401
  • 403
  • 404
  • 302 на /login
401 — нет аутентификации, 403 — нет прав.
Как сделать два набора правил: JWT для /api и form login для /ui?

Объявить два бина SecurityWebFilterChain с разными securityMatcher и @Order: первый — pathMatchers("/api/**") с resource server и без сессии, второй — для остального с formLogin и CSRF. WebFilterChainProxy выбирает первую цепочку, чей matcher совпал.
