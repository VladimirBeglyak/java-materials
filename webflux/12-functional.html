Функциональные эндпоинты

Альтернатива аннотациям: маршруты описываются кодом — RouterFunction сопоставляет запрос с HandlerFunction, которая принимает ServerRequest и возвращает Mono<ServerResponse>. Никакой рефлексии и сканирования: маршрутизация явная, её легко тестировать и собирать из частей. Разбираем DSL, предикаты, вложенность, фильтры и порядок сопоставления.

12.1Модель

@FunctionalInterface
public interface HandlerFunction<T extends ServerResponse> {
    Mono<T> handle(ServerRequest request);
}
@FunctionalInterface
public interface RouterFunction<T extends ServerResponse> {
    Mono<HandlerFunction<T>> route(ServerRequest request);   // пустой Mono = «не мой запрос»
    default RouterFunction<T> and(RouterFunction<T> other) { ... }
    default RouterFunction<T> filter(HandlerFilterFunction<T, T> f) { ... }
}

12.2DSL маршрутов

@Configuration
class OrderRoutes {
    @Bean
    RouterFunction<ServerResponse> orderRouter(OrderHandler h) {
        return route()
            .path("/api/orders", b -> b
                .nest(accept(APPLICATION_JSON), json -> json
                    .GET("/{id}", h::get)
                    .GET("", queryParam("status", s -> true), h::byStatus)
                    .GET("", h::list))
                .POST("", contentType(APPLICATION_JSON), h::create))
            .GET("/health", req -> ok().bodyValue("UP"))
            .filter(this::auth)                       // HandlerFilterFunction на все маршруты выше
            .onError(OrderNotFound.class, (e, req) -> ServerResponse.notFound().build())
            .build();
    }
}

@Component
class OrderHandler {
    Mono<ServerResponse> get(ServerRequest req) {
        long id = Long.parseLong(req.pathVariable("id"));
        return service.find(id)
            .flatMap(o -> ok().contentType(APPLICATION_JSON).bodyValue(o))
            .switchIfEmpty(ServerResponse.notFound().build());
    }
    Mono<ServerResponse> create(ServerRequest req) {
        return req.bodyToMono(CreateOrder.class)
            .doOnNext(validator::validate)            // валидация — вручную
            .flatMap(service::create)
            .flatMap(o -> created(URI.create("/api/orders/" + o.id())).bodyValue(o));
    }
    Mono<ServerResponse> list(ServerRequest req) {
        return ok().contentType(APPLICATION_NDJSON).body(service.all(), Order.class);   // Flux тело
    }
}

12.4ServerRequest и ServerResponse

ServerRequest

  • pathVariable(name) → String (нет переменной — исключение), queryParam(name) → Optional
  • headers(), cookies(), attribute(name)
  • bodyToMono(T.class), bodyToFlux, body(BodyExtractors.toMultipartData())
  • principal(), session() — Mono
  • exchange() — доступ к ServerWebExchange

ServerResponse

  • ok(), created(uri), accepted(), noContent(), notFound(), badRequest(), status(code)
  • .bodyValue(obj) — готовый объект
  • .body(publisher, T.class) — Mono/Flux
  • .render("view", model) — шаблоны
  • ServerResponse.from(other), .headers(h -> ...), .cookie(...)
Mono<ServerResponse> auth(ServerRequest req, HandlerFunction<ServerResponse> next) {
    return req.headers().firstHeader("X-Api-Key") == null
        ? ServerResponse.status(UNAUTHORIZED).build()
        : next.handle(req);
}
// before/after — для простых модификаций
route().GET("/x", h::x)
       .before(req -> ServerRequest.from(req).header("X-Start", now()).build())
       .after((req, resp) -> { log.info("{} {}", req.path(), resp.statusCode()); return resp; })
       .build();

12.6Самопроверка

Что возвращает RouterFunction, если запрос ей не подходит?

  • 404
  • Пустой Mono
  • null
  • Исключение
Пустой Mono позволяет комбинировать маршрутизаторы через and().

Маршрут GET /api/orders объявлен до GET /api/orders с queryParam("status"). Что получит запрос ?status=NEW?

  • byStatus
  • Оба по очереди
  • 404
  • list — первый совпавший маршрут
Сопоставление идёт по порядку, специфичные маршруты должны быть раньше.

Как валидировать тело в HandlerFunction?

  • Явно вызвать Validator в цепочке и вернуть 400 при ошибках
  • @Valid на параметре
  • Автоматически
  • Только через WebFilter
Функциональный стиль не включает автоматический биндинг и валидацию.
Как совместить функциональные маршруты и @RestController в одном приложении?

Можно без ограничений: RouterFunctionMapping (order −1) и RequestMappingHandlerMapping (order 0) работают вместе. Функциональные маршруты проверяются первыми; если RouterFunction вернула пустой Mono, запрос уходит к аннотированным контроллерам. Конфликт одинаковых путей решается в пользу функциональных.
