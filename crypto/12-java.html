Криптография в Java (JCA)

JCA (Java Cryptography Architecture) — стандартный API для криптографии в JDK: Cipher для шифрования, MessageDigest для хэшей, Mac для HMAC, Signature для подписей, KeyStore для хранения ключей. Здесь — рабочие примеры на все изученные примитивы.

12.1Хэш: MessageDigest

MessageDigest md = MessageDigest.getInstance("SHA-256");
byte[] hash = md.digest("hello".getBytes(StandardCharsets.UTF_8));
System.out.println(HexFormat.of().formatHex(hash));   // 2cf24dba…
Не используйте getInstance("MD5"/"SHA-1") Для целостности и паролей — только SHA-256/SHA-3. Пароли — не MessageDigest вовсе, а argon2/bcrypt (тема 03).

12.2HMAC: Mac

SecretKeySpec key = new SecretKeySpec(keyBytes, "HmacSHA256");
Mac mac = Mac.getInstance("HmacSHA256");
mac.init(key);
byte[] tag = mac.doFinal("данные".getBytes(StandardCharsets.UTF_8));
// проверка: пересчитать на своей стороне и сравнить через MessageDigest.isEqual
boolean ok = MessageDigest.isEqual(tag, expectedTag);   // постоянное время!
Сравнивайте HMAC через MessageDigest.isEqual MessageDigest.isEqual сравнивает байты за постоянное время (защита от timing-атак). Обычный Arrays.equals выходит раньше при первом расхождении.

12.3Шифрование: Cipher

KeyGenerator kg = KeyGenerator.getInstance("AES");
kg.init(256);
SecretKey key = kg.generateKey();

byte[] nonce = new byte[12];
new SecureRandom().nextBytes(nonce);

Cipher enc = Cipher.getInstance("AES/GCM/NoPadding");
enc.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, nonce));
byte[] ciphertext = enc.doFinal("секрет".getBytes(StandardCharsets.UTF_8));

Cipher dec = Cipher.getInstance("AES/GCM/NoPadding");
dec.init(Cipher.DECRYPT_MODE, key, new GCMParameterSpec(128, nonce));
byte[] plain = dec.doFinal(ciphertext);
Чего избегать в Cipher Режим AES/ECB, AES/CBC без отдельного HMAC, повторный nonce, new SecureRandom(seed), хранение ключа в строковом виде. Используйте только AEAD (GCM) или ChaCha20-Poly1305.

12.4Подпись: Signature

KeyPairGenerator kpg = KeyPairGenerator.getInstance("EC");
kpg.initialize(256);
KeyPair pair = kpg.generateKeyPair();

Signature sign = Signature.getInstance("SHA256withECDSA");
sign.initSign(pair.getPrivate());
sign.update("данные".getBytes(StandardCharsets.UTF_8));
byte[] signature = sign.sign();

Signature verify = Signature.getInstance("SHA256withECDSA");
verify.initVerify(pair.getPublic());
verify.update("данные".getBytes(StandardCharsets.UTF_8));
boolean valid = verify.verify(signature);   // true

12.5KeyStore

// загрузить PKCS12-хранилище и достать ключ
KeyStore ks = KeyStore.getInstance("PKCS12");
try (InputStream in = Files.newInputStream(Path.of("keystore.p12"))) {
    ks.load(in, "password".toCharArray());
}
Key key = ks.getKey("alias", "password".toCharArray());   // закрытый ключ
Certificate cert = ks.getCertificate("alias");            // сертификат
Форматы и диалекты PKCS12 (.p12) — современный стандарт; JKS устарел. Для ключей в проде используйте KMS, а KeyStore — для локальных/TLS-ключей.

12.6Самопроверка

Какой класс JCA отвечает за симметричное шифрование?

  • Cipher
  • MessageDigest
  • Signature
  • KeyStore
Cipher — шифрование/расшифровка (AES-GCM и др.).

Почему HMAC-теги сравнивают через MessageDigest.isEqual?

  • Он сравнивает за постоянное время, не утекая через timing
  • Он быстрее
  • Он короче
  • Он поддерживает null
Постоянное время сравнения защищает от timing-атак, когда по задержке можно подобрать байты тега.

Какой режим шифрования выбрать в Java по умолчанию?

  • AES/ECB/PKCS5Padding
  • AES/CBC/PKCS5Padding
  • AES/GCM/NoPadding (AEAD)
  • DES/ECB
GCM даёт конфиденциальность и целостность; ECB/CBC без HMAC — антипаттерны.

Каким методом генерируют ключи в Java?

  • new Random().nextBytes
  • Math.random
  • System.currentTimeMillis
  • KeyGenerator или SecureRandom
KeyGenerator генерирует ключи криптографически безопасно; SecureRandom — для nonce/случайных байт.
Что делает GCMParameterSpec и зачем он нужен?

Передаёт в Cipher длину тега (обычно 128 бит) и nonce для режима GCM. Без корректного nonce GCM не работает; повтор nonce с тем же ключом недопустим.

Зачем нужен KeyStore и когда вместо него использовать KMS?

KeyStore хранит ключи и сертификаты локально (PKCS12) — удобно для TLS-ключей и локальной разработки. В проде с ротацией, аудитом и защитой ключей используют KMS/HSM.
