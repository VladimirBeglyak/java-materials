Управление ключами: KDF, обёртывание, KMS

Криптография сильна настолько, насколько защищены её ключи. Алгоритмы взламывают редко; ключи теряют и крадут постоянно. Эта тема — о том, как из пароля получить ключ, как защитить ключи другими ключами и как управлять ими в проде (KMS, ротация).

8.1KDF: из пароля — ключ

Пароли — плохой ключевой материал: короткие, человекочитаемые, низкой энтропии. KDF (Key Derivation Function) превращает пароль (+ соль) в стойкий ключ и специально делает это дорого.

KDFНазначение
PBKDF2из пароля в ключ, настраиваемое число итераций
scrypt / argon2то же, но с требованием памяти
HKDFразвернуть один секрет в несколько ключей (быстро)
$ echo -n "пароль" | openssl kdf -keylen 32 -kdfopt digest:SHA256 \
    -kdfopt pass:пароль -kdfopt salt:a1b2c3d4 -kdfopt iter:600000 PBKDF2
KDF против хэша пароля PBKDF2/argon2 используют и для хранения паролей (тема 03), и для вывода ключей из пароля. Отличие в задаче: в первом случае важна проверка, во втором — получение байтов ключа.

8.2Обёртывание ключей

Ключ шифруется другим ключом — обёртывание (key wrapping). Так ключ данных (data key) можно безопасно хранить рядом с зашифрованными данными: без мастер-ключа его не развернуть.

# data key — случайный AES-ключ для данных
# ключ обёртывания (KEK) — мастер-ключ
$ openssl enc -aes-256-gcm -K $KEK -iv $nonce -in data_key.bin -out data_key.wrapped

8.3Envelope encryption

Схема, используемая облачными KMS: данные шифруются ключом данных, а ключ данных — мастер-ключом, который живёт в KMS и не покидает его.

данныешифруются data key (AES-GCM)→ data keyоборачивается мастер-ключом KMS→ хранениешифротекст + обёрнутый data key

Плюсы: мастер-ключ не копируется, ротация дешёвая (меняется только обёрнутый data key), данные шифруются быстро симметрией.

8.4KMS, HSM и ротация

KMS

Сервис управления ключами (AWS KMS, GCP KMS, Vault): хранит мастер-ключи, выполняет шифрование/обёртывание по API, ведёт аудит, делает ротацию. Ключ не выходит наружу.

HSM

Аппаратный модуль безопасности: ключи физически не извлекаются, операции идут внутри устройства. Максимальная защита, выше стоимость.

Правила управления ключами Разделяйте ключи по назначению (данные, подпись, TLS); никогда не храните ключ в коде/репозитории; ротируйте ключи по расписанию; ведите учёт, где какой ключ используется; данные старого ключа — перешифровать или хранить старые версии ключа.

8.5Самопроверка

Зачем нужен KDF?

  • Превратить пароль (низкой энтропии) в стойкий ключ фиксированной длины
  • Сжать данные
  • Зашифровать файл
  • Сгенерировать соль
Пароль нельзя использовать как ключ напрямую; KDF выводит из него ключ и делает перебор дорогим.

Что такое envelope encryption?

  • Данные шифруются data key, а data key оборачивается мастер-ключом KMS
  • Двойное сжатие
  • Шифрование письма в конверте
  • Только подпись данных
Гибрид на уровне ключей: быстрая симметрия для данных + защита ключа в KMS.

Почему мастер-ключ KMS не покидает сервис?

  • Он слишком большой
  • Это замедлит систему
  • Чем меньше копий ключа, тем меньше поверхность атаки и проще аудит
  • Это требование скорости
KMS выполняет операции внутри себя и отдаёт только обёрнутые ключи — мастер-ключ не расползается по системам.

Где категорически нельзя хранить ключ?

  • В KMS
  • В HSM
  • В переменных окружения сервера
  • В коде/репозитории
Ключ в git-репозитории утекает навсегда вместе с историей. Используйте KMS/менеджер секретов.
Чем PBKDF2 отличается от HKDF?

PBKDF2 — медленный KDF из пароля (настраиваемые итерации, защита от перебора). HKDF — быстрый KDF, разворачивающий уже секретный материал (общий секрет из ECDH) в несколько независимых ключей.

Что даёт ротация ключей?

Ограничивает ущерб от компрометации ключа и объём данных, зашифрованных одним ключом. При ротации новые данные шифруются новым ключом; старые либо перешифровываются, либо для них сохраняются старые версии ключа.
