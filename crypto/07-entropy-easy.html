Случайность и ключи — простыми словами

Ключ — это просто большое случайное число. Его надёжность держится на одном: его невозможно угадать. Разберёмся, что такое «настоящая» случайность, почему обычный генератор случайных чисел для секретов не годится и где ещё в криптографии нужна случайность.

7.1Энтропия: насколько трудно угадать

Энтропия — мера непредсказуемости, её считают в битах. Подбросили монетку — 1 бит. Восемь монеток — 8 бит, 256 вариантов. Ключ AES-128 должен иметь все 128 бит энтропии — это 2¹²⁸ вариантов.

Но число вариантов «на бумаге» и реальная непредсказуемость — не одно и то же. Пароль из 8 символов вроде бы даёт огромное число вариантов, но если это «Пароль1!», его угадают первым же словарём. Ключ, полученный из времени запуска программы, вроде бы 128-битный, но времён запуска всего несколько миллионов — перебрать их можно за секунды.

Главная мысль Важна не длина ключа, а то, сколько вариантов реально пришлось бы перебрать. Источник случайности должен быть непредсказуемым.

7.2Фокусник и честный жребий

java.util.Random — фокусник

Тасует колоду по известной схеме. Числа выглядят случайными, но если подсмотреть пару из них, можно вычислить все следующие. Для игр и тестов — нормально, для секретов — опасно.

SecureRandom — честный жребий

Берёт непредсказуемость у операционной системы (шумы железа, времена прерываний) и перемешивает её криптографически стойко. По прошлым числам будущие не вычислить.

Правило простое: для ключей, токенов, паролей сброса, идентификаторов сессий, nonce — только SecureRandom. Никогда — Random, Math.random(), текущее время или хэш от имени пользователя.

Числа «похожи на случайные», но идут по формуле.

Свои токены злоумышленник видит законно.

У простого генератора внутреннее состояние небольшое — его восстанавливают по выходу.

С SecureRandom такая атака невозможна.

Главная мысль Всё, что должно быть секретным или неугадываемым, — только через криптографически стойкий генератор.

7.3Где ещё нужна случайность

  • Ключи — главное место, где нужна полная энтропия.
  • Соль для паролей — уникальная для каждого пользователя.
  • Nonce/IV для шифрования — должен не повторяться (глава 04).
  • Токены — сессии, ссылки сброса пароля, API-ключи.

Самому делать свою «случайность» не нужно: в Java достаточно одного объекта SecureRandom, создавать его на каждый вызов не обязательно.

Главная мысль Ключи, соль, nonce, токены — всё это берётся у стойкого генератора.

7.5Проверьте себя

Чем генерировать токен для сброса пароля?

  • java.util.Random
  • текущим временем
  • SecureRandom
  • хэшем от email
Остальные варианты предсказуемы.

Почему java.util.Random опасен для секретов?

  • он слишком медленный
  • по нескольким выданным числам можно вычислить следующие
  • он выдаёт только чётные числа
  • он не работает в Linux
Это формула с небольшим внутренним состоянием.

Ключ сделали из хэша текущего времени запуска. В чём проблема?

  • хэш слишком длинный
  • время меняется
  • проблемы нет
  • вариантов времени мало — их легко перебрать, хотя ключ выглядит длинным
Реальная энтропия равна числу возможных времён, а не длине хэша.

Что такое энтропия?

  • мера непредсказуемости — сколько вариантов пришлось бы перебрать
  • скорость шифрования
  • длина пароля в символах
  • тип ключа
Восемь честных монеток — 8 бит энтропии.

Что из этого НЕ требует случайности?

  • ключ
  • соль
  • сам алгоритм шифрования AES
  • nonce
Алгоритм открыт и известен всем — секретом является только ключ.
