Асимметричное шифрование — простыми словами

С одним общим ключом есть проблема: как передать его другу, если вас подслушивают? Асимметричное шифрование решает её парой ключей: один открытый — его можно раздать всем, другой закрытый — его знает только владелец. Разберёмся, как это работает и почему на практике его всегда сочетают с обычным шифрованием.

5.1Пара ключей: почтовый ящик с щелью

Представьте почтовый ящик с щелью. Бросить письмо в щель может любой прохожий. А открыть ящик и прочитать письма может только хозяин — у него ключ. Щель — это открытый ключ: его публикуют, раздают, вешают на сайт. Ключ от дверцы — закрытый: он никогда не покидает хозяина.

Математически ключи связаны: что заперто открытым, отпирается только закрытым. Но вычислить закрытый ключ по открытому практически невозможно. Так исчезает проблема «как передать секрет»: передавать нужно только открытый ключ, а его не жалко показать всем.

Главная мысль Открытый ключ — щель, доступная всем. Закрытый — ключ от ящика, только у владельца.

5.2RSA: секрет в разложении на множители

Перемножить два больших простых числа — легко, это делает калькулятор. А вот по результату найти, из каких двух чисел он получился, — невероятно трудно, если числа огромные (сотни цифр). На этой «улице с односторонним движением» построен RSA, один из первых асимметричных алгоритмов (1977).

Чтобы RSA был надёжным, ключи нужны длинные — от 2048 бит. Он медленный и неудобен для больших данных. И применять его надо с правильной «обёрткой» (дополнением), иначе появляются уязвимости.

Главная мысль RSA держится на том, что большое число трудно разложить на множители. Ключи длинные, работа медленная.

5.3Эллиптические кривые: короче и быстрее

ECC (криптография на эллиптических кривых) использует другую трудную задачу и даёт ту же надёжность с гораздо более короткими ключами: 256-битный ключ ECC примерно равен по силе 3072-битному RSA. Поэтому он быстрее и экономнее — его любят телефоны, TLS и мессенджеры.

Самое частое применение — ECDH: способ, которым двое договариваются об общем секрете, обменявшись только открытыми ключами. Подслушивающий видит обе посылки, но секрет вычислить не может. Подробно — в главе 09 на примере «смешивания красок».

Главная мысль ECC — та же идея пары ключей, но короче и быстрее. ECDH позволяет договориться о секрете на глазах у всех.

5.4Гибридная схема: щель для ключа, сундук для письма

Асимметричное шифрование в тысячи раз медленнее симметричного. Поэтому большие данные им не шифруют. Делают хитрее:

Отправляем большой файл другу
создаём случайный ключ для сундука (AES), одноразовыйкладём файл в сундук: AES-GCM — быстро, хоть гигабайтсам ключ сундука (32 байта) бросаем в щель друга:
шифруем открытым ключом другаотправляем: [запертый ключ] + [запертый файл]
друг: закрытым ключом достаёт ключ сундука → открывает файл

Случайный, только для этого файла.

Быстрое симметричное шифрование для объёма.

Медленное асимметричное — только для маленького ключа.

Так работают TLS, PGP, зашифрованная почта и многое другое.

Главная мысль Данные — быстрым симметричным шифром, ключ от него — медленным асимметричным. Лучшее из двух миров.

5.6Проверьте себя

Какой ключ можно публиковать?

  • закрытый
  • открытый
  • оба
  • никакой
Открытый — «щель», через которую любой может отправить вам секрет.

Почему большие файлы не шифруют напрямую RSA?

  • RSA не умеет шифровать
  • RSA ненадёжен
  • это очень медленно; шифруют AES, а RSA — только ключ
  • файлы станут больше
Это гибридная схема.

Чем ECC лучше RSA на практике?

  • та же надёжность при гораздо более коротких ключах и быстрее
  • ECC не нужен закрытый ключ
  • ECC — симметричный
  • ничем
256 бит ECC ≈ 3072 бита RSA.

На чём держится стойкость RSA?

  • на секретности алгоритма
  • на длине пароля
  • на скорости компьютера
  • на трудности разложения огромного числа на множители
Перемножить легко, разложить обратно — практически невозможно.

Что даёт ECDH?

  • подпись документа
  • общий секрет двух сторон, которые обменялись только открытыми ключами
  • хэш пароля
  • сжатие
Подслушивающий видит обмен, но секрет не вычислит.
