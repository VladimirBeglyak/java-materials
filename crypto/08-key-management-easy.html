8.1KDF: как из пароля сделать ключ

Шифру нужен ключ — ровно 32 случайных байта. А у человека есть пароль «Котик2024». Использовать пароль напрямую нельзя: он короткий и легко угадывается. Нужна функция выработки ключа (KDF) — «мясорубка», которая из пароля (или из другого секрета) делает ключ правильного размера.

  • Из пароля — медленные функции, как для хранения паролей (Argon2, PBKDF2, scrypt). Медленность защищает от перебора.
  • Из уже хорошего секрета (например, общего секрета после обмена ключами) — быстрая HKDF. Она умеет из одного секрета сделать несколько разных ключей: один для шифрования, другой для проверки.
Главная мысль Пароль — не ключ. Ключ из пароля делают медленной KDF, из хорошего секрета — HKDF.

8.2Обёртывание ключей: ключ в конверте

Иногда ключ нужно хранить или передавать. Делать это открыто нельзя. Ключ заворачивают — шифруют другим ключом. Как положить ключ от квартиры в конверт и запечатать его в сейфе: без кода сейфа конверт не открыть.

Ключ, который шифрует данные, называют DEK (ключ данных), а ключ, который шифрует другие ключи, — KEK (ключ ключей).

Главная мысль Ключи хранят в зашифрованном виде — «завёрнутыми» другим ключом.

8.3Конвертное шифрование (envelope)

Это главный рабочий приём в облаках и больших системах:

Шифруем файл клиента
создаём новый ключ данных (DEK) — только для этого файлашифруем файл ключом DEK (AES-GCM) — быстро, локальнопросим KMS: «заверни DEK главным ключом (KEK)»
главный ключ никогда не покидает KMSхраним рядом: [зашифрованный файл] + [завёрнутый DEK]
открытый DEK стираем из памятичтобы прочитать: просим KMS развернуть DEK → расшифровываем файл
KMS записывает в журнал, кто и когда просил

У каждого файла или записи — свой ключ.

Большие данные шифруются прямо в приложении — быстро.

В KMS уходят только 32 байта ключа, не сами данные.

Украли базу — получили мешанину и завёрнутые ключи, которые без KMS бесполезны.

Доступ к главному ключу можно ограничить правами и проверить по журналу.

Плюсы: главный ключ один и хорошо охраняется; ротация главного ключа не требует перешифровывать терабайты — достаточно перезавернуть маленькие DEK.

Главная мысль Данные — своим ключом, этот ключ — главным ключом в KMS. Конверт в сейфе.

8.4KMS, HSM и смена ключей

  • KMS — сервис управления ключами (AWS KMS, Google Cloud KMS, HashiCorp Vault). Как банковская ячейка: ключ хранится там, вы можете попросить им воспользоваться, но забрать его нельзя.
  • HSM — специальное устройство-сейф для ключей. Ключ рождается внутри и физически не может быть извлечён; при попытке вскрыть корпус устройство стирает ключи.
  • Ротация — регулярная смена ключей. Если старый ключ когда-то утёк, ущерб ограничен периодом его действия. Старые ключи хранят для расшифровки старых данных, а новые данные шифруют новым.
Главная мысль Главные ключи живут в KMS или HSM, а не в коде и не в конфиге. Ключи регулярно меняют.

8.6Проверьте себя

Можно ли использовать пароль пользователя напрямую как ключ AES?

  • да, если он длинный
  • нет: нужно пропустить его через медленную KDF с солью
  • да, всегда
  • только для коротких файлов
Пароль короткий и угадываемый, ключ должен быть случайным на вид и нужной длины.

В конвертном шифровании что уходит в KMS?

  • все данные
  • пароли пользователей
  • ничего
  • только маленький ключ данных — чтобы его завернуть или развернуть
Большие данные шифруются локально, в KMS — только 32 байта ключа.

Чем удобна ротация главного ключа при конвертном шифровании?

  • достаточно перезавернуть маленькие ключи данных, а не перешифровывать все данные
  • данные удаляются
  • ключ становится короче
  • ничем
Сами данные не трогаются.

Где лучше всего хранить главный ключ шифрования?

  • в коде программы
  • в файле настроек рядом с базой
  • в KMS или HSM
  • в переменной окружения разработчика
Ключ не покидает охраняемое хранилище, доступ к нему контролируется и журналируется.

Чем HSM отличается от обычного хранения ключа в файле?

  • HSM быстрее читает файлы
  • ключ рождается внутри устройства и не может быть из него извлечён
  • HSM — это просто флешка
  • ничем
Можно попросить HSM зашифровать или подписать, но не получить сам ключ.
