Симметричное шифрование: AES и режимы

Симметричное шифрование использует один ключ и для шифрования, и для расшифровки. Современный стандарт — AES. Но выбор алгоритма — меньшая часть дела: главные ошибки случаются в выборе режима и обращении с IV/nonce. Правило на всю жизнь: не ECB, и использовать аутентифицированный режим.

4.1Блочный шифр AES

AES шифрует данные блоками по 128 бит (16 байт) одним ключом длиной 128, 192 или 256 бит. Один и тот же ключ + один и тот же блок всегда дают один и тот же зашифрованный блок — поэтому сам по себе AES ничего не скрывает о структуре данных. Режим шифрования определяет, как из блоков собирается защита длинного сообщения.

4.2Режимы шифрования

РежимКак работаетВердикт
ECBкаждый блок шифруется независимо одним ключом❌ утекает структура: одинаковые блоки → одинаковый шифротекст
CBCкаждый блок XOR с предыдущим шифроблоком (+ IV)✅ конфиденциальность, но ❌ нет целостности, нужен padding
CTRшифруется счётчик, результат XOR с данными✅ быстрый, параллельный; нужен уникальный nonce
GCMCTR + аутентификационный тег (AEAD)✅✅ конфиденциальность + целостность — выбор по умолчанию
ECB — классическая ошибка В режиме ECB одинаковые 16-байтные блоки дают одинаковый шифротекст. Картинку, зашифрованную ECB, видно «сквозь» шифрование. Никогда не используйте ECB для данных с повторяющимися блоками.

4.3IV и nonce

Чтобы одинаковые сообщения шифровались по-разному, режимы используют IV (initialization vector) или nonce — случайное/уникальное значение, добавляемое к каждому шифрованию.

ПравилоРежимы
IV должен быть случайным, не секретным, уникальным на ключCBC
nonce должен быть уникальным на ключ (можно счётчик)CTR, GCM
Повтор nonce в GCM = катастрофа При повторном nonce с тем же ключом в GCM/CTR можно восстановить XOR двух сообщений и даже подделать тег. Поэтому nonce — либо случайный (96 бит), либо строго монотонный счётчик.

4.4Аутентифицированное шифрование (AEAD)

GCM не только шифрует, но и вычисляет тег аутентичности — короткую подпись всего сообщения и связанных данных (AAD). При расшифровке тег проверяется: если данные изменили, расшифровка завершится ошибкой. Это закрывает разрыв «конфиденциальность ≠ целостность» из темы 01.

# шифрование
$ echo -n "секретные данные" | openssl enc -aes-256-gcm \
    -K 000102...0f  -iv 000102...0b   # ключ 32 байта, nonce 12 байт
# …вывод: шифротекст + тег

# расшифровка (тег проверяется автоматически)
$ echo -n "…" | openssl enc -aes-256-gcm -d -K … -iv …
Выбор по умолчанию AES-256-GCM (или ChaCha20-Poly1305 на устройствах без аппаратного AES) покрывает и конфиденциальность, и целостность. CBC без отдельного HMAC — антипаттерн.

4.5Самопроверка

Чем плох режим ECB?

  • Он медленный
  • Одинаковые блоки дают одинаковый шифротекст — утекает структура данных
  • Он не поддерживает длинные ключи
  • Он необратим
ECB шифрует каждый блок независимо, поэтому повторяющиеся блоки видны в шифротексте.

Что даёт режим GCM по сравнению с CBC?

  • Конфиденциальность + целостность (аутентификационный тег) в одном режиме
  • Только сжатие
  • Только ускорение
  • Ничего
GCM — AEAD: CTR-шифрование плюс тег целостности. CBC целостности не даёт.

Почему нельзя повторно использовать nonce в GCM с тем же ключом?

  • Он перестанет быть случайным
  • Это запрещено стандартом без причины
  • Повтор nonce позволяет восстановить XOR сообщений и подделать тег
  • Nonce вообще не нужен
Повтор nonce в CTR/GCM катастрофически ослабляет шифр — это ошибка уровня «сломали всё».

Должен ли IV быть секретным?

  • Да, всегда
  • Да, в CBC
  • Да, в GCM
  • Нет — IV должен быть уникальным/случайным, но хранится вместе с шифротекстом
Секретность обеспечивает ключ; IV лишь разнообразит шифрование. Он передаётся открыто.
Почему AES сам по себе недостаточен для шифрования длинных данных?

AES — блочный шифр: шифрует только 16-байтные блоки. Режим (CBC/CTR/GCM) определяет, как связать блоки в защищённый поток, добавить IV/nonce и (для GCM) целостность.

Что такое AEAD и зачем он нужен?

Authenticated Encryption with Associated Data — шифрование, которое также проверяет целостность (и связанные открытые данные). Без него атакующий может изменить шифротекст незаметно. GCM и ChaCha20-Poly1305 — AEAD.
