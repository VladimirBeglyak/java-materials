Криптография в Java — простыми словами

В Java есть готовая «мастерская» с проверенными инструментами: отпечатки, печати, замки, сейф для ключей. Главное правило — не изобретать свои замки, а правильно пользоваться готовыми. Здесь — какой инструмент для какой задачи и где обычно ошибаются, без кода.

12.1Хэш: MessageDigest

MessageDigest — инструмент для отпечатков (глава 02). Вы называете алгоритм — «SHA-256» — и скармливаете ему данные, он возвращает хэш. Годится для проверки целостности файлов и для дедупликации. Не годится для паролей — для них нужны медленные функции (глава 03), их берут из отдельных библиотек.

Главная мысль MessageDigest — отпечатки. Алгоритм — SHA-256 или новее, не MD5 и не SHA-1. Для паролей — не он.

В полной главе: 12.1 Хэш: MessageDigest

12.2HMAC: Mac

Mac — инструмент для отпечатков с секретом (HMAC, глава 02). Нужен ключ и алгоритм — например, «HmacSHA256». Подходит для подписи вебхуков, токенов, ссылок. Важная деталь: проверяя пришедший HMAC, сравнивайте его за постоянное время (в Java для этого есть MessageDigest.isEqual), а не обычным сравнением строк — иначе время ответа выдаст секрет (глава 13).

Главная мысль Mac — HMAC. Проверяйте результат сравнением за постоянное время.

В полной главе: 12.2 HMAC: Mac

12.3Шифрование: Cipher

Cipher — главный инструмент шифрования. При создании ему передают строку из трёх частей: алгоритм / режим / дополнение. И вот здесь главная ловушка.

просим просто «AES»

Короткое имя «AES» подставляет опасный режим по умолчанию.

Всегда указывайте режим явно.

Главная мысль Всегда «AES/GCM/NoPadding», новый nonce каждый раз, ключ — не из кода. Никогда просто «AES».

В полной главе: 12.3 Шифрование: Cipher

12.4Подпись: Signature

Signature — инструмент для цифровых подписей (глава 06). Закрытым ключом подписываем, открытым проверяем. Алгоритмы — например, «SHA256withECDSA», «Ed25519» или RSA с современным дополнением (PSS). Пару ключей создаёт KeyPairGenerator.

Главная мысль Signature — подписать закрытым, проверить открытым. Ключи — от KeyPairGenerator или из хранилища.

В полной главе: 12.4 Подпись: Signature

12.5KeyStore: шкатулка для ключей

KeyStore — защищённая паролем шкатулка для ключей и сертификатов, обычно файл в формате PKCS12. В ней хранятся, например, ключ и сертификат вашего сервера для TLS, а также список сертификатов, которым вы доверяете (truststore). Пароль от шкатулки не кладите в код — его берут из секрет-хранилища или переменных окружения на сервере. Для самых важных ключей лучше KMS или HSM (глава 08).

Главная мысль KeyStore — шкатулка для ключей и сертификатов. Пароль к ней — тоже секрет.

В полной главе: 12.5 KeyStore

12.7Проверьте себя

Что опасного в том, чтобы попросить у Cipher просто «AES»?

  • это не работает
  • Java подставит режим по умолчанию — ECB, который выдаёт узоры
  • это слишком медленно
  • ничего
Всегда указывайте режим явно: «AES/GCM/NoPadding».

Каким инструментом проверять подпись вебхука по общему секрету?

  • Cipher
  • Signature
  • KeyStore
  • Mac (HMAC)
Общий секрет + отпечаток = HMAC.

Как сравнивать полученный и вычисленный HMAC?

  • сравнением за постоянное время (MessageDigest.isEqual)
  • обычным equals строк
  • по длине
  • по первому символу
Обычное сравнение останавливается на первом отличии, и время выдаёт секрет.

Подходит ли MessageDigest с SHA-256 для хранения паролей?

  • да
  • да, с солью
  • нет: нужен специально медленный алгоритм вроде Argon2id или bcrypt
  • да, если пароль длинный
SHA-256 слишком быстрый для паролей.

Что хранится в KeyStore?

  • пароли пользователей
  • ключи и сертификаты, защищённые паролем шкатулки
  • логи
  • зашифрованные данные
Например, ключ и сертификат сервера для TLS.
