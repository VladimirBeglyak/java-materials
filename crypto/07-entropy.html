Энтропия и генерация ключей

Ключи и nonce должны быть непредсказуемыми. Вся криптография рушится, если «случайные» значения на самом деле предсказуемы: если злоумышленник угадает ключ или nonce, шифрование бесполезно. Поэтому генерация случайности — фундамент, и здесь нельзя экономить на качестве источника.

7.1Что такое энтропия

Энтропия — мера непредсказуемости. Криптографический генератор берёт энтропию из непредсказуемых физических источников (тайминги устройств, шум) и «собирает» из неё случайные байты. Чем больше энтропии, тем больше вариантов должен перебрать атакующий.

7.2SecureRandom против java.util.Random

java.util.Random — псевдослучайный генератор (LCG), который полностью определяется начальным seed. Зная seed (например, время запуска), атакующий воспроизводит всю последовательность. SecureRandom черпает энтропию из ОС и не предсказуем.

// SecureRandom для ключей и nonce
SecureRandom random = new SecureRandom();        // не задавайте seed вручную!
byte[] key = new byte[32];                        // 256 бит для AES-256
random.nextBytes(key);

// НЕ для ключей:
// Random r = new Random(42);  → последовательность воспроизводима
Не засевайте SecureRandom вручную new SecureRandom(seedBytes) или повторное использование одного и того же seed делает генератор детерминированным. Дайте SecureRandom взять энтропию из ОС самому.

7.3Nonce и случайность

Для GCM nonce должен быть уникальным, для CBC IV — случайным. Оба требования удовлетворяются генерацией через SecureRandom нужной длины (для GCM обычно 96 бит / 12 байт).

byte[] nonce = new byte[12];                       // 96 бит для GCM
new SecureRandom().nextBytes(nonce);               // случайный nonce
// или строгий монотонный счётчик, если гарантирована уникальность

7.4Самопроверка

Почему java.util.Random нельзя использовать для ключей?

  • Он медленный
  • Он предсказуем: зная seed, можно воспроизвести всю последовательность
  • Он возвращает только int
  • Он не входит в JDK
Random — детерминированный LCG. Для ключей нужна криптографическая случайность SecureRandom.

Откуда SecureRandom берёт случайность?

  • Из непредсказуемых источников энтропии ОС
  • Из текущего времени
  • Из фиксированного seed
  • Из java.util.Random
SecureRandom опирается на ОС-источник энтропии (например, /dev/urandom, RDRAND), не предсказуемый извне.

Можно ли задавать SecureRandom свой фиксированный seed?

  • Да, это стандартная практика
  • Да, если seed длинный
  • Нет — это делает генератор детерминированным и предсказуемым
  • Только в тестах можно
Фиксированный seed воспроизводит последовательность — атакующий сможет её повторить. (В тестах — допустимо, но не в проде.)

Какой длины nonce обычно используют для AES-GCM?

  • 8 бит
  • 32 бита
  • 64 бита
  • 96 бит (12 байт)
12 байт — рекомендуемая длина nonce для GCM; главное требование — уникальность на ключ.
Что такое энтропия в контексте криптографии?

Мера непредсказуемости. Криптографический генератор собирает энтропию из физических источников и превращает её в случайные байты для ключей и nonce. Без энтропии нет безопасности.

Чем требования к IV (CBC) и nonce (GCM) различаются?

IV в CBC должен быть случайным и непредсказуемым; nonce в GCM — строго уникальным на ключ (случайный или счётчик), но не обязан быть секретным. Повтор nonce в GCM катастрофичен.
