Блокирующие очереди изнутри

BlockingQueue — основной способ передать данные между потоками: производитель кладёт, потребитель забирает, а очередь сама усыпляет того, кому нечего делать. Семь реализаций устроены очень по-разному: одна блокировка и массив, две блокировки и связный список, куча, очередь с задержками, передача «из рук в руки». Разберём каждую, матрицу методов (бросить, вернуть, ждать, ждать с таймаутом) и почему LinkedBlockingQueue даёт производителям и потребителям работать параллельно.

20.1Четыре формы API

Что сделает метод?

null-элементы запрещены во всех реализациях: poll() возвращает null как признак «пусто». drainTo(collection, max) забирает пачку элементов за один захват блокировки — эффективно для батч-обработки.

20.4Паттерны

static final Event POISON = new Event("STOP");
// потребитель
List<Event> batch = new ArrayList<>(500);
while (true) {
    Event first = queue.take();                     // ждём хотя бы один
    if (first == POISON) break;
    batch.add(first);
    queue.drainTo(batch, 499);                      // плюс всё, что уже накопилось — одним захватом
    if (batch.remove(POISON)) { flush(batch); break; }
    flush(batch); batch.clear();
}
// остановка: queue.put(POISON) — по одной «таблетке» на каждого потребителя; либо interrupt()
Ограничивайте ёмкость Неограниченная очередь между быстрым производителем и медленным потребителем — это отложенный OutOfMemoryError. Ограниченная очередь с put даёт противодавление, с offer(timeout) — контролируемый отказ.

20.5Самопроверка

Почему LinkedBlockingQueue может обслуживать put и take параллельно?

  • Она lock-free
  • У головы и хвоста свои блокировки (takeLock и putLock), счётчик — атомарный
  • Она копирует элементы
  • Она не блокирует
У ArrayBlockingQueue одна блокировка.

Какая ёмкость у new LinkedBlockingQueue<>()?

  • 16
  • 0
  • 1024
  • Integer.MAX_VALUE — фактически без ограничения
Задавайте ёмкость явно.

Что делает SynchronousQueue.put(x)?

  • Ждёт, пока другой поток не заберёт x вызовом take
  • Кладёт в буфер на один элемент
  • Сразу возвращает false
  • Отправляет x всем потребителям
Ёмкость ноль — прямая передача.

Для чего DelayQueue?

  • Для очереди с приоритетом по важности
  • Для медленных потребителей
  • Элементы становятся доступны take только после истечения их задержки — повторы с паузой, истечение кэша, тайм-ауты
  • Для логирования
Элементы реализуют Delayed.getDelay.
ArrayBlockingQueue или LinkedBlockingQueue?

ABQ — когда нужна жёсткая ограниченная ёмкость, предсказуемая память и отсутствие мусора на элемент, нагрузка умеренная (одна блокировка не узкое место). LBQ — когда много производителей и потребителей одновременно, важна пропускная способность (две блокировки), допустим мусор от узлов; всегда с явной ёмкостью. Для максимальной пропускной способности без ожидания — неблокирующие очереди (ConcurrentLinkedQueue, LinkedTransferQueue) или специализированные (JCTools, Disruptor).
