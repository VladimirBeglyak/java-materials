CyclicBarrier, Phaser, Exchanger

Синхронизаторы для вычислений по фазам: потоки делают свою часть работы и ждут остальных перед следующим шагом. CyclicBarrier — фиксированная группа и многократное использование, с «поломкой» барьера при сбое одного участника. Phaser — динамическое число участников, номера фаз и иерархия для тысяч потоков. Exchanger — обмен данными между двумя потоками. Симуляторы барьера и фазера — внутри.

14.1CyclicBarrier

Внутри — не AQS, а ReentrantLock, одна Condition trip, счётчик оставшихся участников и объект поколения (Generation) с флагом broken. Последний пришедший выполняет barrierAction (в своём потоке), будит всех и начинает новое поколение. Если кто-то из ожидающих прерван или вышел по таймауту, барьер «ломается»: все остальные получают BrokenBarrierException, а барьер нужно сбросить reset().

Состояние фазера упаковано в один long: номер фазы, число участников и число не пришедших (поэтому до 65 535 участников на фазер). Для большего числа или снижения конкуренции фазеры объединяют в дерево (new Phaser(parent)): дочерний фазер регистрируется в родителе как один участник.

14.3Exchanger

Exchanger<ByteBuffer> ex = new Exchanger<>();
// поток-заполнитель
ByteBuffer buf = emptyBuf;
while (running) { fill(buf); buf = ex.exchange(buf); }      // отдаёт полный, получает пустой
// поток-потребитель
ByteBuffer cur = fullBuf;
while (running) { cur = ex.exchange(cur); drain(cur); }     // отдаёт пустой, получает полный

Первый пришедший ждёт второго; при высокой конкуренции используется «арена» слотов, чтобы пары встречались в разных ячейках. Применяется редко: конвейеры с двойной буферизацией, генетические алгоритмы.

14.5Самопроверка

В каком потоке выполняется barrierAction у CyclicBarrier?

  • В отдельном служебном потоке
  • В потоке, пришедшем к барьеру последним
  • В первом пришедшем
  • В главном потоке
Остальные ждут, пока действие завершится.

Что произойдёт с другими участниками, если один из ожидающих на CyclicBarrier прерван?

  • Ничего, барьер подождёт замену
  • Барьер уменьшит parties
  • Они будут ждать вечно
  • Они получат BrokenBarrierException; барьер сломан до reset()
Поломка распространяется, чтобы никто не завис.

Чем Phaser отличается от CyclicBarrier?

  • Участников можно регистрировать и снимать динамически; есть номера фаз, неучаствующее ожидание и иерархия
  • Phaser одноразовый
  • Phaser не блокирует потоки
  • Ничем
Phaser — обобщение барьера и защёлки.
Задача: N рабочих потоков вычисляют итерацию симуляции, после каждой итерации нужно собрать результаты и проверить сходимость. Что использовать?

CyclicBarrier(N, action) — action в последнем пришедшем потоке объединяет частичные результаты и выставляет флаг сходимости; потоки после await проверяют флаг и продолжают или выходят. Если число рабочих меняется (динамическое разбиение) или нужно ограниченное число фаз — Phaser с onAdvance, возвращающим true при сходимости. Обязательно обработать BrokenBarrierException и таймауты.
