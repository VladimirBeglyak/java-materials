ScheduledThreadPoolExecutor

Планировщик задач в JDK — это ThreadPoolExecutor с особой очередью: двоичной кучей задач, упорядоченной по времени запуска. Разбираем, чем scheduleAtFixedRate отличается от scheduleWithFixedDelay, когда задача длиннее периода (симулятор временной шкалы), почему одно исключение навсегда останавливает периодическую задачу без единой строчки в логе, и почему maximumPoolSize здесь ничего не значит.

16.1Устройство

  • Очередь — DelayedWorkQueue: двоичная куча (как PriorityQueue) ScheduledFutureTask по времени запуска; при равенстве — по порядковому номеру отправки (FIFO).
  • Поток берёт задачу из головы кучи, только когда её время наступило: один поток-«лидер» спит ровно до времени головы (awaitNanos), остальные ждут без таймаута (паттерн Leader-Follower).
  • Периодическая задача после выполнения вычисляет следующее время и снова кладёт себя в очередь — одновременно две копии одной задачи не выполняются никогда.
  • Очередь неограниченная, поэтому пул никогда не растёт сверх corePoolSize: maximumPoolSize не используется, allowCoreThreadTimeOut — осторожно.

16.3Практика

ScheduledThreadPoolExecutor ses = new ScheduledThreadPoolExecutor(2, Thread.ofPlatform().name("sched-", 0).factory());
ses.setRemoveOnCancelPolicy(true);           // отменённые задачи сразу удаляются из очереди (иначе висят до своего времени)

ScheduledFuture<?> f = ses.scheduleWithFixedDelay(() -> {
    try { refreshCache(); }
    catch (Throwable t) { log.error("refresh failed", t); }   // иначе первое исключение молча остановит расписание
}, 0, 30, TimeUnit.SECONDS);

f.cancel(false);                             // остановить (false — не прерывать текущее выполнение)
ses.schedule(() -> sendReminder(id), 15, TimeUnit.MINUTES);   // однократно с задержкой

16.4Самопроверка

Периодическая задача бросила исключение. Что дальше?

  • Она запустится по расписанию снова
  • Последующие запуски отменены; исключение сохранено в ScheduledFuture
  • Пул остановится
  • Исключение напечатается в лог
Самая частая причина «перестал работать фоновый джоб».

Задача с fixed rate 100 мс выполняется 250 мс. Будут ли параллельные выполнения?

  • Да, три параллельно
  • Да, два
  • Нет: следующее выполнение начнётся сразу после окончания предыдущего
  • Задача будет отменена
Копия задачи перепланируется только после завершения.

Зачем setMaximumPoolSize у ScheduledThreadPoolExecutor?

  • Ни зачем: очередь неограниченная, пул не растёт сверх core
  • Ограничивает число задач
  • Задаёт число периодических задач
  • Ограничивает очередь
Задавайте corePoolSize.
Как устроено ожидание в DelayedWorkQueue без активного опроса?

Leader-Follower: если голова кучи ещё не готова, первый поток становится лидером и спит awaitNanos(delay головы); остальные ждут на условии без таймаута. Лидер просыпается вовремя, забирает задачу и будит следующего, который станет новым лидером. При добавлении задачи с более ранним временем, чем голова, лидер сбрасывается и все ожидающие пересчитывают ожидание.
