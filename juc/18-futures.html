Future, FutureTask, CompletionService

Future — квитанция на результат, который вычисляется в другом потоке. Под ней почти всегда FutureTask с конечным автоматом из семи состояний — разберём его переходы в симуляторе: что делает cancel(true) с выполняющейся задачей, что вернёт get(). Затем — как собирать результаты нескольких задач: invokeAll, invokeAny и CompletionService, отдающий результаты в порядке готовности.

18.3Результаты нескольких задач

Три запроса к сервисам: 300, 1200 и 600 мс
CompletionService<Quote> cs = new ExecutorCompletionService<>(executor);
providers.forEach(p -> cs.submit(() -> p.quote(request)));
for (int i = 0; i < providers.size(); i++) {
    Future<Quote> f = cs.poll(2, TimeUnit.SECONDS);    // следующий готовый
    if (f == null) break;                              // общий таймаут
    try { show(f.get()); } catch (ExecutionException e) { log.warn("provider failed", e.getCause()); }
}

18.4Самопроверка

Что делает cancel(true) с уже выполняющейся задачей?

  • Немедленно останавливает поток
  • Переводит Future в отменённое состояние и прерывает поток-исполнитель; остановится ли код, зависит от его реакции на прерывание
  • Ничего
  • Ждёт завершения
Результат в любом случае будет отброшен.

Как получить исходное исключение задачи из get()?

  • Оно и бросается
  • Через isDone
  • Оно теряется
  • ExecutionException.getCause()
Не логируйте только ExecutionException без причины.

Чем полезен ExecutorCompletionService?

  • Отдаёт завершённые задачи в порядке готовности
  • Отменяет медленные задачи
  • Выполняет задачи последовательно
  • Повторяет упавшие задачи
Внутри — BlockingQueue завершённых Future.
Почему get(timeout) не освобождает ресурсы, и как правильно ограничить время задачи?

TimeoutException означает только, что ожидающий перестал ждать: задача продолжает работать и занимать поток. Нужно явно вызвать future.cancel(true) и писать задачу так, чтобы она реагировала на прерывание (проверяла флаг, использовала прерываемые операции), плюс таймауты на уровне I/O (сокеты, HTTP-клиент, JDBC). В CompletableFuture — orTimeout + отмена, в структурной конкурентности — закрытие области отменяет подзадачи.
