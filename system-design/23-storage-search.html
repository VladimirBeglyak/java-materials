Файлы, CDN и полнотекстовый поиск

Две задачи, с которыми реляционная база справляется плохо: хранить большие двоичные объекты и искать по тексту. Для первой есть объектные хранилища и CDN, для второй — поисковые движки на инвертированном индексе. Оба — производные или вспомогательные хранилища рядом с основной базой, и главный вопрос проектирования — как держать их согласованными с источником истины.

Клиент сообщает, что хочет загрузить

Сервис проверяет права, квоту, тип и размер — до того, как байты куда-либо пошли.

Сервис выдаёт presigned URL

В базе создаётся запись uploads(u-91, owner, status = PENDING). Ссылка подписана ключом сервиса: разрешает один PUT с заданным ключом, типом и максимальным размером, действует 5 минут. Секреты хранилища клиенту не передаются.

Клиент грузит файл прямо в хранилище

Мегабайты не проходят через серверы приложения: те не тратят память, соединения и трафик. Для больших файлов — multipart: части по 5–100 МБ загружаются параллельно и докачиваются по отдельности при обрыве.

Хранилище сообщает о новом объекте

Событие попадает в очередь. Нельзя полагаться на то, что клиент сам сообщит об окончании загрузки: он может закрыть вкладку.

Асинхронная обработка

Воркеры проверяют, что это действительно изображение (не доверяя расширению и Content-Type), удаляют метаданные с геопозицией, создают уменьшенные копии. Операция идемпотентна: повторная доставка события даст те же ключи.

Запись в базе обновлена

Только теперь файл виден в приложении. «Сироты» — объекты, для которых запись так и осталась PENDING, — удаляет правило жизненного цикла по префиксу raw/.

Чтение через CDN

Публичные файлы — через CDN с долгим кэшем (имя содержит идентификатор версии, поэтому содержимое по адресу не меняется). Приватные — по подписанным ссылкам на чтение с коротким сроком или через подписанные cookie CDN.

23.2CDN

Как работает

Пользователь попадает на ближайший узел (anycast или GeoDNS). Узел отдаёт объект из своего кэша или запрашивает у источника (origin), сохраняет согласно Cache-Control и отдаёт следующим. TLS-рукопожатие — с ближним узлом.

Инвалидация

Очистка кэша по всему миру медленная и платная. Надёжнее версионировать адреса: app.3f9a1c.js, /img/u-91/v2/800.webp с Cache-Control: immutable. Меняется содержимое — меняется URL.

Что ещё делает CDN

Защита от DDoS, WAF, сжатие, преобразование изображений на лету, кэширование API-ответов на секунды, вычисления на границе (edge functions).

Риски

Закэшированный персональный ответ, отданный другому пользователю (нужны private/no-store и корректный Vary); зависимость от одного провайдера; «холодный» кэш после очистки бьёт по источнику.

23.3Полнотекстовый поиск: инвертированный индекс

Запрос WHERE description LIKE '%чехол%' заставляет базу читать каждую строку. Поисковый движок заранее строит обратное отображение: слово → список документов, где оно встречается.

Песочница: постройте индекс и выполните запрос

Попробуйте: переключите анализатор на «только нижний регистр» — «Красная сумка» перестанет находиться по слову «красный». Смените оператор на AND. Добавьте документ и посмотрите, как изменятся оценки: редкое слово весит больше частого (IDF), а совпадение в коротком документе ценнее, чем в длинном.

ЭтапЧто происходит
Анализ текстаразбиение на токены → нижний регистр → удаление стоп-слов → приведение к основе (стемминг, лемматизация) → синонимы. Один и тот же анализатор применяется к документам и к запросу
Индексациядля каждого термина — отсортированный список документов с частотами и позициями (позиции нужны для поиска фраз)
Поискнайти списки терминов запроса → пересечь или объединить → оценить релевантность (BM25: частота термина в документе, редкость термина, длина документа) → вернуть первые N
Сегментыиндекс состоит из неизменяемых сегментов; новые документы попадают в новый сегмент (виден после refresh, раз в секунду — «почти реальное время»), сегменты сливаются фоном; удаление — пометка

23.4Синхронизация поискового индекса с базой

СпособКакОценка
Двойная записьсервис пишет в базу и сразу в индексплохо: при сбое между двумя записями хранилища расходятся навсегда и незаметно
Outbox + потребительсобытие в той же транзакции, отдельный процесс индексируетнадёжно; индекс отстаёт на секунды
CDC (Debezium)чтение журнала изменений базы → Kafka → индексаторнадёжно и без изменений в коде сервиса; ловит и правки «в обход» приложения
Периодическая переиндексацияполный или по метке изменениястраховка: исправляет любые расхождения; должна быть всегда
Индекс — производные данные Его всегда можно и нужно уметь перестроить с нуля: смена анализатора или схемы требует полной переиндексации. Приём: строить новый индекс рядом и атомарно переключать псевдоним (alias). Поиск возвращает идентификаторы, а актуальные цена и наличие берутся из основной базы — отставший индекс не должен показывать неверную цену.

23.5Самопроверка

Почему файлы пользователей не хранят в столбцах реляционной базы?

  • Базы не поддерживают двоичные данные
  • Это запрещено стандартом SQL
  • Они раздувают базу, её кэш, репликацию и резервные копии; объектное хранилище дешевле, масштабируется без ограничений и раздаёт напрямую через CDN
  • Файлы нельзя индексировать
В базе хранят ключ объекта и метаданные.

Зачем нужна подписанная (presigned) ссылка для загрузки?

  • Чтобы сжать файл
  • Чтобы клиент мог загрузить файл прямо в хранилище с ограниченными правами и сроком, минуя серверы приложения и не получая секретов
  • Чтобы ускорить CDN
  • Для шифрования файла
Сервис сохраняет контроль (права, размер, тип), не пропуская байты через себя.

Что хранит инвертированный индекс?

  • Для каждого термина — список документов, в которых он встречается
  • Для каждого документа — его полный текст
  • Хэши документов
  • B-дерево по первичному ключу
Поиск по слову превращается из просмотра всех документов в чтение одного готового списка.

Как обновить закэшированный в CDN файл стилей без ожидания и ручной очистки?

  • Уменьшить TTL до нуля
  • Отключить CDN
  • Перезапустить сервис
  • Версионировать имя файла (хэш содержимого в имени): новая версия — новый URL
Неизменяемые адреса позволяют кэшировать «навсегда» и обновлять мгновенно.
Опишите загрузку и раздачу пользовательских изображений.

Клиент запрашивает у сервиса подписанную ссылку → загружает напрямую в объектное хранилище (multipart для больших) → событие в очередь → воркеры проверяют файл и создают производные → статус в базе → раздача через CDN по версионированным или подписанным адресам; сироты удаляет правило жизненного цикла.

Как держать поисковый индекс согласованным с базой?

Не двойной записью, а потоком изменений: outbox или CDC → очередь → идемпотентный индексатор; плюс периодическая сверка и возможность полной переиндексации с переключением псевдонима. Критичные поля (цена, наличие) подтягивать из основной базы при показе.
