RabbitMQ в Spring (Spring AMQP)

Spring AMQP прячет детали протокола за RabbitTemplate (отправка) и @RabbitListener (приём). Вместо ручных каналов и ack вы описываете очереди декларативно и работаете с объектами через конвертеры. Но гарантии доставки всё равно зависят от того, как настроены подтверждения и обработка ошибок.

8.1Конфигурация и декларация

@Configuration
class RabbitConfig {
    static final String EXCHANGE = "orders.exchange";
    static final String QUEUE = "orders.queue";

    @Bean DirectExchange exchange() { return new DirectExchange(EXCHANGE); }
    @Bean Queue queue() { return QueueBuilder.durable(QUEUE)
            .withArgument("x-dead-letter-exchange", "")
            .withArgument("x-dead-letter-routing-key", "orders.dead").build(); }
    @Bean Binding binding(Queue queue, DirectExchange exchange) {
        return BindingBuilder.bind(queue).to(exchange).with("orders.created");
    }
}
spring:

      simple:

        prefetch: 10

8.2RabbitTemplate: отправка

@Service
class OrderEvents {
    private final RabbitTemplate rabbit;

    OrderEvents(RabbitTemplate rabbit) { this.rabbit = rabbit; }

    void publish(OrderCreated event) {
        rabbit.convertAndSend(EXCHANGE, "orders.created", event);
    }
}
convertAndSend Метод сериализует объект конвертером (по умолчанию Java-сериализация, в проде — JSON через Jackson2JsonMessageConverter) и публикует в exchange с routing key.

8.3@RabbitListener: приём

@Component
class OrderHandler {
    @RabbitListener(queues = QUEUE)
    void handle(OrderCreated event, Channel channel,
                @Header(AmqpHeaders.DELIVERY_TAG) long tag) throws IOException {
        try {
            process(event);
            channel.basicAck(tag, false);            // успех — подтвердить
        } catch (RetryableException e) {
            channel.basicNack(tag, false, false);    // в DLX (без requeue)
        }
    }
}
acknowledge-mode: auto против manual auto — Spring сам подтверждает после успешного возврата метода и отклоняет при исключении (проще). manual — полный контроль (как в примере). Для большинства задач auto достаточно, но нужно понимать поведение при исключениях.

8.4JSON-конвертер

@Bean
Jackson2JsonMessageConverter converter() {
    return new Jackson2JsonMessageConverter();   // JSON вместо Java-сериализации
}

@Bean
RabbitTemplate rabbitTemplate(ConnectionFactory cf) {
    RabbitTemplate t = new RabbitTemplate(cf);
    t.setMessageConverter(converter());
    return t;
}
Не оставляйте Java-сериализацию Default-конвертер Spring AMQP — Java-сериализация: несовместима между версиями, небезопасна. Всегда настраивайте JSON-конвертер для прод-сервисов.

8.5Обработка ошибок

Для повторов с задержкой и DLQ удобен неблокирующий подход через @RetryableTopic (Spring AMQP сам строит retry-топики/очереди) или ручная схема из темы 05 (TTL + DLX) с RepublishMessageRecoverer.

@RabbitListener(queues = QUEUE)
@RetryableTopic(attempts = "3", backoff = @Backoff(delay = 1000, multiplier = 2))
void handle(OrderCreated event) {
    process(event);   // при исключении Spring повторит, затем отправит в DLT
}

8.6Самопроверка

Какой класс Spring AMQP отвечает за отправку сообщений?

  • RabbitTemplate
  • @RabbitListener
  • ConnectionFactory
  • MessageConverter
RabbitTemplate — отправка (convertAndSend), @RabbitListener — приём.

Почему в проде нельзя оставлять дефолтный конвертер Spring AMQP?

  • Он использует Java-сериализацию — небезопасно и несовместимо между версиями
  • Он медленный
  • Он не поддерживает JSON
  • Он удаляет сообщения
Default — Java-сериализация. Нужен Jackson2JsonMessageConverter.

Чем acknowledge-mode=auto отличается от manual?

  • Ничем
  • auto быстрее
  • auto — Spring сам ack/nack; manual — вы сами вызываете basicAck/basicNack
  • manual не поддерживается
auto проще; manual даёт полный контроль над подтверждением.

Что делает @RetryableTopic?

  • Автоматически строит retry-очереди и DLT, повторяя обработку при исключении
  • Шифрует топик
  • Ускоряет доставку
  • Отключает ack
Spring AMQP сам создаёт retry-инфраструктуру и после попыток отправляет в DLT.
Какие три вещи нужно настроить для надёжной отправки?

Publisher confirms (publisher-confirm-type=correlated), durable-очередь и persistent-сообщения (через конвертер/декларацию), и JSON-конвертер вместо Java-сериализации.

Как Spring AMQP строит DLQ и повторы?

Либо декларативно через @RetryableTopic (попытки, backoff, DLT), либо вручную: очередь с x-dead-letter-exchange на парковку, парковка с TTL и обратным DLX (тема 05), а RepublishMessageRecoverer отправляет исчерпавшее попытки сообщение в DLQ.
