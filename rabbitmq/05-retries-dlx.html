Повторы и dead-letter (DLX)

Что делать с сообщением, которое не удалось обработать? Наивный requeue зацикливает его, а молчаливый ack — теряет. Правильная схема — повтор с задержкой через TTL и dead-letter exchange, и лишь после исчерпания попыток — в отдельную очередь для разбора.

5.1Dead-letter exchange (DLX)

DLX — обычный exchange, куда брокер отправляет сообщение при трёх событиях: потребитель отклонил без requeue, истёк TTL, или очередь переполнилась. Настроить можно на очередь (для всех её сообщений) или на сообщение.

$ rabbitmqadmin declare queue name=orders.dead durable=true
$ rabbitmqadmin declare queue name=orders durable=true \
    arguments='{"x-dead-letter-exchange":"","x-dead-letter-routing-key":"orders.dead"}'

Пустая строка exchange означает «default exchange», где routing key — имя очереди. Так отклонённое сообщение попадает в orders.dead.

5.2Повтор с задержкой

Чтобы повторить обработку через N секунд, используют связку «очередь-парковка с TTL → DLX обратно в рабочую очередь»:

ordersсообщение не обработалось (nack, requeue=false)→ DLX → orders.retryx-message-ttl=30s, DLX обратно в orders→ через 30 с → ordersповторная попытка 
# рабочая очередь: при отказе уводит в парковку
$ rabbitmqadmin declare queue name=orders durable=true \
    arguments='{"x-dead-letter-exchange":"","x-dead-letter-routing-key":"orders.retry"}'

# парковка: живёт 30 с, затем возвращает в рабочую
$ rabbitmqadmin declare queue name=orders.retry durable=true \
    arguments='{"x-message-ttl":30000,"x-dead-letter-exchange":"","x-dead-letter-routing-key":"orders"}'

5.3Dead-letter очередь

После N попыток сообщение должно уйти в DLQ (dead-letter queue), а не крутиться вечно. Число попыток обычно считают в заголовке сообщения (x-retries): на каждой итерации инкремент, при превышении — в DLQ.

void handle(Message msg) {
    int retries = msg.getRetries();               // из заголовка x-retries
    try {
        process(msg);
        channel.basicAck(tag, false);             // успех — удалить
    } catch (RetryableException e) {
        if (retries >= MAX) {
            channel.basicNack(tag, false, false); // в DLX/DLQ
        } else {
            msg.incrementRetries();
            channel.basicNack(tag, false, false); // в парковку с TTL
        }
    }
}
DLQ — не корзина Рост DLQ нужно алертить и разбирать: это сигнал о системной проблеме (битые данные, сломанный обработчик). Иначе «плохие» сообщения копятся незамеченными.

5.4Самопроверка

В каких случаях сообщение уходит в DLX?

  • Отклонено без requeue, истёк TTL или очередь переполнена
  • Только при удалении очереди
  • При каждом ack
  • При подтверждении продюсера
DLX срабатывает на nack/reject без requeue, на TTL и на переполнение очереди.

Как устроен повтор с задержкой в RabbitMQ?

  • Сообщение держат в парковочной очереди с TTL, по истечении DLX возвращает его в рабочую
  • Потребитель спит
  • Брокер ждёт таймер
  • Только через cron
Связка TTL + DLX даёт отложенный повтор без удержания потребителя.

Почему нельзя бесконечно requeue-ить плохое сообщение?

  • Оно замедлит сеть
  • Оно станет больше
  • Оно зациклится и займёт потребителя навсегда — нужен предел попыток и DLQ
  • Оно потеряется
«Ядовитое» сообщение нужно после N попыток отправить в DLQ, а не крутить вечно.

Что такое DLQ и как с ней работать?

  • Очередь «плохих» сообщений: алертить на рост, разбирать и переотправлять после исправления
  • Очередь для приоритетов
  • Временная очередь
  • Exchange fanout
DLQ накапливает необработанные сообщения; её рост — сигнал проблемы, требует процедуры разбора.
Объясните полную схему повторов с DLX.

Рабочая очередь при отказе (nack без requeue) отправляет сообщение через DLX в парковочную очередь с TTL. Парковка по истечении TTL через свой DLX возвращает сообщение в рабочую очередь. Счётчик попыток в заголовке ограничивает число повторов; при исчерпании — в DLQ.

Чем парковочная очередь отличается от DLQ?

Парковка — промежуточная очередь с TTL для отложенного повтора (сообщение вернётся в работу). DLQ — конечная очередь для сообщений, исчерпавших попытки (требуют ручного разбора).
