3.1Что написано на конверте IP

Главное в заголовке IP: адрес отправителя, адрес получателя, TTL — сколько ещё пересылок пакету разрешено (каждый маршрутизатор уменьшает на 1, на нуле пакет уничтожают — так блуждающие пакеты не живут вечно) и протокол внутри (TCP или UDP).

Главная мысль IP-заголовок — откуда, куда, сколько ещё можно ехать и что внутри.

3.2Адреса и подсети

IPv4-адрес — 4 числа от 0 до 255: 192.168.1.25. Его делят на две части: сеть (улица) и устройство (дом). Запись 192.168.1.0/24 значит: первые 24 бита (три числа) — улица, последнее число — номер дома. На такой улице 256 адресов (из них 254 для устройств). /16 — улица побольше (65 536 адресов), /32 — ровно один адрес.

Главная мысль /N — сколько бит занимает «улица». Чем меньше N, тем больше адресов в подсети.

3.4Напрямую или через шлюз

Компьютер 192.168.1.25/24 отправляет пакет
получатель 192.168.1.40 — та же улица (192.168.1.x)
→ доставлю самARP: «у кого 192.168.1.40? скажите MAC» — крик на всю улицу
ответ: «это я, мой MAC 3c:22:…» → кадр уходит прямо емуполучатель 8.8.8.8 — чужая улица
→ отдам шлюзу (роутеру) 192.168.1.1ARP узнаёт MAC роутера, кадр уходит ему,
а IP-адрес получателя в пакете остаётся 8.8.8.8

Маска говорит, что адресат рядом.

По IP соседа узнаём его MAC.

Всё далёкое — через шлюз по умолчанию.

MAC — следующего шага, IP — конечного адресата.

Главная мысль Свой — напрямую через ARP, чужой — через шлюз. IP конечный, MAC — следующего шага.

3.5Маршрутизация: сортировочные центры

Маршрутизатор — сортировочный центр. У него есть таблица маршрутов: «в такие-то сети — через такого-то соседа». Для каждого пакета он ищет самую точную подходящую запись (самый длинный префикс): маршрут в 10.1.2.0/24 важнее, чем в 10.0.0.0/8. Если ничего не подошло — маршрут по умолчанию (0.0.0.0/0). Маршрутизатор знает только следующий шаг, а не весь путь.

Главная мысль Каждый маршрутизатор знает лишь «куда дальше», выбирая самый точный маршрут.

В полной главе: 3.5 Маршрутизация

3.6ICMP, ping и traceroute

ICMP — служебные сообщения сети: «адресат недоступен», «время жизни истекло», «эхо-запрос». ping отправляет эхо и меряет время туда-обратно. traceroute хитро использует TTL: шлёт пакеты с TTL = 1, 2, 3…, и каждый маршрутизатор на пути, убивая пакет, отвечает «время истекло» — так видна вся цепочка. Учтите: многие узлы ICMP режут, и «звёздочки» в traceroute ещё не значат, что путь сломан.

Главная мысль ping — есть ли связь и сколько ждать; traceroute — через кого идёт путь.

3.7IPv6

IPv4-адресов всего около 4 миллиардов — на всех не хватило. В IPv6 адрес длиной 128 бит (записывается как 2001:db8::1) — адресов хватит на всё. NAT становится не нужен, вместо ARP — свой механизм поиска соседей, устройства могут сами придумать себе адрес. Сегодня работают обе версии параллельно.

Главная мысль IPv6 решает нехватку адресов. Сейчас IPv4 и IPv6 живут вместе.

3.9Проверьте себя

Сколько адресов в подсети /24?

  • 24
  • 65 536
  • 256
  • 1
Остаётся 8 бит на устройство: 2⁸ = 256.

Компьютер 10.0.0.5/24 отправляет пакет на 10.0.0.9. Как?

  • напрямую: узнаёт MAC через ARP
  • через шлюз
  • через DNS
  • через Интернет
Та же подсеть — доставка напрямую.

Какой маршрут выберет роутер для 10.1.2.7, если есть 10.0.0.0/8 и 10.1.2.0/24?

  • первый в списке
  • /8 — он больше
  • оба по очереди
  • /24 — самый точный (длинный префикс)
Правило самого длинного префикса.

Зачем в IP-пакете TTL?

  • для шифрования
  • чтобы пакет, заблудившийся в петле, не жил вечно
  • для скорости
  • для выбора порта
Каждый роутер уменьшает его на 1.

В traceroute видны «* * *». Значит ли это, что сеть сломана?

  • да, всегда
  • да, надо звонить провайдеру
  • не обязательно: многие узлы просто не отвечают на ICMP
  • значит, нет IPv6
