Как устроен Интернет: AS, BGP, CDN

Интернет — это не одна сеть, а ~75 000 независимых сетей, которые договорились обмениваться маршрутами. Как пакет из Минска находит сервер в Калифорнии, почему один неверный анонс может «уронить» половину Интернета и как CDN делает сайты быстрыми.

5.1Автономные системы

Автономная система (AS) — сеть под единым управлением с единой политикой маршрутизации и номером ASN: провайдер, облако, крупная компания, университет. Внутри AS маршрутизация — OSPF/IS-IS (тема 03), между AS — BGP.

  • Транзит — платная услуга «доставлю твой трафик куда угодно в Интернете».
  • Пиринг — взаимный бесплатный обмен трафиком между своими клиентами. Выгоден обеим сторонам, экономит транзит.
  • IXP (Internet Exchange Point) — коммутатор, в который включены десятки сетей и пирингуются друг с другом. Трафик между двумя сайтами одного города часто идёт через местный IXP, а не через другую страну.
  • Межконтинентальный трафик идёт по подводным оптическим кабелям; спутники — малая доля. Обрыв кабеля заметно меняет задержки целых регионов.

5.2BGP: маршрутизация по политикам

BGP (Border Gateway Protocol, работает поверх TCP 179) — протокол path vector: каждая AS сообщает соседям, какие префиксы через неё достижимы и через какую цепочку AS (AS_PATH).

5.3Anycast

Один и тот же префикс анонсируется из десятков точек мира. BGP приводит каждого пользователя к «ближайшей» (по BGP-метрике) точке. Так работают 1.1.1.1, 8.8.8.8, корневые DNS-серверы, CDN и защита от DDoS: атака распределяется по всем точкам. Ограничение — маршрут может смениться посреди соединения, поэтому anycast отлично подходит для UDP/DNS и коротких TCP-соединений, а для долгих сессий провайдеры принимают дополнительные меры.

5.4CDN

  • Ближе к пользователю: TCP- и TLS-рукопожатия завершаются на edge за 10 мс, а не за 150 мс до origin.
  • Кэш статики и разрешённых ответов API по правилам Cache-Control (тема 10).
  • Защита: поглощение DDoS, WAF, сокрытие адреса origin.
  • Даже некэшируемые запросы ускоряются: edge держит постоянные «прогретые» соединения с origin по оптимизированной магистрали.

5.5Сеть дата-центра

Современные дата-центры строят по схеме spine–leaf (Clos): каждый leaf-коммутатор (в верху стойки) соединён с каждым spine. Между любыми двумя серверами одинаковое число прыжков, нагрузка распределяется по множеству равноценных путей (ECMP). Главный трафик — не «пользователь ↔ сервер» (north–south), а между сервисами внутри (east–west): микросервисы, репликация БД, Kafka. Отсюда интерес к задержке внутри ДЦ и зонам доступности.

5.8Самопроверка

Что произойдёт, если автономная система по ошибке анонсирует чужой префикс более длинной маской (/24 вместо /22)?

  • Ничего, анонс отбросят
  • Замедлится DNS
  • Трафик к этому префиксу пойдёт к ней — longest prefix match сильнее всех атрибутов BGP (BGP hijack)
  • BGP выберет кратчайший AS Path
Так происходили крупные утечки маршрутов. Защита — RPKI (подписанные права на анонс) и фильтры у провайдеров.

Как работает anycast?

  • Один адрес рассылается всем узлам сети
  • Один и тот же префикс анонсируется из многих точек; маршрутизация сама приводит пакет в «ближайшую» по BGP
  • DNS возвращает разные адреса
  • Клиент перебирает серверы по списку
Так устроены корневые DNS-серверы, публичные резолверы 1.1.1.1 и 8.8.8.8, входные точки CDN.

Какую задержку CDN убирает в первую очередь?

  • Задержку распространения: контент отдаётся с узла рядом с пользователем
  • Время обработки запроса в базе данных
  • Время сериализации JSON
  • Задержку DNS
Расстояние — единственная составляющая, которую нельзя сократить оптимизацией кода. Плюс TLS-рукопожатие с ближним узлом и разгрузка origin.
Чем BGP отличается от OSPF?

OSPF — внутри одной AS, цель — кратчайший путь по метрике, все маршрутизаторы знают топологию. BGP — между AS, path vector: известны только пути из AS, выбор определяют политики (коммерческие отношения), и никто не видит всю топологию.

Как анонс /24 может «украсть» трафик сервиса, анонсирующего /16?

Маршрутизаторы выбирают самый длинный совпадающий префикс. Более специфичный /24 выиграет у /16 по всему Интернету, где он распространился, независимо от длины AS_PATH. Защита — RPKI ROA и фильтрация анонсов у провайдеров.

Почему CDN ускоряет даже некэшируемый API?

Рукопожатия TCP и TLS завершаются на ближайшем edge (несколько миллисекунд вместо RTT до origin). Edge держит постоянные мультиплексированные соединения к origin по сети CDN, часто с более удачной маршрутизацией и без медленного старта TCP.

Что такое anycast и почему он подходит для DNS?

Один адрес анонсируется из многих точек, BGP направляет клиента к ближайшей. DNS — короткий запрос-ответ по UDP, смена точки между запросами не важна; заодно нагрузка и атаки распределяются по всем точкам.
