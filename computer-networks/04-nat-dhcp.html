DHCP, NAT и домашняя сеть

Как устройство получает адрес, почему десятки устройств выходят в Интернет с одного IP, что из-за этого ломается в веб-приложениях и как эти механизмы выглядят в облаке. В конце — лабораторная на вашем домашнем роутере.

4.1DHCP: адрес за четыре сообщения

Кроме адреса DHCP раздаёт шлюз по умолчанию и DNS-серверы — поэтому подмена DHCP-сервера (rogue DHCP) позволяет перехватить весь трафик сети. В облаках VPC тоже раздают адреса через DHCP; «статический» адрес сервера там — это закреплённая аренда.

4.2NAT и PAT

Частные адреса (RFC 1918) не маршрутизируются в Интернете. NAT на границе сети подменяет адрес источника на свой публичный. Почти всегда это PAT (NAPT, «маскарадинг»): меняются и адрес, и порт, а соответствие хранится в таблице трансляций (conntrack).

Что NAT ломает и как это касается веб-разработки

  • Входящие соединения: пакет снаружи на 203.0.113.9:8080 роутер не знает кому отдать — записи нет. Нужен проброс портов (DNAT) или обходные техники.
  • Один IP — много людей: офис, мобильный оператор, CGNAT. Лимиты по IP (rate limiting, блокировки) задевают всех пользователей за NAT. Используйте идентификатор пользователя/токен, а IP — как вспомогательный сигнал.
  • Таймауты трансляций: запись о простаивающем соединении удаляется (для TCP минуты–часы, для UDP — десятки секунд). Долгоживущие простаивающие соединения (WebSocket, пул соединений к БД через NAT) рвутся молча. Лечится keep-alive чаще таймаута (тема 12).
  • IP клиента за прокси: сервер видит адрес NAT или балансировщика. Настоящий IP передают в X-Forwarded-For / Forwarded или PROXY protocol — и доверять этому заголовку можно только от своих прокси.

4.3CGNAT, проброс портов, NAT traversal

CGNAT (carrier-grade NAT): IPv4 не хватает, и провайдер ставит ещё один NAT у себя. Ваш роутер получает «внешний» адрес из 100.64.0.0/10 или частного диапазона, а в Интернет вы выходите с общего адреса провайдера. Проброс портов на домашнем роутере тогда бесполезен: входящий трафик останавливается на NAT провайдера. Решения: услуга «белого» (публичного) IP у провайдера, IPv6, туннель (Tailscale/WireGuard к VPS, Cloudflare Tunnel).

Проброс портов (DNAT)

Правило «WAN:8443 → 192.168.1.10:443». Для домашнего сервера. Открывайте минимум портов и не выставляйте наружу админки роутера, RDP, SSH с паролем.

UPnP / NAT-PMP

Приложения сами просят роутер открыть порт. Удобно для игр и торрентов, но любая вредоносная программа в сети может сделать то же самое. Безопаснее выключить.

Как два клиента за NAT соединяются напрямую (WebRTC)

  1. STUN: клиент спрашивает внешний сервер «с какого IP:порта ты меня видишь?» — узнаёт свой публичный адрес.
  2. Клиенты обмениваются кандидатами-адресами через сигнальный сервер (ICE).
  3. UDP hole punching: оба одновременно шлют пакеты друг другу; каждый NAT видит исходящий пакет, создаёт запись, и встречный пакет проходит.
  4. Если NAT «симметричный» (новый внешний порт на каждого получателя) — дыра не пробивается, трафик идёт через ретранслятор TURN.

4.4NAT в облаке и исчерпание портов

Сервисы в приватных подсетях выходят в Интернет через NAT Gateway. У одного публичного IP ~64 000 портов на каждую комбинацию «адрес и порт назначения». Если сотни подов одновременно открывают короткие соединения к одному API (например, платёжному шлюзу) без переиспользования, порты кончаются: ошибки подключения при нормальной нагрузке на CPU. Лечится пулом соединений с keep-alive (тема 12), несколькими IP на NAT, VPC endpoint/private link для облачных сервисов.

4.5Лабораторная: ваша домашняя сеть

  1. Откройте веб-интерфейс вашего роутера Netcraze (адрес шлюза из ipconfig/ip route, обычно 192.168.1.1). Найдите список DHCP-клиентов: адреса, MAC, время аренды. Закрепите за своим ПК постоянный адрес.
  2. Найдите на странице состояния интернет-подключения WAN-адрес роутера.
  3. Узнайте адрес, с которым вас видит Интернет: 
    $ curl -4 ifconfig.me
$ curl -6 ifconfig.me      # есть ли у вас IPv6 от провайдера?
  4. Вывод: если WAN-адрес роутера совпадает с публичным — у вас «белый» IP и проброс портов будет работать. Если WAN-адрес из 100.64.x.x, 10.x, 172.16–31.x — вы за CGNAT провайдера (Unet.by), и для входящих подключений нужен публичный IP от провайдера или туннель.
  5. Посмотрите таблицу активных соединений NAT, если интерфейс её показывает, и найдите в ней своё SSH- или браузерное соединение.

4.6Интерактив: таблица трансляций NAT

Симулятор PAT (NAT с подменой портов)

Домашний роутер: внутренняя сеть 192.168.1.0/24, один публичный адрес 203.0.113.7. Для наглядности у роутера всего 4 свободных порта: 40001–40004.

Попробуйте: ноутбук и телефон используют один и тот же исходный порт 51000 — роутер разводит их по разным внешним портам. Создайте больше четырёх соединений, чтобы увидеть исчерпание. В реальности портов ~64 000 на пару «публичный адрес — адрес:порт назначения».

4.7Самопроверка

Почему два устройства за одним NAT могут одновременно открыть соединение к одному серверу с одинаковым исходным портом?

  • Не могут
  • NAT назначает каждому соединению свой внешний порт и хранит соответствие в таблице
  • Сервер различает их по MAC-адресу
  • У них разные TTL
PAT: уникальность обеспечивает пара «внешний адрес : внешний порт».

Соединение с БД простаивало час, следующий запрос завис на минуты. Причина?

  • БД перезапустилась
  • DNS устарел
  • NAT или файрвол на пути удалил запись о соединении; пакеты молча отбрасываются, и TCP ретранслирует их до таймаута
  • Переполнился пул потоков
Лечение: keepalive чаще таймаута простоя, maxLifetime у пула, таймауты сокета.

В каком порядке идут сообщения DHCP при получении адреса?

  • Discover → Offer → Request → Ack
  • Request → Offer → Ack → Discover
  • SYN → SYN-ACK → ACK
  • Offer → Discover → Ack → Request
DORA. Первые сообщения широковещательные — у клиента ещё нет адреса.
Почему DHCP Discover и Request — широковещательные?

У клиента ещё нет IP-адреса и он не знает адрес сервера. Request повторно рассылается всем, чтобы серверы, чьи Offer отклонены, освободили зарезервированные адреса.

Ваш rate limiter банит по IP, и после запуска мобильного приложения поступают жалобы. Что происходит?

Мобильные операторы и CGNAT выводят тысячи абонентов через небольшое число публичных IP. Лимит на IP срабатывает на всех. Нужно лимитировать по идентификатору пользователя, токену, устройству; по IP — только мягкие лимиты против анонимного трафика, с учётом IPv6 /64 как одного «пользователя».

Соединение с WebSocket раз в несколько минут простоя молча рвётся. Почему и что делать?

Промежуточный NAT, файрвол или балансировщик удаляет запись о простаивающем соединении по таймауту. Пакеты после этого никуда не доходят, а стороны узнают об этом только при следующей отправке. Решение — ping/pong или keep-alive чаще самого короткого таймаута по пути (часто ≤ 30–60 с) и переподключение с экспоненциальной паузой.

Что такое CGNAT и как определить, что вы за ним?

NAT на стороне провайдера: ваш роутер получает непубличный WAN-адрес, а в Интернет вы выходите с общего адреса провайдера. Признак — WAN-адрес роутера из 100.64.0.0/10 или RFC 1918 и/или он не совпадает с адресом, который показывает внешний сервис.
